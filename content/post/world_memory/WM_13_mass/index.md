## 1. 这篇论文解决什么问题

### 1.1 多人世界模型的三个结构性症状

[WM 01](../WM_01_why_memory/) 里把视频世界模型写成 $p(o_{t+1:T}\mid o_{t-k:t}, a_{t-k:t})$：**循环记忆寄生在视觉隐变量里**。单玩家时无所谓；一到多人，这个设计一次爆出三个症状：

| 症状 | 机制 | 代价 |
|------|------|------|
| **冗余计算** | 每个玩家的视图各带一份循环历史，同一片世界被编码一千遍 | 模拟成本正比于**观看人数**而非世界本身 |
| **视图不一致** | 各视图的视觉历史独立演化，同一实体可以同时被两台相机看成两种状态 | 跨视图分歧不可修（没有仲裁者） |
| **扩展性差** | 上下文窗口装不下千人世界的联合历史 | 人数一多先糊后崩 |

论文开篇一句话点破根源：多人模拟需要的是「**一个属于世界而非属于任何相机的循环状态**」。既有多人世界模型（Gamma-World、MultiWorld、MultiGen、WanToFight）用联合生成或共享视觉表示做协调——共享的仍然是**视觉的东西**，没有一个把 typed 权威状态同时当循环记忆与同步对象。

### 1.2 药方：把游戏服务器的合同搬进来

在线游戏三十年前就解决过这个问题。游戏网络架构（论文引 Bernier 2001 的经典 GFC 演讲）的合同是：

| 游戏服务器架构 | MASS 的对应物 |
|---------------|--------------|
| 权威服务器推进**一份**规范游戏状态 | 学习的 **Logic Engine** 从联合动作推进全局 typed 状态 |
| 客户端收**版本化快照**，本地预测补延迟 | 预测状态打版本号分发；更新断流时客户端用同一个 Logic Engine 本地续推 |
| 每个客户端渲染自己的相机 | **Rendering Engine** 从共享状态按任意相机按需出视图 |
| 世界模拟一次，与客户端数无关 | 转移每 tick 跑一次；渲染按请求付费 |

两处「学习」替换了「手写」：转移函数 $F_\theta$ 是学的（rollout 全程**零原生引擎调用**），渲染器 $R_\phi$ 是学的。中间那份状态是**显式、typed、可直接评估**的——这是与 [WM 12 StatePlay](../WM_12_stateplay/)（状态由模型预测、误差直通世界）和 WM 11（LLM 在线编排）的分水岭。

### 1.3 五级梯度里站哪一级

| 级 | 状态演化机制 | 论文 |
|---|------------|------|
| 1 | monitor 快进 | WM 10 LiveWorld |
| 2 | LLM 编排 | WM 11 WorldDirector |
| 3 | 双分支联合预测 | WM 12 StatePlay |
| **4** | **学习的逻辑引擎 + 权威共享状态** | **本篇 MASS** |
| 5 | 程序内核（转移不再学习） | WM 14 Programmable WM |

第四级的关键词是**权威**（authoritative）：论文特意定义它为「所有客户端采纳的唯一状态版本，**与预测精度无关**」——部署时预测状态就是世界本身，一致性优先于对某个外部真值的忠实。这个细节 §6.7 的 toy 会给出定量版本。

## 2. 所需背景最小集

- [WM 01 §1.2](../WM_01_why_memory/)：状态/观测两条方程 $s_{t+1}=f(s_t,a_t,\omega_t)$、$o_t=r(s_t,c_t)+\epsilon_t$。MASS 是整个系列里把这两条方程**拆得最彻底**的实现：$f$ 归 Logic Engine，$r$ 归 Rendering Engine，中间以 typed 状态为唯一接口；
- [WM 08 WRBench](../WM_08_wrbench/)：「世界模型缺持久状态内核」——MASS 的 typed 状态就是那个内核的多人版（论文直接引 WRBench 作动机：事件离开视野后模型不再推进）；
- [WM 12 StatePlay](../WM_12_stateplay/)：状态预测分支已证明显式状态能涨机制一致性，但状态仍是「模型的输出」；MASS 把状态升级为「系统的唯一事实来源」；
- 序列建模：decoder-only Transformer + 自回归交叉熵（不展开，任何 LM 教程皆可）；
- 无需视频扩散背景——本篇渲染器是 U-Net 而非扩散（这也是它与 WM 04/05 的有趣的差异，见 §8）。

## 3. 方法总览：一个 tick 的完整旅程

**文字版流程图**（严禁 ASCII，用编号步骤 + 表格）：

| 步骤 | 做什么 | 关键约束 |
|------|--------|---------|
| ① 声明 | 每个游戏交一份 **schema**：实体种类、字段、实例数。架构不变，只换 tokenizer/嵌入/权重 | schema 定义「什么算合法状态」，**不含任何转移规则** |
| ② 拆记录 | 当前状态拆成 $K_g$ 条 typed 记录；每条附上邻域窗口 $c_t^i$（9×9 锚定格）、所属玩家动作、外生输入份额 | 空间锚定：蛇记录锚在蛇头 |
| ③ 推进 | Logic Engine（一个 5.66M 的 decoder-only Transformer）**记录级并行**地自回归预测全部下一条记录 | 自注意力只在记录内部；记录间交互全部经由 $c_t^i$ |
| ④ 装配 | schema 掩码 + 确定性选择器把 token 流装配回 $\hat{s}_{t+1}$ | 结构有效性 by construction；版本号 +1 并发布 |
| ⑤ 渲染 | 每个请求的相机：先做确定性投影 $P_i(\hat s_t)$（占据/语义/归属/深度 → 16 通道张量），残差 U-Net 出 RGB | 渲染器**不读 RGB 历史**——只读这一份状态 |
| ⑥ 断流兜底 | 服务器更新断流时，客户端用**同一个** Logic Engine 从最新版本状态本地续推（自己的动作照给，别人填 no-op） | 新版本到达即整体替换，无需修正网络 |

Snake 大规模实例贯穿全文：512×512 场地，1,024 条蛇记录 + 4,096 个食物桶记录（8×8 分桶）+ 1 条全局记录 = **每 tick 5,121 条记录**，一次转移推进，10,000 步不断。

## 4. 核心原理完整推导

### 4.1 状态与 schema：表示归声明，转移归学习

一个游戏的 schema 是实体种类的声明表：

$$
\Sigma_g=\big\{(\text{kind}_j,\ \text{fields}_j,\ \text{count}_j)\big\}_{j=1}^{J_g}
\tag{Eq.1}
$$

每 tick 的世界状态是全部记录的有序集：

$$
s_t=\big(\rho_t^1,\dots,\rho_t^{K_g}\big),\qquad K_g=\sum_j \text{count}_j
\tag{Eq.2}
$$

schema 只说「什么是一个合法状态」——蛇有几节身体、朝向四选一、食物坐标必须有序去重。**蛇怎么长、箱子怎么推、碰撞怎么解，全部不写**，从录制的轨迹里学。表示是声明式的，转移是学习式的——这是与 WM 14（转移也写成程序）的分界线。

### 4.2 记录级因子分解：扩展性的来源

把每条记录 token 化成一个短前缀：

$$
u_t^i = T_{\Sigma_g}\big(\rho_t^i,\ c_t^i,\ a_t^{\pi(i)},\ e_t^i\big)
\tag{Eq.3}
$$

其中 $c_t^i$ 是从**当前共享状态**算出的邻域窗口，$a_t^{\pi(i)}$ 是该记录所属玩家的动作（蛇记录拿蛇头动作；食物桶没有主人），$e_t^i$ 是外生输入（引擎录制的随机性，如食物刷新——**重放而非预测**）。世界级转移

$$
\hat s_{t+1}=F_\theta(\hat s_t,\ a_t,\ e_t)
\tag{Eq.4}
$$

被因子分解成记录级自回归：

$$
p_\theta(s_{t+1}\mid s_t,a_t,e_t)\;\approx\;\prod_{i=1}^{K_g}\ \prod_j\ p_\theta\big(y_{t+1}^{i,j}\ \big|\ u_t^i,\ y_{t+1}^{i,<j}\big)
\tag{Eq.5}
$$

**自注意力被限制在每条记录的 token 序列内**；记录之间零注意力。这条设计换来两个性质：

| 性质 | 为什么 |
|------|--------|
| 5,121 条记录可一次推进 | 记录无互相注意力 → 训练/推理都按记录自由批处理 |
| 全局一致性不丢 | 交互（相邻蛇头相撞、吃食物）通过 $c_t^i$ 进来——而 $c_t^i$ 取自**装配后的共享状态**，上一 tick 的所有记录都参与构成它 |

代价也明确：**超出邻域窗口的交互进不了上下文**（9×9 半径 4 的格子）——远程事件（隔半张地图的因果链）对单条记录不可见，只能靠多 tick 的状态闭环间接传播。论文的游戏（Snake/Pac-Man 等局部交互游戏）恰好在这个半径内。

### 4.3 训练目标：一步 teacher forcing 的 token 交叉熵

$$
\mathcal{L}_{\text{logic}}=-\sum_{i=1}^{K_g}\sum_j \log p_\theta\big(y_{t+1}^{i,j}\ \big|\ u_t^i,\ y_{t+1}^{i,<j}\big)
\tag{Eq.12}
$$

就是语言模型的损失，训练上下文只有**一步转移**（20k 次更新）。推理时贪心解码、每步把**自己的预测**喂回去——没有任何原生转移调用、状态替换或规则修补。注意这里没有 [WM 03 Memory Forcing](../WM_03_memory_forcing/) 那类训练-推理错配修正：一步 teacher forcing 直接上，长程靠 typed 载体自身的稳定性扛（§6.3 显示确实扛到了 4,096 步）。

### 4.4 结构有效性 ≠ 语义正确性：掩码只保格式

schema 派生的解码掩码保证：tick 字段只出 nibble 范围、朝向只出四个方向、食物坐标强制有序去重、蛇身格不重复。**但移动合法性、碰撞、生长、死亡、收集全部是学出来的**，不在掩码里。于是评测拆成两层：结构有效性（矛盾率）几乎 by construction 为零，语义准确率（字段对不对）才是模型的本事——§6.2 的直接状态评估把这两层分得很开。

### 4.5 渲染：从共享状态按需因子分解

$$
\hat o_t^i = R_\phi\big(P_i(\hat s_t),\ \kappa^i\big),\qquad
p_\phi(\hat o_t^{C_t}\mid \hat s_t, \kappa^{C_t})=\prod_{i\in C_t}p_\phi(\hat o_t^i\mid P_i(\hat s_t),\kappa^i)
\tag{Eq.7/8}
$$

相机 $i$ 先拿到确定性投影 $P_i$（把可见格的占据、语义角色、归属、玩家身份、深度几何光栅化成 16 通道张量），U-Net 只负责「上色」。观测按相机**条件独立**分解——每个视图读同一份 $\hat s_t$，跨视图一致性是**构造保证**而非学习目标。相机可以随时增删、移动、换分辨率，世界转移一个字都不用改。

### 4.6 服务器负载：成本与观众数解耦的定量表述

$$
T_{\text{server}} = T_{\text{logic}}(N) + C\cdot t_{\text{sync}}(S)
\tag{Eq.9}
$$

$N$ 个实体的转移算一次，$C$ 个客户端各自付一份快照同步 $t_{\text{sync}}(S)$，渲染在客户端本地。**世界的模拟成本里没有相机数量**——对照逐视图方案：每视图一套循环历史，转移次数 = 相机数。

<summary><b>数字标本：matched Snake 一步的 447 个 token</b></summary>

matched 基准（48×48 场地、≤8 玩家槽）把整个状态压进一条序列，输入前缀 447 token 的构成：

| 段 | token 数 | 内容 |
|----|---------|------|
| 状态段 | 421 | tick（4 个 nibble）+ 64 个有序食物格 + 玩家数 + 8 个玩家槽（每槽 44：体长 1 + 身体格 ≤40 + 朝向 1 + 存活 1 + 死亡锚 1；空槽全 padding） |
| 动作段 | 8 | 8 个玩家槽的动作 token |
| 外生段 | 13 | tick + 刷新数 + ≤8 个刷新格（补 padding） |
| 输出标记 | 1 | 模型从这里开始自回归解码下一状态 |

两个值得看的细节：**空玩家槽是全 padding 的 typed 记录**，不是序列里的洞——解码器不用处理变长；**外生段在 matched 基准里是「兼容性载荷」**（录制早于引擎原生外生 token 的旧语料），大规模实验才换成引擎原生的前瞻刷新 token。

大规模 Snake 的记录级布局（论文表 A.1）：蛇记录最长 513 token（身体桶 + 邻域），Crate Pusher 2,583 条 × 124，Pac-Man 2,049 条 × 2,590（16×16 豆子块行还附带最多 64 条局部 Pac-Man/幽灵记录）。

</details>

<details>
<summary><b>为什么「权威」与「准确」要分开定义</b></summary>

论文的原话：权威状态是「所有客户端采纳的唯一状态版本，**无论预测精度如何**」（regardless of prediction accuracy）。这不是遮羞——它是部署语义的需要：

- 真值只在基准里有。部署时没有引擎在旁边对照，**预测状态就是世界**：两台相机必须看到同一个世界，这个「同」比「对」更根本；
- 于是评测拆成两个正交轴：跨视图分歧（一致性，部署生命线）与对引擎真值的状态恢复（基准里测的准确率）。§6.7 toy 的 Panel B 会给出这两个轴**可以反向**的定量例子：逐视图方案在「自己看得见的地方」更准、但互相矛盾。

这与 [WM 01](../WM_01_why_memory/) 的信念状态视角严丝合缝：MASS 维护的不是「对世界的正确信念」而是「一份被全员采纳的信念」——一致性是协议性质，准确率是模型性质，两者解耦后才能分别优化。

</details>

## 5. 训练与推理细节

| 项 | 设置 |
|----|------|
| Logic Engine | decoder-only Transformer，宽 256、6 层、8 头、MLP 扩张 4、绑定 token 嵌入；matched 版 **5.66M** 参数，最长 1,024 |
| 优化 | AdamW lr 2×10⁻⁴、wd 10⁻⁴、batch 8、梯度裁剪 1.0、bf16、**20,000 次一步 teacher forcing 更新** |
| 解码 | 纯贪心；预测 token 全量回灌（零引擎调用/状态替换/规则修补） |
| Rendering Engine | 64 通道 stem（16 语义通道 + 坐标/梯度特征）→ 3 次下采样 → 5 个膨胀残差块 → 3 次跳连上采样 → sigmoid RGB；损失 = 物体加权 Charbonnier + 多尺度 L1 + 梯度对齐 + SSIM + 饱和度，**无感知损失无对抗** |
| 渲染训练 | 真值状态 + 录制相机 ↔ 离线目标帧配对；推理时**不收目标像素、不收 RGB 历史** |
| matched 数据 | 48×48 多智能体 Snake：N∈{2,4,8} 各 128 训练 episode（192 转移/条），val 16 / test 32 条（160 转移/条）；成像评测用 N=2、8 条 test episode、双同步相机、128 tick、128×128 |
| 基线 | MultiWorld（官方代码重训，5.60B 可训练参数、官方 35 epoch）；B-PV 逐视图视频预测器 8.13M；B-SL 共享视觉 latent 12.72M；**B-UN 稠密联合状态 U-Net 3.69M（保留 MASS 其余管线、只换载体——关键消融）**；内部基线同 20k 预算 |
| 相机协议 | 相机路径**取自录制真值**而非各方法自己的预测——所有方法在完全相同的视角位置上比较 |

外生输入的处理值得单独记：食物刷新这类随机性**不预测**，作为引擎录制的 token 随动作流重放。模型只学「世界对输入怎么响应」，不学「输入本身怎么来」——把不可学的随机性从学习目标里干净地剥离。

## 6. 实验与消融

### 6.1 主表：六项领先、一项构造保证

matched Snake，128 tick rollout（论文 Table 2）：

| 指标 | MASS | MultiWorld | B-PV | B-SL | B-UN |
|------|------|-----------|------|------|------|
| LPIPS ↓ | **0.098** | 0.277 | 0.397 | 0.396 | 0.123 |
| Parser ↑（状态恢复） | **0.764** | 0.067 | 0.128 | 0.083 | 0.000 |
| Count ↑ | **0.234** | 0.006 | 0.141 | 0.109 | 0.051 |
| Position ↑ | **0.355** | 0.250 | 0.286 | 0.180 | 0.002 |
| Event F1 ↑ | **0.552** | 0.065 | 0.542 | 0.528 | 0.007 |
| X-view ↓（跨视图分歧） | **0.000** | 0.984 | 1.000 | 1.000 | 0.051 |
| Invalid ↓ | 0.177 | 0.981 | **0.052** | **0.052** | 1.000 |

三个读法：

- **状态恢复 0.764 vs 最强视频基线 0.128**——近 6 倍。Parser 是冻结解析器从渲染帧恢复的前景 F1：typed 载体滚 128 步后仍有一多半可恢复世界内容；
- **X-view 0.000 是构造保证的验证**：两台相机解码同一份预测，学习出的渲染器没有引入分歧（数值 0 不是巧合，是架构性质的实测确认）；
- **B-UN 的 LPIPS 陷阱**：感知距离 0.123 全场第二好，Parser 却是 0.000——**帧长得像 ≠ 帧里有一个可恢复的世界**。这是全系列反复出现的主题（[WM 08](../WM_08_wrbench/) 的「外观对、事件错」），MASS 用受控消融把它钉死了。

### 6.2 直接状态评估：载体决定身份存亡

把渲染拿掉，直接比预测状态与引擎状态（论文 Table B.2/B.4，24 条验证 episode）：

| 载体 | H=1 位置准确率 | H=32 | H=128 | 矛盾率 |
|------|--------------|------|-------|--------|
| 独立头 CNN | 2.7% | 0.1% | 0.0% | **100%** |
| 联合 U-Net（B-UN） | 0.0% | 0.0% | 0.0% | **100%** |
| RSSM | 0.0% | 0.0% | 0.0% | **100%** |
| **typed token（MASS）** | **99.1%** | **90.2%** | **72.3%** | **0%** |

最扎眼的对照：稠密载体**语义准确率**一步时都在 91% 以上（字段大体对），但**位置准确率**全部 ≤2.7% 且每步自相矛盾。论文的诊断值得全文引用：稠密网格无法跨 tick 保持实体身份——**同一个格子每步装的是不同实体**，而 U-Net 没有任何机制追踪「哪个是哪个」。字段级的「对」掩盖了实体级的「全错」。

<details>
<summary><b>typed 也要付的账：延迟、全状态精确率、训练预算敏感性</b></summary>

- **延迟**：typed Transformer 45.55 ms/步 vs 稠密基线 3.07–3.94 ms——慢一个数量级（自回归逐 token 解码 vs 一次前向）。论文的立场：20 Hz tick 预算内（matched 规模）够用，且记录可并行批处理；
- **全状态精确率**：H=1 只有 41.7%——一步之内全部字段全对的概率。错在哪？N=8 时**同时多处食物更新**这类稀疏并发事件（不是结构矛盾：矛盾率为 0）。token 顺序也有影响：玩家段挪到食物段前，H=1 精确率 41.7%→45.8%，但 H=32 位置准确率 90.2%→80.4%——序列化顺序本身是个超参；
- **训练预算**：20k→100k 更新，H=1 精确率到 45.8%，H=32/H=128 位置准确率到 96.4%/83.0%。按观测刷新率加权的重采样则**降低** active 准确率——均匀采样保留为正式配置，其余按固定诊断报告（不做事后挑选）。

</details>

### 6.3 规模与长程：千蛇万步，结构不塌

- **1,024 玩家实体推进 10,000 个循环步**（512×512 Snake，每 tick 5,121 条记录）；
- 长程压力测试（无真值延续，H=4,096）：N∈{2,4,8} 全部保住完整 roster、64 个食物槽、**零结构无效步、零崩溃**；状态多样性在 277–306 个唯一状态后进入循环吸引子（20k 检查点），100k 检查点两个初始化分别达到 1,850 / 302 个唯一状态——**训练更久能显著拉长多样演化**，且初始状态的影响很大；
- 跨游戏：换 codec 与数据即可跑 Breakout（H=1 active-token 99.5%、全状态精确 84.5%）、Tile Merger（H=128 仍保 72.5% active-token 且全程结构有效——把「结构有效性」与「随机格子精确匹配」分得很开）。

### 6.4 成本与观众数解耦的实测

固定 tick 140 的预测状态，单张 H100 上扫请求视图数 $C_r$：渲染总成本 189.6 ms（1 视图）→ 842.4 ms（1,024 视图），其中学习 CNN 分量 4.4 → 379.7 ms。**学习转移零变化**——视图数翻一千倍，世界的模拟工作量纹丝不动。这就是 Eq.9 的实测版。

### 6.5 客户端预测：断流时「自己那格永远对」

模拟服务器更新断流 1–8 步（论文 Table 4）：

| 断流步数 k | 1 | 2 | 4 | 8 |
|-----------|---|---|---|---|
| 视野内一致率（oracle 联合输入） | 1.000 | 1.000 | 1.000 | 1.000 |
| 视野内一致率（只有本地动作） | 0.815 | 0.652 | 0.604 | 0.429 |
| 本地化身位移（格） | 0.00 | 0.00 | 0.00 | 0.00 |

oracle 条件全 1.000 ⇒ 衰减**全部**来自「不知道别人的动作」，不是转移本身；本地化身位移恒 0——自己控制的角色永远不需要位置修正。这正是游戏客户端预测三十年的标准体验，第一次由学习式世界模型复现。

### 6.6 SRSC 四轴分解：错误归因的架构红利

显式状态接口让 MASS 能做四路对照（教师渲染真值状态 / 教师渲染预测状态 / 学习渲染真值 / 学习渲染预测），VLM 逐轴打分。关键结果：**Renderer-GT 轴（去掉 Logic Engine）跨 1,200 步平稳无衰减**（Snake 63.8–75.0 波动、Crate Pusher 基本满分）——语义衰减几乎全部来自学习转移而非渲染器。评测循环性（用 VLM 评生成模型，[WM 01 §7](../WM_01_why_memory/) 的老问题）的防御：logic 轴分数与程序化状态指标相关 **r=0.962**，且确定性指标做定量结论、VLM 只做归因。

### 6.7 toy 实验：载体与协议的两个受控对照

脚本 `scripts/world_memory_experiments/wm13_toy.py`（24×24 环面、40 实体、共享质量的预测器：每实体每步 1% 概率猜错位移、20 episodes）。

**Panel A（载体对照，对应 B-UN 消融）**：同一份转移噪声，typed 载体（槽位↔实体永久绑定）vs 稠密载体（只发布格子集合，身份靠下游贪心最近邻重关联）：

| tick | 位置准确率 typed / dense | 身份准确率 typed / dense |
|------|------------------------|------------------------|
| 50 | 0.820 / 0.067 | 1.000 / 0.051 |
| 100 | 0.687 / 0.016 | 1.000 / 0.017 |
| 200 | 0.496 / 0.010 | 1.000 / 0.014 |
| 300 | 0.376 / 0.004 | 1.000 / 0.001 |

typed 的 0.687@100 与论文的 72.3%@128 意外地同量级；dense 的崩溃机制在 toy 里看得一清二楚：**预测撞格 → 格子集合去重丢链 → 槽位冻结后重关联到邻近的别的实体 → 永久换链**。身份一旦换过，没有任何东西能换回来——载体里没有「我是谁」。

**Panel B（协议对照，对应 B-PV 基线）**：权威共享（转移一次、人人读同一份）vs 逐视图历史（6 个视图各自外推看不见的实体；视野内观测**完美**——对它是宽容假设）：

| tick | 跨视图分歧 Auth / PerView | 位置 MAE（格）Auth / PerView |
|------|--------------------------|----------------------------|
| 50 | 0.000 / 0.347 | 0.865 / 0.411 |
| 100 | 0.000 / 0.416 | 1.466 / 0.523 |
| 200 | 0.000 / 0.430 | 2.296 / 0.571 |
| 300 | 0.000 / 0.435 | 2.968 / 0.596 |

第二列藏着一个反直觉的事实：**逐视图的位置 MAE 反而更低**（视野内被观测不断刷新、误差封顶 0.6 格；权威服务器对外部真值的漂移单调涨到 3 格）。但两列要一起读——逐视图用 35–44% 的跨视图分歧买来了局部精度，权威共享牺牲对「某个真值」的忠实换来了**全员零分歧**。这就是 §1.3「权威与准确分开定义」的定量版本：**局部精度与全局一致性是正交属性，只有先决定要哪个，才能谈误差大小**。成本另计：转移执行次数 1 vs 6（=相机数）。

## 8. 局限与思考

1. **2D 网格游戏的世界**。Snake/Pac-Man 的状态是离散格子 + 少量字段；连续物理、开放域外观都还没碰（结论自陈：3D 与更丰富交互是 future work）。渲染器是 U-Net 而非视频扩散——风格化小游戏够用，照片级场景要等 WM 14 那条「生成式渲染」路线；
2. **学习转移的误差依旧累积**。位置准确率 72.3%@128、SRSC logic 轴 H=600 后崩到 1.2——权威保证的是「大家一致地错」，不是「不错」。第四级的软肋正好是第五级的动机；
3. **记录级因子分解 = 局部性假设**。交互全部经 9×9 邻域窗口进上下文；窗口外的因果（隔屏狙击、全局经济）对单条记录不可见。游戏选型恰好局部，但「因子化半径」本质上是被架构固定的先验；
4. **typed 慢一个数量级**（45.55 ms vs 3.3 ms）。可批处理、可并行，但自回归逐 token 解码在实时线上仍是负担——与 [WM 04 RELIC](../WM_04_relic/)（蒸馏换实时）的取舍方向相反：MASS 用延迟换可评估性与同步能力；
5. **每游戏一份 schema + 轨迹**。架构复用是真的（换 codec 即换游戏），但数据工程没消失——谁写 schema、谁录轨迹，是成本转移而非成本消灭（WM 14 把这一步交给 coding agent）；
6. **评测的两个软肋**：matched 基准的 Snake 是自家生成；VLM judge 是 Qwen3.5-27B（虽做了 r=0.962 相关性校准与确定性指标主结论的分层）。

**面试可能被问的三个问题**：typed 载体 vs 稠密 latent，本质差别是什么？（身份的载体：记录槽位是身份的一等公民，格子里没有）；权威状态错了怎么办？（部署语义下「一致地错」可接受、且可评估可归因——SRSC 四轴；对真值的错靠更大模型/更多数据压，不靠协议）；这个架构为什么撑得住多人？（转移次数与相机数解耦 + 一致性 by construction，两个都是架构性质不是学习性质）。
