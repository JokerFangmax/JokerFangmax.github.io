## 1. 这一篇解决什么问题

任务：交互式长视频生成（interactive long video generation）——用户给相机控制信号，模型流式地生成视频。论文开篇给的记忆失败样本是 Oasis：能生成很长的 Minecraft 视频，但「先左转再立刻右转」就会看到完全不同的场景。这个病在 Genie 2、GameFactory 等一排 SOTA 上普遍存在：**帧间连续性有，长程场景一致性没有**。

论文的诊断与 [WM 02（VMem）](../WM_02_vmem/) 完全同源：这些方法生成每帧时只能引用**有限窗口里的最近几十帧**（Diffusion Forcing 类），窗口外的历史彻底丢失——走远再回来时，真正相关的帧早被挤出窗口。而如果每帧都能引用**全部历史帧**，生成模型就可以主动从历史里挑相关内容复制进当前帧——**全部历史上下文本身就是记忆**。

「全历史当记忆」直觉上对，但论文列出三条不行的地方：

| 困难 | 内容 |
|------|------|
| 算力 | 全历史进注意力，开销随视频长度线性（注意力平方）增长 |
| 浪费 | 与当前帧相关的历史只占一小部分，算其余全是白算 |
| 噪声 | 无关历史帧是干扰项，反而妨碍当前帧生成 |

于是答案是**记忆检索（Memory Retrieval）**：从全历史里挑出真正相关的一小撮帧当条件。Context as Memory 的完整方案只有两加一：

1. **存储**：生成的上下文帧**原样存储**（frame format，无特征嵌入提取、无 3D 重建等后处理）；
2. **条件注入**：上下文与待预测帧**沿帧维拼接**进输入，无外挂控制模块（adapter / cross-attention 都不要）；
3. **检索**：利用相机控制带来的位姿标注，按 FOV（Field of View，视场）重叠挑相关帧。

一句话总结：**Context as Memory = 原始帧存储 + 帧维拼接的条件学习 + 相机轨迹 FOV 检索，在 UE5 长视频数据上教会 1B T2V 模型「记住看过的场景」，并泛化到训练没见过的开放域**。

## 2. 背景最小集

三块前置，每块两句话。

**[WM 01 §3](../WM_01_why_memory/) 的设计位置。** 检索式记忆（位置 ①）的读取操作是从存储集合里挑内容回放；对静态量这是最优解，边界是「检索只能返回存过的东西」。本篇是位置 ① 在交互式长视频上的最直接实现——存的就是 RGB 帧本身，连 latent 化都放在条件注入时才做。

**流式视频生成与固定窗口。** 自回归分解 $p(x_0,\dots,x_n)=\prod_i p(x_i\,|\,x_{0:i-1})$；Diffusion Forcing 类方法实际只能条件于**固定窗口的最近几十帧**。本篇的对照系 DFoT（固定窗口）与 FramePack（分层压缩到 2–3 帧）都属于「只看最近」家族——[WM 03（Memory Forcing）](../WM_03_memory_forcing/) 训练协议篇、[WM 04（RELIC）](../WM_04_relic/) 压缩 KV 篇都与它们对过表。

**相机控制视频生成。** 底座是相机条件 T2V（ReCamMaster 一系）：相机轨迹 $[R, t]$ 编码后加进特征。这一步是本篇检索的**免费地基**——每帧生成时用的条件位姿，事后就是该帧的位姿标注，**不需要额外的位姿估计器**。没有相机控制的模型（纯动作输入）做不到这一点，这是 FOV 检索路线的隐性门槛。

## 3. 方法总览

一个循环，四个步骤，全部用文字说清：

**生成开始**，用户给初始帧与目标相机位姿。**每一轮**：① 用户给出下一段的目标相机位姿；② **检索**——拿目标位姿与全部历史帧的位姿做 FOV 重叠判定，筛出共可见的候选，再去掉连续帧冗余，取 $k-1$ 帧，加上最近生成的 1 帧保证连续性，凑成 $k=20$ 帧上下文；③ **条件生成**——20 帧上下文（无时间连续性，逐帧单独过 3D VAE）与待预测段的噪声 latent 沿帧维拼接，进 DiT 联合注意力，只更新待预测部分；④ 生成结果连同其位姿**原样追加**进历史。循环往复，历史无限增长，上下文恒为 $k$ 帧。

三个设计判断值得点破：

1. **存储零后处理**。与 [VMem](../WM_02_vmem/) 的 surfel 索引、3D 重建路线的显式表示相比，这里记忆就是「帧 + 位姿标注」两张表——写路径没有任何可学、可错、可漂移的组件；
2. **条件注入零新模块**。上下文帧不是经 adapter 或 cross-attention 旁路注入（WorldMem 的做法），而是与预测帧**同等地位**参与主注意力——「上下文学习」而非「上下文控制」；
3. **检索是纯规则**。FOV 重叠判定只用相机几何，不学任何参数；论文的表述是 occasional missed or incorrect candidates don't substantially affect overall performance——漏检容错。

## 4. 核心原理

### 4.1 底座与相机注入：位姿从哪来

底座是全序列 T2V 扩散模型：因果 3D VAE（时间压缩率 $r=4$）+ DiT，每个 DiT 块依次为 2D 空间注意力 → 3D 时空注意力 → cross-attention → FFN。训练目标是标准的噪声预测：

$$
\mathcal{L}(\phi) = \mathbb{E}\big[\|\epsilon_\phi(z_t,\, p,\, t) - \epsilon\|\big]
\tag{Eq. 1}
$$

其中 $z_t$ 是加噪 latent，$p$ 是文本 prompt，$\epsilon$ 是所加噪声。相机控制沿用 ReCamMaster 机制：位姿 $\mathrm{cam} = [R, t] \in \mathbb{R}^{f \times (3 \times 4)}$（$f$ 帧的内外参）经相机编码器 $E_c$（一层 MLP）映射到特征维度，加在空间注意力输出上、作为 3D 注意力的输入：

$$
F_i = F_o + E_c(\mathrm{cam})
\tag{Eq. 2}
$$

相机训练损失与 Eq. 1 同形，只是条件里多了 cam：

$$
\mathcal{L}_{\text{cam}}(\phi, \phi_{\text{MLP}}) = \mathbb{E}\big[\|\epsilon_{\phi,\phi_{\text{MLP}}}(z_t,\, p,\, \mathrm{cam},\, t) - \epsilon\|\big]
\tag{Eq. 3}
$$

关键推论在**推理侧**：每帧生成时用户提供的条件位姿被一并存进历史——**位姿标注是相机控制的副产品**。检索模块由此拿到全部历史帧的精确相机几何，零估计误差（对比：真实视频要先跑位姿估计器）。

### 4.2 上下文学习：拼接与位置编码

设上下文 latent 为 $z^c$（干净），待预测段为 $z^t$（加噪）。条件去噪器学 $p(z^{t-1} \mid z^t, z^c)$：**干净上下文与噪声预测 latent 在 DiT 块内同等参与注意力**；输出时只更新噪声部分，上下文保持不变。

两个工程决断：

- **帧维拼接而非 adapter/通道拼接**。上下文在生成过程中不断变长，adapter 与通道拼接都是为定长条件设计的；沿帧维拼接天然支持任意长度——这就是「零新模块」的由来。
- **位置编码的分治**。预测帧保持预训练阶段的 RoPE 位置（保住底座的生成能力），上下文帧分配**新的**位置编码。RoPE 对变长位置的适应性让这件事不需要重训底座。这个「新旧位置分离」的处理与 [WM 05（WorldPlay）](../WM_05_worldplay/) 的 temporal reframing 是同一坐标系里的两个操作——WorldPlay 重写**已有**帧的相对位置，本篇给**新增**上下文帧发新位置。

### 4.3 Memory Retrieval：FOV 重叠判定与去冗余

论文先摆三种备选的失败方式，值得整段吸收：

| 备选 | 机制 | 失败模式 |
|------|------|---------|
| 随机选帧 | 历史里随机挑 | 上下文少时靠相邻帧冗余还能用；几百帧时找不到有价值帧 |
| 窗口近邻 | 最近 $k$ 帧 | 相邻帧彼此冗余（信息增量小）；远处帧全部忽略 → 不停生成新场景，一致性崩 |
| FramePack 式分层压缩 | 按时间近邻指数衰减压缩到 2–3 帧 | 指数衰减丢历史信息太多；作者建议手工保留关键帧但没给选择标准 |

<details>
<summary><b>展开：FramePack 两帧压缩的算术与「为什么指数衰减致命」</b></summary>

FramePack 把上下文压到定长（如 2 帧）：最近 1 帧占满一帧，第 2 近占半帧，第 3 近占四分之一……指数衰减意味着**越老的帧分辨率越低**——而重访场景恰恰需要的是时间上很远、分辨率不低的帧。本篇 §6 的实验里 FramePack 甚至输给随机选帧：压缩吞吐了历史的量，衰减丢掉了历史的质。这个「按时间定压缩率」的缺口正是 [WM 21（WorldPack）](../WM_21_worldpack/) 的切入点——压缩率改由 3D 空间相关性决定。

</details>

**本篇的检索**分三层。第一层 **FOV 过滤**：本篇把相机运动限制在 XY 平面、只绕 z 轴旋转（数据收集时即如此约束），于是每帧视野是平面上的一个扇形，两帧共可见 ≈ 两个扇形有重叠。判定规则只需检查两相机**左右边界射线**这四条线的交点。

<details>
<summary><b>展开：四射线求交规则与它的失效情形（论文 Fig. 4）</b></summary>

实用规则：**左右两对射线都相交**（图 a、b）判为重叠；交点**离相机太近**（图 d）或**太远**（图 c）的过滤掉——太近通常意味着擦边一瞬、太远意味着重叠区域小到没用。论文坦承规则不完美：遮挡情形（图 e、f 这类 corner case）会误判，但「偶尔漏检或错检不影响整体性能」——检索是选条件而非生成本身，容错率高。

这个 2D 简化是双刃剑：换来的是**每对相机 O(1) 的判定成本**（对比 [VMem](../WM_02_vmem/) 的 surfel splat 渲染投票、WorldMem 的 3D 视锥重叠采样）；代价是没有遮挡推理、且只适用于平面运动相机。论文的局限一节自己点名：互联互通的室内多遮挡场景里 FOV 重叠难以识别真正相关的帧。

</details>

第二层 **Non-adj 去冗余**：FOV 过滤后的候选仍可能超预算，且候选里常有**成串的连续帧**（相机缓慢扫过同一区域时，几十帧都互相重叠）——连续帧之间几乎无信息增量。规则：每组连续帧里只取一帧。第三层 **Far-space-time 补充**（可选）：再补几帧空间或时间上最远的，兜住可能缺失的长程信息——消融显示这一步收益最小（§6）。

**训练与推理的对接**（论文 Algorithm 1/2）：训练时从几千帧的 GT 长视频里随机截一段当预测序列，对剩余帧跑同样的 Memory Retrieval 取 $k-1$ 帧上下文（帧间重叠关系预计算好），预测序列首帧也进上下文保证连续；**10% 概率只用最近一帧**，模拟长视频开头「无历史可检索」的情形。推理时对每段从已生成帧里检索 $k-1$ 帧 + 最近帧。训练与推理用同一套检索协议——这一点承接 [WM 03](../WM_03_memory_forcing/) 的教训：**记忆怎么用，要在训练里教**。

## 5. 训练与推理细节

| 项 | 值 |
|---|---|
| 底座 | 内部 1B 参数预训练 T2V DiT（研究用），640×352 |
| 生成长度 | 77 帧 / 段；3D VAE 4× 时间压缩 → 20 个 latent |
| 上下文 | $k=20$ 帧 RGB（无时间连续性，逐帧单独过 3D VAE → 20 个 latent） |
| 训练量 | >10,000 迭代，batch 64，8×A100 |
| 采样 | 文本 CFG，50 步 |

**数据**是为记忆专门造的：UE5 渲染，**100 条长视频 × 7,601 帧（30 fps）**，12 种场景风格，每 77 帧由多模态 LLM（MiniCPM-V）标一条字幕；相机焦距 24 mm、FOV **52.67°**，轨迹为 B-spline 平滑折线，每 77 帧段内平移限制在 [3 m, 6 m]、xy 平面内旋转 < 60°——**同一区域被不同时间、不同视角反复拍摄**，FOV 检索与长程一致性监督都靠这个性质喂出来。

## 6. 实验与消融

**协议**：留出 5% 数据；FID/FVD 量视频质量，PSNR/LPIPS 量记忆。记忆评测有两个口径——**GT 对比**（上下文从 GT 帧里选，预测帧与 GT 比）与**历史对比**（新生成帧与**此前生成**的帧比）。后者更难也更真实：评的是自生成内容的一致性。测试轨迹刻意简单：**转 $n$ 度再转回来**，方便找到对应帧算指标。

**主对比（Table 1，GT 对比 / 历史对比）**：

| 方法 | PSNR ↑ | LPIPS ↓ | FID ↓ | FVD ↓ |
|------|--------|---------|-------|-------|
| 仅首帧上下文 | 15.72 / 14.53 | 0.5282 / 0.5456 | 127.55 / 157.44 | 937.51 / 1029.71 |
| 首帧 + 随机上下文 | 17.70 / 17.07 | 0.4847 / 0.3985 | 115.94 / 119.31 | 853.13 / 882.36 |
| DFoT（固定窗口） | 17.63 / 15.70 | 0.4528 / 0.5102 | 112.96 / 121.18 | 897.87 / 919.75 |
| FramePack | 17.20 / 15.65 | 0.4757 / 0.4947 | 121.87 / 131.59 | 901.58 / 974.52 |
| **Context as Memory** | **20.22 / 18.11** | **0.3003 / 0.3414** | **107.18 / 113.22** | **821.37 / 859.42** |

（所有基线都在同一底座、同一数据、同一训练配置下复现。）两个读数：**（i）随机上下文赢了 DFoT 和 FramePack**（历史对比 PSNR 17.07 vs 15.70 / 15.65）——随机选帧平均能捞到更多信息，而「只看最近」家族被相邻帧冗余锁死；**（ii）FID/FVD 同步改善**——上下文不仅给记忆，还通过降低生成不确定性、让条件里带着更干净的早期帧，减缓了误差累积。

**上下文大小（Table 2，GT / 历史对比）**：

| $k$ | PSNR ↑ | LPIPS ↓ | 速度 (fps) ↑ |
|-----|--------|---------|--------------|
| 1 | 15.72 / 14.53 | 0.5282 / 0.5456 | 1.60 |
| 5 | 17.37 / 15.97 | 0.4825 / 0.5063 | 1.40 |
| 10 | 19.14 / 17.75 | 0.3554 / 0.3985 | 1.20 |
| **20** | **20.22 / 18.11** | **0.3003 / 0.3414** | 0.97 |
| 30 | 20.31 / 18.19 | 0.3137 / 0.3319 | 0.79 |

注意 $k{=}30$ 的 GT 口径是**分裂的**：PSNR 还微升（20.31）但 LPIPS 反而变差（0.3137 vs 0.3003）——更多上下文带来的是「平均像素更准」与「感知质量更糊」的混合效应，论文只笼统说 30 相对 1 有明显速度下降、20 是好的权衡。历史对比口径下 30 仍微升（18.19 / 0.3319）。这是一个论文没有展开解释的细节，如实记录。

**检索策略（Table 3，GT / 历史对比 LPIPS ↓）**：

| 策略 | PSNR ↑ | LPIPS ↓ |
|------|--------|---------|
| Random | 17.70 / 17.07 | 0.4847 / 0.3985 |
| FOV + Random | 19.17 / 17.47 | 0.3825 / 0.3896 |
| FOV + Non-adj | 20.11 / 18.19 | 0.3075 / 0.3571 |
| FOV + Non-adj + Far-space-time | 20.22 / 18.11 | 0.3003 / 0.3414 |

FOV 过滤贡献最大（LPIPS 0.4847 → 0.3825），Non-adj 去冗余次之（→ 0.3075），Far-space-time 边际（→ 0.3003）——与 §4.3 的机制分析一致。

**开放域（Fig. 6）**：拿网图（黑神话、塞尔达、原神风格等）当首帧，「转走再转回」轨迹下生成新内容后仍能保持一致——定性结果，无定量指标。

### 6.1 toy 实验：检索键决定记忆上限

把「选哪些帧当条件」缩成最小模型（`scripts/world_memory_experiments/wm20_toy.py`）：48×48 网格世界，相机约束在平面、只绕 z 轴转、FOV 52.67°（忠实复刻论文设定），agent 沿锚点巡游（1.2% 概率跳切场景）；每帧存储可见格集合与位姿，查询时按各策略选 $k{=}20$ 帧上下文，重建当前视野。误差模型：格被上下文覆盖 → 取最早覆盖帧的漂移噪声 $\mathrm{drift}(\tau) = 0.03 + 0.09\,\tau/T$（越晚生成的帧累积误差越大，对应历史对比口径），未覆盖 → 幻觉 1.0；按「该格距上次观测的时长 Δ」分桶。

| 策略（k=20） | 总体 MAE ↓ | 长程段（Δ≥80）MAE ↓ | 长程段覆盖率 |
|--------------|-----------|--------------------|--------------|
| recent-1（仅最近帧） | 0.226 | 1.000 | 0.00 |
| temporal-20（时间近邻） | 0.216 | 1.000 | 0.00 |
| random-20 | 0.176 | 0.664 | 0.27–0.42 |
| fov-random-20（FOV 过滤后随机） | 0.093 | 0.096 | 0.92–0.97 |
| fov-nonadj-20（+ 去冗余） | **0.088** | **0.065** | 0.97–0.99 |
| all-history（全历史，上界） | 0.085 | 0.044 | 1.00 |

三个读数，与论文三张表一一对应：

1. **时间近邻崩在长程段**（Δ≥80 覆盖率 0.00，MAE 1.000）：Δ>20 后最近 20 帧与当前视野几乎零重叠（20–80 桶覆盖率仅 0.014）——Table 1 里 DFoT 历史对比 15.70 的机制版。**随机帧都好过它**（0.176 < 0.216）：随机至少以正比于「该区域历史占比」的概率命中，复现了论文「random beats DFoT/FramePack」的反直觉结果。
2. **FOV 检索逼近全历史上界**：fov-nonadj 0.088 vs all-history 0.085（长程段 0.065 vs 0.044）——20 帧选得好，接近「全部历史都进上下文」。Table 2 里 $k{=}20$ 后收益骤减的同构现象。
3. **去冗余的收益集中在长程段**：fov-random → fov-nonadj，总体只差 0.005，但 240 以上桶 0.119 → 0.073——连续帧冗余在「同一次到访的帧串」里最严重，去冗余把省下的名额摊给更早的到访，正对应 Table 3 的 FOV+Non-adj 跃升。

$k$ 扫描（fov-nonadj）：$k = 1/5/10/20/30$ → 总体 MAE **0.226 / 0.113 / 0.095 / 0.089 / 0.087**，长程段 **1.000 / 0.231 / 0.109 / 0.065 / 0.054**——20→30 的边际收益只有 0.002，与论文 Table 2 的 20.22→20.31、fps 0.97→0.79 同一个「饱和早于算力代价」的形状。

**边界同样被 toy 复现**：first 桶（从未见过的格子）所有策略 MAE = 1.000——检索只能返回存过的东西（[WM 01](../WM_01_why_memory/) 的结论一），新内容只能靠生成先验。

> 写入端理想化的说明：toy 假设「覆盖即恢复」、无遮挡、无视角误差，FOV 重叠用可见格集合的交直接算（论文用四射线求交近似）；它只隔离「选哪些帧」这一个变量。脚本教训一条：fov-nonadj 的贪心选择循环最初在 $k{=}1$ 时仍会选中一帧（`len(picked) >= k-1` 的判断放在 append 之后，$k{-}1{=}0$ 时先 append 再判停），导致 Part 2 的 $k{=}1$ 行比 recent-1 好了 0.03——**「k=1 应严格等于仅最近帧」这条恒等式检查抓出了这个 off-by-one**。

## 8. 局限与个人评价

**论文自认的四条**：静态场景限定（动态场景的记忆检索更难）；多遮挡复杂场景（互联互通的室内）里 FOV 重叠难以识别真正相关帧；长视频固有的误差累积仍在，只能靠更大模型与更多训练缓解（附录 C 补充：1B 底座在复杂轨迹下连高质量生成都撑不住，误差累积到不可接受）。

**顺着系列主线能看出的三条**：

1. **检索式记忆的天花板在检索键，而 FOV 是个 2D 键**。52.67° 扇形求交不知道遮挡为何物——VMem 用 surfel 深度排序换来的遮挡感知，在这里被「偶尔漏检无大碍」一句带过。这个取舍在开阔场景（论文的 UE5 数据与「转走转回」评测都是低遮挡）里成立，在它自己点名的室内多遮挡场景里会加倍偿还。检索键从 2D 几何走向带遮挡的 3D 共可见，是这条线还没走完的一步。
2. **「全历史即记忆」其实只兑现了「全历史可检索」**。$k=20$ 的窗口外历史虽然还在存储里，但本轮生成完全看不到它们；真正意义上的「全部历史都参与」，要等 [WM 21](../WM_21_worldpack/) 把丢弃改成压缩。toy 里 fov-nonadj 与 all-history 在 240+ 桶的差距（0.073 vs 0.043）就是「窗口外丢失」的定量影子。
3. **速度是这个方案绕不开的税**。0.97 fps 离交互差一个数量级，且瓶颈在 $k$ 帧上下文的注意力——Table 2 的 fps 列几乎随 $k$ 线性下降。检索键再好，也改变不了「上下文帧数 × 每帧 token 数」的算力账单；这笔账的两种付法（压缩 token 的 [WM 04](../WM_04_relic/)、压缩帧的 [WM 21](../WM_21_worldpack/)）构成了这个系列的「压缩-覆盖」主线。

一句话评价：这篇论文的价值在于把位置 ① 的检索式记忆做到**机制上无可再简**——存储零后处理、注入零模块、检索零参数——然后用干净的消融证明每个简化都站得住。它同时把检索路线的两个先天边界（2D 键、窗口外丢弃）暴露得清清楚楚，恰好是下一篇的靶子。
