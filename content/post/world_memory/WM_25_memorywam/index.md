# WM 25：MemoryWAM——锚帧、滑窗与 gist token 的三级 KV 记忆

> 📖 系列总起见 [WM 01](../WM_01_why_memory/)。本篇是第二辑 **VLA/机器人操纵记忆组（WM 23–27）的第三篇**：[WM 23（MemoryVLA）](../WM_23_memoryvla/)把记忆做成检索式银行，本篇换一个视角——**记忆的预算问题**。KV cache 里每一个 token 都要在延迟和显存上付钱，问题变成：给定每帧预算，钱该花在哪一段历史上？

## 1. 这一篇解决什么问题

世界动作模型（World Action Model，WAM）是 VLA 的动力学版：不只学「观测 → 动作」，还学「动作之后世界怎么变」——典型实现是视频 DiT 提供动力学感知的视觉表示，动作头从表示读动作。RMBench 基准（Chen 等，arXiv:2603.01229）专测**非马尔可夫操纵**：九个双臂任务里，决策依赖的历史信息会滑出观测窗口（开局看到球在哪个壳下、桌上的数字、积木的初始排列）。

论文 Fig. 1 画出这个领域的两难：

| 记忆设计 | 复杂度 | RMBench 平均 | 代价 |
|------|------|------|------|
| 有界窗口（π0.5 / FastWAM） | O(1) | 10.4% / 5.9% | 滑出窗口即遗忘，非马尔可夫任务直接崩溃 |
| 全历史 KV（LingBot-VA） | O(N) | 78.2% | 延迟与显存随轨迹线性膨胀——真机 Shell Game 上**推理太慢，动作执行时杯子已经换完**（Table 2 里 13/20 的失败原因之一） |

要持久记忆，又付不起全历史的钱。MemoryWAM 的答案是借人类记忆的三种成分（论文引 Atkinson & Shiffrin 1968、Baddeley & Hitch 1974、Brainerd & Reyna 2005 的 verbatim/gist 二分、Zacks 等 2007 的事件边界理论）：

| 成分 | 对应历史段 | 存储形态 | 逐出策略 |
|------|------|------|------|
| 短期记忆（滑窗） | 最近 4 帧干净帧 | 全 token | 滑出窗口逐出 |
| 事件边界记忆（锚帧） | 开局 2 帧 | 全 token | **永不逐出**（sink） |
| gist 记忆 | 其余全部历史帧 | 每帧 8 个可学习 gist token | **永不逐出**（帧的全 token 逐出，gist 保留） |

一句话主线：**把「存多细」变成历史段上的分段函数——近期与开局给逐字细节（verbatim），中程只给要义摘要（gist）；每帧 token 从 120 压到 8（压缩比 d=15），长期 KV cache 与注意力成本降 15 倍，而 RMBench 平均反超全历史基线 4.8 个点。**

## 2. 所需背景最小集

- **[WM 01](../WM_01_why_memory/)**：记忆 = 部分可观测下对世界状态的信念；窗口式记忆把信念截断在最近 N 帧——本篇把「窗口该多长」升级成「预算怎么分段花」；
- **[WM 04（RELIC）](../WM_04_relic/)**：压缩换覆盖的正和交易（视频世界模型版：压缩 token 换 4× 上下文覆盖）——本篇是操纵版，但压缩发生在** token 维**（每帧 120→8），帧一个不丢；
- **[WM 06（HyDRA）](../WM_06_hydra/)**：混合记忆（静态档案员 + 动态追踪者）——按**内容动态性**分层；本篇按**时间角色**分层（近期/边界/远期），分层标准不同，混合哲学相同；
- **[WM 23（MemoryVLA）](../WM_23_memoryvla/)**：同引 Brainerd & Reyna 的 verbatim/gist 二分——感知记忆流 ≈ verbatim，认知流 ≈ gist；MemoryWAM 把这个二分从「两条检索流」改成「cache 里的三种 token 待遇」，对照读最能看清设计空间；
- **[Sparse Forcing](../../forcing_19/)**：KV cache 压缩与 sink token（开头几帧吸收大量注意力质量、稳定训练）——锚帧就是 sink 思想在操纵记忆里的功能化；
- **[VG 01（扩散模型基础）](../../video_generation/VG_01_diffusion_basics/)**：连续 flow matching 与去噪采样——训练目标与推理协议的公式基础。

## 3. 方法总览：从三相机 mosaic 到混合 cache 的六步

**文字版流水线**（输入到输出）：

1. **观测拼接**：头部 + 左右腕三个相机的 RGB 拼成 384×320 的 mosaic（头 256×320 在下，双腕各 128×160 沿宽拼成 128×320 在上），经 Wan2.2 因果视频 VAE 编码、patchify（1×2×2 over 48 通道 latent）后**每帧 120 个 latent token**；
2. **视频 DiT 写缓存**：当前帧的干净 latent 只前向一次，更新视频侧 KV cache——这一路就是 [WM 04（RELIC）](../WM_04_relic/)式「latent token 进 cache」的操纵版；训练时视频分支还要去噪未来帧（给动力学密集监督），**推理时视频生成整个关闭**（FastWAM 式）；
3. **三级记忆维护**：锚帧（开局 2 帧，全 token，永不逐出）∪ 滑窗（最近 4 帧干净帧，全 token，旧帧逐出）∪ gist（每帧 8 个 token，永不逐出，帧的全 token 逐出）；
4. **动作 DiT 读缓存**：约 1B 的动作专家（30 层、24 头 ×128，与视频 DiT 同深度同注意力形状，hidden 压到 1024）去噪出 16 步动作块（双臂 14 维关节向量）；本体感觉经线性投影挂进文本上下文；
5. **执行与采样**：16 步动作执行后，从子步 {3, 7, 11, 15} 抽 4 个新 mosaic 重新编码，追加进观测缓冲；
6. **回环**：新帧的干净 latent 与 gist token 的 K/V 预填充进 cache，动作专家开始下一块去噪。

两个容易看漏的结构事实：**记忆不是模型的输入，而是注意力的缓存**——视频 DiT 是唯一写者，动作 DiT 是纯读者（§4.2）；**训练与推理看同一个 cache**——训练序列逐帧自回归地交错干净/加噪 token，注意力掩码精确复现推理时的逐出规则（§4.4），这是全篇最重要的工程决定。

## 4. 核心原理完整推导

### 4.1 从有界窗口到缓存式记忆

论文 Eq. 1 写出主流 VLA/WAM 的共同形式——只看最近 N+1 帧与指令 $l$：

$$
a_t = \pi_{\text{short}}\big( o_{t-N:t},\, l \big)
\tag{Eq. 1}
$$

非马尔可夫环境下，决策所需的信念在 $o_{1:t-N}$ 里，窗口外无解。全历史 KV 的修法是把全部观测塞进自回归 Transformer 的上下文——精度回来，钱没了。MemoryWAM 的第一步是把「策略的输入」改写成「**缓存的更新与读取**」：观测 $o_t$ 先经因果 VAE 得 latent $z_t$，视频 DiT 前向一次更新视频侧 KV cache（论文 Eq. 2）：

$$
C^v_t = \Phi_v\big( z_t,\, l;\, C^v_{<t} \big)
\tag{Eq. 2}
$$

动作 DiT 在去噪动作 token 时对这个缓存做注意力（论文 Eq. 3）：

$$
a_{t:t+h-1} = \Phi_a\Big( x^a_\tau,\, l;\, C^v_{\le t} \Big), \qquad h = 16
\tag{Eq. 3}
$$

**写者与读者分离**是效率的关键：视频分支每帧只前向一次（不需要去噪循环），去噪循环只发生在小得多的动作分支上——这就是「视频生成只在训练时用」的结构基础。

### 4.2 混合记忆：token 待遇的三段函数

论文 Eq. 4 定义缓存为三个成分的并集：

$$
C^v_{\le t} = C^v_{\text{short}} \cup C^v_{\text{anchor}} \cup C^v_{\text{gist}}
\tag{Eq. 4}
$$

设每帧含 $L$ 个视觉 token，$N$ 帧后全历史缓存的规模（论文 Eq. 5）：

$$
|C^v_{\text{full}}| = O(NL)
\tag{Eq. 5}
$$

存储与注意力成本都随 $N$ 线性涨。MemoryWAM 给每帧挂 $M \ll L$ 个可学习 gist token，长期缓存规模变为（论文 Eq. 6）：

$$
|C^v_{\text{gist}}| = O(NM) = O\!\left( \frac{NL}{d} \right), \qquad d = \frac{L}{M} = \frac{120}{8} = 15
\tag{Eq. 6}
$$

动作生成时动作 DiT 读整个混合缓存（论文 Eq. 7）：

$$
a_{t:t+h-1} = \Phi_a\Big( x^a_\tau,\, l;\, C^v_{\text{short}} \cup C^v_{\text{anchor}} \cup C^v_{\text{gist}} \Big)
\tag{Eq. 7}
$$

注意三级之间的分工是**按信息的时间角色切的**：近期帧保接触状态与手-物构型（高频变化，控制必需）；锚帧保开局场景（指令里的「哪个壳」「什么数字」往往由初始画面定义，且之后会被遮挡或滑出窗口）；gist 保中程「发生过什么」的要义。恰好对应 RMBench 三类任务依赖。

### 4.3 gist token 的机制细节

gist token 是**可学习参数**：每帧前向时，这 8 个 token 作为额外 query 参与注意力——读该帧的 120 个 token 及其历史上下文——产生的 K/V 写入缓存；之后该帧的全 token K/V 被逐出，后续所有视频与动作 token 只能通过 gist 访问这一帧。位置编码上有一个漂亮的设计：gist token 放在与所属帧**相同的 3D RoPE 时间坐标**，空间坐标 $(h, w)$ 钉在一个常量标记上；动作专家共享视频分支的 3D RoPE 基。

<details>
<summary><b>展开：为什么 gist 钉在「真时间、假空间」的 RoPE 坐标上</b></summary>

3D RoPE 让注意力打分天然带时空距离惩罚（[WM 05（WorldPlay）](../WM_05_worldplay/)讨论过它的长程副作用）。MemoryWAM 的摆法等于声明：**gist 的身份由「何时」定义，不由「何处」定义**。

- 时间坐标真实：查询「第 40 帧发生了什么」时，第 40 帧的 gist 与查询 token 的时间距离正常参与打分——历史事件的时序可检索；
- 空间坐标钉常量标记：gist 是全帧摘要，没有资格冒充某个具体位置的 token。若给它真 $(h,w)$，注意力会误以为「这里有东西」，与该位置真正的（若在窗口内）全 token 冲突。

反过来看锚帧：锚帧保留**全部 120 个真坐标 token**，所以开局场景的「何处」精确可查——Shell Game 需要的正是「球在哪个壳下」的空间信息。三级结构 = 空间精度按时间角色分配：开局全精度、近期全精度、中程只留时间戳。

论文没有写明的一处含糊：8 个 gist token 是全轨迹共享一组可学习参数，还是每帧独立参数。从「realized as learnable parameters」加缓存 K/V 的描述看应是**共享 query、每帧独立 K/V**（否则参数量随帧数涨，与 O(NM) 的复杂度声明矛盾），本篇按此理解，如实标注。

</details>

### 4.4 训练：让训练看见推理的 cache

训练用与推理完全一致的连续 flow matching（1000 步，MSE 损失，视频/动作两分支权重各 1.0）。两个关键机制：

- **掩码复现**：每个 episode 构造成逐帧自回归的序列（干净/加噪视频 token 交错 + 对应动作块），训练注意力直接施加 §4.2 的混合记忆掩码——**训练时每个位置的可见集合就是推理时 KV cache 的内容**。没有这一步，模型训练时看全历史、推理时看逐出后的历史，检索行为会系统性错配（[WM 03（Memory Forcing）](../WM_03_memory_forcing/)训练-推理错配家族的 cache 版）；
- **条件噪声增强**：每个干净条件 latent 以 $[0,1]$ 均匀比例混入高斯噪声（概率 p=1.0，仅视频侧）——Self Forcing 式的防过拟合，避免训练时把条件帧当完美干净帧依赖、推理时被误差累积的链式条件打垮。

## 5. 训练与推理细节

| 项 | 设置 |
|----|------|
| 底座 | Wan2.2-TI2V-5B：视频 DiT（hidden 3072 / FFN 14336 / 24 头×128 / 30 块 / patch 1×2×2）+ T5 文本编码器 + 3D 因果 VAE |
| 动作专家 | 1B DiT（hidden 1024 / FFN 4096 / 30 块 / 24 头），权重沿 hidden 维插值自视频 DiT 初始化；总参数约 6B |
| 记忆配置 | $M_v=8$ gist/帧，锚帧 $N_{init}=2$，滑窗 $N_{recent}=4$；每帧 $L=120$ latent token，$d=15$ |
| 动作空间 | 双臂 14 维关节向量，horizon $h=16$（帧 stride 4 × 时间 VAE stride 4） |
| 优化 | AdamW（lr 2×10⁻⁴，wd 0.01，β=(0.9, 0.95)），8 GPU × batch 1，bfloat16 + FSDP + 逐块激活检查点 + 梯度裁剪 1.0 |
| 噪声调度 | shifted logit-normal：视频 shift 5.0 / 动作 shift 1.0 |

<details>
<summary><b>展开：推理协议与公平性处理的三个标本</b></summary>

**推理协议**：闭环控制中视频生成关闭。每个 transformer 块维护三级 cache：锚帧 K/V（前 2 帧干净帧）、滑窗 K/V（最近 4 帧干净帧，旧帧逐出）、全部历史帧的 gist K/V（永不逐出）。动作块执行后，新 mosaic 经 VAE 编码，干净帧与 gist 的 K/V 预填充进 cache，动作专家再去噪下一块。去噪步数：仿真 50 步，真机 10 步。真机部署单卡 RTX 4090，块内控制 10 Hz，**块间延迟约 0.3 秒**——这个数字就是「为什么 LingBot-VA 的全历史方案在真机会错过杯子交换」的量化背景：延迟随历史长度涨，动作执行时世界已经变了。

**公平性处理**（附录 A.1，如实记录）：为对齐 LingBot-VA（其在大规模真机/仿真数据上预训练且使用动作历史），MemoryWAM 在 Swap T 任务上给动作专家自回归加入动作历史、在 Observe and Pick Up 任务上用 RoboTwin 数据预训练；其余七个任务**既不预训练也不用动作历史**。Observe and Pick Up 的无预训练对照：MemoryWAM 5% vs LingBot-VA 3%——这个任务本身极难（最好成绩也只有 27%）。

**任务侧写**：真机两任务设计得很准——Shell Game 测遮挡物体跟踪（换壳期间球不可见，需开局锚帧），Look and Press 测计数与工作记忆（看到两个 1–5 的数字，按相应次数按左右键，再按后键报告完成——中程计数靠 gist 级摘要）。各收 50/100 条演示。

</details>

## 6. 实验与消融

### 6.1 记忆机制的系统对比（Fig. 4）

在单层内对比四种记忆机制（TTT/RNN 的接入方式沿用 Zhang 等：滑窗自注意力 + 记忆模块，输出逐元素相加）：TTT 与 RNN 对序列长度是常数复杂度，但**额外的参数与更新操作让它们在短轨迹上就付高基础延迟**；全注意力保完整历史、延迟与显存线性涨；混合记忆两头都占——**1600 帧时仍比 RNN/TTT 更高效**。性能侧（Press Button 任务）：全注意力 87%，混合记忆同样 87%，RNN/TTT 更低——过压缩或更新式的状态装不下记忆依赖任务所需的细节。「参数即记忆」（[WM 22（World-T3）](../WM_22_world_t3/)的 TTT 路线）在操纵场景的实测位置：容量够但检索精度与效率都不占优。

### 6.2 主对比：RMBench 与真机

**RMBench**（Table 1，每任务 50 条演示、100 次 rollout）：

| 任务 | π0.5 | FastWAM | LingBot-VA | **Ours** |
|------|------|---------|-----------|----------|
| Observe and Pick Up | 9 | 0 | 13 | **27** |
| Rearrange Blocks | 13 | 0 | 100 | **100** |
| Put Back Block | 11 | 0 | 100 | **100** |
| Swap Blocks | 24 | 0 | 99 | **100** |
| Swap T | 15 | 7 | 88 | **94** |
| Battery Try | 16 | 20 | 41 | 41 |
| Blocks Ranking Try | 6 | 26 | 100 | **100** |
| Cover Blocks | 0 | 0 | 79 | **98** |
| Press Button | 0 | 0 | 84 | 87 |
| **平均** | 10.4 | 5.9 | 78.2 | **83.0（+4.8）** |

三个读数：① 窗口式基线在非马尔可夫任务上**结构性崩溃**（五个任务 0%）；② 全历史基线 LingBot-VA 已经很强——本篇的增量是把 83.0 拿到手的同时把延迟和显存压回去（Fig. 1：延迟每动作块从 LingBot-VA 的约 3 秒级降到约 250 ms 级）；③ 唯一没涨的 Battery Try（41 = 41）与唯一大涨的 Cover Blocks（79→98，+19）说明压缩不是均匀代价——**任务越依赖开局场景，锚帧的边际收益越大**。

**真机**（Table 2，ARX 双臂 + RealSense D455，20 trials）：Shell Game 18/20 vs LingBot-VA 13/20 vs π0.5 5/20；Look and Press 15/20 vs 14/20 vs 0/20。论文特别指出 LingBot-VA 的 Shell Game 失败里有一类是**高推理延迟导致动作执行时错过杯子交换**——记忆容量够、读得太慢，在实时控制里等于没有。

### 6.3 消融：三级各值多少分（Table 3）

| 变体 | Cover Blocks | Press Button | 平均 |
|------|------|------|------|
| w/o Anchor Frames | 58 | 90 | 74.0 |
| w/o Gist Tokens | 75 | **5** | 40 |
| w/o Sliding Window | 96 | 69 | 82.5 |
| Full Attention | 96 | 87 | 91.5 |
| **Ours** | **98** | 87 | **92.5** |

gist 最关键（−52.5）：Press Button 掉到 5%——没有长期摘要，数到第几下全靠窗口内猜测。锚帧次之（−18.5）：Cover Blocks 掉到 58%——开局积木排列丢了。滑窗第三（−10.0）。**全注意力 91.5 反而低于完整混合记忆 92.5**：论文的解释是稠密历史引入冗余、干扰任务相关信息的检索——注意这只是定性论断，1 个点的差距在 100 次 rollout 下接近噪声（toy 里我们会把这条论断显式建模成假设项）。整体结论：混合记忆不是效率妥协，而是**按信息时间角色分配精度的有效结构**。

### 6.4 toy 实验：预算该花在哪一段历史

把三级记忆缩成等预算的存储-检索博弈：长 N 帧轨迹上有三类查询——**onset**（开局信息，精容差）、**mid**（中程语义/进度/计数，粗容差）、**recent**（即时控制构型，精容差），每集 1+8+2 条。存储层级决定检索精度：全 token σ=0.8，gist σ=6.0，逐出只剩先验猜测（误差期望 25）。四种策略：FIFO-4（FastWAM/π0.5）、Full（LingBot-VA，另加 σ_int·N 的检索干扰——**假设项**，模型化论文「冗余妨碍检索」的定性论断，置 0 则 Full 是精度上限）、Hybrid（MemoryWAM）、FIFO-eq（把 Hybrid 的全部预算换算成更长的 FIFO 窗口）。

**① 总体精度 vs 轨迹长度 N**：

| N | FIFO-4 | Full | Hybrid | FIFO-eq |
|---|--------|------|--------|---------|
| 50 | 40.2% | 100% | 99.2% | 40.7% |
| 200 | 40.5% | 100% | 99.2% | 42.5% |
| 400 | 40.5% | 100% | 99.0% | 43.8% |
| 1600 | 39.5% | 97.4% | 99.3% | 44.5% |

**上下文 token 成本 vs N**：

| N | FIFO-4 | Full | Hybrid | FIFO-eq（窗口帧数） |
|---|--------|------|--------|---------|
| 400 | 60 | 6000 | 484 | 480（32 帧） |
| 1600 | 60 | 24000 | 1684 | 1680（112 帧） |

两组数字合起来就是论文的赌注：**预算摊给「锚帧 + gist」买到恒定 99% 的覆盖，把同样的预算堆给「更长的窗口」只买到 43%**——FIFO-eq 在 N=1600 时窗口有 112 帧，但 onset 查询在 1600 帧的轨迹里年龄 1598，怎么堆窗口都够不着。Full 的 97.4%（N=1600 时 recent 掉到 91.6%）完全来自 σ_int 假设项；把 σ_int 置 0，Full 是 100% 的精度上限、24000 token 的成本——对应论文 Table 3 里 Full 91.5 vs Ours 92.5 那 1 个点的**定性论断**，不是测量。

**② N=400 组件消融**（对标 Table 3）：w/o Anchor 93.5% / w/o Gist 49.1% / w/o Window 88.0% / Full 100% / Ours 99.0%。gist 一致是最关键组件（−49.9 vs 论文 −52.5）；但 **anchor 与 window 的相对次序和论文互换**（论文 w/o Anchor 74.0 < w/o Window 82.5；toy 里 w/o Anchor 93.5 > w/o Window 88.0）——原因在查询构成：toy 里 recent 权重 2/11、onset 权重 1/11，滑窗的价值天然是锚帧的两倍；论文的 Cover Blocks/Press Button 恰恰更吃开局信息。**消融排序是任务分布的函数，不是组件的固有属性**——这点论文没有讨论，读消融表时值得警惕。

**③ N=800 精粒度查询的 MAE vs 年龄**（FIFO-eq 窗口 58 帧）：

| 年龄桶 | Hybrid | FIFO-eq | Full |
|---|---|---|---|
| 0–4 | 0.63 | 0.62 | 0.90 |
| 4–16 | 4.09 | **0.62** | 0.84 |
| 16–64 | 4.78 | 3.36 | 0.89 |
| 64–256 | 4.89 | 24.91 | 0.92 |
| 256–798 | 4.89 | 24.34 | 0.91 |

FIFO-eq 是**悬崖**（窗口边缘 58 帧处 MAE 从 3.4 跳到 24.9，退回先验水平）；Hybrid 是**平台**（gist 的 σ=6 决定的 4.9 天花板）——gist 保住「粗粒度上一直有」，代价是「细粒度上永远不够」：4–16 岁桶里它 4.09 的 MAE 反而不如窗口内的 FIFO-eq（0.62）。这是 verbatim/gist 二分的定量画像：**gist 的误差不是随年龄增长的斜坡（MemoryVLA 那种），而是一开始就付掉的常数税**——只要任务的查询容差粗于 σ_gist，这笔税就白付了一半；一旦需要精确空间信息，三级结构里没有为「远期 verbatim」留位置（只有开局例外）。

> 脚本：`scripts/world_memory_experiments/wm25_toy.py`。脚本教训：首版把三类查询的误差分支写成 if/else 链，粗粒度查询落进了「只处理精粒度」的分支直接 raise——重写为干净的 `estimate_error(variant, age, N)` 分发函数后一次跑通；另有一处 NAMES2 里的 "Ours" 忘了映射到 "Hybrid" 变体名，KeyError 才发现对照表与变体表是两套命名。

## 8. 局限与个人评价

1. **gist 是常数税，不是斜坡**（toy ③）：中程历史只有 σ=6 的摘要精度，任何需要**远期精确空间信息**的查询（不止开局）都无解——三级结构里「远期 verbatim」没有位置。论文的锚帧只锚开局（见下一条），如果任务在中途揭示关键信息（中途掀开壳看一眼再盖上），信息滑出窗口后只剩 gist。RMBench 恰好全是开局揭示型任务，基准与设计互相适配。
2. **「事件边界」名不副实**：Zacks 等的事件边界理论说的是**每个**事件边界都该被优先编码；实现只有 $N_{init}=2$ 的开局帧。开局是事件边界的一个特例（任务初始化），论文借了整个理论的名字却只实现了第一格。中程事件边界的自适应锚定（什么时候值得为一个新事件花 120 个 token）是显然的下一步，论文未做。
3. **「冗余妨碍检索」是定性论断**：Table 3 的 Full 91.5 vs Ours 92.5 只有 1 个点，100 次 rollout 下接近噪声；toy 的 σ_int·N 干扰项是为展示这条机制而设的**假设**（置 0 则 Full 是精度上限）——本篇如实标注，读者请勿把它当论文的测量结果。
4. **论文自述局限**：继承视频扩散模型较弱的语义理解与推理能力，未来工作方向是双系统架构或统一模型——这与 [WM 23](../WM_23_memoryvla/) 的认知流（语义摘要）恰好互补，两篇的作者群各自引了对方的想法（参考文献 [66, 67]）。
5. **公平性是有条件的**：Swap T 加动作历史、Observe and Pick Up 用 RoboTwin 预训练（对齐 LingBot-VA 的设置），其余任务裸训。Observe and Pick Up 上 27% vs 13% 的领先部分来自预训练；无预训练对照是 5% vs 3%——这个任务上两者其实都接近失败。
6. **面试可能被问的点**：为什么锚帧永不逐出？（sink 现象 + 开局场景定义指令中的关键信息且之后必然滑出窗口。）为什么 gist 钉在真时间、假空间的 RoPE 坐标？（时间可检索、空间不冒充——见 §4.3 折叠块。）训练怎么保证推理时的记忆行为？（注意力掩码逐帧复现推理 KV cache 的逐出规则，训练-推理可见集合同一。）以及：压缩比 d=15 怎么来的？（L=120 由 VAE 分辨率决定，M=8 是设计选择——论文没给 M 的敏感性消融，这是隐含的遗憾。）
