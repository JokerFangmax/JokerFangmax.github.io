# WM 17：总结——记忆的三个设计轴与五个答案

> 📖 系列终章。前置：全部 16 篇（[01](../WM_01_why_memory/)–[16](../WM_16_flowm/)）——本篇不引入新机制，只做三件事：把 15 篇论文放进一张终版地图、回答 [WM 01](../WM_01_why_memory/) §7 埋下的五个问题、汇总全部 toy 实验的斜率。没读过前面的读者，本篇的表格可以当索引用——每行都标了出处篇目。

## 1. 系列主线回顾：从「看见」到「知道」

[WM 01](../WM_01_why_memory/) 用两个方程把「世界模型」拆开：状态演化 $s_{t+1}=f(s_t,a_t,\omega_t)$ 与观测渲染 $o_t=r(s_t,c_t)$。视频生成器只学了第二个方程的逆（从观测到观测）；世界模型必须维护第一个方程的信念。**记忆就是这个信念的载体**——它决定 $s_t$ 的哪些分量在离开视野后还活着、怎么活。

三层递进（WM 01 §1.1）在 15 篇论文里的兑现：

| 层次 | 要求 | 解决它的论文 | 状态（2026.09） |
|------|------|------------|----------------|
| 静态一致性 | 重访时**长得一样** | VMem（WM 02）、Memory Forcing（WM 03）、RELIC（WM 04）、WorldPlay（WM 05） | ✅ 工程上已解决：几何索引、训练协议、压缩、位置编码重排各有定论 |
| 状态演化 | 看不见的东西**继续变** | HyDRA（WM 06，隐式）、LiveWorld（WM 10，monitor）、WorldDirector（WM 11，LLM 编排） | 🔶 结构性破口已确认（WM 07–09 三个基准），显式方案开始出现 |
| 机制一致性 | 变化**由规则决定** | StatePlay（WM 12）、MASS（WM 13）、Programmable WM（WM 14） | 🔶 前夜：typed 状态与逻辑引擎在受控域已验证，开放域未解 |

时间线也说明了这是一场范式迁移而非渐进改良：**2025.06–2026.01**（VMem→RELIC/WorldPlay）大家默认「静态画布」，比的是检索与压缩；**2026.03** 是转折月——StEvo-Bench、HyDRA、LiveWorld 同月出现，「看不见时怎么演化」第一次成为一等公民；**2026.06–09** 三个基准完成确诊（WM 08 的 scaling 反例是判决书），同一时期状态内核范式（WM 10–14）密集落地。**病越来越贵，药越来越显式。**

## 2. 三轴地图终版

15 篇论文 = 同一个问题在三个设计轴上的取值（[WM 01](../WM_01_why_memory/) §4 的初版地图，此处填满）：

| 论文 | 存哪 | 存什么 | 看不见时怎么演化 |
|------|------|--------|----------------|
| VMem（[02](../WM_02_vmem/)） | 像素/视图 + surfel 几何索引 | 静态画布 | 冻结（存什么回什么） |
| Memory Forcing（[03](../WM_03_memory_forcing/)） | 像素 + 时空双索引 | 静态画布 | 冻结 |
| RELIC（[04](../WM_04_relic/)） | 压缩 latent token（KV cache） | 静态画布 | 冻结 |
| WorldPlay（[05](../WM_05_worldplay/)） | 压缩 latent + 位置重排 | 静态画布 | 冻结 |
| HyDRA（[06](../WM_06_hydra/)） | 双库：静态档案 + 动态实体 latent | 静态背景 + 动态主体 | 隐式（生成先验外推轨迹） |
| LiveWorld（[10](../WM_10_liveworld/)） | 静态 3D 点云 + 显式实体列表 | 静态背景 + 动态主体 | monitor 快进 |
| WorldDirector（[11](../WM_11_world_director/)） | 显式轨迹库 + appearance 绑定 | 静态背景 + 动态主体 | LLM 编排（轨迹=承诺） |
| StatePlay（[12](../WM_12_stateplay/)） | typed 游戏状态（HP/气/计时） | 全动态 typed 状态 | 双分支联合预测（隐式状态，显式监督） |
| MASS（[13](../WM_13_mass/)） | typed 状态（唯一权威副本） | 全动态 typed 状态 | 学习的逻辑引擎 |
| Programmable WM（[14](../WM_14_programmable_wm/)） | 程序 + 状态机 | 全动态 typed 状态 | 程序内核（确定性执行） |
| C-JEPA（[15](../WM_15_causal_jepa/)） | 对象槽位 latent | 结构化（对象级分解） | 结构保证（掩码→交互推断） |
| FloWM（[16](../WM_16_flowm/)） | 等变 latent 流 | 结构化（时间参数化对称性） | 等变变换（结构保证） |

读法：**横着看是四个时代**（冻结→隐式→显式编排→结构保证），**竖着看是三轴各自的演化**（载体从像素到 latent 到状态到结构；内容假设从「世界不动」到「背景不动」到「都动」到「动的规律本身可参数化」）。

三个基准（[07](../WM_07_stevo_bench/)–[09](../WM_09_memobench/)）不占格子——它们是这张地图的**测量仪**：StEvo-Bench 测「隐期演化率」（全程可见 84.6% vs 加遮挡 17.4%）、WRBench 测「重访状态恢复」（23 模型 0.62–0.66 天花板 + scaling 反降）、MemoBench 测「消失-重现后的状态正确性」（无模型 ORS 过 0.6）。三个数字联合证明：**上表前四行的「冻结」列不是工程瑕疵，是训练目标里没有「看不见时的演化」这一项的结构性后果**（[WM 07](../WM_07_stevo_bench/) 的冻结定理：MSE 最优生成器的隐期演化率 = 数据先验 $q$，静态渲染语料 $q=0$）。

## 3. 五个问题的答案

[WM 01](../WM_01_why_memory/) §7 留了五个问题。逐一清算：

### 问题一：检索能变成外推吗？

**部分能，且有明确的失效边界。** HyDRA（[06](../WM_06_hydra/)）证明检索可以升级到「内容级」——时空亲和检索把重访误差从平坦 8.5–9.7 格改写为 $0.039\times D$ 的斜率（斜率 = 轨迹外推的学习误差），配合 59K 的 HM-World 数据集把「取回什么」做到极致。但 WorldDirector（[11](../WM_11_world_director/)）指出隐式外推撑不过长遮挡与多主体交互——它的答案是显式化：**LLM 生成的轨迹是承诺而非预测**，重入身份由 appearance binding 锚定（去掉后 DSC_DINO 0.769→0.693）。toy 的对照数字（[WM 06](../WM_06_hydra/) vs [WM 11](../WM_11_world_director/)）：隐式内容检索斜率 0.039×D，显式编排全程贴 0.08 执行噪声地板、身份绑定失败率 0%。**结论：短遮挡用隐式（便宜），长遮挡与多主体必须显式（可控）。**

### 问题二：状态内核要多显式？

**四级梯度，每级买一样东西、付一样代价：**

| 级别 | 论文 | 买到什么 | 付什么代价 |
|------|------|---------|-----------|
| monitor 快进 | LiveWorld（[10](../WM_10_liveworld/)） | 动态实体 Chamfer 误差比基线低 38 倍 | 实体类型一多，手工 monitor 扩展性崩溃 |
| LLM 编排 | WorldDirector（[11](../WM_11_world_director/)） | 语义级轨迹规划，实体类型开放 | 64×A100 72h 训练；LLM 是黑盒 |
| 双分支联合预测 | StatePlay（[12](../WM_12_stateplay/)） | 机制保真 82.3/78.3，端到端可学 | 状态类型需人工标注（HP/气/计时） |
| 学习的逻辑引擎 | MASS（[13](../WM_13_mass/)） | 权威状态 + 多人同步（1024 玩家 10⁴ 步），跨视图分歧恒 0.000 | 转移表只覆盖见过的规则 |
| 程序内核 | Programmable WM（[14](../WM_14_programmable_wm/)） | 可编程/可编辑/可验证（State Acc 98.0 vs 学习引擎 8.0；重放终局标准差 0.000 vs 17.476） | 覆盖外冻结；一条规则写错 → 系统性错误（hp MAE 56.32 = 学习引擎 3.5 倍） |

规律：**越显式，一致性/可验证性越好、开放域的可用性越差**。MASS 的「PerView 位置 MAE 反而更低（0.596 vs 2.968）但分歧 0.347 vs 0.000」给出了定量版本——局部精度与全局一致性是正交的两根轴，显式内核买的是后者。

### 问题三：结构先验值多少？

**两个方向都有干净的交易记录。** C-JEPA（[15](../WM_15_causal_jepa/)）：掩掉一个对象的历史 = 对可观测性的隐式干预，自动力学捷径被堵死 → 训练信号放大 51.1×（理论 $\Delta^2/2=50\times$），1.02% token 拿到 88.67% 的 Push-T 成功率（全量 91.33%）、规划快 8.6×。FloWM（[16](../WM_16_flowm/)）：等变约束逼 latent 与世界同构 → 长度外推 MSE 0.0018 vs 0.2111（约 100×），latent 里能直接解码出物体位置（96% vs 基线 <1%）。**代价是写入端采样需求**（FloWM 诊断出 2.2% 对象未被近距离两次观测 → 在集残差 0.27）——结构先验不豁免数据需求，只是把它从「量」换成「质」。

### 问题四：scaling 为什么不修复？

**因为损失函数里没有那个梯度。** WRBench（[08](../WM_08_wrbench/)）的反例：Wan 1.3B→14B，重访状态 0.657→0.621——不升反降。机制解释在 [WM 07](../WM_07_stevo_bench/) 的冻结定理：训练目标（去噪/流匹配）最优解的隐期演化率由**数据先验 $q$** 决定，而静态渲染语料 $q=0$。参数量放大的是「拟合 $q=0$ 的能力」，不是 $q$ 本身。**要改的是数据（WM 06 的 HM-World 主动制造离场-回场监督）或架构（WM 10–14 的显式状态变量），二者缺一不可**——这与 VG 系列的老结论同构：CFG 大 scale 崩不是模型不够大，是控制律不对（[VG 11](../../video_generation/VG_11_cfg_ctrl/)）。

### 问题五：评测会不会循环？

**有自我兑现的风险，三个基准各自给了对冲。** StEvo-Bench 用程序可验证的事件判定（推进率）替代 VQA；WRBench 用 human-calibrated 链（人校准后指标才可信）并公开 9,600 视频供复检；MemoBench 则暴露了循环评测的反面——**静态相机的模型搭便车**：LTX-Video 三项质量第一但相机控制 17.1，一致性指标会奖励「不动」而非「记得对」（[WM 09](../WM_09_memobench/) toy：一致性排序与状态误差排序完全倒挂）。**结论：指标必须同时测「变对」与「不变对」，否则评测本身会选出退化的模型。** 这是 VG 12 §8「评估循环性」问题在世界模型领域的重演与加深。

|------|--------|----------|------------|------|
| wm01（总起） | 动态格误差斜率 | Replay 0.285 | Oracle 0.000（Hybrid 0.045） | 630×（Δ=128–256 时 48.9 vs 0.08） |
| wm02（VMem） | 重访桶覆盖率 | Temporal 0.08–0.10 | VMem 投票 0.996 | 10× |

| wm07（StEvo） | 隐期演化率 | 静态先验 $q=0$ → 0.000 | $q\geq 0.5$ → 0.501+ | 冻结是最优解，非 bug |
| wm08（WRBench） | 重访状态 | 14B 0.621（反降） | —— | scaling 不在解空间里 |
| wm09（MemoBench） | 状态误差 | StaticCam 5.382（但一致性最优 0.080） | ActiveOracle 0.080 | 排序倒挂 |
| wm10（LiveWorld） | 实体误差斜率 | 冻结 18.44/回合 | monitor 0.70；Oracle 0.04 | 26× |
| wm11（WorldDirector） | 重入误差 | Frozen 饱和 11.5（16 步） | 编排贴 0.08 地板，绑定失败 0% | 全程 |
| wm12（StatePlay） | 违规率 | 像素读数漏触发 8.18% / 事件期 100% 违规 | 状态直读 1.12% / 0% | 机制版「零血攻击」 |
| wm13（MASS） | 身份/分歧 | dense 0.001@300 / 分歧 0.347 | typed 恒 1.000 / 分歧 0.000 | 构造保证 |

| wm15（C-JEPA） | 训练信号 | 无掩码：捷径 0.032 | 掩码放大 51×；SelfDyn 0.571 | 18× |
| wm16（FloWM） | 动态物体斜率 | Frozen 恰为 \|v\|=1（WM01 空间版） | SME+VC 全消融最优 | 等变给坐标系 |

三行加粗的规律：

- **冻结的误差是「平坦的错误值」**（wm02/05/06/11 的饱和、wm07 的 0.000 演化率）——它不随努力变好，因为它在给定信息下就是最优；
- **知识的误差是「斜率」**（wm01/06/10/16）——斜率逐级压低的过程就是「monitor→编排→引擎→程序」梯度的定量含义；
- **显式的风险是「系统性」**（wm14 的 56.32、wm13 的 0.001）——错误从弥散变成尖锐，可验证性（σ=0.000）与错误集中度是同一枚硬币的两面。

## 5. 概念辨析总表

全系列踩过的易混概念，最终版（出处篇目可回查）：

| 概念对 | 一句话辨析 | 出现于 |
|--------|-----------|--------|
| 上下文窗口 vs 记忆 | KV cache 是载体，记忆是功能；窗口有限 → 压缩（RELIC）/检索（VMem）/重排（WorldPlay） | 02–05 |
| 时间记忆 vs 空间记忆 | temporal 利于探索、spatial 利于重访——不是二选一，是训练分布怎么配（Hybrid Training） | 03 |
| 静态一致性 vs 状态一致性 | 「长得一样」2025 已解决；「演化对」2026 才开打——三个基准就是分界线 | 06–09 |
| object permanence vs out-of-sight dynamics | 存在性持续是状态持续演化的子问题 | 06, 09, 10 |
| 回放 vs 模拟 | 检索只能返回存过的；演化需要动力学模型——toy 斜率 0.285 vs 0.045 vs 0 | 全系列 |
| teacher forcing / self-forcing / context forcing | 链式 rollout 制造真实误差分布、memory 对齐蒸馏保留长程——训练-推理错配一族（呼应 VG 10） | 03, 04, 05 |
| 隐式 latent 状态 vs 显式 typed 状态 | 可学性 vs 可验证性；MASS 证明两者可以共存（typed 状态 + 学习的转移） | 10–14 |
| 权威状态 vs 多视角渲染 | 状态只有一份（服务器），视图按需渲染（客户端）——分歧 0.000 是构造性质 | 13 |
| 等变 vs 不变 | 输入变换 → 表示可预测地变换（不是保持不变）——FloWM 的群作用是时间参数化的 | 16 |
| 评测循环性 | 用 LLM/VQA 评 LLM 时代的模型——必须人校准（WRBench）或程序可验证（StEvo），否则选出退化模型 | 07–09 |
| in-view vs occlusion consistency | 现有基准大多只测前者；「看不见」才暴露状态内核的有无 | 07–09 |

## 6. 与 VG 系列的合流：版图缺角的补全

[VG 12](../../video_generation/VG_12_summary/) §8 把「长程一致性/记忆」列为 2024–2026 生成模型版图的缺角。本系列 15 篇论文是对这个缺角的独立测绘，两条线在两处直接握手：

| 交汇点 | VG 侧 | WM 侧 |
|--------|-------|-------|
| 蒸馏的效率-能力交易 | VG 06（leap flow 压采样步数）、VG 12 §8（蒸馏压平采样空间） | WM 04/05：蒸馏同时压 KV cache 的记忆容量——Context Forcing 证明对齐记忆条件后 4 NFE 反超 100 NFE（18.94 vs 16.27），压平不是宿命 |
| 干预信号的形状 | VG 11（CFG=比例控制、大增益超调）、VG 12（梯度无界/选择对数/切换折中） | WM 08：scaling 不改信号形状（参数量是增益，不是控制律）；WM 10–14：显式状态是新的干预通道——可编程、可验证 |

两系列合起来的总图景：**生成模型的失控都源于「控制信号没有落在该落的变量上」**——CFG 落在噪声预测上（VG 11），世界状态落在冻结的 KV cache 上（本系列）。修法也同构：换控制律（滑模 / 显式状态内核），而不是加参数。

## 7. 遗留的开放问题

1. **开放域的状态类型从哪来？** StatePlay/MASS/PWM 的 typed 状态（HP/资源/位置）都来自游戏。开放世界的「类型系统」是枚举不完的——[WM 15](../WM_15_causal_jepa/) 的对象槽位是候选答案（类型 = 槽位 + 关系），但离游戏级的机制保真还有距离。
2. **隐式与显式的混合比例。** wm06/11 的对照说明短遮挡隐式便宜、长遮挡显式必要——谁来学这个切换策略？（worlddirector 的 LLM 是手工接管的；学习式切换器没人做）
3. **评测的地面真值。** 三个基准的「状态正确性」都依赖程序生成或人校准。真实视频的世界里没有 ground truth 状态——自由运行的世界模型怎么评？
4. **记忆的写入端采样需求。** FloWM 发现 2.2% 对象观测不足 → 残差 0.27。主动视觉（去看一眼再回来）与记忆的关系，这个系列完全没碰——是天然的下一篇。
5. **理论线太短。** C-JEPA/FloWM 是仅有的两篇结构先验；冻结定理（wm07）还停留在 toy 级。「部分可观测下的世界模型可学性」缺一个像 ELBO 之于 VAE 那样的统一定理。
