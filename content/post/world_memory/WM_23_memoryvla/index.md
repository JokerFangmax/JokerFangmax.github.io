# WM 23：MemoryVLA——感知-认知双记忆银行的机器人操纵

> 📖 系列总起见 [WM 01](../WM_01_why_memory/)。本篇是第二辑 **VLA/机器人操纵记忆组（WM 23–27）的开篇**：前 22 篇都在视频世界模型里讨论记忆，从这里开始，同一个 POMDP 问题换到操纵场景——相机看得见的信息不够，动作还依赖看不见的历史。

## 1. 这一篇解决什么问题

主流 VLA 模型（OpenVLA、π0、CogACT）把策略当成**单帧映射**：当前 RGB + 指令 → 动作。论文 Fig. 1a 给了一个干净的失效样本：Push Buttons 任务里，按钮**按下前后几乎没有视觉差异**——单帧观测无法区分「还没按」和「已经按过」，机器人要么重复按、要么提前收工。这就是操纵的非马尔可夫性：**早先的动作改变了不可见的世界状态，而这个状态决定下一步该做什么**。

朴素的补救是把连续帧拼进输入，论文指出两条硬伤：① 自注意力二次复杂度撑不住长时程；② 序列帧输入偏离了 VLM 单帧机器人预训练分布。

MemoryVLA 的答案是直接搬人类的记忆结构（论文 Fig. 1b，引 Baddeley & Hitch 1974 的工作记忆、Tulving 1972 的情景记忆、Reyna & Brainerd 1995 的 verbatim/gist 二分）：

| 认知科学概念 | MemoryVLA 对应物 | 存什么 |
|------|------|------|
| 工作记忆（神经活动，秒级） | 当前感知 token + 认知 token | **现在**：256 个细粒度视觉 token + 1 个高层语义 token |
| 情景记忆 verbatim（逐字痕迹） | 感知记忆流 | **过去的事实**：物体级视觉细节快照 |
| 情景记忆 gist（要义痕迹） | 认知记忆流 | **过去的语义**：任务进度、决策要点 |

一句话主线：**Cognition-Memory-Action 三段式——VLM 出感知/认知双 token 组成工作记忆，海马体式的感知-认知记忆银行（PCMB）负责长期保存，检索-融合-整合三个操作把历史接回当前决策，扩散动作专家输出动作块。**

值得先亮出定位：本篇与 [WM 09（MemoBench）](../WM_09_memobench/)是同一枚硬币的两面——MemoBench 在**视频世界模型**里系统诊断「消失-重现」失败，MemoryVLA 在**机器人策略**里给出工程解；两者共享同一个病根（[WM 01](../WM_01_why_memory/) §1.3：看不见的演化在训练目标里没有梯度），只是解的方向不同。

## 2. 所需背景最小集

- **[WM 01](../WM_01_why_memory/)**：状态/观测两条方程；「记忆 = 部分可观测下对世界状态的信念」。本篇的感知记忆近似「物体在哪」（信念的一阶量），认知记忆近似「任务推进到哪」（信念的摘要量）——正是 [WM 01](../WM_01_why_memory/) 双系统讨论的操纵版；
- **[WM 09（MemoBench）](../WM_09_memobench/)**：消失-重现 + 状态变化四支柱——感知记忆要解决的正是「重现时还认得、还记得上次状态」；
- **[WM 11（WorldDirector）](../WM_11_world_director/)**：认知侧记忆（LLM 编排世界事件）——本篇的认知 token 是它的低配版：不编排未来，只总结过去；
- **[WM 06（HyDRA）](../WM_06_hydra/)**：档案员 + 追踪者的混合记忆——本篇的双流是同一思想在 token 空间的重演（感知流 = 档案员，认知流 = 追踪者的语义摘要）；
- 扩散策略（Diffusion Policy / DiT 动作头）：动作专家用 DDIM 采样连续动作块，公式与直觉见 [VG 01（扩散模型基础）](../../video_generation/VG_01_diffusion_basics/)。

## 3. 方法总览：从单帧观测到记忆动作的五步

**文字版流水线**（输入到输出）：

1. **编码**：当前第三人称 RGB（224×224）经并行 DINOv2 + SigLIP 得原始视觉 token；一路过 SE-bottleneck 感知压缩模块，压成 256 个感知 token $p$；另一路投影进语言空间、与指令拼接喂 LLaMA-7B，**取 EOS 位置的输出作为认知 token $c$**。$\{p, c\}$ 即工作记忆；
2. **检索**：工作记忆当双 query，对 PCMB 两条流做**带时间步位置编码的交叉注意力**（2 层），得到检索嵌入 $H^p, H^c$；
3. **门控融合**：$H$ 与当前 token 逐通道门控混合，得记忆增强表示 $\tilde{p}, \tilde{c}$；
4. **整合写回**：$\tilde{p}, \tilde{c}$ 同时送去动作专家并写入 PCMB；容量满时各流内部**相邻余弦相似度最大的一对合并**（平均），腾出位置；
5. **动作生成**：记忆增强 token 条件一个约 300M 的 DiT 动作专家，DDIM 10 步去噪出 16 步 7-DoF 动作块（$\Delta$平移 3 + $\Delta$旋转 3 + 夹爪 1）。

注意一个容易看漏的结构事实：**PCMB 的写入源是融合后的 token**（$\tilde{x}$ 而非原始 $x$）——记忆银行存的不是「当时看到了什么」，而是「当时的看到了什么与记起的过去的混合」。这让记忆具有递归性（今天的记忆里掺着昨天的记忆），是 §8 批评的第一个点。

## 4. 核心原理完整推导

### 4.1 问题形式化与工作记忆

论文 Eq. 1 把 VLA 写成序贯决策：给定当前观测 $I$ 与指令 $L$，

$$
A = (a_1, \ldots, a_T) = \pi(I, L), \qquad a_t = [\Delta x, \Delta y, \Delta z, \Delta\theta_x, \Delta\theta_y, \Delta\theta_z, g]^\top
\tag{Eq. 1}
$$

主流模型就停在这里——$\pi$ 只见当前帧。MemoryVLA 在 VLM 出口处把表示一分为二（论文 Eq. 2）：

$$
M^{wk} = \big\{\, p \in \mathbb{R}^{N_p \times d_p},\; c \in \mathbb{R}^{1 \times d_c} \,\big\}, \qquad N_p = 256
\tag{Eq. 2}
$$

$p$ 走 SE-bottleneck（通道注意力压到 256 维），$c$ 取 LLM 的 EOS 输出。**为什么要劈成两半而不是都用视觉 token**：物体级细节（哪个按钮、食物在哪）和任务级语义（进行到第几步）的信息密度和变化速率完全不同——前者高频、空间化，后者低频、序贯化。硬塞进同一种 token，检索时两种查询会互相干扰。

### 4.2 PCMB：两条流的记忆银行

论文 Eq. 3–4 定义银行（集合记号，不展开成公式块）：每条流维护至多 $L$ 个条目，

$$
M^{pcmb} = \{ m^x \mid x \in \{\text{per}, \text{cog}\} \}, \qquad m^x = \{ m_i^x \in \mathbb{R}^{N_x \times d_x} \}_{i=1}^{L}
$$

感知条目 $m_i^{per}$ 存细粒度视觉细节（256 token），认知条目 $m_i^{cog}$ 存高层语义摘要（1 token）。认知流每条目只有 1 个 token——**极端不对称的容量分配**，这是全篇最省的设计（§6 效率数字的来源），也引出「1 个 4096 维 EOS token 够不够」的消融（附录 Table 11：加到 4 个反而 71.9 → 69.8，论文的解读是单个 EOS 已装下足够语义）。

### 4.3 检索：时间步 PE + 交叉注意力

每个记忆条目挂一个正弦时间步编码 $\mathrm{TE}(t_i)$，加在 key 上（论文 Eq. 5–6）：

$$
K^x = [\, m_1^x + \mathrm{TE}(t_1);\, \ldots;\, m_L^x + \mathrm{TE}(t_L) \,], \qquad V^x = [\, m_1^x;\, \ldots;\, m_L^x \,]
\tag{Eq. 5}
$$

$$
\hat{H}^x = \mathrm{softmax}\!\left( \frac{(q^x)(K^x)^\top}{\sqrt{d_x}} \right) V^x, \qquad q^x \in \{p, c\}
\tag{Eq. 6}
$$

后接 FFN 组成一层，堆 2 层得最终 $H^p, H^c$。三个值得停下来的设计：

- **时间步 PE 加在 key 不加在 value**：查询「上次看到这个物体是什么时候」时，时间戳参与打分；但取回的内容本身不被时间戳污染。消融（Table 7）：去掉时间步 PE，71.9 → 69.8；
- **两条流各自独立检索**：感知 query 查感知流、认知 query 查认知流——没有跨流注意力。检索是**按查询类型分流的内容搜索**，不是把历史摊平了让注意力自己找；
- **无 top-K、全量注意力**：容量 $L$ 本身就是预算（Bridge/LIBERO 上 16，真机长时程 256），靠整合机制控制有效条目数——和 [WM 06（HyDRA）](../WM_06_hydra/)的 top-K 检索是两种预算哲学（条目数 vs 注意力带宽）。

### 4.4 门控融合

检索嵌入与当前表示的混合不搞加法，走逐通道门控（论文 Eq. 7–8）：

$$
g^x = \sigma\big( \mathrm{MLP}(\mathrm{concat}[x, H^x]) \big)
\tag{Eq. 7}
$$

$$
\tilde{x} = g^x \odot H^x + (1 - g^x) \odot x
\tag{Eq. 8}
$$

直觉：**当前观测与历史记忆不是平等的投票者**。抓取一个眼前的物体时，位置信息该信现在（门开向 $x$）；判断「按过没有」时，该信记忆（门开向 $H$）。门控把「信现在还是信过去」变成逐通道的可学开关，而且这个开关本身以 $(x, H)$ 为条件——**什么时候该查记忆，是模型学出来的**。消融（Table 7）：换成简单相加，71.9 → 67.7。

### 4.5 整合：相邻相似合并

容量超限时，各流内部找**相邻条目间余弦相似度最大的一对**合并（论文 Eq. 9）：

$$
i_x^{\star} = \arg\max_{i=1,\ldots,L-1} \cos(\tilde{x}_i, \tilde{x}_{i+1}), \qquad
m_{i_x^{\star}}^x \leftarrow \tfrac{1}{2}\big( \tilde{x}_{i_x^{\star}} + \tilde{x}_{i_x^{\star}+1} \big)
\tag{Eq. 9}
$$

这是全篇最「海马体」的部件：不丢弃最老的（FIFO），而是**合并最像的**——机械重复的操作片段（连续的同质帧）被压成一条，任务转折点（语义突变）因与邻居不相似而幸存。消融（Table 7）：FIFO 替代合并，71.9 → 66.7；真机 Clean Table & Count 上 84 → 76（附录 Table 13）。

<details>
<summary><b>展开：合并保「什么」不保「什么」——顺序信息的隐性风险</b></summary>

相邻合并的打分是 $\cos(\tilde{x}_i, \tilde{x}_{i+1})$——**纯内容相似度，不看时间戳的方向**。它天然保住「世界里有什么」（同质内容合并后均值仍是该内容的表示），但对「**先做了什么后做了什么**」没有保护：如果第 3 步和第 7 步的语义恰好相似（比如「按了两次同一个区域的按钮」），中间隔着的不相似条目会让它们逃过合并；可一旦相邻的两个**不同事件**表示相近（「按了 A」与「按了 B」在语义空间里都是「按了个按钮」），合并后的均值就同时丢掉了「是 A 还是 B」和「发生了几次」。

这正是 toy 实验（§6.4）里认知流用「每个已推事件以 $q=0.98$ 独立幸存」来建模的原因：合并吞事件是 PCMB 认知通道的主要失效模式，而它恰恰打击**顺序敏感的任务**——论文自己最强的一类任务。论文没有分析这一层，Table 6 的「双流 71.9 vs 单流 63.5/64.6」里有多少损失来自合并、多少来自容量，是拆不开的。

另一个连带问题：记忆写入源是**融合后**的 $\tilde{x}$（§3 结尾）。门控开错一次（比如把幻觉的检索内容融进了当前表示），错误就随写入永久化，还会在后续检索中被放大——记忆的递归污染。论文的消融没有触及这一点。

</details>

## 5. 训练与推理细节

| 项 | 设置 |
|----|------|
| 底座 | 7B Prismatic VLM（OXE 机器人预训练后），LLaMA-7B + DINOv2/SigLIP |
| 输入/输出 | 单第三人称 RGB 224×224；16 步 7-DoF 动作块（无腕相机、无本体感知） |
| 动作专家 | DiT ≈ 300M，DDIM 10 步，CFG 1.5，MSE 损失（训练时 4 个重复扩散步） |
| 记忆长度 | Bridge/Fractal/LIBERO/Mikasa = 16；真机长时程 = 256 |
| 优化 | 8×A100 FSDP，全局 batch 256（32×8），lr 2×10⁻⁵，梯度裁剪 1.0 |
| 训练量 | Bridge v2 50k 步 / RT-1 80k 步 / LIBERO 20k–40k 步 / 真机 5k–20k 步 |

<details>
<summary><b>展开：数据装载与推理效率的三个标本</b></summary>

**流式 dataloader（Bridge/Fractal）**：episode 按帧展开、标记 episode ID，batch 尽量由同一 episode 的连续帧填满——episode 结尾才切到下一条。这保证训练时记忆条目来自**时间上连续的真实历史**，而不是随机拼贴的帧组合。LIBERO/Mikasa 改用分组采样：每组从一个 episode 里抽 16 帧、组内保序。这个细节是记忆类 VLA 的隐形命门——记忆模块学到「检索什么」完全取决于训练时见过的（历史, 当前）配对分布。

**动作集成**：SimplerEnv 评测沿用 CogACT 协议的自适应动作集成（系数 α=0.1，集成时域 Bridge 7 / Fractal 2）；LIBERO 与 Mikasa 不用集成。

**效率（附录 Table 15，RTX 4090，bfloat16，300 次平均）**：基线 0.187 s / 85.6 Hz / 15.8 GB → MemoryVLA 0.194 s / 82.5 Hz / 16.6 GB——延迟 +3.6%、显存 +0.8 GB。记忆模块轻量的三个来源：认知条目单 token、感知 token 压到 256 通道、整合持续合并冗余。

**数据长度与记忆长度的匹配（附录 F，Table 9）**：真机长时程任务原始长度中位数 981 步、最长 7704 步；按运动幅度过滤（平移 > 1 cm 或旋转 > 0.4 rad 才留帧）后中位数 236。论文据此论证长时程任务用 256 记忆长度——**记忆长度是按任务时长配的，不是全局常数**。

</details>

## 6. 实验与消融

### 6.1 主对比：四个基准

**SimplerEnv-Bridge**（Table 1，WidowX，24 trials/任务）：

| 方法 | 成功率 |
|------|--------|
| OpenVLA / Octo-Base / TraceVLA | 4.2 / 17.5 / 27.7 |
| SpatialVLA / Magma / CogACT-Base | 42.7 / 44.8 / 51.3 |
| π0-Beta / CogACT-Large / CronusVLA | 68.4 / 57.3 / 60.4 |
| **MemoryVLA** | **71.9（+14.6 over CogACT-Large）** |

逐任务 75.0 / 75.0 / 37.5 / 100.0。与最强的时序基线 CronusVLA（滑动窗口聚合多帧特征）差 11.5 分——**窗口式时序建模与银行式持久记忆的差距**，正是 toy（§6.4）第二条曲线的实测版。

**其余三个基准**（Table 2–4）：Fractal 72.7（VM 77.7 / VA 67.7，比 CogACT 分别 +2.9 / +6.4——视觉扰动越大记忆优势越大）；LIBERO 五套件 96.5（Long-90 95.6，且**只用第三人称 RGB**，π0/π0-FAST 带腕相机与本体感知）；Mikasa-Robo 41.2 vs π0 29.4 / OpenVLA-OFT 28.4 / CronusVLA 18.0——ShellGameTouch 单任务 88%（次优 47%），这正是「壳下哪个球」的消失-重现任务（[WM 09](../WM_09_memobench/) 的操纵版）。

### 6.2 真机：长时程才是主战场

Table 5（Franka + WidowX，仅第三人称 RGB）：通用 6 任务 85%（CogACT 76，π0 72）；**长时程时序 6 任务 83%（CogACT 57，+26；π0 52；OpenVLA 9）**。逐任务增益：Seq. Push Buttons +43（15→58）、Change Food +38（47→85）、Guess Where +32（40→72）、Clean Table & Count +17（67→84）。

附录 E 的案例研究值得记：Change Food 里桌上同时有两个食物、单帧无法分辨该拿哪个时，注意力权重集中在「歧义出现前的最后一个决定性帧」；Shell Game 里模型持续关注**开局揭示帧**——唯一可靠的信息源。检索到的是**消歧所需的历史**，不是冗余回放。

鲁棒性（附录 B）：真机 OOD 变体大多保 86–100%；仿真里**未见相机视角是唯一大滑坡**（Pick Coke Can 92.0 → 42.0）——记忆救得了时间维的分布漂移，救不了观测方程本身的漂移（[WM 01](../WM_01_why_memory/) 观测方程里的 $c_t$ 变了，历史条目的坐标系全部失效）。

### 6.3 消融：每个部件都在挣分

| 消融（Bridge） | 变体 | 成功率 |
|------|------|--------|
| 记忆类型（Table 6） | 仅认知 / 仅感知 / 双流 | 63.5 / 64.6 / **71.9** |
| 记忆长度（Table 6） | 4 / 16 / 64 | 67.7 / **71.9** / 67.7 |
| 时间步 PE（Table 7） | 无 / 有 | 69.8 / **71.9** |
| 融合（Table 7） | 加法 / 门控 | 67.7 / **71.9** |
| 整合（Table 7） | FIFO / 相邻合并 | 66.7 / **71.9** |

记忆长度的非单调（4 与 64 打平在 67.7）论文只给了数据侧解释（附录 F 的长度统计），没有机制分析；真机 Clean Table & Count 上 64/256/512 = 78/84/81（Table 10），同样是中间最优。**记忆不是越长越好，也不是越省越好——存在任务相关的最优容量**，这一点 §8 再回来。

### 6.4 toy 实验：双流的两条失效曲线

把 PCMB 缩成最小可算模型：桌面 6 个按钮按指定顺序推按，两条记忆需求——**感知通道**（按钮被周期性遮挡，遮挡期位置随机游走 σ_drift=0.35/√步，看不见只能靠「最后可见快照」）与**认知通道**（推按前后按钮无视觉差异，进度只能靠记住「哪些已推过」，每次推按只有一个一步长的事件）。五种策略共享同一世界实现：None（单帧）、FIFO-16（窗口，CronusVLA 式）、PCMB（双流）、PCMB-cog / PCMB-per（单流消融）。评估分两趟：同轴评估（oracle 时间轴，各策略样本严格同分布）+ 各自闭环（整任务成功率）。

**感知通道——悬崖 vs 斜坡**（遮挡时目标按钮位置 MAE，按遮挡时长分桶）：

| 遮挡时长 A | Ā | n | None | FIFO-16 | PCMB |
|---|---|---|------|---------|------|
| 1–16 | 7 | 7340 | 24.99 | **1.05** | 1.04 |
| 16–32 | 23 | 3943 | 25.37 | 25.37 | **1.54** |
| 32–64 | 44 | 3173 | 25.28 | 25.28 | **1.99** |
| 64–128 | 72 | 331 | 26.23 | 26.23 | **2.62** |
| 当前可见 | — | 9213 | 0.39 | 0.40 | 0.40 |

FIFO 是**悬崖**：A 一旦超过窗口 16，误差跳到 25（先验猜测水平，与单帧无异）；PCMB 是**斜坡**：拟合 MAE ≈ 0.267·√A，与理论主导项 σ_drift·√(2/π) = 0.279 吻合。[WM 01](../WM_01_why_memory/)/[WM 06](../WM_06_hydra/) 的「误差斜率 = 对动力学的无知程度」在 VLA 设置重演：**持久记忆修复了锚点（不再因遮挡丢失），但遮挡期间会动的物体（被换位的壳、被拿走的食物）依然只能靠过期的快照**——MemoryVLA 没有动力学外推部件，这是它和 WM 10–14 状态内核路线的本质分界。

**认知通道——时间混淆的三档**（进度判断准确率 vs 已完成数 k）：

| k | None | FIFO-16 | PCMB |
|---|------|---------|------|
| 0 | 100% | 100% | 100% |
| 1 | 0% | 73.7% | 97.8% |
| 2 | 0% | 7.9% | 96.3% |
| 3 / 4 / 5 | 0% | 0% | 93.9% / 91.6% / 90.8% |

None 在 k≥1 直接归零——单帧策略永远以为任务刚开始（论文 Fig. 1a 的定量版）。FIFO 只记得住「上一步」：k=1 的 73.7% 精确等于 P(移动间隔 < 16) = 73.3%（间隔 ~ U(5,20)），k≥2 后连上一步都留不住。PCMB 靠持久认知流保住 91–98%，缓慢衰减对应合并偶尔吞事件（q=0.98）。

**闭环整任务成功率**（6 个按钮全按对）：None 0% / FIFO-16 0% / **PCMB 87.5%** / PCMB-cog 0.7% / PCMB-per 0%——单流各自卡死在另一条通道上（cog-only 被 k=0 的遮挡拦住 58.5%，per-only 被 k=1 的时间混淆归零），与论文 Table 6「双流 71.9 vs 单流 63.5/64.6」的**方向一致但幅度放大**：我们的任务把两条通道都做成硬约束（对齐 Mikasa 而非 Bridge——Bridge 里多数子任务其实不需要记忆）。

> 脚本：`scripts/world_memory_experiments/wm23_toy.py`。脚本教训三条：① 首版让五种策略各自闭环，失败提前终止后各策略的后续时间轴分叉，分桶样本不可比——改为「同轴评估（oracle 时间轴）+ 各自闭环」两趟；② 可见行求 bin 时被 `min(max(bi,0),N_BIN−1)` 钳进了最后一个年龄桶，首版斜率拟出 −0.035 的错值——**给「特殊档」留独立下标，别用 clamp 复用边界**；③ 用「段端点位移线性插值」模拟遮挡期漂移，会把随机游走方差变成 σ²A²/D、系统性低估漂移——改为按 √age 抽取并按段缓存（各策略共享同一决策时钟，缓存保证它们看到同一个真值）。

## 8. 局限与个人评价

1. **没有动力学，只有回放**。toy 的 √A 斜坡说清了边界：PCMB 修复锚点（遮挡不丢），但遮挡期间**会动**的物体只能给过期快照。壳被换位、食物被拿走这类「遮挡即变化」的场景，正是 [WM 09](../WM_09_memobench/) 状态变化支柱的考题——MemoryVLA 的架构里没有为「看不见时的演化」留任何部件。系列叙事里，这是检索式记忆在 VLA 里的极限位置，往下要靠 [WM 27（EvoMem-VLA）](../WM_27_evomem_vla/)的演化式记忆。
2. **合并保内容、不保顺序**（§4.5 折叠块）：相邻相似合并对时序信息没有保护，而论文最强的长时程任务恰恰是顺序敏感的。论文未做「合并错误率 vs 任务时长」的分析。
3. **记忆写入源的递归污染**：银行存的是门控融合后的 $\tilde{x}$，检索错误会随写入永久化。论文的消融没有隔离这条路径。
4. **容量非单调没有机制解释**：4 与 64 打平（67.7）、真机 512 < 256，论文只用数据长度统计带过。合理猜想是长记忆引入更多同质条目 → 合并更频繁 → 顺序信息损失加大，但这与第 2 条是同一个未验证假设。
5. **数字上的小瑕疵**（如实记录）：§4.1 称 Fractal 评测「336 variants, yielding 2,856 trials」，而附录 K.2/K.3 写「336 variants, producing 2,352 evaluation trials」（336×7=2352）——两处不一致；摘要写真机「84.0% success score」，正文 Table 5 是通用 85% / 时序 83%（84 为两者均值）。
6. **面试可能被问的点**：为什么认知 token 只用 EOS 位置单个、不加多？（Table 11：4 个反而掉分；4096 维单 token 已够语义容量，多 token 增加检索干扰。）门控融合为什么优于相加？（当前与历史不是平等投票者；门控让「信现在还是信过去」成为逐通道可学的条件开关。）以及：为什么时间步 PE 加在 key 不加在 value？（时间参与打分不污染内容。）
