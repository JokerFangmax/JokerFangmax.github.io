# WM 12：StatePlay——状态感知的游戏世界模型

> 📖 系列总起见 [WM 01](../WM_01_why_memory/)。本篇是状态内核范式的第三级：[WM 10（LiveWorld）](../WM_10_liveworld/)的 monitor、[WM 11（WorldDirector）](../WM_11_world_director/)的 LLM 编排之后，「双分支联合预测」这一级。
> 论文：*StatePlay: State-Aware Game World Models for Mechanics-Consistent Generation*（arXiv:2607.26754v1，2026.07）。Zijun Lin、Zeqing Wang 共同一作（腾讯实习），Cheston Tan、Bihan Wen、Yeying Jin（项目负责）。腾讯 + NTU + 新加坡国立 + A*STAR。本篇所有数字按论文 v1 正文与附录逐条核对。
>
> 📂 阅读方式同系列惯例：正文只留主线，推导与数字走查收折叠块。

## 1. 这一篇解决什么问题

[WM 01](../WM_01_why_memory/) 的第三个失败场景出自本篇：

> 对战游戏里把对手血量打到 0，对手**还在攻击**——血条空了，规则没触发。

论文开篇把这件事说得更重：**游戏不由像素定义**（games are not defined by pixels alone）。格斗游戏受三类内部状态变量支配——血量（HP）、技能条（skill meter）、计时器（timer）。它们与画面紧耦合，又决定玩法如何演进：技能条满了才能放超必杀、任一方 HP 归零回合必须结束。不建模这些状态动力学的世界模型，能生成视觉上以假乱真的对局，却**违反底层规则**：满气放不出超必杀、零血继续对打、该结束的局面不结算。这样的「游戏」只是一个视觉 demo，不可玩。

本篇的关键观察一句话：

> **玩家动作直接反映在像素变化里，而内部状态的动力学无法仅从视觉观测可靠学出。**

所以只含「帧 + 动作」的世界模型数据集，原则上就**不够**学出状态转移与游戏规则。StatePlay 从数据与模型两头回应：

| 侧 | 做法 |
|----|------|
| **数据** | 从街霸 3（SF3）模拟器内存里同步抽取五类状态变量（计时器、双方 HP、双方技能条），构造「状态-帧-动作」三对齐数据集，并按机制类别配平（40% 状态关键片段） |
| **模型** | mixture-of-transformers（MoT）双分支：轻量状态分支（0.76B）+ 视觉分支（5B），共享联合注意力交互；状态预测反过来引导帧生成 |

在四级梯度（monitor → LLM 编排 → 双分支联合预测 → 逻辑引擎/程序内核）里，本篇的位置很清晰：**状态内核第一次作为模型的内部成员参与生成**——不是外挂的监控（WM 10）、不是外部的剧本（WM 11），而是与视觉分支同训练、同推理的一条网络分支。

## 2. 所需背景最小集

- **[WM 01](../WM_01_why_memory/) §1.2**：观测方程 $o_t = r(s_t, c_t)$——HUD（血条/技能条）只是状态 $s_t$ 的一种**有损渲染**，本篇整个论证建立在这一点上；
- **[WM 11](../WM_11_world_director/) §4.4 折叠块**：「小面积像素区域承载的关键能力，端到端隐式学习会输给显式监督」——本篇是同一论证的状态版；
- **[WM 10](../WM_10_liveworld/)**：显式状态路线的起点（monitor），本篇把状态演化从管线外挂移进网络内部；
- **flow matching**：视觉分支的训练目标（速度场回归），见 [VG 01（扩散模型基础）](../../video_generation/VG_01_diffusion_basics/)；
- **RL 的状态/观测之分**：MDP 里的 $s_t$ 与智能体实际拿到的 $o_t$——见 [RL 01](../../RL/RL_01_foundations/)。本篇把这个决策论区分搬进了生成模型：状态分支学的正是 $s_{t+1}=f(s_t,a_t)$，视觉分支学的是 $o_t = r(s_t)$。

## 3. 方法总览

**一句话主线**：把「预测下一帧画面」的单一任务，改写成「联合预测画面 + 游戏状态」的双任务——动作序列同时注入两条分支；两条分支各自先做模内自注意，再通过共享的联合注意力交换信息（状态知道画面在演什么，画面知道状态该是什么）；输出端各用各的损失：视觉分支走 flow matching 去噪，状态分支走直接回归。

三个组成部分：

| 部分 | 内容 |
|------|------|
| **数据构造**（§3.1） | SF3 + stable-retro：11 维动作空间（4 移动 + 6 普攻 + 1 超必杀）、5 个状态变量从模拟器内存直读、每局打到 KO 切成 5 秒片段 @ 20 fps；按机制类别配平成 10,000 片段；Gemini 给 NPC 行为打策略标签（进攻/控制/防守）作为文本条件 |
| **MoT 架构**（§3.2） | 状态分支 0.76B（编码器 + 自注意 + 解码器）与视觉分支 5B（Wan2.2-TI2V-5B 底座）并行，联合注意力双向交互；动作嵌入在 token 嵌入后注入两分支 |
| **双目标训练**（§3.2） | 视觉：flow matching；状态：Smooth L1 回归——同一网络里两种模态两种损失 |

值得强调数据配平的细节：四类**状态关键片段**各 1,000 条——result win（"You Win" 画面 + 玩家 HP>0 且 NPC HP=0）、result lose、macro success（超必杀实际命中 + 指令存在 + 技能条 ≥ 阈值）、macro fail（指令存在但技能条不足，只打出普攻）——加 6,000 条 normal。视觉条件与状态条件**同时满足**才归入该类。这直接回应了 WM 01 的问题四：普通数据里「看不见的状态演化」监督稀薄，这里靠机制类别的**显式过采样**补。

## 4. 核心原理：扰动、交互、双损失

### 4.1 状态分支：像扩散一样扰动，像回归一样监督

训练时，干净状态序列 $s_0\in\mathbb{R}^{B\times f\times S}$（$f$ 为 latent 帧数、$S$ 为状态变量数，本游戏 $S=5$）按采样时间步 $t$ 加噪（论文 Eq. 1）：

$$
s_t = (1-t)\,s_0 + t\,\epsilon_s, \qquad \epsilon_s\sim\mathcal{N}(0,I)
\tag{Eq. 1}
$$

视觉分支对 latent $x_0$ 做同样的事（Eq. 2）：

$$
x_t = (1-t)\,x_0 + t\,\epsilon_v, \qquad \epsilon_v\sim\mathcal{N}(0,I)
\tag{Eq. 2}
$$

推理时，**首帧状态作为条件给定，其余帧状态从噪声初始化、由模型预测**。也就是说状态分支是一个以噪声尺度 $t$ 为条件的去噪器——但监督方式不是 flow matching（见 §4.3），而是对干净序列的直接回归。

附录 E 消融了这个设计：把输入换成「首帧干净状态广播到所有时间步」不如加噪输入（状态对齐 0.938 → 0.947，机制保真度 78.3 → 82.3）——广播给出的是过静态的初始化，反而妨碍模型学「随时间演化的帧动力学」。

### 4.2 联合注意力：双向交互、模内特化

状态表征 $H_s\in\mathbb{R}^{B\times L_s\times C}$（$L_s=25$ 个状态 token）与视觉表征 $H_v\in\mathbb{R}^{B\times L_v\times C}$（$L_v=9750$ 个视觉 token，维度 $C=3072$ 对齐）经各自的专家分支（自注意 + FFN）后，通过共享联合注意力交换（论文 Eq. 3）：

$$
H'_v = H_v + \mathrm{MHA}(H_v,\, H_s,\, H_s), \qquad
H'_s = H_s + \mathrm{MHA}(H_s,\, H_v,\, H_v)
\tag{Eq. 3}
$$

两个方向各有用途：视觉 token 当 query、状态 token 当 key/value——**画面生成吸收机制信息**（HP 归零了就别让角色站着打）；状态 token 当 query、视觉 token 当 key/value——**状态预测借助画面动态**（画面里正在播超必杀动画，技能条该清零了）。残差连接保证交互是叠加而非替换——每个模态保留自己的专家表征。

动作序列 $A\in\mathbb{R}^{B\times f\times K}$（$K=11$）经动作编码器投影后，在 token 嵌入之后**同时注入两条分支**——玩家的输入平等地调制画面与状态。

### 4.3 双损失：为什么状态不用 flow matching

视觉分支沿用 Wan 系游戏世界模型的标准 flow matching 目标，学去噪速度场（论文 Eq. 4）：

$$
\mathcal{L}_{\text{video}} = \mathbb{E}_{x_0,\epsilon_v,t}\Big[\big\|v_\theta(x_t,t) - (\epsilon_v - x_0)\big\|_2^2\Big]
\tag{Eq. 4}
$$

状态分支不用它，而是对解码出的状态序列直接回归（Eq. 5）：

$$
\mathcal{L}_{\text{state}} = \mathrm{SmoothL1}\big(D_s(H'_s),\, s_0\big)
\tag{Eq. 5}
$$

总目标（Eq. 6）：

$$
\mathcal{L}_{\text{train}} = \lambda_{\text{state}}\mathcal{L}_{\text{state}} + \lambda_{\text{video}}\mathcal{L}_{\text{video}}, \qquad \lambda_{\text{state}}=\lambda_{\text{video}}=1
\tag{Eq. 6}
$$

<details>
<summary><b>「动作适合 flow matching、状态适合回归」的机制论证</b></summary>

论文的对比论证值得完整记录（§4.4 消融数字支持）：

- **动作**是连续控制信号，随策略自由变化——分布连续、无内在结构，flow matching 学一个把噪声分布搬运到动作分布的传输场是合理选择（world action model 的标准做法）；
- **游戏状态**是**低维、受规则支配、时间结构化**的变量：HP 只在受击后下降、技能条缓涨且超必杀后清零、计时器线性递减。转移几乎由机制**决定**，不需要从分布层面建模。

对这种变量强上 flow matching 有两个具体代价：① 对低维状态注入随机扰动再学传输场，是把「查表可得的规则」绕道生成式建模；② 传输场学的是分布边缘，**不保证逐点精度**——而机制触发恰恰是逐点的（差 0.01 就是不触发）。回归损失直接逐点对齐真值轨迹。

消融数字（同为 MoT 架构）：状态用 flow matching 0.845 vs 回归 0.943（共享式骨干）；MoT 下 FM 0.845 → 回归 0.947，状态对齐相对提升 12.1%；机制保真度 60.7/62.0 → 82.3/78.3，**+21.6 个百分点**。

这与 [WM 01](../WM_01_why_memory/) toy 的结论三同一逻辑：状态演化的误差下界由「对动力学的无知程度」决定——回归监督把 HP/技能条的转移规则直接写进梯度，flow matching 只写了分布。

</details>

## 5. 训练与推理细节

| 项 | 设置 |
|----|------|
| 视觉底座 | Wan2.2-TI2V-5B + Wan2.2 VAE + UMT5-XXL 文本编码器 |
| 总参数 | 5.759B（视觉 5B + 状态 0.76B） |
| 数据 | 10,000 条 5 秒片段（480×832 @ 20 fps），带动作/状态/NPC 策略文本 |
| 超参 | $N=30$ 个 block、$L_s=25$、$L_v=9750$、$f=25$、$C=3072$、$K=11$、$\lambda=1/1$ |
| 优化 | 40,000 步、batch 4、lr $5\times10^{-5}$ |
| 推理 | 首帧画面 + 首帧状态 + 动作序列 + NPC 策略文本为条件；其余帧画面与状态均由模型生成 |

评测协议四维（100 个测试片段，机制类别均匀覆盖）：视觉质量（SSIM/LPIPS vs 引擎真值）、动作控制（Move-Acc：SAM2.1 + Grounding DINO 跟踪角色位移是否达标；Att-Acc：自训 ClipAttackNet——ResNet-18 + 4 层膨胀 TCN，约 5k 片段训练，6 类帧级攻击分类，置信阈 0.7）、状态对齐（五个状态变量的归一化 L1 距离，得分 = 1 − 距离）、机制保真度（Gemini-3.1-Pro 看全视频 + GPT-5.5 看 24 均匀采样帧，严格 prompt + 真值参考图 + 固定决策优先级，3 次运行取均值±标准差）。

<details>
<summary><b>机制保真度 judge 的决策优先级（附录 D）——「严格」具体指什么</b></summary>

judge prompt 的几条硬规则，每条都在堵一个可能的放水口：

| 规则 | 堵住的放水口 |
|------|-------------|
| `result_win` **只在** "YOU WIN" 结算画面可见时判赢 | K.O. 帧、对手倒地、胜利姿势、HP 打空、最后一击**都不算**——防止把「打得像赢」当赢 |
| `result_lose` 同理要求 "YOU LOSE" 画面 | 同上 |
| `macro_success` 要求超必杀**实际命中**（大特效/冻结闪屏/多段演出） | 只摆出招姿势不算——区分「放了」与「放中了」 |
| `macro_fail` = 尝试了但被格挡/落空/打断 | 与 success 互斥，对应数据集里的 macro fail 类别 |
| 固定决策优先级：WIN 画面 > LOSE 画面 > 超必杀命中 > 超必杀失败 > normal | 消除类别歧义下的 judge 自由裁量 |

外加三张真值参考图（win/lose/超必杀各一），要求输出 JSON（含 `evidence` 字段逐项报告 YOU WIN 是否可见等）。这套协议把 judge 从「看起来对吗」改造成「符合判定清单吗」——比自由打分强得多，但 §8 第 2 条的循环性担忧依然成立：清单本身也是 LLM 可读的，清单之外的错误形态（比如结算画面出现但角色还在动）不在监控范围内。

</details>

## 6. 实验与消融

### 6.1 主对比

**Zero-shot**（各模型原版权重）：最好的 ReactiveGWM（域内数据训练）视觉质量领先（SSIM 0.340），但机制保真度两家 judge 都不超 50%（48.0/43.3）——**视觉上像那么回事，规则全错**。

**状态感知微调**（同一数据集上微调各基线——检验「仅靠视觉监督能否涌现机制一致性」）：

| 方法 | SSIM↑ | LPIPS↓ | Move-Acc↑ | Att-Acc↑ | 状态对齐↑ | 机制保真度 Gemini↑ | GPT↑ |
|------|-------|--------|-----------|----------|-----------|--------------------|------|
| Matrix-Game 3.0（6.3B） | 0.240 | 0.478 | 40.0 | 6.67 | – | 48.7±1.7 | 58.3±0.9 |
| HY-World 1.5（18.1B） | 0.352 | 0.521 | 40.0 | 11.7 | – | 41.7±0.5 | 38.3±0.5 |
| ReactiveGWM（5.0B） | 0.376 | 0.439 | **95.0** | **100.0** | – | 63.7±2.1 | 59.7±0.9 |
| **StatePlay（5.76B）** | **0.378** | **0.424** | 92.5 | 95.0 | **0.947** | **82.3±0.5** | **78.3±0.5** |

（LingBot 系因 >24B 参数未参与微调对比。）

三个读数：

1. **微调救不了无状态模型**：ReactiveGWM 在同一数据上微调 40,000 步，机制保真度只到 63.7/59.7——视觉监督的梯度挤不进状态动力学（§4.3 折叠块的论证）；
2. **状态对齐 0.947**：归一化 L1 平均 0.053，即五个状态变量（含双方 HP、技能条逐帧轨迹）的预测误差平均不到量程的 5.3%；
3. **机制保真度领先 18.6 个百分点**——论文摘要里的「18.6%」，按双 judge 平均计算：StatePlay (82.3+78.3)/2 = 80.3，最强基线 (63.7+59.7)/2 = 61.7，差 18.6。**核对说明**：论文未写明口径，这是从 Table 1 唯一能复原出的算法；若按 Gemini 单项算是 +29.2%（相对）。引用时建议直接给表内数字。

而且这些收益**不以牺牲本职能力为代价**：视觉质量（SSIM/LPIPS）与动作控制（Move/Att）与 ReactiveGWM 相当或更好——状态分支不是税，是免费的结构先验。

### 6.2 消融：两个设计各值十几二十个点

| 骨干 | 状态损失 | SSIM↑ | 状态对齐↑ | 机制保真度 Gemini↑ | GPT↑ |
|------|---------|-------|-----------|--------------------|------|
| Shared（统一骨干） | FM | 0.309 | 0.804 | 52.0±0.9 | 49.7±1.2 |
| Shared | 回归 | 0.355 | 0.943 | 64.7±2.1 | 67.7±0.5 |
| MoT | FM | 0.363 | 0.845 | 60.7±1.2 | 62.0±1.4 |
| **MoT** | **回归** | **0.378** | **0.947** | **82.3±0.5** | **78.3±0.5** |

- **MoT vs Shared（同为回归）**：82.3 vs 64.7，**+17.6 个百分点**（论文口径，Gemini 单项百分点差）。把帧 token 与状态 token 塞进完全共享的 latent 空间会互相干扰——高维视觉细节与低维规则敏感的时间动力学是两种表征，**部分特化 + 受控交互**（Eq. 3 的残差式联合注意力）好于全共享；
- **回归 vs FM（同为 MoT）**：状态对齐 0.947 vs 0.845（相对 +12.1%），机制保真度 +21.6 个百分点——§4.3 论证的兑现。

定性对照（论文 Fig. 4）把三个失败场景钉死：ReactiveGWM 满气放不出超必杀（还把两个角色画缠在一起）；NPC HP 归零后还在站着攻击；玩家 HP 归零反而庆祝胜利。StatePlay 三种情形全部按规则生成。

### 6.3 toy 实验：规则为什么对像素读数这么苛刻

两个失真机制，都是纯模拟（脚本 `scripts/world_memory_experiments/wm12_toy.py`）。

**Part A：阈值密度放大器。** 机制决策是状态的阈值函数（放超必杀 ⟺ $m\ge\tau$）。像素分支从 HUD 读技能条：32 个像素格、只画已充满的格（向下取整）+ 渲染噪声；状态分支直接回归（噪声 0.003 ≪ 格宽 0.031）。技能条分布取两种：玩家攒气（30% 集中在 $\tau=0.95$ 附近）vs 均匀：

| 分布 | $f(\tau)$ | Pixel 漏触发 | Pixel 违规触发 | State 合计翻转 |
|------|-----------|--------------|----------------|----------------|
| 攒气 | 4.58 | **8.18%** | 0.00% | 1.12% |
| 均匀 | 1.01 | 1.86% | 0.00% | 0.26% |

三个观察：① 翻转率随 $f(\tau)$ **近似线性放大**（密度 4.5× → 翻转 4.4×）——玩家把气攒在阈值附近的行为，恰好把状态分布推到像素读数最不准的地方；② Pixel 的错误**单向**：向下取整的 HUD 只会漏触发，不会违规触发——正是 ReactiveGWM「气满了也放不出超必杀」的机制版；③ 状态直读把翻转压到 1.1%/0.3%——格点量化这个失真源对它是透明的。

**Part B：事件期视觉屏蔽 + 自由生成。** 超必杀触发瞬间画面闪光 15 帧，HUD 恰在状态跳变最大的时刻不可读（技能条清零、对手 −30 HP）。自由 rollout 里，没有事件转移模型的像素分支只能按平均速率漂移内部状态；状态分支按学到的规则推进：

| 量（事件后 40 帧） | Pixel 分支 | State 分支 |
|--------------------|-----------|-----------|
| 违规再放超必杀概率（内部 $\hat m\ge\tau$） | **100%** | 0% |
| 技能条内部误差 | +0.680 | +0.000 |
| 对手 HP 内部误差 | **+30.0** | +0.000 |

Pixel 的 HP 永久偏差整整一条超必杀伤害：真实世界里对手剩 4–10 点血、再挨一记普攻就该 KO，而它的内部 HP 还停在 40——于是继续生成对打。**「零血攻击」不是模型笨，是它从未获得过能看见这次跳变的任何监督**（WM 01 §1.3 的机制重演，这次发生在事件帧而不是离场期）。

## 8. 局限与思考

1. **单游戏验证**（论文自述）：SF3 之外的游戏缺乏「状态-帧-动作」同步数据集；$S=5$ 个状态变量、11 维动作都是**手工 schema**——换游戏要重抽。跨游戏泛化需要带状态标注的更大规模数据（WildWorld、"From Pixels to States" 一系在做）；
2. **机制保真度的评测循环性**：judge 是 Gemini/GPT。双 judge + 严格 prompt + 参考图 + 3 次运行控制了方差，但两个 LLM judge 的相关偏差（比如都偏信参考图）无法靠重复运行暴露。82.3% 这个数的安全性依赖「LLM 看错的方向与模型犯错的方向不相关」这个假设；
3. **状态分支是任务特定的**：0.76B 参数只认这 5 个变量、这套规则。与 WM 14（程序内核：换游戏改程序不改权重）相比，每个新规则系统都要重新收集数据 + 训练；
4. **像素级指示器仍有残余不一致**（论文附录 C 自述）：状态预测对了，画出来的血条偶尔还是错的——状态分支管 $s_t$，渲染 $o_t=r(s_t)$ 的保真仍受视觉分支能力限制；多机制同时发生（超必杀撞上回合结束）时画质退化。两条方程解耦了一半：$f$ 有了，$r$ 还在同一个生成器里；
5. **面试可能被问的点**：为什么状态分支输入也要加噪（Eq. 1）而不是直接回归干净状态？（与视觉分支共享时间步条件化：推理时状态从噪声起步、与画面同链路迭代生成；广播干净状态的消融差 0.9 个状态对齐点。）以及：MoT 的联合注意力为什么用残差而非替换？（模内表征是特化资产，跨模信息只该做增量修正——与 WM 11 上下文「只自注意」同一设计哲学：**交互不能污染特化**。）
