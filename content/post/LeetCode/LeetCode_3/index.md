# LeetCode 3. 无重复字符的最长子串

> 题目链接：[https://leetcode.cn/problems/longest-substring-without-repeating-characters/](https://leetcode.cn/problems/longest-substring-without-repeating-characters/)  
> 难度：中等  
> 标签：哈希表、字符串、滑动窗口

---

## 1. 题目描述

给定一个字符串 `s`，请你找出其中**不含有重复字符**的**最长子串 (substring)**的长度。注意是子串（连续），不是子序列；字符区分大小写，且 `s` 可以包含空格、数字和符号。

**数据范围：**

- $0 \le s.length \le 5 \times 10^4$
- `s` 由英文字母、数字、符号和空格组成

**示例：**

```
输入：s = "abcabcbb"
输出：3      // 最长子串是 "abc"

输入：s = "bbbbb"
输出：1      // 最长子串是 "b"

输入：s = "pwwkew"
输出：3      // 最长子串是 "kew"，注意 "pwke" 是子序列不是子串

输入：s = ""
输出：0
```

---

## 2. 思路分析

### 2.1 暴力：枚举所有子串

双重循环枚举全部 $O(n^2)$ 个子串，每个子串用哈希集合检查是否有重复字符，检查本身 $O(n)$，总计 $O(n^3)$。$n = 5 \times 10^4$ 时完全不可行。优化一步：固定左端点向右扩展、边扩展边维护集合，遇到重复立即停止—— $O(n^2)$，仍然超时。

### 2.2 套用滑窗判据：这个条件是"至多"型

套用[滑动窗口 (sliding window) 模板笔记](../../algorithms/sliding_window/)里的适用判据：定义谓词 $P(l, r)$ = "子串 $s[l..r]$ 无重复字符"，检查它随窗口伸缩的单调性。窗口内的字符集合只会因扩张而变多、因收缩而变少，因此：

1. **收缩保真**：若 $P(l, r)$ 成立，则它的任何子窗口（$l' \ge l$ 且 $r' \le r$）字符只会更少，必然也无重复——"无重复"这一性质从大窗口传给小窗口；
2. **扩张保假**：若 $P(l, r)$ 不成立（有重复），任何包含它的大窗口字符只多不少，重复仍在——"有重复"也随扩张传递。

两条恰好把搜索空间切干净：对固定的 $r$，满足 $P$ 的 $l$ 构成一个前缀 $[0, l_{\max}(r)]$，以 $r$ 结尾的最长无重复子串就是 $l = l_{\max}(r)$。而 $r$ 右移时 $l_{\max}(r)$ **单调不减**：若新字符 $s[r+1]$ 不与窗口内字符重复，旧起点仍然合法；若与位置 $p$（$p \ge l_{\max}(r)$）的字符重复，$l_{\max}$ 也只是右移到 $p + 1$。两种情况左指针都无需回退，双指针各走一遍即 $O(n)$。

这正是"**至多型条件**求**最长**"的标准滑窗形态（对照 LC 76 的"至少型求最短"，方向正好互为镜像）：

- 右指针 `r` 负责扩张，把窗口尽量撑大；
- 一旦条件破坏（出现重复），左指针 `l` 收缩到条件恢复为止；
- 条件满足的每个时刻都可能是答案，**记录答案放在收缩完成后**。

### 2.3 检查重复的 $O(1)$ 维护：计数数组

窗口内的"至多一个"条件用频次计数维护：`cnt[c]` 为字符 $c$ 在窗口中的出现次数。纳入 `s[r]` 后若 `cnt[s[r]] == 2`，说明刚引入重复，进入收缩；收缩时 `cnt[s[l]]--`、`l++`，直到重复消除。字符集是 ASCII（含空格、符号），用 `int cnt[128]` 足够——能用数组别用 `unordered_map`，这是[哈希表模板笔记](../../algorithms/hash_table/)的老原则。

### 2.4 更快一步：记住"上次出现位置"，左指针直接跳

收缩版每步只挪一格。还有一个更利落的变体：**`last[c]` 记录字符 $c$ 上次出现的下标**。纳入 `s[r]` 时，若 `last[s[r]] >= l`，说明重复字符在窗口内，直接把 $l$ 跳到 `last[s[r]] + 1`——一步跨过整个重复段，省去逐格收缩。两版都是 $O(n)$，后者少一层内层循环、常数更小，但"跳"的语义要理解透（见第 5 节疑问二）。

### 2.5 执行过程演示

`s = "pwwkew"`，收缩版逐轮走查（`[ ]` 括住当前窗口，$l$、$r$ 为下标）：

| $r$ | 纳入 | 事件 | 窗口（$l$..$r$） | 最长 |
|-----|------|------|------------------|------|
| 0   | p    | 无冲突 | `[p]` ($l{=}0$)         | 1 |
| 1   | w    | 无冲突 | `[p w]` ($l{=}0$)       | 2 |
| 2   | w    | `cnt[w]=2`，重复 → 弹 p、弹 w | `[w]` ($l{=}2$) | 2 |
| 3   | k    | 无冲突 | `[w k]` ($l{=}2$)       | 2 |
| 4   | e    | 无冲突 | `[w k e]` ($l{=}2$)     | **3** |
| 5   | w    | 看似冲突（见下文） | `s[3..5]`（收缩后） | 3 |

第 5 步值得单独拆开：新纳入的 `w` 上一次出现在下标 2，收缩后 $l = 2$，此时 `cnt[w]` 是 1（下标 2 那个还在窗口里）——纳入后 `cnt[w] = 2`，**确实重复**！收缩弹掉 `s[2] = w` 后 $l = 3$，窗口变为 `s[3..5] = "kew"`，长度 3，答案不变。

这一步容易想岔的地方是"旧 w 到底在不在窗口里"：判断依据**只有一个**——下标 2 是否 $\ge l$。收缩版的 `cnt` 只数窗口内字符，跳跃版的 `last[c] >= l` 判据，两者在这一点上完全等价。最终答案 3，对应子串 `"kew"`。

顺带用跳跃版复核全程：$r=2$ 时 `last[w]=1 >= l=0` → $l$ 跳到 2；$r=5$ 时 `last[w]=2 >= l=2` → $l$ 跳到 3。$l$ 的轨迹 $0 \to 2 \to 3$ 与收缩版完全一致。

## 3. 代码实现

```cpp
// 主推: 收缩版（两个 class Solution 二选一提交）
class Solution {
public:
    int lengthOfLongestSubstring(string s) {
        int cnt[128] = {};                  // 窗口内每个字符的出现次数
        int ans = 0;
        for (int l = 0, r = 0; r < (int)s.size(); r++) {
            unsigned char c = s[r];
            cnt[c]++;
            while (cnt[c] > 1) {            // 刚引入重复，收缩到恢复
                cnt[(unsigned char)s[l]]--;
                l++;
            }
            ans = max(ans, r - l + 1);      // 收缩完成后记录
        }
        return ans;
    }
};

// 备选: 跳跃版（last 记上次出现位置，左指针一步跳过重复段）
```

几个实现细节：

1. **收缩版记录答案在 `while` 之后**——此时窗口必然无重复，是"以 $r$ 结尾的最长无重复子串"；若在收缩前记录会把含重复的窗口算进去。
2. **跳跃版必须先判 `last[c] >= l` 再更新 `last[c] = r`**，顺序反了会把"自己和自己"判成重复。
3. **`(unsigned char)` 强转**：`char` 在多数平台是有符号的，扩展 ASCII 区（128–255）的字符转成 `int` 后是负数，直接当下标是未定义行为。题面允许符号出现，这一步不是多余的。
4. `cnt[128] = {}` 零初始化数组；`last` 用 `fill` 置 $-1$ 表示"从未出现"。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。右指针走 $n$ 步，左指针全程只前进不后退，合计至多 $n$ 步；每步的计数更新和判断都是 $O(1)$。跳跃版右指针 $n$ 步、左指针靠跳跃最多累计前进 $n$，同样 $O(n)$ 但无内层循环。
- **空间复杂度**：$O(|\Sigma|) = O(128)$，两个定长数组，与 $n$ 无关。

对比：暴力 $O(n^3)$ → 枚举起点 + 集合 $O(n^2)$ → 滑动窗口 $O(n)$。能从 $O(n^2)$ 降到 $O(n)$ 的根本原因仍是**指针不回退**：左端点 $l_{\max}(r)$ 随 $r$ 单调不减（一个更靠右的终点，其最远合法起点不会更靠左），这与 [LeetCode 76](../LeetCode_76/) 里的论证完全同构。

## 5. 常见疑问

**疑问一：收缩为什么只弹到"重复消除"就停，而不是弹到空？** 贪心地想，窗口越长越好，而条件破坏只可能由**刚纳入的那个字符**的重复引起（其余字符在上一轮已保证各至多一个）。所以收缩的终止条件是 `cnt[c] == 1`（c 为 `s[r]`）——把左端一路弹到旧 c 出局为止。弹多了白白丢掉合法长度，弹少了窗口带着重复不合法。

**疑问二：跳跃版的 `if (last[c] >= l)` 为什么不能写成 `if (last[c] != -1)`？** 字符的"上次出现"可能发生在**窗口之外**——那时它早已随收缩被移出，不构成任何冲突。只判"出现过"会把这种"历史重复"误判为冲突：有的输入上只是虚惊（`l = last[c]+1` 恰好不小于当前 $l$，指针白设一次），但 `abba` 一测就现形——第二个 `b` 把 $l$ 推到 2，随后 `a` 若只判"出现过"（上次在 0）会执行 `l = 0 + 1 = 1`：**左指针倒退**，窗口 `bba` 带着重复还算出长度 3（正确答案是 2）。判 `>= l` 等价于"重复字符确实还在窗口里"，是跳跃正确性的全部保险。`abba` 因此成为本题最经典的反例用例。

**疑问三：能不能用 DP，`dp[i]` = 以 $i$ 结尾的最长无重复子串长度？** 能，而且就是跳跃版的另一种说法：$dp[i] = \min(dp[i-1] + 1,\ i - last[s[i]])$。转移含义是"要么在上一个的右边延长一格，要么被窗口内的旧字符拦腰截断"。它与跳跃版逐字符等价，殊途同归——本题的滑动窗口本质就是这个 $O(1)$ 转移的指针化写法。

> 📚 系统整理见模板笔记：[滑动窗口：单调性判据与三种基本形态](../../algorithms/sliding_window/)（本题是"至多型条件 + 求最长"形态的代表）、[哈希表：从查找到计数的问题模式](../../algorithms/hash_table/)（频次计数与"上次出现位置"两种用法）。

**可复用模板**（"至多型条件求最长"骨架）：

```cpp
int l = 0;
for (int r = 0; r < n; r++) {
    /* 纳入 s[r]，增量更新窗口状态 */
    while (/* 条件被破坏 */) {
        /* 移出 s[l]，增量更新窗口状态 */
        l++;
    }
    ans = max(ans, r - l + 1);   // 记录在收缩之后
}
```

与 LC 76 的"求最短"骨架对照：循环结构完全相同，差别只在**记录答案的位置**——求最长在收缩循环外（窗口恢复合法后越长约好），求最短在收缩循环内（边缩边记）。一进一出，两道题互为镜像。

**一句话总结**：无重复字符的最长子串是"**至多型条件 + 求最长**"的滑窗范式题——计数数组 $O(1)$ 判重、左指针只进不退；跳跃版用"上次出现位置"把逐格收缩变成一步跳跃，坑全在 `last[c] >= l` 这个"重复字符仍在窗口内"的判据上。
