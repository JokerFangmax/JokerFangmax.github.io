# LeetCode 64. 最小路径和

> 题目链接：[https://leetcode.cn/problems/minimum-path-sum/](https://leetcode.cn/problems/minimum-path-sum/)  
> 难度：中等  
> 标签：数组、动态规划、矩阵

---

## 1. 题目描述

给定一个 $m \times n$ 的非负整数矩阵 `grid`，你从**左上角**出发，每一步只能**向右**或**向下**移动一格，走到**右下角**。路径上经过的所有数字之和称为"路径和"，返回**最小的路径和**。

**数据范围：**

- $m = grid.length$，$n = grid[i].length$
- $1 \le m, n \le 200$
- $0 \le grid[i][j] \le 255$

**示例：**

```
输入：grid = [[1,3,1],
             [1,5,1],
             [4,2,1]]
输出：7
解释：路径 1 → 3 → 1 → 1 → 1 的和最小，为 7。

输入：grid = [[1,2,3],
             [4,5,6]]
输出：12
解释：路径 1 → 2 → 3 → 6，和为 12。
```

注意方向只有右和下，**不能向上、向左、斜着走**——这个限制是后面所有分析的前提。

---

## 2. 思路分析

### 2.1 暴力：枚举所有路径

从左上角到右下角，每条路径由 $m + n - 2$ 步组成（$m-1$ 步向下 + $n-1$ 步向右），路径总数是组合数 $\binom{m+n-2}{m-1}$。$m = n = 200$ 时约为 $\binom{398}{199}$——一个天文数字（超过 $10^{100}$），暴力枚举完全不可行。

问题出在：**不同的路径共享大量前缀**，例如 "右右下" 和 "右右下下" 的前一段完全重合，但暴力做法会把这段重复走一遍、重复算一遍。我们需要一个结构，让每段公共前缀只算一次。

### 2.2 贪心为什么不行

一个自然的幻想："每一步都走相邻两格中较小的那个"。用题目示例本身就能推翻它：

```
grid = [ 1  3  1 ]
       [ 1  5  1 ]
       [ 4  2  1 ]

贪心：1 → 1 → 4 → 2 → 1 = 9   （第一步看到下方 1 < 右边 3 就走下）
最优：1 → 3 → 1 → 1 → 1 = 7   （先吃下 3 的代价，换来后面一路 1）
```

贪心只看"眼前的下一步"，而**当前局部较优的选择可能把后面更便宜的路堵死**（一旦走到底行，就再也回不到第一行了）。局部最优推不出全局最优，必须用能"看到全局"的方法——动态规划 (dynamic programming)。

### 2.3 状态定义与转移：从终点往回看

换一个视角：不从起点往前走，而是问**"到达格子 $(i, j)$ 的最小路径和是多少"**。

关键观察：由于只能向右或向下移动，**到达 $(i, j)$ 的最后一步，要么从 $(i-1, j)$ 下来，要么从 $(i, j-1)$ 过来**——只有这两种可能，别无他法。于是定义：

> $dp[i][j]$ = 从 $(0, 0)$ 走到 $(i, j)$ 的最小路径和。

转移方程就是"两种来路取较优，再加上自己的代价"：

$$dp[i][j] = grid[i][j] + \min(dp[i-1][j],\; dp[i][j-1])$$

边界：第一行的格子只能从左边来（$dp[0][j] = dp[0][j-1] + grid[0][j]$），第一列只能从上面来。这两条边界是递推的起点。

**为什么这个定义没有后效性？** $dp[i][j]$ 一旦算出就不再改变，且它只依赖"更靠左上"的状态——未来怎么走不影响它，它也不需要知道前面的路径具体长什么样。这正是 DP 可行的两个条件：**最优子结构**（到达 $(i,j)$ 的最优路径，其前缀也必是到达来路格子的最优路径，否则把前缀换成更优的，整体更优，矛盾）和**无后效性**（"只能右/下走"保证了这一点——如果允许向上走，"来路"就有无穷种，状态就不干净了）。

### 2.4 用示例走一遍 DP 表

`grid = [[1,3,1],[1,5,1],[4,2,1]]`，逐行递推：

| 递推位置 | 计算 | $dp$ 值 | 说明 |
|---|---|---|---|
| $dp[0][0]$ | 边界 | **1** | 起点 |
| $dp[0][1]$ | $1 + 3$ | **4** | 第一行，只能从左来 |
| $dp[0][2]$ | $4 + 1$ | **5** | 同上 |
| $dp[1][0]$ | $1 + 1$ | **2** | 第一列，只能从上来 |
| $dp[1][1]$ | $5 + \min(4, 2)$ | **7** | 来路是上 (2) 更便宜 |
| $dp[1][2]$ | $1 + \min(5, 7)$ | **6** | 来路是左 (5) 更便宜 |
| $dp[2][0]$ | $2 + 4$ | **6** | 第一列 |
| $dp[2][1]$ | $2 + \min(7, 6)$ | **8** | 来路是上 (6) 更便宜 |
| $dp[2][2]$ | $1 + \min(6, 8)$ | **7** | 答案 |

最终 $dp[2][2] = 7$，对应的路径是 $1 \to 3 \to 1 \to 1 \to 1$，与期望一致。

整个 DP 表写成矩阵的样子：

```
grid          dp
1 3 1         1  4  5
1 5 1    →    2  7  6
4 2 1         6  8  7   ← 右下角即答案
```

### 2.5 空间优化：一维滚动数组

递推第 $i$ 行时，只用到第 $i-1$ 行（上方的 $dp[j]$）和本行左边（$dp[j-1]$）。用一个长度为 $n$ 的一维数组即可：遍历到 $j$ 时，数组里 $dp[j]$ 还存着上一行的值，$dp[j-1]$ 已更新为本行的值——恰好就是转移需要的两个来源。

## 3. 代码实现

```cpp
class Solution {
public:
    int minPathSum(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        vector<int> dp(n, INT_MAX);   // dp[j] 滚动保存"当前行"的递推值
        dp[0] = 0;                    // 配合下面的 dp[0] += grid[i][0] 完成初始化

        for (int i = 0; i < m; i++) {
            dp[0] += grid[i][0];      // 第一列：只能从上面来，逐行累加
            for (int j = 1; j < n; j++)
                dp[j] = grid[i][j] + min(dp[j], dp[j-1]);
                //                  ↑ 此时 dp[j] 是上一行的值（从上来）
                //                       dp[j-1] 是本行的值（从左来）
        }
        return dp[n - 1];
    }
};
```

几个实现细节：

1. **`dp` 初始化为 `INT_MAX`、`dp[0] = 0`** 是一个偷懒技巧：第一行递推时 `min(dp[j], dp[j-1])` 中 `dp[j]` 是 `INT_MAX`，`min` 自动选中 `dp[j-1]`，第一行"只能从左来"的边界无需单独写一个循环。
2. **没有 `+1` / `-1` 的下标戏法**：$dp[j]$ 直接对应第 $j$ 列，状态含义与矩阵下标一一对应，减少差一错误。
3. 面试中若允许修改输入，可以**原地**把 `grid` 当作 dp 表用，空间 $O(1)$——但会破坏输入数组，工程上要谨慎（见第 5 节）。

## 4. 复杂度分析

- **时间复杂度**：$O(mn)$。每个格子恰好计算一次，每次 $O(1)$（一次 `min`、一次加法）。$m = n = 200$ 时约 $4 \times 10^4$ 次操作，毫秒级。相比暴力路径数 $\binom{m+n-2}{m-1}$ 的指数级，是"重叠子问题只算一次"带来的收益。
- **空间复杂度**：$O(n)$。一维滚动数组，长度为列数（也可以按列递推，压到 $O(m)$，取较小者更优；二维 dp 则是 $O(mn)$）。

顺带一提，答案上界是 $200 \times 200 \times 255 \approx 10^7$，`int`（上限约 $2.1 \times 10^9$）绰绰有余，不需要 `long long`。

## 5. 常见疑问

**Q1：DP 表能不能"从终点倒着推"？**

可以。定义 $dp[i][j]$ = 从 $(i, j)$ 走到终点的最小路径和，转移为 $dp[i][j] = grid[i][j] + \min(dp[i+1][j], dp[i][j+1])$，答案在 $dp[0][0]$。两种方向完全对称，正确性同理。**但两种定义不能混用**——"起点到 $(i,j)$ 的最小和"与"$(i,j)$ 到终点的最小和"是不同的量，写代码前先想清楚自己定义的是哪一个。

**Q2：原地修改 `grid` 为什么有争议？**

`grid[i][j] += min(grid[i-1][j], grid[i][j-1])` 之后 `grid` 里存的就是 dp 值，空间 $O(1)$，在线判题系统上完全能过。但函数签名传的是引用，**调用方的原矩阵被永久改掉了**。竞赛无所谓；工程代码里"顺手改掉输入"往往是 bug 来源。折中方案就是本题采用的 $O(n)$ 滚动数组——只多一个向量，换来对输入的零侵入。

**Q3：如果还允许"向右下走一格"（对角线）呢？**

转移方程多一项：$dp[i][j] = grid[i][j] + \min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])$。可见 DP 的框架不依赖"只有两种走法"，只依赖**"到达每个状态的来路可以枚举完"**。反过来，一旦允许向上/向左走，来路无法枚举、还会产生环，这种朴素 DP 就失效了（那是图论最短路的问题，得用 Dijkstra）。

## 6. 相关题目与模板

**可复用模板**（网格 DP 通用骨架，本系列反复出现）：

```cpp
// 网格 DP（只能向右/向下）：
// 1. 明确 dp[i][j] 的含义（到 (i,j) 的指标 / 从 (i,j) 出发的指标）
// 2. 处理第一行、第一列两条边界
// 3. 双层循环内做 min/max 转移
// 4. 视情况压成一维滚动数组
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        dp[i][j] = grid[i][j] + best(dp[i-1][j], dp[i][j-1]);
```

**同类题目（按难度递进）：**

- [LeetCode 62. 不同路径](https://leetcode.cn/problems/unique-paths/)：把 min 换成加法计数，$dp[i][j] = dp[i-1][j] + dp[i][j-1]$，还能用组合数 $O(m+n)$ 秒杀
- [LeetCode 63. 不同路径 II](https://leetcode.cn/problems/unique-paths-ii/)：加了障碍物，障碍格 dp 置 0，边界处理更细
- [LeetCode 120. 三角形最小路径和](https://leetcode.cn/problems/triangle/)：来路变成"正上/左上"，且可以原地倒推
- [LeetCode 931. 下降路径最小和](https://leetcode.cn/problems/minimum-falling-path-sum/)：方向换成向下三选一，骨架不变
- [LeetCode 1289. 下降路径最小和 II](https://leetcode.cn/problems/minimum-falling-path-sum-ii/)：转移要"除自己以外的最小值"，需要维护行内最小、次小——网格 DP 与预处理技巧的结合

**方法论总结**：这类"网格 + 受限移动 + 最优化指标"的题，识别信号非常明显——移动规则保证了**无后效性**，每个状态的来路（或去路）可枚举，直接套网格 DP 模板即可。

**一句话总结**：最小路径和是网格 DP 的教科书题——"到达每个格子的最优 = 自身代价 + 两种来路的最优"，$\binom{m+n-2}{m-1}$ 条路径的重复前缀被压缩成一张 $m \times n$ 的表，每个格子只算一次。
