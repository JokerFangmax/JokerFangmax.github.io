# LeetCode 763. 划分字母区间

> 题目链接：[https://leetcode.cn/problems/partition-labels/](https://leetcode.cn/problems/partition-labels/)  
> 难度：中等  
> 标签：贪心、哈希表、双指针、字符串

---

## 1. 题目描述

给你一个字符串 `s`，要求把 `s` 划分成**尽可能多**的片段，使得每个字母最多只出现在**一个**片段中，返回一个列表，表示每个片段的长度。

划分结果需满足：把所有片段按顺序连接后得到的字符串仍是 `s`（即划分是"切割"，不能重排、不能丢弃字符）。

**数据范围：**

- $1 \le s.length \le 500$
- `s` 仅由小写英文字母组成

**示例：**

```
输入：s = "ababcbacadefegdehijhklij"
输出：[9, 7, 8]
解释：划分成 "ababcbaca"、"defegde"、"hijhklij" 三段。
     每个字母只出现在一个片段里；段数 3 已是最大。
     注意划分成更多段（如 4 段）是不可能的：
     字母 a 的出现横跨下标 0..8，这一坨必须整体进第一段。
```

---

## 2. 思路分析

### 2.1 暴力：枚举切割点，反复检查

从左到右贪心地试：第一段先取 `s[0]`，看这段里的字母是否在后面还有出现——有就把段右端右移一格，再检查……直到段内所有字母都不再出现为止，切一刀，对剩余部分重复。每次右移后都要检查段内**所有**字母在**剩余全部**后缀中的出现情况，最坏 $O(n)$ 段 $\times$ $O(n)$ 扩展 $\times$ $O(n)$ 检查 $\approx O(n^3)$（利用 $n \le 500$ 的数据范围勉强能过，但毫无美感）。

瓶颈在于：**"字母 c 还会不会再出现"这个查询被重复问了千百遍**，而它的答案其实只取决于一个数——字母 `c` 最后一次出现的下标。

### 2.2 关键观察：每个字母只有一个"末次出现"

预处理数组 `last[c]`：字母 `c` 在 `s` 中最后出现的下标（仅有 26 个小写字母，用长度 26 的数组当**哈希表 (hash table)** 即可，可参考 [哈希表模板笔记](../../algorithms/hash_table/)）。

于是"下标 `i` 可以作为切割点"当且仅当：

$$\forall\, c \in s[0..i]:\quad last[c] \le i$$

即**当前段内出现过的每个字母，其末次出现都不越过 $i$**。更进一步，扫描时不必回头枚举段内字母，维护一个变量 `end`——**当前段所有字母的 `last` 的最大值**：

$$\text{end} = \max_{c \in \text{当前段}} last[c]$$

- 扫到 `i` 时，`end = max(end, last[s[i]])`；
- 当 `i == end` 时，段内任何字母都不会在 `end` 之后出现，**此处切割绝对安全**；同时由于 `end` 是被段内某字母的末次出现顶到这里的，在 `end` 之前切必然把某个字母一分为二——所以在 `i == end` 切，得到的是**最靠左的合法切割点**。

### 2.3 贪心：最靠左的切割点为什么最优

设第一个合法切割点是 $p_1$（即上面的第一个 `end`）。对任意一种合法划分，其第一段右端 $q \ge p_1$——若 $q < p_1$，则段内含某字母 $c$ 且 $last[c] > q$，与合法矛盾。第一段取 $[0, p_1 - 1]$（长度 $p_1$）后，剩余子串是原问题在 $s[p_1..n-1]$ 上的实例，规模严格变小且**子串内的 `last` 关系完全不变**（末次出现位置关于子串的限制是全局一致的）。第一段更短不损害后续任何选择余地，故"每步切在最靠左的合法点"得到全局最多段——交换论证 + 子问题独立性，标准贪心。

这个结构也可类比 [LeetCode 56. 合并区间](https://leetcode.cn/problems/merge-intervals/)：每个字母 `c` 给出区间 $[\text{first}(c),\; last(c)]$，把互相重叠的字母区间并成尽可能多的"粘连块"，每块对应一个片段。`end` 变量就是在扫描线中实时维护"当前粘连块的右端"。

### 2.4 手动模拟（以示例走一遍）

`s = "ababcbacadefegdehijhklij"`，末次出现位置：

| 字母 | a | b | c | d | e | f | g | h | i | j | k | l |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| `last` | 8 | 5 | 7 | 15 | 14 | 11 | 13 | 19 | 22 | 23 | 20 | 21 |

扫描过程（段起点 `start`，段右端候选 `end`）：

| $i$ | $s[i]$ | $last[s[i]]$ | `end` | 说明 |
|---|---|---|---|---|
| 0 | a | 8 | **8** | a 的末次出现顶出初始 end |
| 1 | b | 5 | 8 | 未超越 |
| 2 | a | 8 | 8 | — |
| 3 | b | 5 | 8 | — |
| 4 | c | 7 | 8 | — |
| 5 | b | 5 | 8 | — |
| 6 | a | 8 | 8 | — |
| 7 | c | 7 | 8 | — |
| 8 | a | 8 | 8 | $i == end$：**切！段长 $8 - 0 + 1 = 9$**，`start = 9` |
| 9 | d | 15 | **15** | 新段，d 顶出 end |
| 10 | e | 14 | 15 | — |
| 11 | f | 11 | 15 | — |
| 12 | e | 14 | 15 | — |
| 13 | g | 13 | 15 | — |
| 14 | e | 14 | 15 | — |
| 15 | d | 15 | 15 | $i == end$：**切！段长 $15 - 9 + 1 = 7$**，`start = 16` |
| 16..23 | h i j h k l i j | 19..23 | **23** | h 顶到 19，j 顶到 23 |
| 23 | j | 23 | 23 | $i == end$：**切！段长 $23 - 16 + 1 = 8$** |

输出 `[9, 7, 8]`，与期望一致。注意第 0 步：单看 `s[0] = 'a'` 就知道第一段至少要延伸到下标 8——`end` 一开始就被"钉"在了 8。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<int> partitionLabels(string s) {
        int n = s.size();
        int last[26] = {0};
        for (int i = 0; i < n; i++)
            last[s[i] - 'a'] = i;          // 同一字母反复覆盖，留下末次出现

        vector<int> ans;
        int start = 0, end = 0;            // 当前段 [start, end] 的两个端点
        for (int i = 0; i < n; i++) {
            end = max(end, last[s[i] - 'a']);  // 段内字母把段右端往外顶
            if (i == end) {                    // 扫描指针追上段右端：
                ans.push_back(end - start + 1);//   此前不会再有字母越界，安全切割
                start = i + 1;                 //   开启新段
            }
        }
        return ans;
    }
};
```

实现细节：

1. **`last` 用一遍倒序或正序覆盖均可**：正序扫时同一字母后面的下标覆盖前面的，循环结束留下的自然是末次出现；`int last[26] = {0}` 的初值只会被实际出现的字母覆盖，本题逻辑下每个 `end` 都来自真实字母，无假阳性。
2. **`start` 与 `end` 构成一对双指针**：`end` 由段内字母的 `last` 推动，`i` 是扫描指针；`i == end` 是"指针追平段右端"的信号，比 `end` 小时绝不能切，比 `end` 大则不可能（`i` 走到哪，`last[s[i]]` 至少是 `i` 自己，`end` 不会落后于 `i`）。
3. 段长是 `end - start + 1`，**加一别丢**——这是本题最高频的 WA 点。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。预处理 `last` 一遍 $O(n)$，主扫描一遍 $O(n)$，每步 $O(1)$（字母表大小 26 视为常数）。
- **空间复杂度**：$O(|\Sigma|) = O(26) = O(1)$。`last` 数组与答案之外无额外开销（不计输出）。

对比：暴力反复检查 $O(n^2)$ 至 $O(n^3)$ → 预处理末次出现 + 一次扫描 $O(n)$。优化本质是**把"后缀里还有没有 c"这个反复的查询，预计算成 `last[c]` 一个数**。

## 5. 常见疑问

**Q1：`i == end` 时切割，怎么保证段内字母不会在 `end` 之后出现？**

段内字母的集合是 $s[\text{start}..i]$ 中出现过的所有字母，而 `end` 是它们 `last` 值的最大值——每个字母的末次出现都 $\le \text{end} = i$，所以 $i$ 之后不可能再冒出段内任何字母。反之，若在 $i' < \text{end}$ 处切，`end` 恰是段内某字母 $c$ 的 `last`，$c$ 在 $(i',\; \text{end}]$ 内还有出现，切了就违规。**`i == end` 是唯一的、也是最早的合法时机。**

**Q2：为什么贪"最早切割"就能得到最多段？**

段数最大 $\Leftrightarrow$ 每段尽量短。第一段取最短合法长度后，剩下的子问题完全独立（后续段的合法性只依赖 `last` 的相对大小，与前面切在哪无关），第一段每短一格，后续的"活动空间"只会更宽松。严格地说，任何最优解的第一段都可以替换成最靠左的切割而不影响后续切割的合法性（后续切割点全在第一段右侧，仅需 $\ge$ 某个下界，而那个下界没变），交换论证即得贪心正确。

**Q3：为什么不用真的去"合并区间"？**

两种做法等价：56 式做法为每个字母建区间 $[\text{first}, \text{last}]$，排序后合并粘连块，$O(|\Sigma| \log |\Sigma|)$ 排序 + $O(n)$ 收集；本文做法直接在原串上扫描，用 `end` 实时维护"当前粘连块右端"，连排序都省了。后者相当于发现了一个隐藏性质：**按左端点（即扫描下标）的天然顺序处理区间，就无需排序**。数据范围 $n \le 500$ 下两者都轻松通过，但 $O(n)$ 扫描版更值得记住。
