# LeetCode 56. 合并区间

> 题目链接：[https://leetcode.cn/problems/merge-intervals/](https://leetcode.cn/problems/merge-intervals/)  
> 难度：中等  
> 标签：数组、排序

---

## 1. 题目描述

给出一组**闭区间** `intervals`，其中 `intervals[i] = [start_i, end_i]`。请合并所有**重叠的区间**，返回一个不重叠的区间数组，且需**恰好覆盖输入中的所有区间**。

两个闭区间 $[a, b]$ 和 $[c, d]$ 重叠（可以合并）当且仅当它们有公共点；注意闭区间的端点也算在内——$[1, 4]$ 和 $[4, 5]$ 共享点 4，**要合并**成 $[1, 5]$。

**数据范围：**

- $1 \le intervals.length \le 10^4$
- $intervals[i].length = 2$
- $0 \le start_i \le end_i \le 10^4$

**示例：**

```
输入：intervals = [[1,3],[2,6],[8,10],[15,18]]
输出：[[1,6],[8,10],[15,18]]
// [1,3] 与 [2,6] 重叠（2 落在 [1,3] 内），合并为 [1,6]

输入：intervals = [[1,4],[4,5]]
输出：[[1,5]]
// 两个区间在端点 4 相接，闭区间共享点 4，视为重叠
```

（第二个示例是本题最经典的边界：端点相接即重叠——闭区间的端点也是自己的点，$[1,4] \cup [4,5]$ 连成一段 $[1,5]$。）

---

## 2. 思路分析

### 2.1 暴力：两两检查、反复合并

任取两个区间，若重叠就合并成一个，再反复扫描直到没有可合并的对。问题有三：

1. 每轮合并都可能催生新的重叠（$[1,3]$ 与 $[3,5]$ 合并成 $[1,5]$ 后，原本不相干的 $[4,6]$ 变得可合并），需要反复多轮，最坏 $O(n^2)$ 轮；
2. 合并的结果放回哪里、和已处理部分的关系都变得混乱；
3. $n = 10^4$ 时 $O(n^2) = 10^8$ 的比较在常数不小的情况下也会吃紧。

**本质困难：区间在输入里是乱序的，我们不知道"谁和谁相邻"。** 合并的直觉是"从左往右扫，把碰在一起的粘起来"——那就先让它们从左到右**有序**。

### 2.2 关键观察：按左端点排序后，可合并的区间一定连续

将所有区间按**左端点 $start$ 升序**排序。设排序后为 $I_1, I_2, \dots, I_n$，有：

> 若 $I_j$ 与某个 $I_i$（$j > i$）能合并，则 $I_i$ 与 $I_{i+1}, \dots, I_j$ 中所有与 $I_i$ 的并集重叠的区间也连成一片——**合并组在排序后的序列中是连续段**。

理由：排序保证 $start$ 单调不减。考察当前已合并段 $[L, R]$ 与下一个区间 $[s, t]$：

- 若 $s \le R$：它与当前段重叠，并入，$R \leftarrow \max(R, t)$；
- 若 $s > R$：由于后面所有区间的 $start \ge s > R$，**它们谁也够不着当前段**，当前段封笔，开新段。

第二条就是"敢于封笔"的依据——排序让"后面的更远"成为保证，一次线性扫描即可，不需要回头看。这也是为什么按左端点排序优于按右端点：**扫描是从左往右推进的，锁住左端点，右端点才由 $\max$ 动态维护**。

### 2.3 操作流程（以示例演示）

`intervals = [[1,3],[2,6],[8,10],[15,18]]`，已按左端点有序。当前合并段记 $[L, R]$：

| 步 | 当前区间 $[s, t]$ | 比较 $s$ 与 $R$ | 动作 | 合并段 | 已封笔的段 |
|---|---|---|---|---|---|
| 1 | $[1, 3]$ | （首段） | 开段 $L=1, R=3$ | $[1, 3]$ | — |
| 2 | $[2, 6]$ | $2 \le 3$ ✅ | 并入，$R = \max(3, 6) = 6$ | $[1, 6]$ | — |
| 3 | $[8, 10]$ | $8 > 6$ ❌ | 封笔 $[1,6]$，开新段 | $[8, 10]$ | $[1,6]$ |
| 4 | $[15, 18]$ | $15 > 10$ ❌ | 封笔 $[8,10]$，开新段 | $[15, 18]$ | $[1,6],[8,10]$ |

扫描结束，封笔最后一段，输出 `[[1,6],[8,10],[15,18]]`。

再看**端点相接**的例子 `[[1,4],[4,5],[6,7]]`：

| 步 | 当前区间 | 比较 | 动作 | 合并段 |
|---|---|---|---|---|
| 1 | $[1, 4]$ | — | 开段 | $[1, 4]$ |
| 2 | $[4, 5]$ | $4 \le 4$ ✅ | 并入，$R = \max(4,5) = 5$ | $[1, 5]$ |
| 3 | $[6, 7]$ | $6 > 5$ ❌ | 封笔，开新段 | $[6, 7]$ |

条件写成 $s \le R$（而不是 $s < R$）正是为了把端点相接算作重叠。若题目改成开区间或"相接不算重叠"，把 $\le$ 改成 $<$ 即可——一个字符的差别。

### 2.4 为什么只需要 $\max$ 更新右端点

并入区间 $[s, t]$ 时左端点为什么不动？因为排序后 $s \ge L$ 恒成立，$L$ 已是当前段的最左端。而 $t$ 与 $R$ 大小关系不定（小区间可以整个埋在大区间里，如 $[1, 10]$ 后跟 $[2, 3]$），所以右端点必须取 $\max$。漏写 $\max$ 直接写 $R = t$ 的话，`[[1,10],[2,3]]` 会错误输出 $[1,3]$。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<vector<int>> merge(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end());   // 默认按 start 升序，start 相同按 end
        vector<vector<int>> ans;
        for (auto& iv : intervals) {
            int s = iv[0], t = iv[1];
            if (!ans.empty() && s <= ans.back()[1]) {
                // 与当前段重叠（含端点相接）：只扩张右端点
                ans.back()[1] = max(ans.back()[1], t);
            } else {
                // 排序保证后面的区间 start 更大，够不着当前段，开新段
                ans.push_back({s, t});
            }
        }
        return ans;
    }
};
```

几个实现细节：

1. **`sort` 对 `vector<vector<int>>` 的默认字典序**恰好就是"先按 $start$、再按 $end$"，无需自定义比较函数。若自己写比较器，只比较 $start$ 即可（`end` 的次序不影响正确性，见疑问二）。
2. **合并直接在答案数组末尾进行**：`ans.back()` 就是"当前未封笔的段"，省掉单独的 $[L, R]$ 变量；扫完自然封笔，不需要收尾处理。
3. **`s <= ans.back()[1]`** 的 $\le$ 承载了"闭区间端点相接即重叠"的语义，改题面时从这改。
4. 原地修改了输入 `intervals`（排序），若不允许可先拷贝一份。

## 4. 复杂度分析

- **时间复杂度**：$O(n \log n)$。排序主导；线性扫描部分 $O(n)$。这也是基于比较的排序做法的下界——想让"谁和谁相邻"可判定，至少要把乱序输入变成某种有序，而区间合并输出本身可以做到 $O(n)$ 个段。
- **空间复杂度**：$O(\log n)$ 排序栈（不计输出）。若计入输出的 `ans`，最坏 $O(n)$（所有区间互不相交）。

| 做法 | 时间 | 备注 |
|------|------|------|
| 反复两两合并 | 最坏 $O(n^2)$ 轮 | 合并催生新重叠，难写难分析 |
| **排序 + 扫描** | $O(n \log n)$ | 一次扫描封笔，永不回头 |
| 已排序输入 | $O(n)$ | 现实数据若天然有序可跳过排序 |

## 5. 常见疑问

**疑问一：区间 A 包含区间 B，例如 `[1,10]` 后跟 `[2,3]`，逻辑对吗？** 对。$s = 2 \le R = 10$，并入时 $R = \max(10, 3) = 10$ 不变——包含关系被 $\max$ 自然消化。这就是 2.4 节强调的：右端点必须取 $\max$，它同时处理"相交"与"包含"两种重叠形态。

**疑问二：`start` 相同的区间需要按 `end` 排序吗？** 不需要单独考虑——默认字典序恰好排了，但即使不排也不出错：$s$ 相同时 $s \le R$ 必然成立（第一个该组的区间已在段里），无论先后并入，$\max$ 都会把右端点抬到组内最大。换句话说，**算法只依赖左端点有序这一个前提**。

**疑问三：为什么不用差分/标记数组？** 值域 $10^4$ 很小，确实可以开 $2 \times 10^4$ 的数组打 +1/-1 标记再扫前缀和（把"覆盖次数 ≥ 1 的极大连续段"作为答案）——但那是**坐标记数**做法，值域一大（如 $10^9$）就崩，而且"端点相接即合并"与"整数点覆盖"的语义在实数区间上并不等价。排序法只依赖 $O(n \log n)$ 次比较，对任意整数/实数/甚至字符串坐标的区间都成立，是普适解。

## 6. 相关题目与模板

**可复用模板**（区间问题的"排序 + 扫描"骨架）：

```cpp
sort(intervals.begin(), intervals.end());   // 按左端点
for (auto& iv : intervals) {
    if (!ans.empty() && iv[0] <= ans.back()[1])      // 与当前段相交
        ans.back()[1] = max(ans.back()[1], iv[1]);   // 只扩右端
    else
        ans.push_back(iv);                           // 开新段
}
```

**方法论总结：** 区间题的第一反射动作是**按左端点排序**，排序后几乎所有区间问题都退化为一次线性扫描：

- 求**合并**后的不重叠覆盖（本题）——扫描中封笔旧段；
- 求"最多保留多少个互不重叠区间"（贪心）——通常改按**右端点**排序，以便"最早结束者优先"；
- 求区间的**最大重叠层数**（差分/堆）——扫描时维护"当前在场的右端点"。

**同类题目：**

- [LeetCode 57. 插入区间](https://leetcode.cn/problems/insert-intervals/)：本题的"在线"版本——已排序且互不重叠的区间里插入一个新区间，只需局部合并
- [LeetCode 435. 无重叠区间](https://leetcode.cn/problems/non-overlapping-intervals/)：贪心经典，按右端点排序数"必须删掉的"
- [LeetCode 252. 会议室](https://leetcode.cn/problems/meeting-rooms/) / [LeetCode 253. 会议室 II](https://leetcode.cn/problems/meeting-rooms-ii/)：区间调度入门与"最大同时在册数"（堆 / 差分）
- [LeetCode 1288. 删除被覆盖区间](https://leetcode.cn/problems/remove-covered-intervals/)：排序后判包含，只删不合并

**一句话总结**：按左端点排序把"谁和谁相邻"变成确定的事实，之后一次线性扫描、每步一个 $\max$——区间合并的全部技巧就这两下。
