# LeetCode 22. 括号生成

> 题目链接：[https://leetcode.cn/problems/generate-parentheses/](https://leetcode.cn/problems/generate-parentheses/)  
> 难度：中等  
> 标签：字符串、回溯

---

## 1. 题目描述

给定一个整数 $n$，代表括号对数，请生成**所有**可能的、格式正确的（valid）括号组合。

"格式正确"指整个串可以被配对解析：任意前缀中右括号的数量不超过左括号的数量，且最终两者相等。例如 `"(()())"` 合法，`"())("` 与 `"((()"` 不合法。

**数据范围：**

- $1 \le n \le 8$

**示例：**

```
输入：n = 3
输出：["((()))","(()())","(())()","()(())","()()()"]

输入：n = 1
输出：["()"]
```

$n = 8$ 时答案共 $1430$ 个——虽然不大，但盲目枚举所有 $2^{16} = 65536$ 个括号串再过滤，已经是两倍以上的浪费了。

---

## 2. 思路分析

### 2.1 暴力：枚举全部串再验证

长度为 $2n$ 的串，每位二选一（`(` 或 `)`），共 $2^{2n}$ 个候选；逐个用栈或计数器验证合法性，代价 $O(2^{2n} \cdot n)$。$n = 8$ 时约 $65536 \times 16 \approx 10^6$，勉强能过，但这是**先犯错再纠错**的做法：一个串前缀里右括号已经多出来了，后面填什么都救不回来，却还要继续生成、继续验证。

### 2.2 关键观察：合法性可以在构造过程中"提前锁定"

用两个计数器描述当前状态：已用的左括号数 `open`、右括号数 `close`。站在路径长度为 $k$ 的位置，下一步：

- 可以放 `(`，当且仅当 `open < n`——左括号不能超预算；
- 可以放 `)`，当且仅当 `close < open`——右括号必须跟着一个还没配对的左括号。

**只要每一步都遵守这两条，最终串一定合法**。理由拆成两半：

1. **任意前缀 `)` 不多于 `(`**：因为每个 `)` 放下时都有 `close < open` 兜底；
2. **最终两者相等**：路径长度到达 $2n$ 时若 `open < n`，说明还能放 `(`，生成不会停止——换言之，终止的路径必然 `open == n`，而 `close` 每次都追着 `open` 且不超过它，故 `close == n`。

于是"生成后验证"退化为"生成时约束"，非法分支在树上就被掐灭，这就是**回溯 (backtracking) + 剪枝 (pruning)**。

### 2.3 逐步走一遍：n = 2

树边上的字符是选择，`(3,2)` 表示 `(open, close)`：

```
                     (0,0)
                 '(' /      \ ')'：close<open 不成立 → 剪掉
                (1,0)
            '(' /      \ ')'
           (2,0)         (1,1)         ← path = "()"
        ')' /   '('✗   '(' /   \ ')'：close==open ✗
      (2,1)            (2,1)     [死路]
     ')' /  '('✗       ')' /
    (2,2)✓            (2,2)✓
    "(())"            "()()"
```

逐条路径核对：

| 路径 | 生成串 | 结果 |
|------|--------|------|
| `(` → `(` → `)` → `)` | `(())` | 收获 |
| `(` → `)` → `(` → `)` | `()` + `()` = `()()` | 收获 |
| 开头就放 `)` | — | `close < open` 不成立，剪掉 |
| `(())` 后再放 `(` | — | `open == n == 2`，剪掉 |

答案恰好是 `["(())", "()()"]` 两个。注意第 4 行：合法答案收集发生在**长度到达 $2n$** 时，而不是"放不出字符"时——两者靠剪枝条件保证同时发生。

### 2.4 顺带一提：答案的规模是卡特兰数

$n$ 对括号的合法串个数是**卡特兰数 (Catalan number)**

$$C_n = \frac{1}{n+1}\binom{2n}{n}$$

$n = 1,2,3,\dots$ 依次为 $1, 2, 5, 14, 42, \dots, 1430\ (n=8)$。剪枝后的搜索树恰好每个叶子都对应一个合法串，所以树的时间开销与答案数量同级——这道题是"回溯树 = 解空间树"的理想样本。

## 3. 代码实现

```cpp
class Solution {
    vector<string> ans;
    string path;

    void dfs(int n, int open, int close) {
        if ((int)path.size() == 2 * n) {   // open==n==close 必然成立
            ans.push_back(path);
            return;
        }
        if (open < n) {                    // 还有左括号预算
            path.push_back('(');
            dfs(n, open + 1, close);
            path.pop_back();               // 撤销，尝试另一分支
        }
        if (close < open) {                // 有等待配对的左括号
            path.push_back(')');
            dfs(n, open, close + 1);
            path.pop_back();
        }
    }

public:
    vector<string> generateParenthesis(int n) {
        dfs(n, 0, 0);
        return ans;
    }
};
```

三个细节：

1. 两个 `if` 是**并列**而非 `else if`——同一位置可能既允许 `(` 也允许 `)`，两条分支都要走；正因为走完第一分支后 `pop_back()` 恢复了现场，第二分支才从同一状态出发；
2. 终止条件用 `path.size() == 2n` 而非检查计数器：由 2.2 的论证，能到达这一层的路径必然合法，无需再验；
3. `path` 作为成员复用，收集时 `push_back(path)` 拷贝一份进答案——回溯共享路径、答案各自留副本，是这类题的通用写法。

## 4. 复杂度分析

- **时间复杂度**：$O\!\left(\dfrac{4^n}{\sqrt{n}}\right)$。搜索树的每个叶子产出（拷贝长度 $2n$ 的串），叶子数即卡特兰数 $C_n \sim \dfrac{4^n}{n^{3/2}\sqrt{\pi}}$；树的内节点总数不超过叶子的常数倍，均摊后总代价仍与 $\dfrac{4^n}{\sqrt{n}}$ 同阶。$n \le 8$ 时约几千次操作。
- **空间复杂度**：$O(n)$（不计输出）。递归深度与 `path` 长度均为 $2n$。

对比暴力 $O(2^{2n} \cdot n)$：剪枝砍掉的不是常数，而是整棵"注定非法"的子树——非法前缀的全部延续都被免除。

## 5. 常见疑问

**Q1：只检查 `close < open` 和 `open < n` 真的够吗？会不会漏掉或混入非法串？**

不会混入：2.2 已证两条约束分别保证"前缀合法"与"终止时配平"。也不会漏掉：任何一个合法串从左到右扫描，每一步必然满足这两条约束（合法串的前缀仍合法），所以它在树上对应的路径全程畅通，一定会被枚举到。**约束条件与合法性判定逐字符等价**，这是"构造时剪枝"能够替代"生成后验证"的根本原因。

**Q2：为什么不用记忆化？回溯和动态规划不是常一起出现吗？**

记忆化针对的是**重叠子问题**：不同决策路径殊途同归地到达同一状态，缓存结果可以省掉重复计算。本题每个叶子都是要输出的**不同答案**，任何两条路径即使前缀状态相同、后续也必须各自完整展开——没有可丢弃的重复计算。对比 [LeetCode 322. 零钱兑换](https://leetcode.cn/problems/coin-change/)：同样"凑"的结构，只问最少硬币数，`(rest)` 一个参数就有大量重叠，用 DP 省掉指数级路径。**要方案枚举全部用回溯，只要最值/计数用 DP**，这道题是前者的代表。

**Q3：能不能用 `else if` 或把括号拼成参数传递？**

`else if` 会漏分支：`(open < n) && (close < open)` 同时成立的层（例如 `(1,0)` 且 $n > 1$）必须两个字符都试一遍。至于把 `path` 作为递归参数按值传递（`dfs(path + "(")`），功能等价、代码更短，但每层拷贝整条路径，代价 $O(k)$，撤销操作也从 $O(1)$ 的 `pop_back` 退化成自动析构；规模小无所谓，养成共享路径的习惯对后续大状态空间的题（如 N 皇后）更有利。

## 6. 相关题目与模板

**可复用模板**（带计数约束的字符串构造回溯）：

```cpp
void dfs(int open, int close) {
    if (path.size() == 2 * n) { ans.push_back(path); return; }
    if (open < n)          { path += '('; dfs(open + 1, close); path.pop_back(); }
    if (close < open)      { path += ')'; dfs(open, close + 1); path.pop_back(); }
}
```

这个骨架的推广形态是"**状态计数器决定分支合法性**"：把约束写成若干个 `if`，每个 `if` 守护一种选择。同族题目里计数器换成了别的东西而已。

**同类题目：**

- [LeetCode 17. 电话号码的字母组合](https://leetcode.cn/problems/letter-combinations-of-a-phone-number/)：无约束的纯枚举回溯，可对照感受"约束"给回溯带来了什么
- [LeetCode 2116. 判断一个括号字符串是否有效](https://leetcode.cn/problems/check-if-a-parentheses-string-can-be-valid/)：括号合法性的判定与计数推理
- [LeetCode 96. 不同的二叉搜索树](https://leetcode.cn/problems/unique-binary-search-trees/)：卡特兰数的动态规划版——同一个 $C_n$，一个数方案数，一个枚举方案
- [LeetCode 301. 删除无效的括号](https://leetcode.cn/problems/remove-invalid-parentheses/)：括号 + 回溯枚举删除位置，本题约束思想的进阶版

**方法论总结**：当"生成所有候选再验证"代价过高时，检查**合法性判定能否逐字符/逐元素地分解**——若能，就把判定条件变成搜索分支的准入条件，让非法分支在诞生的那一刻就被剪掉。括号生成的两条计数约束就是最经典的例子。

**一句话总结**：括号合法当且仅当"**右括号永远追不上左括号，最后恰好追平**"——把这句话翻译成两个 `if`，就是这道题的全部。
