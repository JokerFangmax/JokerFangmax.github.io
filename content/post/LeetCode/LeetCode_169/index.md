# LeetCode 169. 多数元素

> 题目链接：[https://leetcode.cn/problems/majority-element/](https://leetcode.cn/problems/majority-element/)  
> 难度：简单  
> 标签：哈希表、数组、计数

---

## 1. 题目描述

给定一个大小为 $n$ 的数组 `nums`，返回其中的**多数元素 (majority element)**。多数元素指在数组中出现次数**大于** $\lfloor n/2 \rfloor$ 的元素。

题目保证数组是非空的，并且给定的数组中**总是存在**多数元素。

**数据范围：**

- $n = nums.length$
- $1 \le n \le 5 \times 10^4$
- $-10^9 \le nums[i] \le 10^9$

**示例：**

```
输入：nums = [2,2,1,1,1,2,2]
输出：2

说明：n = 7，⌊n/2⌋ = 3，2 出现 4 次 > 3，是多数元素。

输入：nums = [3,2,3]
输出：3

说明：n = 3，⌊n/2⌋ = 1，3 出现 2 次 > 1。
```

注意条件是**严格大于**：$n = 4$ 时出现 $2$ 次不算多数元素，必须至少出现 $3$ 次。这意味着多数元素若存在则**唯一**——两个不同元素都超过半数在计数上是不可能的。

---

## 2. 思路分析

### 2.1 暴力：对每个元素数一遍

最直接的做法：对每个候选 `x`，扫一遍全数组统计它出现的次数，若次数 $> \lfloor n/2 \rfloor$ 就返回。双重循环，时间 $O(n^2)$。$n = 5\times10^4$ 时约 $2.5 \times 10^9$ 次比较，超时。

稍加观察可以只统计"还没被统计过的值"，但最坏情况（一半 1 一半 2 加一个 1）仍是 $O(n^2)$。

### 2.2 哈希表：一趟计数

与其反复扫数组，不如**扫一遍，把每个值的出现次数实时记进哈希表 (hash table)**，哪个值先超过 $\lfloor n/2 \rfloor$ 就立刻返回：

- 时间 $O(n)$，空间 $O(n)$。

这是最稳、最能体现"计数"思想的解法，详细做法见模板笔记 [哈希表：从计数到索引加速](../../algorithms/hash_table/)。但如果面试官追问"能不能不用额外空间"，就得继续想。

### 2.3 排序：多数元素必然霸占中位数

把数组排序。多数元素出现超过一半，那么**无论它分布在哪，排序后它必然连续占据一段长度超过 $n/2$ 的区间，从而必然盖住下标 $\lfloor n/2 \rfloor$**——也就是中位数位置。

```
n = 7，x 出现 4 次，排序后最靠左的情况：
[x x x x a b c]
      ↑
    中位数下标 3，仍是 x
```

于是 `sort(nums); return nums[n/2]`，两行搞定。时间 $O(n \log n)$，空间取决于排序实现（快排递归栈 $O(\log n)$）。代码极短，但复杂度不是最优。

### 2.4 摩尔投票：不同元素两两抵消

能不能 $O(n)$ 时间、$O(1)$ 空间？核心想法来自一个"打仗"的比喻：

> 把数组想象成战场，每个值是一个阵营。多数元素一方的兵力**严格超过全场的一半**。让所有不同阵营的士兵**一对一同归于尽**，最后必然是兵力过半的那个阵营还有幸存者。

这个"抵消"可以在线完成，不需要真的知道阵营配对：维护一个候选者 `candidate` 和它的**相对票数** `count`：

- `count == 0` 时，把当前元素立为新候选，`count = 1`；
- 当前元素等于候选，`count++`；
- 不等于候选，`count--`（视为一票候选的拥护者与一票反对者同归于尽）。

**为什么最后剩下的一定是多数元素？** 把整个过程里的每一次 `count--` 看成"消耗 1 个多数元素 + 至少 1 个其他元素"的配对。多数元素总数 $> n/2$，其他所有元素加起来 $< n/2$，即使每一对抵消都花掉一个多数元素，也至多消耗 $< n/2$ 个，多数元素必有剩余——而候选者的位置上站着的正是它。

用 `nums = [2,2,1,1,1,2,2]` 走一遍：

| i | nums[i] | 操作 | candidate | count | 说明 |
|---|---------|------|-----------|-------|------|
| 0 | 2 | 立候选 | 2 | 1 | count 为 0，2 上台 |
| 1 | 2 | 同阵 +1 | 2 | 2 | |
| 2 | 1 | 异阵 -1 | 2 | 1 | 一个 2 和一个 1 抵消 |
| 3 | 1 | 异阵 -1 | 2 | 0 | 又一个 2 和 1 抵消 |
| 4 | 1 | 立候选 | 1 | 1 | 台上空了，1 上台 |
| 5 | 2 | 异阵 -1 | 1 | 0 | 1 和 2 抵消 |
| 6 | 2 | 立候选 | 2 | 1 | 最后一个 2 上台 |

扫描结束，`candidate = 2`，即答案。这就是**博耶-摩尔投票算法 (Boyer-Moore voting algorithm)**。

## 3. 代码实现

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        int candidate = 0, count = 0;
        for (int x : nums) {
            if (count == 0) {
                candidate = x;   // 台上无人，当前元素上台
                count = 1;
            } else if (x == candidate) {
                count++;         // 同阵营，票数 +1
            } else {
                count--;         // 异阵营，一对一抵消
            }
        }
        return candidate;        // 多数元素必然幸存
    }
};
```

若想同时保留哈希表解法作为对照（面试中可先说哈希表再优化）：

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        unordered_map<int, int> cnt;
        int half = nums.size() / 2;
        for (int x : nums) {
            if (++cnt[x] > half) return x;   // 严格大于 ⌊n/2⌋ 即命中
        }
        return -1;   // 题目保证存在，不会走到这里
    }
};
```

## 4. 复杂度分析

| 解法 | 时间 | 空间 | 备注 |
|------|------|------|------|
| 暴力枚举 | $O(n^2)$ | $O(1)$ | 超时 |
| 哈希表计数 | $O(n)$ | $O(n)$ | 一趟扫描，最直观 |
| 排序取中位数 | $O(n \log n)$ | $O(\log n)$ | 代码两行 |
| **摩尔投票** | $O(n)$ | $O(1)$ | **理论最优** |

摩尔投票每个元素只访问一次、只做常数次比较，$n$ 个元素共 $O(n)$ 时间；只用了 `candidate` 和 `count` 两个变量，空间 $O(1)$。

## 5. 常见疑问

**疑问一：`count` 是不是多数元素真正的出现次数？**

不是。`count` 只是与当前候选配对后**尚未被抵消的相对优势**，中途甚至会归零换候选。以 `[2,2,1,1,1,2,2]` 为例，结束时 `count = 1`，而 2 实际出现了 4 次。算法只保证"最后站在台上的候选是谁"是对的，不保证票数信息正确——想要真实次数仍需哈希表。

**疑问二：如果题目不保证多数元素存在，摩尔投票还成立吗？**

不成立。反例 `[1,2,3]`：i=0 立候选 1，i=1 抵消，i=2 立候选 3，返回 3——但没有任何元素超过半数。原因是"抵消后幸存"只说明它**可能**是多数元素（多数元素若存在则必幸存，但幸存者未必真是多数元素）。所以不保证存在时，投票后必须**再扫一遍数组验证**候选的真实出现次数，总复杂度仍是 $O(n)$。本题加了这个保证，才省掉了验证。

**疑问三：为什么排序后取 `nums[n/2]` 一定对，而取 `nums[0]` 或众数不行？**

`nums[0]` 显然不行：多数元素可能全部堆在右半段（如 `[1,2,2,2,2]`）。而中位数位置有"居中必被覆盖"的性质：一段长度 $> n/2$ 的连续区间，无论放在 $[0, n-1]$ 的哪个位置，都必然包含下标 $\lfloor n/2 \rfloor$。反证：若该区间不含 $\lfloor n/2 \rfloor$，则它整体在左边或整体在右边，长度至多 $\lfloor n/2 \rfloor$（左边至多 $\lfloor n/2 \rfloor$ 个下标，右边同理），与长度 $> n/2$ 矛盾。

## 6. 相关题目与模板

> 📚 计数类问题的通用套路见模板笔记：[哈希表：从计数到索引加速](../../algorithms/hash_table/)。

**摩尔投票可复用模板**（求"超过 $1/k$ 出现次数的候选"，$k=2$ 即本题）：

```cpp
// Boyer-Moore 投票骨架：一趟扫描，O(1) 空间
int candidate = 0, count = 0;
for (int x : nums) {
    if (count == 0) candidate = x;
    count += (x == candidate) ? 1 : -1;   // 抵消视角
}
// 若不保证多数元素存在，需再扫一遍验证 candidate 的真实次数
```

**方法论总结**：本题展示了非常典型的一条优化链——**暴力计数 → 哈希表换空间 → 利用排序结构（中位数）→ 利用数量假设（投票抵消）**。越是利用题目的特殊保证（"多数元素一定存在"），越能压出更低的复杂度。

- [剑指 Offer 39. 数组中出现次数超过一半的数字](https://leetcode.cn/problems/shu-zu-zhong-chu-xian-ci-shu-chao-guo-yi-ban-de-shu-zi-lcof/)：本题原题换皮

- [LeetCode 287. 寻找重复数](https://leetcode.cn/problems/find-the-duplicate-number/)：同样是"利用元素分布的特殊性"做到 $O(1)$ 空间

**一句话总结**：超过半数的元素在"一对一抵消"中必然幸存——摩尔投票用两个变量就把这场投票战争模拟完了。
