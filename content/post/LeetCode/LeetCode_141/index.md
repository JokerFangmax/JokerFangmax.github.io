# LeetCode 141. 环形链表

> 题目链接：[https://leetcode.cn/problems/linked-list-cycle/](https://leetcode.cn/problems/linked-list-cycle/)  
> 难度：简单  
> 标签：哈希表、链表、双指针

---

## 1. 题目描述

给你一个链表的头节点 `head`，判断链表中**是否有环**。

如果链表中某个节点可以通过连续跟踪 `next` 指针再次到达它，则链表中存在环。参数 `pos` 表示链表尾连接到链表中的位置（从 0 开始索引）；`pos` 为 $-1$ 表示无环。**注意：`pos` 只作为说明传入，并不作为参数传递给你**——你不能靠读 `pos` 作弊，必须靠遍历本身发现环。

进阶：你能用 $O(1)$ 空间解决吗？

**数据范围：**

- 链表中节点数目 $0 \le n \le 10^4$
- $-10^5 \le Node.val \le 10^5$
- $-1 \le pos \le n - 1$

**示例：**

```
输入：head = [3,2,0,-4], pos = 1

      3 -> 2 -> 0 -> -4
           ^          |
           └──────────┘   （-4 的 next 指回下标 1 的节点 2）

输出：true
解释：链表中存在一个环，尾部连接到第二个节点（下标 1）。
```

---

## 2. 思路分析

### 2.1 暴力：数步数

没有环的链表，从头走到 `null` 至多 $n$ 步（$n$ 个节点恰好 $n$ 次 `next`）。反过来读就是判定规则：**如果走了 $n + 1$ 步还没到 `null`，说明一定有节点被访问了两次，即有环**（鸽笼原理：$n + 1$ 次落点只能落在 $n$ 个节点上，必有一次重复）。

实现上先遍历一遍数出 $n$，再从头走 $n + 1$ 步检查。时间 $O(n)$，空间 $O(1)$——居然直接满足进阶要求！但它有个不优雅之处：需要遍历两遍，且"数长度"这个动作和"找环"这个目标耦合得很生硬。更重要的是，当链表有环时**根本数不出 $n$**（第一遍就转不出来了），得反过来"边走边数、超过某个上界就停"——把上界设成 $10^4$ 级别才行，思路变得别扭。

### 2.2 哈希表：记住走过的每一个节点

更直接的思路：**走过的节点记下来，再次遇到就是环**。用 `unordered_set<ListNode*>` 存指针，遍历链表，每个节点先查集合再入集合：

- 命中——这个指针之前来过，有环；
- 走到 `null`——遍历正常结束，无环。

时间 $O(n)$（每个节点一次均摊 $O(1)$ 的查询），空间 $O(n)$。思路朴素、正确性一目了然，但进阶的 $O(1)$ 空间没达到：最坏要存下全部 $10^4$ 个指针。

到此为止都是"记日志"式思路。换一个视角：不记历史，能不能**让两个速度不同的指针替我们发现环**？

### 2.3 快慢指针：龟兔赛跑

让 `slow` 每次走 1 步、`fast` 每次走 2 步，同时从 `head` 出发：

- **无环**：`fast`（或 `fast->next`）先撞上 `null`，循环结束，返回 `false`；
- **有环**：两个指针迟早都进入环，之后变成在**环形跑道上的追及问题**——`fast` 每轮比 `slow` 多走 1 步，相对速度为 $1$，两者在环内的距离**每轮严格缩小 1**，从任何初始距离出发最终都会缩小到 $0$——相遇，返回 `true`。

这就是**快慢指针 (Floyd's cycle detection)**，也叫龟兔赛跑算法 (tortoise and hare)。

用示例 `[3,2,0,-4], pos = 1` 走一遍（节点记作 3→2→0→-4→回到 2）：

| 轮次 | slow 位置 | fast 位置 | 环内间距（fast 领先） |
|------|-----------|-----------|----------------------|
| 0 | 3 | 3 | 起点相同 |
| 1 | 2 | 0 | 2 |
| 2 | 0 | 2 | 1 |
| 3 | **-4** | **-4** | 0 —— 相遇！ |

第 3 轮两指针同时落在 -4 上，判定有环。注意看间距列：$2 \to 1 \to 0$，每轮恰好减 1——这正是"相对速度为 1，不会跳过"的直观体现。

## 3. 代码实现

```cpp
class Solution {
public:
    bool hasCycle(ListNode *head) {
        ListNode *slow = head, *fast = head;
        while (fast && fast->next) {   // fast 能走两步的前提：自己和下一个节点都存在
            slow = slow->next;         // 龟：每次 1 步
            fast = fast->next->next;   // 兔：每次 2 步
            if (slow == fast) return true;   // 相遇必有环
        }
        return false;                  // fast 撞到 null，无环
    }
};
```

几个实现细节：

1. **循环条件 `fast && fast->next` 的顺序不能换**。`fast->next` 的解引用必须发生在 `fast != null` 确认之后，靠 `&&` 的短路求值保证。写成 `fast->next && fast` 在 `fast = null` 时直接解引用空指针，未定义行为。
2. **判相遇放在两指针都移动之后**。初始 `slow == fast == head`，若把判等放在循环开头，无环节点数 $\le 1$ 时会误报（还没走就"相遇"了）。
3. **`slow = slow->next` 不需要判空**。`fast` 比 `slow` 走得快，若 `slow` 会撞 `null`，`fast` 早已撞过并让循环退出——`slow` 永远走在被 `fast` 验证过的安全区里。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。设头到环入口距离为 $a$，环长为 $L$。`slow` 走 $a$ 步进环（若 $a$ 步内 `fast` 撞 `null` 则无环，代价 $\le n$）；进环时 `fast` 已在环内，两者间距 $g \le L - 1$，每轮缩 1，至多再走 $L - 1$ 轮相遇。`slow` 总步数 $\le a + L \le n$，`fast` 是它的两倍，仍为 $O(n)$。
- **空间复杂度**：$O(1)$。两个指针，完胜哈希表的 $O(n)$。

对比：哈希表 $O(n)$ 空间 → 快慢指针 $O(1)$ 空间，时间同为 $O(n)$。用"相对运动"替代"记历史"，是空间优化的经典范式。

## 5. 常见疑问

**Q1：`fast` 一次走两步，会不会一步跨过 `slow`、永远错过？**

不会，这是本算法最常被质疑的点。关键在于**相对速度恰好是 1**：每轮结束后，两者距离恰好变化 1（`fast` 相对 `slow` 前进 1）。距离是整数，从任意正值逐轮减 1，必然**精确地经过 0**——不可能从 1 直接跳到 -1（那意味着一步之内距离变了 2）。对比"fast 一次走 3 步"：相对速度 2，距离按 $g, g-2, g-4, \dots$ 变化，若 $g$ 是奇数就会跳过 0，可能永远错开。所以**"1 步对 2 步"不是随手选的，是唯一保证不跳档的速度组合之一**（如 2 步对 3 步、3 步对 4 步等相对速度为 1 的组合也可以，但 1 对 2 最简单）。

**Q2：空链表、单节点、两个节点，代码都安全吗？**

- $n = 0$：`head = null`，循环条件 `fast` 为假直接退出，返回 `false`；
- $n = 1$ 且 `pos = 0`（自环）：首轮 `slow = fast = 该节点`，判等命中返回 `true`；$n = 1$ 无环：`fast->next = null`，循环退出返回 `false`；
- $n = 2$ 互成环：`slow` 停在原地、`fast` 转一圈回来，第 1 轮就相遇。

所有边界都被 `while (fast && fast->next)` 与"移动后判等"的组合自然覆盖，无需特判。

**Q3：为什么哈希表存指针而不是存值？**

值不能标识节点：$-10^5 \le val \le 10^5$ 允许重复，两个值相同的节点是完全不同的对象（对照 [LeetCode 160. 相交链表](https://leetcode.cn/problems/intersection-of-two-linked-lists/) 的同款陷阱）。环的判定依据是"**同一个节点**被访问两次"，只有指针（对象地址）具有唯一性。同理，"给走过节点的值打个标记"也不可行——既污染数据，又会在值重复时误判。

## 6. 相关题目与模板

> 📚 "用集合判重"的一般套路见模板笔记：[哈希表：从判重到两数之和](../../algorithms/hash_table/)；本题则是它的 $O(1)$ 空间替代方案。

**可复用模板**（Floyd 判环，只判存在性的最小骨架）：

```cpp
ListNode *slow = head, *fast = head;
while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) { /* 有环 */ }
}
/* 循环自然退出则无环 */
```

**方法论**：凡是可以抽象成"反复应用同一个后继函数、判断是否回到旧状态"的问题，都能套快慢指针判环——链表只是它最直观的载体。

- [LeetCode 287. 寻找重复数](https://leetcode.cn/problems/find-the-duplicate-number/)：把数组看成"下标 → 值"的隐式链表，重复数即环入口，Floyd 两阶段全套用上
- [LeetCode 160. 相交链表](https://leetcode.cn/problems/intersection-of-two-linked-lists/)：同样是"指针走到老地方"的判定，对照记忆

**一句话总结**：不用记住走过的每一步路——派一只跑得快的兔子和一只乌龟同场竞速，**速度差为 1**，有环则必相遇，无环则兔子先撞墙。
