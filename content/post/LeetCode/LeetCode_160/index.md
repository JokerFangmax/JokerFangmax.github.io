# LeetCode 160. 相交链表

> 题目链接：[https://leetcode.cn/problems/intersection-of-two-linked-lists/](https://leetcode.cn/problems/intersection-of-two-linked-lists/)  
> 难度：简单  
> 标签：哈希表、链表、双指针

---

## 1. 题目描述

给你两个单链表的头节点 `headA` 和 `headB`，请你找出并返回两个单链表**相交的起始节点**。如果两个链表不相交，返回 `null`。

所谓"相交"，是指两条链表从某个节点开始**共享同一段后缀**：由于单链表每个节点只有一个 `next` 指针，一旦两条链表汇合，它们就会一直共用到底，不会再次分叉——整个结构像字母 `Y`。

注意：

- 题目**保证**整个链表结构中**无环**；
- 函数返回结果后，链表必须**保持其原始结构**（不许改指针）；
- 进阶：能否设计一个 $O(m + n)$ 时间、$O(1)$ 空间的算法？

**数据范围：**

- listA 长度为 $m$，listB 长度为 $n$：$1 \le m, n \le 3 \times 10^4$
- $1 \le Node.val \le 10^5$
- `intersectVal = 0` 表示两链表不相交，否则等于相交节点的值
- $0 \le skipA \le m$，$0 \le skipB \le n$（各自跳到相交节点前的节点个数）

**示例：**

```
输入：intersectVal = 8, listA = [4,1,8,4,5], listB = [5,6,1,8,4,5], skipA = 2, skipB = 3

listA:        4 -> 1 ─┐
                      ├─> 8 -> 4 -> 5 -> null
listB:   5 -> 6 -> 1 ─┘

输出：Intersected at '8'
解释：相交节点的值为 8（从 listA 头跳过 2 个节点、从 listB 头跳过 3 个节点后，恰好落在同一个节点对象上）。
```

---

## 2. 思路分析

### 2.1 暴力：逐个配对

对 listA 的每个节点，都从头扫一遍 listB，看是否有一个节点**和它同一个对象**（比较指针，不是比较值）。两层循环，总代价 $O(mn)$，最坏 $3\times10^4 \times 3\times10^4 = 9 \times 10^8$ 次指针比较，必然超时。

问题本质：**我们反复地问同一个问题——"这个节点在 B 里出现过吗"**。这种"出现过没有"的查询，正是哈希表 (hash table) 的主场。

### 2.2 哈希表：空间换时间

把 listA 的所有节点指针存进 `unordered_set<ListNode*>`，再遍历 listB：第一个出现在集合里的节点就是交点；走到 `null` 都没命中则不相交。

| 步骤 | 操作 | 代价 |
|------|------|------|
| 1 | 遍历 listA，$m$ 个指针入集合 | $O(m)$ |
| 2 | 遍历 listB，逐个查询集合 | $O(n)$（均摊 $O(1)$ 查询） |

时间 $O(m + n)$，空间 $O(m)$。已经能过，但进阶要求 $O(1)$ 空间——哈希表装不下 $3 \times 10^4$ 个指针的这条路被堵死了，必须想别的。

### 2.3 双指针：你走完我的路，我走完你的路

观察两条链表的长度差。设 listA **独有** $a$ 个节点，listB **独有** $b$ 个节点，公共部分 $c$ 个节点（不相交时 $c = 0$）。交点在 listA 中是第 $a + 1$ 个节点，在 listB 中是第 $b + 1$ 个节点。

两个指针 `pA`、`pB` 分别从 `headA`、`headB` 出发，每次各走一步；**`pA` 走到 listA 末尾后转去走 listB，`pB` 走到 listB 末尾后转去走 listA**。

它们会在交点相遇吗？算一下各自到达交点所需的步数：

- `pA` 的路径：listA 全程 $a + c$ 步 + listB 开头 $b$ 步 = $a + c + b$ 步；
- `pB` 的路径：listB 全程 $b + c$ 步 + listA 开头 $a$ 步 = $b + c + a$ 步。

**两者相等**。即使 $a \ne b$，换路这一步恰好把长度差补齐了——这就是双指针版"对齐长度"的内核。

用示例走一遍（$a = 2, b = 3, c = 3$）：

| 步数 | pA 位置 | pB 位置 | 说明 |
|------|---------|---------|------|
| 0 | 4 (A) | 5 (B) | 起点 |
| 1 | 1 | 6 | |
| 2 | 8 (A 段交点) | 1 | 注意：还没相遇，位置不同 |
| 3 | 4 | **8 (B 段交点)** | |
| 4 | 5 | 4 | |
| 5 | 5 (转入 B) | 5 (转入 A) | 双双换路 |
| 6 | 6 | 4 | |
| 7 | 1 | 1 | |
| 8 | **8** | **8** | 同一时刻落在同一节点，返回它 |

不相交时（$c = 0$）：`pA` 走 $m + n$ 步到达 `null`，`pB` 走 $n + m$ 步也到达 `null`——两个 `null` 相等，循环条件 `pA != pB` 结束，返回 `null`，同样正确。

## 3. 代码实现

```cpp
class Solution {
public:
    ListNode *getIntersectionNode(ListNode *headA, ListNode *headB) {
        // pA 走 listA 再走 listB，pB 走 listB 再走 listA
        // 两条路径长度都是 a + b + c，必然同时到达交点（或同时到达 null）
        ListNode *pA = headA, *pB = headB;
        while (pA != pB) {
            // 走到 null 说明本条链表走完，换到另一条的头部；
            // 若两边同时为 null，while 条件已保证退出，不会死循环
            pA = pA ? pA->next : headB;
            pB = pB ? pB->next : headA;
        }
        return pA;   // 交点，或 null（不相交）
    }
};
```

几个实现细节：

1. **换路写法 `pA = pA ? pA->next : headB`**。`pA` 为 `null` 时不解引用，而是"折返"到另一条链表头部。这个三元表达式让换路和前进合并在一行里，不需要额外的标志位。
2. **不需要预处理链表长度**。换路本身就是隐式的长度对齐，省去一次统计长度的遍历。
3. **整段代码不修改任何 `next` 指针**，天然满足"保持原始结构"的要求。

---

## 4. 复杂度分析

- **时间复杂度**：$O(m + n)$。`pA` 至多走 $m + n + 1$ 步（走完 listA、走完 listB、各一次判空），`pB` 同理，循环在两者相等时立即退出，不会走满。
- **空间复杂度**：$O(1)$。只用了两个指针，没有额外数据结构。

对比：暴力 $O(mn)$ → 哈希表 $O(m+n)$ 时间但 $O(m)$ 空间 → 双指针 $O(m+n)$ 时间且 $O(1)$ 空间，达到了进阶要求。

## 5. 常见疑问

**Q1：不相交时会死循环吗？比如两个指针永远在"换路"上打转？**

不会。不相交时 $c = 0$，`pA` 的完整路径是 listA（$m$ 步）接 listB（$n$ 步），共 $m + n$ 步到达 `null`；`pB` 对称地走 $n + m$ 步到达 `null`。两个 $m + n$ 相等，所以它们**在同一轮循环中同时为 `null`**，`pA != pB` 判定为假，循环退出。换路最多各发生一次，不存在打转。

**Q2：判"相交"比的是指针还是值？两个值为 1 的节点算相交吗？**

比的是**指针（对象同一性）**。示例里 listA 的 `1` 和 listB 的 `1` 值相同，但它们是两个不同节点，各自有独立的 `next`，不是交点。这也解释了为什么题目规定相交节点的值不能是 0：`intersectVal = 0` 被专门用作"不相交"的标记值，若交点值也可能是 0 就会产生歧义。相应地，哈希表解法里存的是 `ListNode*` 而不是 `int` 值。

**Q3：先算两条链表长度、让长的先走长度差步再同步走，行不行？**

行，而且它和双指针法**本质相同**：都是把两条路径的长度补齐。区别只是形式——

| 做法 | 长度对齐方式 | 遍历次数 |
|------|--------------|----------|
| 先算长度差 | 显式：长的先走 $|m - n|$ 步 | 2 次（统计 + 同步走） |
| 换路双指针 | 隐式：各自走完自己的再走对方的 | 1 次 |

两者都是 $O(m+n)$ 时间、$O(1)$ 空间，面试里说出任何一个并说清"为什么对齐后必然同时到交点"即可。

## 6. 相关题目与模板

> 📚 哈希表解法涉及的"用集合判重"套路，系统整理见模板笔记：[哈希表：从判重到两数之和](../../algorithms/hash_table/)。

**可复用模板**（双链表双指针，"互换赛道"对齐长度通用骨架）：

```cpp
// 适用于：两条链表（或序列）从某个"汇合点"开始重合，
// 求汇合点 / 判断是否汇合
ListNode *pA = headA, *pB = headB;
while (pA != pB) {
    pA = pA ? pA->next : headB;   // 走完自己，走对方
    pB = pB ? pB->next : headA;
}
// pA 即答案（交点或 null）
```

关键点就一句：**把两条长度不等的路径首尾相接成两条等长路径**，等长路径上的同步指针必然同时到达任何"位置由路径长度决定"的地点。

**同类题目：**

- [LeetCode 141. 环形链表](https://leetcode.cn/problems/linked-list-cycle/)：同样是"指针走到曾经的位置"的判定，用快慢指针做到 $O(1)$ 空间
- [LeetCode 142. 环形链表 II](https://leetcode.cn/problems/linked-list-cycle-ii/)：把"环"看成"尾巴接到入口"，与本题的数学推导异曲同工
- [LeetCode 876. 链表的中间结点](https://leetcode.cn/problems/middle-of-the-linked-list/)：链表双指针的另一经典——快慢指针找中点
- [LeetCode 21. 合并两个有序链表](https://leetcode.cn/problems/merge-two-sorted-lists/)：双指针在两条链表上同步推进的基础题

**一句话总结**：相交链表的 $O(1)$ 空间解法是一次浪漫的交换——你走完我的路，我走完你的路，$a + b + c$ 步后，我们站在同一个路口。
