# LeetCode 739. 每日温度

> 题目链接：[https://leetcode.cn/problems/daily-temperatures/](https://leetcode.cn/problems/daily-temperatures/)  
> 难度：中等  
> 标签：栈、数组、单调栈

---

## 1. 题目描述

给定一个整数数组 `temperatures` 表示每天的气温，返回一个数组 `answer`，其中 `answer[i]` 表示：**对于第 `i` 天，还要等多少天才能等到一个更暖和的日子**；如果之后都不会更暖和，则记为 `0`。

换句话说，对每个下标 $i$，求最小的 $j > i$ 使得 $temperatures[j] > temperatures[i]$，答案为 $j - i$；不存在则为 $0$。这是典型的「下一个更大元素 (next greater element)」问题。

**数据范围：**

- $1 \le temperatures.length \le 10^5$
- $30 \le temperatures[i] \le 100$

**示例：**

```
输入：temperatures = [73,74,75,71,69,72,76,73]
输出：[1,1,4,2,1,1,0,0]

解释：
- 第 0 天 73 度，第 1 天 74 度更暖，等 1 天；
- 第 2 天 75 度，要一直等到第 6 天的 76 度，等 4 天；
- 第 6、7 天之后再没有更暖的日子，记 0。
```

---

## 2. 思路分析

### 2.1 暴力：对每天向后扫

对每个 $i$ 从 $i+1$ 向右扫描，遇到第一个更大的温度就停下。最坏情况（温度单调递减，如 `[100,99,98,...]`）每个 $i$ 都要扫到数组末尾，总代价 $O(n^2)$。$n = 10^5$ 时约 $10^{10}$ 次比较，必然超时。

问题出在**大量重复的比较**：温度递减段里，第 $i$ 天扫过的所有"比我冷"的日子，第 $i+1$ 天（如果也更冷）还得再扫一遍。能不能让"被比较过且还没答案"的日子**不重复排队**？

### 2.2 换个方向：让"更暖的日子"来结算等待者

正着看是"每天向后找"，反过来想：**当一个更暖的日子 $j$ 到来时，所有在它之前出现、且温度严格低于它的日子，答案都被它一次性敲定了**。

于是维护一个栈，存放"**到目前为止还没有等到更暖日子**"的下标：

> 新的一天 $j$ 入栈前，把栈顶所有温度 $< temperatures[j]$ 的下标弹出来，它们的答案就是 $j - i$。

为什么弹出的元素可以放心删掉？因为它们已经**有答案了**，之后再也不会被问到。而留在栈里的元素，说明到目前为止没人比它们暖——它们还在等。观察栈内温度：

- 栈底到栈顶，温度**单调递减**。因为一旦出现更暖的，栈顶就会被弹掉。

这就是**单调栈 (monotonic stack)**。它与[单调队列](../../algorithms/monotonic_queue/)是同一个思想的两面：**及时丢弃永远不会再被用到的候选者**。区别在于单调队列两端都能弹（服务滑动窗口的过期淘汰），单调栈只在栈顶弹（服务"下一个更大"的结算）。

### 2.3 用示例走一遍

`temperatures = [73,74,75,71,69,72,76,73]`，栈内元素用「下标(温度)」表示，从左到右为栈底到栈顶：

| i | 温度 | 弹栈过程 | 栈（下标） | 本轮确定的答案 |
|---|------|----------|-----------|----------------|
| 0 | 73   | —        | 0(73)     | —              |
| 1 | 74   | 弹 0(73) | 1(74)     | $ans[0] = 1$   |
| 2 | 75   | 弹 1(74) | 2(75)     | $ans[1] = 1$   |
| 3 | 71   | —        | 2(75) 3(71) | —            |
| 4 | 69   | —        | 2(75) 3(71) 4(69) | —      |
| 5 | 72   | 弹 4(69)、3(71) | 2(75) 5(72) | $ans[4]=1,\ ans[3]=2$ |
| 6 | 76   | 弹 5(72)、2(75) | 6(76)     | $ans[5]=1,\ ans[2]=4$ |
| 7 | 73   | —        | 6(76) 7(73) | —            |

扫描结束后栈里剩 6(76)、7(73)，永远等不到更暖的日子，$ans[6] = ans[7] = 0$。最终答案 `[1,1,4,2,1,1,0,0]`，与期望一致。

注意第 6 行：新来的 76 一次性结算了两个等待者——**"当前元素"是所有比它冷的等待者的共同答案**，这正是单调栈比暴力快的原因。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();
        vector<int> ans(n, 0);          // 默认 0：等不到更暖的日子
        stack<int> st;                  // 存下标，对应温度从栈底到栈顶递减

        for (int i = 0; i < n; i++) {
            // 当前温度更暖，结算栈顶所有比它冷的等待者
            while (!st.empty() && temperatures[st.top()] < temperatures[i]) {
                int j = st.top(); st.pop();
                ans[j] = i - j;         // 等待天数 = 下标差
            }
            st.push(i);                 // 自己入栈，开始等待
        }
        return ans;                     // 栈中残留的下标答案保持 0
    }
};
```

几个实现细节：

1. **栈里存下标而不是温度**。答案要的是"天数差" $i - j$，只有下标能相减；且温度可能重复，下标天然唯一。
2. **弹栈条件用严格小于 `<`**。温度相等不算"更暖"，`[70,70]` 的答案是 `[0,0]`，所以相等的日子也要继续在栈里等（栈内温度是**不严格**递减也无所谓，只是并列者会一起被下一个更暖的日子结算）。
3. **`ans` 初始化为全 0**，扫描结束后不用再处理栈中残留元素——它们等不到答案，保持默认值即可，省去一次显式的清栈循环。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。虽然有两层循环，但每个下标**恰好入栈一次、至多出栈一次**，出入栈总次数不超过 $2n$，均摊到每轮是 $O(1)$。这是与[LeetCode 239 滑动窗口最大值](../LeetCode_239/)完全相同的均摊分析。
- **空间复杂度**：$O(n)$。最坏情况（温度单调递减）所有下标都留在栈里；输出数组不计入。

对比：暴力 $O(n^2)$ → 单调栈 $O(n)$。本题每个元素至少要看一眼，$O(n)$ 已是理论最优。

## 5. 常见疑问

**疑问一：能不能倒着扫，用已算出的答案"跳着"找？**

可以。从右往左，对每个 $i$ 从 $j = i+1$ 出发：若 $t[j] \le t[i]$ 且 $ans[j] > 0$，就直接跳到 $j + ans[j]$——因为中间的日子都不比 $j$ 暖，自然也不比 $i$ 暖。这也是 $O(n)$ 均摊的（每个位置最多被跳过常数次连锁），且只用 $O(1)$ 额外空间。它是单调栈的"指针跳跃"版，面试里两种都值得会，但单调栈是更通用、更可迁移的模板。

**疑问二：为什么栈内是递减的，239 题的队列却是递减的"队头大"？**

两者都是"保强弃弱"：739 求**下一个更大**，能压住别人的是后来的强者，弱者（早来且更冷）被后来者弹掉，所以栈底到栈顶递减；239 求**窗口最大**，队头到队尾递减。方向相反的问题（如"下一个更小"，[LeetCode 84](../LeetCode_84/)）就把弹栈条件反转为 `>`，维护递增栈——**单调栈的单调方向由问题方向决定**。

**疑问三：温度范围 $30 \le t \le 100$ 只有 71 种取值，能不能利用？**

可以但没必要。值域这么小，可以倒着维护"每个温度最早出现的下标"，对每天查比它暖的最小下标，$O(71n)$ 也能过。这提示一个通用思维：**值域小时计数/桶方法往往可行**（[LeetCode 347](../LeetCode_347/) 会再用到）。但单调栈不依赖值域大小，是更本质的做法。

## 6. 相关题目与模板

> 📚 系统整理见模板笔记：[单调队列：滑动窗口最值与决策单调性](../../algorithms/monotonic_queue/)（同一"保强弃弱"思想在队列上的版本）。

**可复用模板**（"下一个更大元素"通用骨架）：

```cpp
// 求每个元素右侧第一个更大元素的下标 dist[i]（不存在为 0）
stack<int> st;                    // 存下标，对应值递减
for (int i = 0; i < n; i++) {
    while (!st.empty() && a[st.top()] < a[i]) {
        dist[st.top()] = i - st.top();
        st.pop();
    }
    st.push(i);
}
```

改两处即可迁移：求"下一个更小"把 `<` 换成 `>`（栈变递增）；要求元素值而非距离，就把 `i - st.top()` 记成 `a[i]`。

**单调栈的三类经典应用：**

1. **下一个更大/更小元素**（本题）：直接套骨架；
2. **以每个元素为最值的最大区间**（[LeetCode 84](../LeetCode_84/) 柱状图最大矩形）：找两侧第一个更小元素，确定它能横跨的宽度；
3. **计数"子数组最值"贡献**（LeetCode 907 子数组最小值之和）：每个元素作为最小值的区间左右端点，乘法原理计数。

**同类题目：**

- [LeetCode 496. 下一个更大元素 I](https://leetcode.cn/problems/next-greater-element-i/)：本题的简化版，答案存值不存距离
- [LeetCode 503. 下一个更大元素 II](https://leetcode.cn/problems/next-greater-element-ii/)：循环数组，用 $2n$ 取模扫两遍即可
- [LeetCode 901. 股票价格跨度](https://leetcode.cn/problems/online-stock-span/)：求"左侧连续多少天不超过自己"，即反向单调栈
- [LeetCode 84. 柱状图中最大的矩形](https://leetcode.cn/problems/largest-rectangle-in-histogram/)：单调栈最经典的应用，见[下一篇](../LeetCode_84/)

**一句话总结**：单调栈的本质是**让更强者来结算等待者**——还在栈里的都是没等到答案的，一旦等到，答案就永远确定了，删掉不回头。
