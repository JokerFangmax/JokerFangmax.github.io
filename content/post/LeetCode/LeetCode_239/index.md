# LeetCode 239. 滑动窗口最大值

> 题目链接：[https://leetcode.cn/problems/sliding-window-maximum/](https://leetcode.cn/problems/sliding-window-maximum/)  
> 难度：困难  
> 标签：队列、单调队列、滑动窗口

---

## 1. 题目描述

给你一个整数数组 `nums`，有一个大小为 `k` 的滑动窗口从数组的最左侧移动到最右侧。你只能看到滑动窗口内的 `k` 个数字，窗口每次向右移动一位。

返回**每个窗口位置的最大值**所组成的数组。

**数据范围：**

- $1 \le nums.length \le 10^5$
- $-10^4 \le nums[i] \le 10^4$
- $1 \le k \le nums.length$

**示例：**

```
输入：nums = [1,3,-1,-3,5,3,6,7], k = 3

窗口位置                  最大值
─────────────────────    ─────
[1  3  -1] -3  5  3  6  7   3
 1 [3  -1  -3] 5  3  6  7   3
 1  3 [-1  -3  5] 3  6  7   5
 1  3  -1 [-3  5  3] 6  7   5
 1  3  -1  -3 [5  3  6] 7   6
 1  3  -1  -3  5 [3  6  7]  7

输出：[3,3,5,5,6,7]
```

---

## 2. 思路分析

### 2.1 暴力：每个窗口扫一遍

对 $n - k + 1$ 个窗口各扫 $k$ 个元素求最大值，总代价 $O(nk)$。最坏 $n = 10^5, k = 5\times10^4$ 时约 $5 \times 10^9$ 次比较，必然超时。

问题的本质在于：**窗口每次只挪走一个元素、挪进一个元素，大量信息是重复的，但暴力做法每次都从零开始重新计算最大值**。我们需要一个数据结构，支持"进一个元素、出一个元素、随时问最大值"。

### 2.2 想法的自然演进

**想法一：用堆（优先队列）。** 大根堆里放 `(值, 下标)`，取堆顶后检查下标是否已滑出窗口，滑出就弹出。可行，$O(n \log n)$，但有两个不优雅之处：堆里会积压大量已失效的元素；且"删除的是任意下标"这件事堆并不原生支持，只能靠懒删除。

**想法二：只保留"还有希望成为最大值"的元素。** 前提观察：窗口是**先进先出**的——元素从右端进、左端出，最早进入的最早离开。考察场景：窗口里 `[..., 1, ..., 3, ...]`，1 比 3 先进窗口且 $1 \le 3$——那么 1 会比 3 先离开，**1 余下的生命周期里 3 始终在场且压着它**，1 永远当不上最大值，没必要存。

（反过来 `[..., 3, ..., 1, 2, ...]` 里后来的小元素 1、2 并没有死：3 出界后它们可能接班，要存。判死刑的永远是"**早来且不大于后来者**"的元素。）

把这个观察推广成维护规则：

> 队列中保存下标，对应的值**从队头到队尾严格递减**。新元素 `x` 入队时，把队尾所有 $\le x$ 的元素全部弹掉——它们比 `x` 早进窗口、又不超过 `x`，已经死了。

这就是**单调队列（monotonic deque）**。每个窗口的最大值永远是**队头**。

### 2.3 为什么是双端队列

单调队列需要两种操作，方向相反：

- **入队时从队尾弹出**比新元素小的元素（维护单调性）；
- **窗口滑动时从队头弹出**下标已出界的元素（淘汰过期者）。

普通队列 `queue` 只支持一端进另一端出，两头都要能弹，所以必须用双端队列 `deque`。

### 2.4 操作流程（以示例演示）

`nums = [1,3,-1,-3,5,3,6,7], k = 3`，队列内容用「下标(值)」表示：

| i | 入队前弹尾 | 队列（下标） | 队头值 | 说明 |
|---|-----------|--------------|--------|------|
| 0 | —         | 0(1)         | —      | 未成窗 |
| 1 | 弹 0(1)   | 1(3)         | —      | 3 > 1，1 被 3 压死 |
| 2 | 无        | 1(3) 2(-1)   | **3**  | 首个窗口 [1,3,-1] |
| 3 | 无        | 1(3) 2(-1) 3(-3) | **3** | 窗口 [3,-1,-3] |
| 4 | 弹 3,2,1  | 4(5)         | **5**  | 5 压掉所有更小的；1 已出界也随之消失 |
| 5 | 无        | 4(5) 5(3)    | **5**  | 窗口 [-3,5,3] |
| 6 | 弹 5(3)   | 4(5) 6(6)    | **6**  | 6 > 3；窗口 [5,3,6] |
| 7 | 弹 6,4    | 7(7)         | **7**  | 7 压掉一切 |

输出 `[3,3,5,5,6,7]`，与期望一致。

注意第 4 步：新元素 5 很"强"，一口气清空了整个队列——包括已经出界的下标 1。这说明**队头的出界检查必须在取答案前做**（见下节顺序），而不能只在"滑动窗口"时做。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        int n = nums.size();
        deque<int> dq;              // 存下标，对应值从队头到队尾严格递减
        vector<int> ans;
        ans.reserve(n - k + 1);

        for (int i = 0; i < n; i++) {
            // 1. 维护单调性：弹掉队尾所有不大于 nums[i] 的下标
            //    它们比 i 先进窗口、值又不超过 nums[i]，永远翻不了身
            while (!dq.empty() && nums[dq.back()] <= nums[i])
                dq.pop_back();

            dq.push_back(i);

            // 2. 淘汰过期：队头下标已滑出窗口 [i-k+1, i]
            if (dq.front() <= i - k)
                dq.pop_front();

            // 3. 窗口成型后，队头即最大值
            if (i >= k - 1)
                ans.push_back(nums[dq.front()]);
        }
        return ans;
    }
};
```

几个实现细节：

1. **存下标而不是存值**。窗口滑动时需要知道"队头元素是否已出界"，这只有下标能回答；存值的话过期后无从判断。（另一个好处：能处理"值相同的不同元素"。）
2. **弹尾用 `<=` 而不是 `<`**。值相等的元素留两个没有意义——后进的那个在窗口里待得更久，先进的注定先离开却永远不会更大，直接弹掉，队列保持**严格**递减。（用 `<` 也能过，只是队列稍长。）
3. **弹尾发生在入队之前、出界检查发生在取答案之前**，顺序不能乱。尤其注意：新元素很强时可能把队头也弹掉，所以不能假设上一轮的队头仍然有效。
4. **`ans.reserve(n - k + 1)`**：答案长度固定，预留空间避免 `vector` 反复扩容。$10^5$ 规模下是免费的习惯性优化。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。看似两层循环，但每个下标**最多入队一次、出队一次**（要么从队尾被弹，要么从队头过期），两个操作的总次数加起来是 $2n$，均摊到每轮是 $O(1)$。这是"均摊分析"的标准例子。
- **空间复杂度**：$O(k)$。队列中下标对应的值严格递减，而窗口内至多 $k$ 个元素，故队列长度 $\le k$（不计输出数组）。

对比：暴力 $O(nk)$ → 堆 $O(n\log n)$ → 单调队列 $O(n)$。单调队列是这道题的理论最优（每个元素至少要看一眼）。

## 5. 常见疑问：能不能像"区间和"那样用前缀和？

做惯了前缀和的题，很自然会产生这个想法：预处理 `pre[]`，然后对每个终点 $i$ 用 $pre[i] - pre[i-k]$ 得到长度为 $k$ 的窗口和，$O(n)$ 扫完取最大。

**这个做法求的是"窗口**和**最大"，而本题问的是"窗口**元素**最大"**——两者是完全不同的量。

更深层的原因在于**前缀和技术依赖运算可逆**：

- 加法有逆运算（减法），所以 $sum(i..j) = pre[j] - pre[i-1]$ 成立——前面那段的贡献可以被精确地"减掉"；
- 异或自逆（$a \oplus a = 0$），所以异或前缀和同样成立；
- **`max` 没有逆运算**。看反例：

```
nums      = [5, 1, 3]
prefixMax = [5, 5, 5]

窗口 [1, 3]（下标 1..2）的最大值是 3。
但 prefixMax[2] = 5，且 5 来自已滑出窗口的下标 0——
max 不支持"减去前一段的贡献"，无法回退。
```

所以区间最值需要换结构，各自的代价：

| 结构 | 预处理 | 单次查询 | 适用场景 |
|------|--------|---------|----------|
| 暴力扫描 | — | $O(k)$ | 每个窗口重扫 |
| ST 表（稀疏表） | $O(n\log n)$ | $O(1)$ | 静态区间最值 |
| 线段树 | $O(n)$ | $O(\log n)$ | 带修改的区间最值 |
| **单调队列** | — | 均摊 $O(1)$ | **窗口单调滑动** |

本题窗口逐格右移、每步一进一出，正是单调队列的主场：它利用"早进窗口且不大于我的元素永远没机会"这一时序信息，达成 $O(n)$ 总复杂度，是这些结构中唯一做到线性且代码最短的。

> 顺带一个下标细节：若 `pre[i]` 定义为前 $i$ 项之和，则以 $i$ 结尾、长度为 $k$ 的窗口和是 $pre[i] - pre[i-k]$（不是 $pre[i-k-1]$）——前缀和的差一错误是最常见的 WA 来源。

## 6. 相关题目与模板

> 📚 系统整理见模板笔记：[单调队列：滑动窗口最值与决策单调性](../../algorithms/monotonic_queue/)（含 DP 优化模板）、[前缀和：从区间和到子数组计数](../../algorithms/prefix_sum/)（为什么 max 不可前缀化）。

**可复用模板**（定长滑动窗口最值通用骨架）：

```cpp
// 滑动窗口最大值：dq 存下标，值从队头到队尾递减
deque<int> dq;
for (int i = 0; i < n; i++) {
    while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();
    dq.push_back(i);
    if (dq.front() <= i - k) dq.pop_front();
    if (i >= k - 1) ans.push_back(nums[dq.front()]);   // 取最小值只需反过来
}
```

求**最小值**时把弹尾条件改成 `>=` 即可；区间不定长的问题则去掉过期判断，改为判断队头是否还在区间内。

**单调队列的两类经典应用：**

1. **滑动窗口最值**（本题）：定长区间，配 `i - k` 出界判断；
2. **单调队列优化 DP**：形如 $dp[i] = \min_{i-k \le j < i} dp[j] + cost$ 的转移，决策候选区间单调滑动，用单调队列把每步转移从 $O(k)$ 降到 $O(1)$——典型如 [洛谷 P1886](https://www.luogu.com.cn/problem/P1886)（模板题）、多重背包的二进制拆分优化后进一步用单调队列优化、以及剑指 Offer 59 同款本题。

**同类题目：**

- [LeetCode 155. 最小栈](https://leetcode.cn/problems/min-stack/)：单点插入/删除 + 最值查询的单调结构入门（不过期，只单调）
- [LeetCode 739. 每日温度](https://leetcode.cn/problems/daily-temperatures/)：单调**栈**版，与单调队列思想同源——"被压住的元素永远不会再被用到"
- [LeetCode 862. 和至少为 K 的最短子数组](https://leetcode.cn/problems/shortest-subarray-with-sum-at-least-k/)：前缀和 + 单调队列的综合题，单调队列用于排除"不可能成为最优决策"的前缀和下标
- [LeetCode 1438. 绝对差不超过限制的最长子数组](https://leetcode.cn/problems/longest-continuous-subarray-with-absolute-diff-less-than-or-equal-to-limit/)：同时维护窗口最大值和最小值两个单调队列

**一句话总结**：单调队列的本质是**及时丢弃永远不会再赢的候选者**——"比我早来还比我弱"的元素，它的余生与我无关。
