# LeetCode 23. 合并 K 个升序链表

> 题目链接：[https://leetcode.cn/problems/merge-k-sorted-lists/](https://leetcode.cn/problems/merge-k-sorted-lists/)  
> 难度：困难  
> 标签：链表、分治、堆

---

## 1. 题目描述

给你一个链表数组 `lists`，其中每个元素都是一条**升序**排列的链表。请将所有链表合并成一条升序链表，返回合并后的头节点。

**数据范围：**

- $k = lists.length$，$0 \le k \le 10^4$
- $0 \le lists[i].length \le 500$
- 所有链表节点总数 $\le 10^4$
- $-10^4 \le lists[i][j] \le 10^4$
- 各链表均已按升序排列

**示例：**

```
输入：lists = [[1,4,5],[1,3,4],[2,6]]

输出：[1,1,2,3,4,4,5,6]

三条链表：
  1 -> 4 -> 5
  1 -> 3 -> 4
  2 -> 6
```

---

## 2. 思路分析

### 2.1 暴力：两种"不动脑"的做法

**做法一：全部抽出来排序。** 把 $N$ 个节点的值倒进数组，`sort` 一遍，重建链表。时间 $O(N \log N)$、空间 $O(N)$（$N$ 为节点总数，本题 $\le 10^4$）。能过，但它**完全无视了"每条链表已经有序"这一已知条件**——题目白送的信息被扔掉了。

**做法二：顺序两两合并。** 拿一条"已合并"的链表，依次把 `lists[i]` 合进来。每次合并代价是两条链表长度之和：

$$\underbrace{k}_{\text{第 1 次}} + \underbrace{k+1}_{\text{第 2 次}} + \cdots \approx O(kN)$$

最坏情形（$k$ 条链表长度接近、总计 $10^4$ 节点时 $\approx 10^8$ 量级）会超时。病根在于：**最早的链表被反复扫描**——第 1 条链表参与了全部 $k-1$ 次合并。

### 2.2 关键观察：每次只需要比较 k 个"候选人"

有序链表的合并，本质是**反复选出全局最小节点**。候选者是谁？——**每条链表当前未被取走的头节点**，至多 $k$ 个（某条链表耗尽后候选人减少）。

所以"选最小"根本不需要看全部 $N$ 个节点，维护这 $\le k$ 个候选人的最小值即可。两个数据结构擅长这件事：

1. **小根堆 (min-heap)**：插入、弹出 $O(\log k)$；
2. **两两分治合并**：每轮配对，链表数减半。

### 2.3 解法一：小根堆

堆里始终放着**每条链表的当前头节点**（非空的）。循环三拍子：

1. 弹出堆顶（当前全局最小），接到结果尾部；
2. 若被弹出节点有后继，把后继压入堆；
3. 堆空即合并完成。

**用示例 `[[1,4,5],[1,3,4],[2,6]]` 走一遍**（堆中内容按值排列）：

| 步 | 弹出 | 压入 | 堆中候选头节点 | 已产出 |
|----|------|------|----------------|--------|
| 0  | —    | 1,1,2（初始化） | {1,1,2} | 空 |
| 1  | 1（链A） | 4 | {1,2,4} | 1 |
| 2  | 1（链B） | 3 | {2,3,4} | 1,1 |
| 3  | 2（链C） | 6 | {3,4,6} | 1,1,2 |
| 4  | 3（链B） | 4 | {4,4,6} | 1,1,2,3 |
| 5  | 4（链A） | 5 | {4,5,6} | 1,1,2,3,4 |
| 6  | 4（链B） | —（链B 耗尽） | {5,6} | 1,1,2,3,4,4 |
| 7  | 5，然后 6 | — | 空 | **1,1,2,3,4,4,5,6** |

每个节点进堆一次、出堆一次，总代价 $O(N \log k)$。

### 2.4 解法二：分治两两合并

回到 2.1 做法二的病根——"同一条链表被反复扫"。改成**配对式**合并：第 1 轮两两配对合并成 $k/2$ 条，第 2 轮 $k/4$ 条……每条链表每轮只参与一次合并，共 $O(\log k)$ 轮。

$$\underbrace{\text{第 1 轮}}_{O(N)} \to \underbrace{\text{第 2 轮}}_{O(N)} \to \cdots \to O(\log k) \text{ 轮} \implies O(N \log k)$$

这也是 [148. 排序链表](../LeetCode_148/) 的归并思想从"一条链表的两半"推广到"k 条链表"的形态。

| 解法 | 时间 | 空间 | 备注 |
|------|------|------|------|
| 排序重建 | $O(N \log N)$ | $O(N)$ | 浪费已知条件 |
| 顺序两两合并 | $O(kN)$ | $O(1)$ | 超时 |
| **小根堆** | $O(N \log k)$ | $O(k)$ | 本题解 |
| **分治合并** | $O(N \log k)$ | $O(\log k)$（递归栈） | 与堆同阶 |

## 3. 代码实现

```cpp
class Solution {
    // 小根堆的比较器：C++ 的 priority_queue 默认是大根堆，
    // a->val > b->val 表示"值大者优先级低"，从而堆顶是值最小的
    struct Cmp {
        bool operator()(ListNode* a, ListNode* b) {
            return a->val > b->val;
        }
    };

public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        priority_queue<ListNode*, vector<ListNode*>, Cmp> pq;

        // 初始化：每条链表的非空头节点入堆
        for (ListNode* head : lists)
            if (head) pq.push(head);

        ListNode dummy(0);
        ListNode* tail = &dummy;

        while (!pq.empty()) {
            ListNode* node = pq.top(); pq.pop();  // 全局最小
            tail->next = node;                    // 接到结果尾部
            tail = tail->next;
            if (node->next) pq.push(node->next);  // 让位给同链的后继
        }
        return dummy.next;
    }
};
```

几个实现细节：

1. **堆里存的是"节点指针"而不是"值"**：弹出后需要顺着 `node->next` 找到后继继续入堆，只有指针能提供这个信息。
2. **`if (head) pq.push(head)`**：`lists` 里可能有空链表（长度 0），`lists` 本身也可能为空（$k=0$），两类都要在入口处自然消化——空链表不入堆，堆空循环不执行，返回 `dummy.next = nullptr`。
3. **`dummy` 哨兵**：结果链表的头节点来自第一次弹出的堆顶，事先无法确定，哨兵把这个特判吃掉，`tail` 逻辑全程统一。
4. 比较器里是 `>` 而不是 `<`，这是 `priority_queue` 的经典反直觉点：传入的比较器定义的是"**a 排在 b 后面**"的规则。

## 4. 复杂度分析

- **时间复杂度**：$O(N \log k)$，$N$ 是所有链表节点总数。每个节点恰好入堆、出堆各一次，单次 $O(\log k)$——注意堆的大小被**非空链表条数**钳制在 $k$ 以内，与 $N$ 无关。当 $k \ll N$（本题 $k \le 10^4$ 而 $N$ 也可小至 500）时显著优于 $O(N \log N)$ 排序。
- **空间复杂度**：$O(k)$，堆中至多同时存 $k$ 个节点指针（不计输出链表）。

对比分治版：时间同为 $O(N \log k)$，空间为 $O(\log k)$ 递归栈；两者都是标准答案。

## 5. 常见疑问

**Q1：为什么是 $\log k$ 而不是 $\log N$？**

堆的代价取决于**堆内元素个数**。任一时刻堆里只保存"每条非空链表各一个头节点"，所以堆的大小 $\le k$——不管每条链表有 1 个还是 500 个节点。这正是本解法对"排序重建"的优势所在：它把"有序"这个条件兑换成了更小的比较深度。

**Q2：`lists` 是空的 / 里面全是空指针，代码还能跑吗？**

能。$k = 0$ 时初始化循环一次不执行，堆空、`while` 不进，返回 `nullptr`。元素为空指针时被 `if (head)` 拦下。**不要**习惯性地写 `if (lists.empty()) return nullptr;` 之外的特判——哨兵 + 空堆的写法已经把所有空情形统一进主循环了。

**Q3：堆和分治，实际该用哪个？**

理论同阶，差异在场景：

| 场景 | 更优解 | 原因 |
|------|--------|------|
| 链表长度悬殊（一条占大头） | 堆 | 长链表只在堆里占一个名额，不受影响 |
| 数据流式到达（合并时还能加新链表） | 堆 | 分治需要固定的分治树 |
| 不想手写比较器 / 追求代码最短 | 分治 | 复用 21 题的 merge 即可 |
| 内存极度受限 | 分治（迭代版） | $O(\log k)$ 递归栈可再消成 $O(1)$ |

## 6. 相关题目与模板

**"多路归并 + 小根堆"通用模板**（K 路有序源取最小）：

```cpp
priority_queue<T, vector<T>, Cmp> pq;   // 堆中放"各路当前最小元素"
// 初始化：每一路的第一个候选入堆
while (!pq.empty()) {
    T t = pq.top(); pq.pop();           // 取全局最小
    处理(t);
    if (t 还有后继) pq.push(t 的后继);  // 该路补上下一个候选
}
```

**方法论总结**：凡是"K 个有序源、要求全局有序取出"的问题，第一反应就是**多路归并**——堆负责"选出当前最小"，每个源负责"供应下一个候选"。这套路在数组、外排序、任务调度里一模一样。

**同类题目：**

- [LeetCode 21. 合并两个有序链表](https://leetcode.cn/problems/merge-two-sorted-lists/)：$k=2$ 的特例，本题与分治版的地基
- [LeetCode 148. 排序链表](https://leetcode.cn/problems/sort-list/)：归并思想的"单链表二分"版本，本系列已写
- [LeetCode 632. 最小区间](https://leetcode.cn/problems/smallest-interval-in-arrays-includes-numbers-from-each-list/)：K 路归并的变体，堆顶堆底同时维护
- [LeetCode 373. 查找和最小的 K 对数字](https://leetcode.cn/problems/find-k-pairs-with-smallest-sums/)：堆中存"二元组候选"，同款"弹出后补后继"

**一句话总结**：合并 K 条有序链表，不需要看全部节点——每条链表只派一个"头节点代表"进堆，谁是全局最小谁出列，身后一个顶上，$O(N \log k)$ 干完收工。
