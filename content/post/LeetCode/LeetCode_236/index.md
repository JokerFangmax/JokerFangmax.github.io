# LeetCode 236. 二叉树的最近公共祖先

> 题目链接：[https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/)  
> 难度：中等  
> 标签：树、深度优先搜索、二叉树

---

## 1. 题目描述

给定一棵二叉树和树中两个节点 `p`、`q`，求它们的**最近公共祖先 (Lowest Common Ancestor, LCA)**：同时是 `p` 和 `q` 的祖先（允许祖先是节点本身）中，**深度最大**的那个节点。

例如 `p` 是 `q` 的父亲，那么 LCA 就是 `p` 自己。本题保证 `p`、`q` 一定存在于树中。

**数据范围：**

- 树中节点数为 $[2, 10^5]$
- 所有节点值互不相同，$-10^9 \le \text{Node.val} \le 10^9$
- `p != q`，且 `p`、`q` 均存在于给定的二叉树中

**示例：**

```
输入：root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1

输出：3

解释：节点 5 和 1 的公共祖先包括 3；最近公共祖先即 3。

另一组：p = 5, q = 4 时输出 5
（4 在 5 的子树里，祖先"允许是节点本身"，LCA 是 5）
```

---

## 2. 思路分析

### 2.1 暴力：两条根路径取最后一个公共段

先想"祖先"怎么表示。从根走到 `p` 记下路径 $P$，从根走到 `q` 记下路径 $Q$，两条路径必然有公共前缀（至少共享根），LCA 就是**公共前缀的最后一个节点**——两条路径在这里"分岔"。

这个做法两次 DFS + 一段扫描，$O(n)$，本身已经不慢，但它把信息存成了显式路径，多了一层中间结构；更妙的问题是：**能不能在一次 DFS 里直接把答案"顶"出来？**

### 2.2 关键观察：LCA 是"p、q 分居两侧的最低节点"

自顶向下看：从根出发，p、q 的分布只有三种情况：

1. **都在左子树**或**都在右子树**——分岔点在更深处，当前节点不是 LCA；
2. **分居两侧**（一左一右），或**当前节点就是 p 或 q**——当前节点就是 LCA。

而这恰好是后序遍历 (postorder traversal) 能自然回答的问题：递归函数返回"当前子树里 p/q 的查找情况"，左右子树的结果**同时非空**即命中情形 2。

设计递归语义：`dfs(root)` 返回——

- 若当前子树中找到了 `p` 或 `q`（或子树里已有 LCA），返回那个节点；
- 否则返回 `nullptr`。

于是 `dfs(root)` 的逻辑：

1. `root` 为空，或 `root` 就是 `p`/`q`：直接返回 `root`；
2. 递归左右子树得 `left`、`right`；
3. **两者都非空**：p、q 分居两侧，`root` 就是 LCA，返回 `root`；
4. 只有一个非空：说明 p、q（至少一个）都在那一侧，把非空的往上交（它可能就是 LCA，也可能只是"找到了其中一个"的占位）。

### 2.3 用示例走一遍

树 `root = [3,5,1,6,2,0,8,null,null,7,4]`，`p = 5`，`q = 1`。关注每个子树返回什么（L = 左返回，R = 右返回）：

| 节点 | L | R | 返回值 | 判断 |
|---|---|---|---|---|
| 6 | null | null | null | 空，未命中 |
| 7 | null | null | null | 未命中 |
| 4 | null | null | null | 未命中 |
| 2 | null（左孩 7 非 p/q） | null（右孩 4 非 p/q） | null | 子树无 p/q |
| 5 | —（不递归） | —（不递归） | **5** | 节点等于 p，提前返回自身 |
| 0 | null | null | null | 未命中 |
| 8 | null | null | null | 未命中 |
| 1 | —（不递归） | —（不递归） | **1** | 节点等于 q，提前返回自身 |
| 3 | **5** | **1** | **3** | 左右都非空 → LCA = 3 |

树是自底向上"汇合"的：`5` 和 `1` 作为两个气泡从两侧浮上来，在 `3` 处第一次相遇——相遇点即 LCA。（表里为完整对照把 5、1 的子树也列了出来；实际执行中 5、1 命中即提前返回，6、2、7、4 根本不会被访问——这正是提前返回省时间的地方。）

再看 `p = 5, q = 4`：`4` 不会单独触发返回（它不是 p/q），但 `5` 命中后直接返回，`3` 的左子树返回 `5`、右子树返回 null，一路把 `5` 交到根，最终答案 `5`——**"祖先允许是节点本身"自动被覆盖**，因为祖先命中后另一目标是否在其下方根本不再需要检查。

### 2.4 为什么"提前返回"是安全的

第 1 步遇到 `p` 就返回、不继续搜它的子树，看似会漏掉"q 在 p 的子树里"的情况。但如上分析：这种情况下 p 本身就是 LCA，而 p 已经作为非空结果被交上去了；上层若同时从另一侧收到非空才需要"分岔"判断——另一侧永远收不到（q 在 p 的子树里），所以最终答案就是先被交上去的那个 `p`。**提前返回不会丢答案，只会丢"多余的信息"，而这部分信息恰好不影响结论。**

## 3. 代码实现

```cpp
class Solution {
public:
    TreeNode* lowestCommonAncestor(TreeNode* root, TreeNode* p, TreeNode* q) {
        if (!root || root == p || root == q) return root;  // 空 / 命中目标

        TreeNode* left  = lowestCommonAncestor(root->left,  p, q);
        TreeNode* right = lowestCommonAncestor(root->right, p, q);

        if (left && right) return root;   // p、q 分居两侧 -> 分岔点
        return left ? left : right;       // 都在一侧：把非空结果上交
    }
};
```

四行核心逻辑，几乎没有多余代码。两个注意点：

1. **比较的是指针不是值**（`root == p`）。题目虽保证值互异，但用指针比较是更稳健的习惯，天然支持有重复值的树；
2. 想要非递归版本（防栈溢出 / 面试加分），可以先扫一遍建「子节点 → 父节点」哈希表，再把 `p` 的全部祖先（含自身）丢进集合，最后让 `q` 沿父指针上溯，第一个落在集合里的节点即 LCA——时间同为 $O(n)$，空间 $O(n)$，完全不递归。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。每个节点至多被访问一次；遇到目标节点即提前返回，实际往往更快。
- **空间复杂度**：$O(h)$，$h$ 为树高。递归栈深度最坏 $n$（链状）、平衡时 $O(\log n)$。哈希父指针版则恒为 $O(n)$。

| 做法 | 时间 | 空间 | 特点 |
|---|---|---|---|
| 两条根路径求公共前缀 | $O(n)$ | $O(n)$ | 直观，需两次遍历 + 存路径 |
| 哈希存父指针 + 集合 | $O(n)$ | $O(n)$ | 非递归，天然防深递归爆栈 |
| **一次后序 DFS** | $O(n)$ | $O(h)$ | 最优雅，无需额外结构 |

## 5. 常见疑问

**疑问一：`left` 非空返回的一定是 p 或 q 吗？不可能是别的吗？**

返回值有三种可能：`nullptr`（子树里啥都没有）、p 或 q 本身、或**子树里已经算出的 LCA**。第三种情况出现在更深处分岔后：LCA 作为非空结果一路上传，上层若另一侧为 null，继续原样上交。所以"非空"的语义是"这棵子树里有情况"，至于是哪种，上层若不能分岔就不必区分——这个"模糊语义"正是代码极简的原因，也是初读时最容易别扭的地方。

**疑问二：如果题目不保证 p、q 存在于树中，会怎样？**

会出 bug：`p` 不存在时可能把 `q` 单独交上去、把 `q` 误判为 LCA。处理办法是把返回值改成"子树中找到的目标**个数**"：只有某节点处左右个数之和恰为 2（或累计达 2 的最低节点）才确定为 LCA。[LeetCode 1644](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree-ii/) 就是这个变体，且不能提前返回，必须完整遍历。它反过来印证了本题"提前返回"依赖的是**存在性保证**。

**疑问三：这题和 BST 版的 LCA（235 题）区别在哪？**

235 题利用 BST 的有序性可以直接**自顶向下**走：p、q 都小于当前节点就往左，都大于就往右，分居两侧即答案，连递归栈都可以省掉（迭代 $O(h)$ 时间、$O(1)$ 空间）。普通二叉树没有序性可用，只能靠后序自底向上汇合。两者是"利用特有性质压掉遍历成本"的经典对照。

## 6. 相关题目与模板

**可复用模板**（"后序汇合"骨架，凡"在树中找同时满足两侧条件的最低节点"都可用）：

```cpp
TreeNode* dfs(TreeNode* root) {
    if (!root || 命中条件(root)) return root;
    auto L = dfs(root->left), R = dfs(root->right);
    if (L && R) return root;      // 两侧各有 -> 分岔点
    return L ? L : R;             // 单侧有 -> 上交
}
```

把"命中条件"替换一下，同一骨架可解：LCA（本题）、深度最大的叶子（1123 题）、到两目标距离和最小的节点等。

**同类题目：**

- [LeetCode 235. 二叉搜索树的最近公共祖先](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-search-tree/)：BST 特化版，自顶向下迭代即可
- [LeetCode 1644. 二叉树的最近公共祖先 II](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree-ii/)：节点可能不存在，须计数处理
- [LeetCode 1650. 二叉树的最近公共祖先 III](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree-iii/)：节点带父指针，脱链上溯 + 交换走法（类似两链表求交点）
- [LeetCode 1123. 最深叶节点的最近公共祖先](https://leetcode.cn/problems/lowest-common-ancestor-of-deepest-leaves/)：把"命中 p/q"换成"子树最大深度"的汇合判断

**一句话总结**：LCA 是两条根路径的分岔点——后序遍历让 p、q 如气泡从两侧上浮，**第一次相遇的地方**就是答案；"遇到目标即返回"的截断之所以安全，全靠题目"两节点必在树中"的保证。
