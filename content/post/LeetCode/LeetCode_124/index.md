# LeetCode 124. 二叉树中的最大路径和

> 题目链接：[https://leetcode.cn/problems/binary-tree-maximum-path-sum/](https://leetcode.cn/problems/binary-tree-maximum-path-sum/)  
> 难度：困难  
> 标签：树、深度优先搜索、动态规划、二叉树

---

## 1. 题目描述

给你一棵二叉树的根节点 `root`，路径定义为：从树中**任意节点**出发，沿父子连接**至多一次拐弯**，到达任意节点的序列。路径**至少包含一个节点**，不必经过根。求所有可能路径中**节点值之和的最大值**。

直观地说，一条合法路径形如：先从某个后代向上爬到某个"最高点"，再向下爬进另一棵子树——整个路径像一座山，山顶就是那个最高点；当然也可以只向上不拐弯，或只有一个节点。

节点值**可以为负**，这打破了"路径越长越好"的直觉。

**数据范围：**

- 树中节点数 $1 \le n \le 3 \times 10^4$
- $-1000 \le \text{Node.val} \le 1000$

**示例：**

```
输入：root = [-10,9,20,null,null,15,7]

输出：42

解释：最优路径是 15 -> 20 -> 7，和为 15 + 20 + 7 = 42。
（注意：不选根 -10，也不选 9——它们都是负贡献。）
```

---

## 2. 思路分析

### 2.1 暴力：枚举每个节点作为"拐弯点"

每条路径都有唯一的"最高点"（山顶）。于是可以按最高点分类：枚举每个节点 `u` 作为山顶，最优路径是「`u` 的左子树里最佳 downward 路径 + $val(u)$ + `u` 的右子树里最佳 downward 路径」（两边的最佳都可以是空，因为值可能为负）。

若每次都重新递归计算"以 `u` 为起点向下的最大路径和"，单点是 $O(n)$，总代价 $O(n^2)$，$n = 3\times10^4$ 时约 $9 \times 10^8$——超时。瓶颈：**同一个子树的 downward 最优值被反复计算**。

### 2.2 优化：一次后序 DFS，边"汇报"边"结算"

注意到「以 `u` 为山顶的答案」与「以 `u` 为起点的 downward 最大和」是两个不同的量，而且后者可以递归定义：

$$gain(u) = val(u) + \max(0,\ gain(left),\ gain(right))$$

- 子树的 `gain` 为负时宁可不要（取 0），这就是 $\max(0, \cdot)$ 的含义；
- 而 `u` 作为山顶的候选答案是：

$$best(u) = val(u) + \max(0, gain(left)) + \max(0, gain(right))$$

两者在**同一次后序遍历**中就能一起算出：递归函数返回 `gain(u)` 给父节点用，同时在节点 `u` 处用 `best(u)` 更新全局答案。每个节点只算一次，$O(n)$。这本质是**树形动态规划 (tree DP)**：`gain` 是向上汇报的"子问题答案"，`best` 是把左右子树答案合并的"决策"。

### 2.3 为什么 `gain` 只能选一侧、`best` 却能两侧都要

这是本题最核心的不对称，值得单独想清楚：

- **向上汇报时只能带一侧**。父节点调用返回值是把它拼进自己的一条直线路径，路径不允许两次拐弯——若 `gain(u)` 同时含左右两支，再接到父节点上就成了「下山又上山」的非法形状（会经过 `u` 两次）。
- **山顶结算时可以两侧都要**。`best(u)` 以 `u` 为最高点，左边一段向下、右边一段向下，恰好只拐一次弯，合法。

一句话：**递归返回值受"还能不能继续往上接"约束，全局答案不受这个约束**——两个量的定义域不同，不能混用。

### 2.4 用示例走一遍

`root = [-10, 9, 20, null, null, 15, 7]`，`ans` 初始化为 $-\infty$：

| 节点 | 左 gain | 右 gain | gain（上交） | best（结算） | ans |
|---|---|---|---|---|---|
| 9 | —（叶） | —（叶） | $9$ | 9 | 9 |
| 15 | — | — | $15$ | 15 | 15 |
| 7 | — | — | $7$ | 7 | 15 |
| 20 | 15 | 7 | $20 + 15 = 35$ | $20 + 15 + 7 = 42$ | **42** |
| -10 | 9 | 35 | $-10 + 35 = 25$ | $-10 + 9 + 35 = 34$ | 42 |

看两处细节：

- 节点 `20` 上交的 `gain` 是 35（只带左边的 15，不带 7——两个都要就无法再接父节点了），但它自己作为山顶的 `best` 是 42（两边都吃下）；
- 根 `-10` 结算出 34 < 42：全局答案在**中途的某个节点**处就已锁定，根没有任何特殊性——这正是用全局变量而不是返回值承载答案的原因。

## 3. 代码实现

```cpp
class Solution {
    int ans = INT_MIN;    // 全局答案；初始为 -inf，应对"全负树"

    // 返回以 node 为起点、只向下走一条链的最大和（可为负，父节点决定要不要）
    int gain(TreeNode* node) {
        if (!node) return 0;

        int l = max(gain(node->left),  0);   // 负贡献的子树直接弃掉
        int r = max(gain(node->right), 0);

        ans = max(ans, node->val + l + r);   // 以 node 为山顶结算（两侧都要）

        return node->val + max(l, r);        // 向上只能带一侧
    }

public:
    int maxPathSum(TreeNode* root) {
        gain(root);
        return ans;
    }
};
```

实现要点：

1. **`ans` 初始化为 `INT_MIN` 而不是 0**：路径至少一个节点，全负树（如单节点 `-3`）的答案是负数，用 0 初始化会把不存在的空路径当成答案；
2. **`max(gain(...), 0)` 写在结算之前**：`l`、`r` 是"剪枝后"的增益，山顶结算和向上汇报都用剪枝后的值，保持一致；
3. **空节点返回 0**：作为递归边界，同时天然满足"单侧为空 = 没有贡献"。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。每个节点恰好访问一次，做常数次比较与加法。
- **空间复杂度**：$O(h)$ 为递归栈深度，最坏（链状）$O(n)$，平衡树 $O(\log n)$。

| 做法 | 时间 | 说明 |
|---|---|---|
| 暴力枚举山顶 | $O(n^2)$ | 每个山顶重新计算 downward 最优 |
| **后序 DFS（树形 DP）** | $O(n)$ | `gain` 上交、`best` 结算，一次遍历 |

对比 543（二叉树的直径）：把本题的"路径和"换成"边数"、把 $\max(0,\cdot)$ 换成"至少为 0"，骨架完全相同——543 是 124 的零花钱版。

## 5. 常见疑问

**疑问一：为什么递归返回值不能是"这棵子树内部的答案"？**

如果 `gain(u)` 返回"子树内部（不含向父延伸）的最优"，父节点拼接时会出错：把一个"内部已拐过弯"的路径再接上父节点，形状非法。所以返回值必须换成**可拼接的量**——"从 u 向下一条链的最大和"。很多树形 DP 的设计难点都在这里：**向上汇报的量必须保证父节点还能继续利用**，它与最终答案的量往往不是同一个。

**疑问二：全是负数时为什么不选"空路径"？**

题目规定路径至少包含一个节点，空路径（和为 0）非法。这就是 `ans` 必须初始化 $-\infty$、且不能给 `node->val + l + r` 里偷偷塞 0 的原因。反例：树 `[-3]` 答案是 $-3$，不是 0。同理，"负子树弃掉"只发生在**拼接**环节（$\max(gain, 0)$），节点自身的值永远无法弃掉——山顶必须是真实节点。

**疑问三：会不会出现"路径穿过某个节点两次"？**

不会，形状约束被两条规则共同守住：结算时山顶两侧只向下（$l$、$r$ 各是一条纯向下链，仅在山顶相遇一次）；上交时只带一侧（不会再创造第二个拐点）。有人想模拟"路径拆成三段 (u→v) + (v→w)"之类的通用模型，在这棵树上等价于枚举拐点——即本题做法本身，绕一圈还会回到同一骨架。

## 6. 相关题目与模板

**可复用模板**（"山顶结算 + 单侧上交"骨架，贡献法在树上的标准形态）：

```cpp
int gain(TreeNode* u) {              // 返回：可继续向上拼接的最优值
    if (!u) return 边界值;
    int l = gain(u->left), r = gain(u->right);
    ans = max(ans, combine(u, l, r));   // 在 u 处结算最终形态的答案
    return 向上携带一侧(l, r);           // 受"还能否拼接"约束
}
```

把「上交量」与「结算量」换成别的语义，可解一整族题：最大路径和（本题）、直径（543）、最长同值路径（687）、最大 BST 子树（333）等。

**同类题目：**

- [LeetCode 543. 二叉树的直径](https://leetcode.cn/problems/diameter-of-binary-tree/)：本题的无权版，先做它再回看 124 会非常顺
- [LeetCode 687. 最长同值路径](https://leetcode.cn/problems/longest-univalue-path/)：结算时子路径值不等则弃，约束换成"同值"
- [LeetCode 112. 路径总和](https://leetcode.cn/problems/path-sum/)：约束最严（根到叶），对比感受"路径约束每放宽一档，状态设计多一个维度"
- [LeetCode 337. 打家劫舍 III](https://leetcode.cn/problems/house-robber-iii/)：另一种经典树形 DP（返回值是状态二元组），与本题互补

**一句话总结**：把"拐弯点"作为分类轴，每个节点结算一次"山顶答案"、上交一次"单侧链增益"——**上交受拼接约束，结算不受**，这对不对称就是整道题的全部机关。
