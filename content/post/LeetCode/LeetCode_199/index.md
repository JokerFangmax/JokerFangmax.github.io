# LeetCode 199. 二叉树的右视图

> 题目链接：[https://leetcode.cn/problems/binary-tree-right-side-view/](https://leetcode.cn/problems/binary-tree-right-side-view/)  
> 难度：中等  
> 标签：树、深度优先搜索、广度优先搜索、二叉树

---

## 1. 题目描述

给定一棵二叉树的根节点 `root`，想象自己站在树的**右侧**，按照**从顶部到底部**的顺序，返回你能看到的节点值组成的数组。

站在右侧时，同一层上你看到的是**最右边**的那个节点（它左边的节点都被它挡住）。

**数据范围：**

- 树中节点数目范围 $[0, 100]$
- $-100 \le Node.val \le 100$

**示例：**

```
输入：root = [1,2,3,null,5,null,4]

        1        <- 第 0 层
       / \
      2   3      <- 第 1 层
       \   \
        5   4    <- 第 2 层

输出：[1,3,4]
解释：站在右侧，每层只能看到最右边的节点：第 0 层 1，第 1 层 3，第 2 层 4。
```

---

## 2. 思路分析

### 2.1 暴力：每层取最右

"右视图"翻译成序列语言就是：**每一层各取一个最靠右的节点**。于是问题分解为两步：

1. 把树按层展开（层序遍历，即广度优先搜索 BFS）；
2. 每层的最后一个元素进答案。

这已经是可提交的正确解法了。真正的思考点在于：**"每层最右"还有没有别的获取方式？最右的节点会不会被某种遍历顺序最先访问到？**

### 2.2 观察：根-右-左的 DFS 恰好"每层先撞见最右节点"

考察深度优先搜索 (Depth-First Search, DFS) 的访问顺序。如果规定**先访问右孩子、再访问左孩子**（"根-右-左"），那么：

- 访问根（深度 0）——此时深度 0 的答案还没定，根就是最右；
- 走右子树，一路向下，**每进入一个新深度，第一个撞见的节点必然来自"尽量靠右的路径"**——因为 DFS 的整个相位都偏右，左侧节点永远更晚到达同一深度。

用示例走一遍（顺序标记为访问序号）：

| 访问序号 | 节点 | 深度 | 该深度是否已有答案 | 动作 |
|---------|------|------|-------------------|------|
| 1 | 1 | 0 | 无 | ans[0] = 1 |
| 2 | 3 | 1 | 无 | ans[1] = 3 |
| 3 | 4 | 2 | 无 | ans[2] = 4 |
| 4 | 2 | 1 | 已有（3） | 跳过 |
| 5 | 5 | 2 | 已有（4） | 跳过 |

答案是 $[1, 3, 4]$，正确。注意节点 5 虽然比 4 "更靠左"，但它**到达更晚**——DFS 右先行的策略保证了每个深度上最右节点总是第一个报到。

于是得到两条并列的解法路线：

| 方案 | 遍历方式 | "每层最右"的来源 | 核心判断 |
|------|---------|-----------------|---------|
| BFS 层序 | 队列逐层展开 | 每层**最后**出队的节点 | 出队时判断是否层内最后一个 |
| DFS 根右左 | 递归，右孩子在前 | 每层**最先**访问到的节点 | `depth == ans.size()` 时记录 |

### 2.3 两种方案的性格对比

| 维度 | BFS 层序 | DFS 根右左 |
|------|---------|-----------|
| 空间（最坏） | $O(w)$，$w$ 为最大宽度 | $O(h)$，$h$ 为树高 |
| 满二叉树时 | $w = n/2$，约 $O(n)$ | $h = \log n$ |
| 链状树时 | $O(1)$ | $O(n)$ |
| 提前终止 | 天然按层产出 | 不适合（第 $d$ 层最右未出前不能确定浅层？不——浅层早已确定，但无法"只看前几层"就停） |
| 代码形态 | 队列 + 内层 for 分层 | 递归三行核心 |

两者最坏都是 $O(n)$ 时间。选择看树的形状偏好：极宽的树 DFS 省空间，极深的树 BFS 省空间；面试中先讲 BFS（更贴"右视图 = 每层最右"的直觉），再补 DFS 作为加分项。

### 2.4 一个易错推论：右视图 ≠ 一直向右走

注意"根-右-左"DFS 拿到的**不是**"从根一直沿右指针下行的路径"。反例：

```
        1
       / \
      2   3
     /
    4         <- 右视图应包含 4（第 2 层只有它）
```

一直向右走只得到 $[1, 3]$，漏掉 4。正确答案 $[1, 3, 4]$：右孩子缺席时，**同一层最靠右的"现存"节点**顶上——这正是"每层最右"定义优于"沿右指针走"定义的地方，也是本题最经典的 WA 来源。

## 3. 代码实现

```cpp
class Solution {
    vector<int> ans;

    // 根-右-左 DFS：每层第一个被访问的节点即该层最右
    void dfs(TreeNode* root, int depth) {
        if (root == nullptr) return;
        if (depth == (int)ans.size())   // 该深度第一次报到 -> 就是最右
            ans.push_back(root->val);
        dfs(root->right, depth + 1);    // 右孩子优先！
        dfs(root->left,  depth + 1);
    }
public:
    vector<int> rightSideView(TreeNode* root) {
        dfs(root, 0);
        return ans;
    }
};
```

等价的 BFS 层序写法（两版任选其一提交）：

```cpp
class Solution {
public:
    vector<int> rightSideView(TreeNode* root) {
        vector<int> ans;
        if (root == nullptr) return ans;
        queue<TreeNode*> q;
        q.push(root);
        while (!q.empty()) {
            int sz = q.size();               // 当前层的节点数，固定下来
            for (int i = 0; i < sz; i++) {
                TreeNode* cur = q.front();
                q.pop();
                if (i == sz - 1)             // 层内最后一个出队 = 最右
                    ans.push_back(cur->val);
                if (cur->left)  q.push(cur->left);
                if (cur->right) q.push(cur->right);
            }
        }
        return ans;
    }
};
```

几个实现细节：

1. **DFS 版 `depth == ans.size()` 是精髓**。答案数组长度恰好等于"已出现过的最大深度 + 1"，进入从未到过的深度时 `ans` 长度追上来，该节点必是本层第一个（最右）。
2. **右孩子必须先于左孩子递归**，顺序一换就变成"左视图"。
3. **BFS 版的 `sz` 必须在入队前取出**。循环体内 `q.push` 会改变 `q.size()`，直接用 `q.size()` 做边界会错乱——"先存层大小再循环"是层序遍历的标准防坑姿势。
4. **空树返回空**：数据范围允许 $n = 0$，DFS 版天然处理，BFS 版需要显式判断。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。两种方案每个节点都恰好访问一次，每次访问 $O(1)$。
- **空间复杂度**：DFS 为 $O(h)$（递归栈，$h$ 为树高，最好 $\log n$、最坏 $n$）；BFS 为 $O(w)$（队列，$w$ 为最大宽度，最好 $1$、最坏约 $n/2$）。

两种方案在最坏情况下都不超过 $O(n)$；同一棵树上一个用栈深、一个用队宽，形状互补，这正是"DFS 与 BFS 空间画像相反"的经典例证。

## 5. 常见疑问

**疑问一：DFS 的"每层第一个访问的就是最右"凭什么成立？**

归纳证明：深度 0 只有根，显然成立。设深度 $d$ 上第一个被访问的节点是 $x$，它是某个深度 $d-1$ 节点 $p$ 的孩子；由于右孩子先于左孩子被递归，且 $x$ 是"深度 $d$ 的第一报到者"，$x$ 必是 $p$ 的**右孩子**（否则 $p$ 的右孩子会在 $x$ 之前到达深度 $d$）。进一步，在 $p$ 之前被处理的深度 $d-1$ 节点都位于 $p$ 的右侧——它们的右孩子（若有）会更早到达深度 $d$，与"$x$ 第一"矛盾，所以这些右侧节点的子树在深度 $d$ 处是空的，即 $x$ 右侧无节点，$x$ 就是最右。逐层归纳即得一般性。

**疑问二：题目是"右视图"，改成"左视图 / 下视图"要动哪里？**

左视图：DFS 交换两个孩子顺序（或 BFS 取层内**第一个**出队者）。下/上视图则是另一类问题（每列最下/最上节点），需要按"水平坐标"哈希分组，DFS 时把坐标 $(depth, \mathrm{col})$ 传下去。可见"视图"类题的通用心法是：**给每个节点定位到一个可比较的坐标轴，每条轴上只留一个代表**。

**疑问三：BFS 里 `i == sz - 1` 和"先右后左入队、最后出队即答案"等价吗？**

等价，且后者可以少一个判断：因为队列先进先出，层内若**只入队存在的孩子**且右孩子后入队……小心，这并不保证右孩子最后出队——右孩子入队早于本层后续节点的左孩子。所以稳妥做法还是老老实实数下标 `i == sz - 1`，或者反过来"先右后左入队、取每层**第一个**出队者"。试图靠入队顺序的巧合省判断，是层序遍历 bug 的常见产地。

## 6. 相关题目与模板

**可复用模板**（"根-右-左 + 深度首次报到"可复用于一切"每层代表元"问题）：

```cpp
// 每层取最右代表元的 DFS 骨架（改比较方向即得左视图）
vector<int> ans;
void dfs(TreeNode* root, int depth) {
    if (!root) return;
    if (depth == (int)ans.size()) ans.push_back(root->val);
    dfs(root->right, depth + 1);   // 想取哪侧，哪侧先行
    dfs(root->left,  depth + 1);
}
```

**方法论总结**：视图类问题 = 遍历 + "每层（每条坐标轴）保留一个代表元"。BFS 用"层内首/尾出队"选代表，DFS 用"深度首次报到"选代表，本质都是**给代表元的出现次序编号，只接受每个编号的第一个**。

**同类题目：**

- [LeetCode 102. 二叉树的层序遍历](https://leetcode.cn/problems/binary-tree-level-order-traversal/)：BFS 分层模板的母题，本题先掌握它
- [LeetCode 515. 在每个树行中找最大值](https://leetcode.cn/problems/find-largest-value-in-each-tree-row/)：把"层内最右"换成"层内最大"，同一 DFS/BFS 骨架
- [LeetCode 116. 填充每个节点的下一个右侧节点指针](https://leetcode.cn/problems/populating-next-right-pointers-in-each-node/)：另一种"横向看树"的视角
- [LeetCode 987. 二叉树的垂序遍历](https://leetcode.cn/problems/vertical-order-traversal-of-a-binary-tree/)：坐标轴从"深度"换成"水平位置"，视图思想的推广
- [LeetCode 144. 二叉树的前序遍历](https://leetcode.cn/problems/binary-tree-preorder-traversal/)：本题 DFS 其实就是"前序遍历换孩子顺序"

**一句话总结**：右视图 = 每层最右代表元——BFS 取每层最后一个出队者，或 DFS 按"根-右-左"取每个深度**第一个报到**的节点；千万别沿着右指针一路走到底。
