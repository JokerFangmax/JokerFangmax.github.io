# LeetCode 238. 除自身以外数组的乘积

> 题目链接：[https://leetcode.cn/problems/product-of-array-except-self/](https://leetcode.cn/problems/product-of-array-except-self/)  
> 难度：中等  
> 标签：数组、前缀和

---

## 1. 题目描述

给定一个整数数组 `nums`，返回数组 `answer`，其中 `answer[i]` 等于 `nums` 中**除 `nums[i]` 之外**其余所有元素的乘积。

题目有两条硬性要求，正是本题的考点：

1. 时间复杂度 $O(n)$；
2. **不能使用除法**（所以"先算总乘积再除以自己"这条路被堵死）；
3. 进阶：$O(1)$ 额外空间（**不视输出数组为额外空间**）。

**数据范围：**

- $2 \le nums.length \le 10^5$
- $-30 \le nums[i] \le 30$
- 保证所有元素乘积在 32 位整数范围内（$[-2^{31}, 2^{31} - 1]$）

**示例：**

```
输入：nums = [1,2,3,4]
输出：[24,12,8,6]
// answer[0] = 2*3*4 = 24, answer[1] = 1*3*4 = 12,
// answer[2] = 1*2*4 = 8,  answer[3] = 1*2*3 = 6

输入：nums = [-1,1,0,-3,3]
输出：[0,0,9,0,0]
// 只有下标 2 之外的元素不含 0，其乘积为 -1*1*-3*3 = 9
```

---

## 2. 思路分析

### 2.1 暴力：每个位置重乘一遍

对每个 $i$ 把 $n - 1$ 个数乘起来，总代价 $O(n^2)$。$n = 10^5$ 时约 $10^{10}$ 次乘法，超时。

第一反应的"聪明办法"是**除法**：总乘积 $P$ 除以 $nums[i]$ 即得 $answer[i]$。但有两个致命伤：

- 题目明令禁止；
- 即使允许，$nums[i] = 0$ 时除法直接失效——总乘积为 0，得逐个分类讨论"零的个数"，代码很快变丑。

所以必须回到乘法本身，找一个能把重复计算摊掉的结构。

### 2.2 关键观察：每个答案都是"左边一段 × 右边一段"

$answer[i]$ 要的是"除 $i$ 以外全部元素的乘积"。把数组在 $i$ 处劈开，它恰好等于：

$$answer[i] = \underbrace{\prod_{j < i} nums[j]}_{\text{前缀积 } L[i]} \times \underbrace{\prod_{j > i} nums[j]}_{\text{后缀积 } R[i]}$$

两边互不相干，各自独立可算。而**前缀积正是不动点扫描的产物**——从左往右扫一遍就能递推出来，后缀积对称地从右往左：

$$L[0] = 1,\quad L[i] = L[i-1] \times nums[i-1]; \qquad R[n-1] = 1,\quad R[i] = R[i+1] \times nums[i+1]$$

（边界取 $1$ 是乘法单位元，与[前缀和模板](../../algorithms/prefix_sum/)里 $pre[0] = 0$ 取加法单位元完全同构：**把"和"换成"积"、"0"换成"1"**，前缀和的整套方法论平移过来。）

### 2.3 操作流程（以示例演示）

`nums = [1, 2, 3, 4]`：

| $i$ | $nums[i]$ | $L[i]$（左侧全乘） | $R[i]$（右侧全乘） | $answer[i] = L \times R$ |
|---|---|---|---|---|
| 0 | 1 | $1$ | $2 \cdot 3 \cdot 4 = 24$ | $1 \times 24 = 24$ |
| 1 | 2 | $1$ | $3 \cdot 4 = 12$ | $1 \times 12 = 12$ |
| 2 | 3 | $1 \cdot 2 = 2$ | $4$ | $2 \times 4 = 8$ |
| 3 | 4 | $1 \cdot 2 \cdot 3 = 6$ | $1$ | $6 \times 1 = 6$ |

输出 `[24, 12, 8, 6]`。零元素无需任何特判：`[-1,1,0,-3,3]` 的下标 2 处 $L[2] = -1$、$R[2] = -9$，乘积 9，其余位置左右两侧各含一个 0，自动为 0——**分类讨论被结构本身消化了**。

### 2.4 进阶：砍掉两个辅助数组

上表用了 $L$、$R$ 两个 $O(n)$ 数组。注意到两件事：

1. $L$ 的值算完一个就用一个，不必整段保存；
2. 输出数组 `answer` 本身**不算额外空间**——可以先把它当 $L$ 用。

于是两趟扫描：

- **第一趟从左往右**：`answer[i] = L`（当前前缀积），然后 `L *= nums[i]`，为下一站备货；
- **第二趟从右往左**：用一个滚动变量 $R$ 累积后缀积，`answer[i] *= R`，然后 `R *= nums[i]`。

辅助数组归零，额外空间只剩两个整型。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<int> productExceptSelf(vector<int>& nums) {
        int n = nums.size();
        vector<int> ans(n);

        int L = 1;                          // 左侧前缀积（乘法单位元 1）
        for (int i = 0; i < n; i++) {
            ans[i] = L;                     // 先收货：ans[i] 暂存 L[i]
            L *= nums[i];                   // 再更新：把 nums[i] 纳入前缀
        }

        int R = 1;                          // 右侧后缀积
        for (int i = n - 1; i >= 0; i--) {
            ans[i] *= R;                    // 补上右半边的贡献
            R *= nums[i];                   // 把 nums[i] 纳入后缀
        }
        return ans;
    }
};
```

几个实现细节：

1. **"先收货、再更新"的顺序不能反**。第一趟里若先 `L *= nums[i]` 再赋值，`answer[i]` 就混进了 $nums[i]$ 自己——这正是"除自身以外"要排除的那个元素，是本解法唯一的位置陷阱。
2. **单位元初值是 1 不是 0**。前缀积的恒等元是 1；写成 0 会让所有前缀积变 0（对应前缀和里初值 0 的位置，换个运算单位元跟着换）。
3. **零元素零特判**。任何位置只要左侧或右侧含 0，对应的前缀/后缀积自然是 0，逻辑无需分支——这是结构化解法相对于除法解法最干净的地方。
4. **溢出不用担心**：题目保证全体乘积在 32 位范围内；又因 $|nums[i]| \le 30$，任何前缀/后缀积都是总乘积的因子，必然同样在范围内。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。两趟线性扫描，每步一次乘法（或两次）。
- **空间复杂度**：$O(1)$ 额外空间。两个滚动整型 $L, R$；输出数组按题意不计。若计入输出则为 $O(n)$。

| 做法 | 时间 | 空间 | 备注 |
|------|------|------|------|
| 逐位重乘 | $O(n^2)$ | $O(1)$ | 超时 |
| 总积 ÷ 自己 | $O(n)$ | $O(1)$ | 被禁止；零元素要分类讨论 |
| 前缀积 + 后缀积数组 | $O(n)$ | $O(n)$ | 最好写、最好想 |
| **滚动变量版** | $O(n)$ | $O(1)$ | 复用输出数组存前缀积 |

## 5. 常见疑问

**疑问一：如果允许除法，正确的写法是什么？为什么还是不推荐？** 统计零的个数 $z$：若 $z \ge 2$，全答案为 0；若 $z = 1$，除零位外全 0，零位等于非零元素总积；若 $z = 0$，$answer[i] = P / nums[i]$。三段分支都能写对的话功能上没问题，但"先数零再分情况"的代码路径多、易漏，而且**除法解法对"元素乘积溢出"更脆弱**（$P$ 可能溢出而因子不溢出）。前缀积版两条都不怕，还多学一个模板。

**疑问二：负数会影响什么吗？** 不影响正确性，但值得知道一个小应用：`answer[i]` 的符号恰好告诉"除 $i$ 外负数个数的奇偶"——本题的变体常拿它出题（如"除自身外的负数个数"统计，把前缀积换成前缀负数计数即可）。前缀思想的核心是**"劈两半、各自可累积"**，累积的运算可以换成任何满足结合律的东西：乘法、负号计数、`max`（见 [LeetCode 239 题解](../LeetCode_239/) 里"max 为何不可逆"的讨论——不可逆没关系，本题不需要做逆运算，只需要双侧可累积）。

**疑问三：为什么输出数组可以"不算"额外空间？** 这是工程与算法度量口径的约定：输出是结果本身，任何解法都绕不开，把它当工作区复用是常见技巧（类似的还有"原地哈希"把 `answer` 当桶用）。做题时看清进阶要求的括号说明，别把 $O(n)$ 的输出也省成不写。

## 6. 相关题目与模板

> 📚 系统整理见模板笔记：[前缀和：从区间和到子数组计数](../../algorithms/prefix_sum/)（本题是"前缀和 → 前缀积"的一次单位元替换练习）。

**可复用模板**（双侧前缀/后缀累积，$O(1)$ 额外空间）：

```cpp
// answer[i] = op(所有 j < i 的元素) ∘ op(所有 j > i 的元素)
// op 取 sum、乘积、max、异或……只需换初值（单位元）与运算符
int L = e;                       // e = 单位元（和为 0，积为 1，异或为 0）
for (int i = 0; i < n; i++) { ans[i] = L;  L = L ∘ a[i]; }
int R = e;
for (int i = n - 1; i >= 0; i--) { ans[i] = ans[i] ∘ R;  R = R ∘ a[i]; }
```

- [LeetCode 303. 区域和检索 - 数组不可变](https://leetcode.cn/problems/range-sum-query-immutable/)：前缀和的裸模板，入门第一站
- [LeetCode 724. 寻找数组的中心下标](https://leetcode.cn/problems/find-pivot-index/)：同样是"左半 × 右半"的劈半结构，只是把积换成和、把乘换成比较
- [LeetCode 560. 和为 K 的子数组](https://leetcode.cn/problems/subarray-sum-equals-k/)：前缀和 + 哈希的组合拳（详见[我的题解](../LeetCode_560/)）

**一句话总结**：把"除自身以外的乘积"看成"左前缀积 × 右后缀积"，两趟扫描、两个滚动变量——前缀和的方法论换个单位元就免费迁移到乘法世界。
