# LeetCode 437. 路径总和 III

> 题目链接：[https://leetcode.cn/problems/path-sum-iii/](https://leetcode.cn/problems/path-sum-iii/)  
> 难度：中等  
> 标签：树、深度优先搜索、二叉树、前缀和

---

## 1. 题目描述

给定一棵二叉树的根节点 `root` 和一个整数 `targetSum`，求树中**节点值之和等于 `targetSum` 的路径数目**。

这里的路径不需要从根开始、也不需要到叶子结束，但必须**向下**：即从某个节点出发，沿父指针一路走到它的某个后代。路径至少包含一个节点，且**可以只有一个节点**。

注意本题节点值可以为负，所以路径上不能「见到和超标就提前剪枝」——后面的负数还可能把和拉回来。

**数据范围：**

- 树上节点数 $1 \le n \le 1000$
- $-10^9 \le \text{Node.val}, \text{targetSum} \le 10^9$

**示例：**

```
输入：root = [10,5,-3,3,2,null,11,3,-2,null,1], targetSum = 8

输出：3

和为 8 的三条路径：
  5 -> 3          （10 的左子树中）
  5 -> 2 -> 1
  -3 -> 11        （10 的右子树中）
```

---

## 2. 思路分析

### 2.1 暴力：枚举每个起点，向下穷举路径

最直接的做法：对每个节点 `u`，从 `u` 出发做一次 DFS，枚举它向下的所有路径并累加求和，等于 `targetSum` 就计数。

两层 DFS 嵌套，外层访问 $n$ 个节点，内层最坏走 $O(n)$ 条路径边（链状树时），总时间 $O(n^2)$。$n = 1000$ 时约 $10^6$，能过，但如果路径计数改在链上退化就是瓶颈——我们需要把它变成一次遍历。

### 2.2 关键转化：路径和 = 两个「根到节点」前缀和之差

换一个视角。树上每条向下路径 $(u \to v)$（$u$ 是 $v$ 的祖先或 $u = v$）可以写成两条**从根出发的前缀路径**之差：

$$sum(u \to v) = S(v) - S(parent(u))$$

其中 $S(x)$ 表示从根到 $x$ 的路径和（即「树上前缀和 (prefix sum on tree)」）。于是问题变成：**对每个节点 $v$，数一数它的祖先中（含自己）有多少个 $x$ 满足 $S(v) - S(x) = target$，即 $S(x) = S(v) - target$。**

这正是数组版「和为 K 的子数组」的树上翻版（见 [LeetCode 560](../LeetCode_560/)）：把数组换成「根到当前节点的链」，子数组换成路径。

### 2.3 用哈希表沿 DFS 维护前缀和集合

DFS 过程中，当前根到节点链上的所有前缀和恰好是「活着的候选 $S(x)$」集合。维护一个哈希表 `cnt[s]` = 链上前缀和为 $s$ 的节点数，进入节点 `v` 时：

1. 先把 `ans += cnt[cur - target]`（`cur` 是根到 `v` 的前缀和，含 `v` 自身——这自然覆盖了「单节点路径」，因为 $S(parent)$ 也在表中）；
2. 把 `cnt[cur]++`，递归左右子树；
3. **回溯时 `cnt[cur]--`**，把该前缀和撤出集合。

每一步进一个节点、出一个节点，哈希表始终只描述「当前这条链」，时间 $O(n)$。

### 2.4 用小例子走一遍

取示例的右半边 `10 -> -3 -> 11`，`target = 8`，并设根之上的「虚拟前缀和」为 0。设 `cnt` 初始为 `{0: 1}`（哨兵：从根出发的路径需要对 $S(parent(root))$ 取差）。

| 节点 | 进入时 `cur` | 查询 `cnt[cur-8]` | 命中情况 | 入表后 |
|---|---|---|---|---|
| 10 | 10 | `cnt[2]` = 0 | 无 | `{0:1, 10:1}` |
| -3 | 7 | `cnt[-1]` = 0 | 无 | `{0:1, 10:1, 7:1}` |
| 11 | 18 | `cnt[10]` = 1 | **路径 10 -> -3 -> 11，和 8** | `{..., 18:1}` |

再看左子树 `10 -> 5 -> 2 -> 1` 这条链：走到 `2` 时 `cur = 17`，查 `cnt[9]` = 0；走到 `1` 时 `cur = 18`，查 `cnt[10]` = 1——命中的是根 10，对应路径 `5 -> 2 -> 1`（和 $18 - 10 = 8$），但**不**是 `10 -> 5 -> 2 -> 1`（和 18）。这就是差式计数「自动排除链外节点、自动对齐端点」的体现。

## 3. 代码实现

```cpp
class Solution {
    long long target;
    long long ans = 0;
    unordered_map<long long, int> cnt;   // 当前链上：前缀和 -> 出现次数

    void dfs(TreeNode* node, long long cur) {
        if (!node) return;
        cur += node->val;                       // 根到当前节点的前缀和
        ans += cnt.count(cur - target) ? cnt[cur - target] : 0;
        cnt[cur]++;                             // 把自己挂进链
        dfs(node->left, cur);
        dfs(node->right, cur);
        cnt[cur]--;                             // 回溯：撤出链（关键！）
    }

public:
    int pathSum(TreeNode* root, int targetSum) {
        target = targetSum;
        cnt[0] = 1;      // 哨兵：路径起点是根时，被减对象是"根之上的 0"
        dfs(root, 0);
        return (int)ans;
    }
};
```

实现要点：

1. **`cnt[0] = 1` 哨兵**：单节点路径、以及从根出发的路径，被减的前缀和是「根之前」，约定为 0。没有它，从根出发的路径全部漏数；
2. **查询在 `cnt[cur]++` 之前**：若 `target = 0`，先加自己会把「空路径」也数进去；
3. **回溯时 `cnt[cur]--`**：不加这一行，已经离开的兄弟分支会污染后续统计（见疑问一）；
4. **全程 `long long`**：链上 1000 个节点、每个绝对值至多 $10^9$，前缀和幅度可达 $10^{12}$，`int` 必然溢出。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。每个节点进出各一次，每次做常数次哈希操作。
- **空间复杂度**：$O(n)$。哈希表至多存 $n$ 个不同前缀和；递归深度为树高，最坏 $O(n)$。

| 做法 | 时间 | 空间 | 说明 |
|---|---|---|---|
| 暴力双重 DFS | $O(n^2)$ | $O(h)$ | 枚举每个起点 |
| **前缀和 + 哈希** | $O(n)$ | $O(n)$ | 一次遍历，边走边数 |

## 5. 常见疑问

**疑问一：为什么回溯时必须把 `cnt[cur]` 减回去？**

哈希表维护的是「**当前根到节点链**上的前缀和集合」。DFS 进入兄弟分支后，前一个分支的节点已经不是当前节点的祖先，若仍留在表中，就可能把「拐弯的路径」（先下到左子树再跳到右子树）也数进去——而树的路径不允许拐弯。减回去的操作让哈希表始终精确镜像递归栈，这是**树上差分/树上统计类题目的通用回溯套路**（对照线段树合并、启发式合并里的"撤销"思想）。

**疑问二：节点值有负数，能不能像路径总和 II 那样遇到和超过 target 就剪枝？**

不能。路径总和 II 限定路径**必须到叶子**，剪枝没有理论依据但可接受；本题路径终点任意，且负值意味着「当前和偏大，后面减回来」完全可能成立。例如 `target = 3`，链 `1 -> 5 -> -3`：走到 5 时和为 6 偏大，但整条链和恰为 3，提前剪枝会漏解。正确姿势就是前缀和差——它对正负值一视同仁。

**疑问三：这题和 560（和为 K 的子数组）到底是不是一回事？**

算法内核完全一致：枚举右端点，用哈希表查「左端前缀和 = $cur - target$」的个数。差异只在数据结构形状——数组的前缀和集合天然是「滑动的连续前缀」，树上的前缀和集合是「随 DFS 进出的链」，因此多了第 3 点的回溯撤销。数组版无需撤销是因为遍历顺序保证旧前缀和不会再用到，而树会"回头"。
