# LeetCode 240. 搜索二维矩阵 II

> 题目链接：[https://leetcode.cn/problems/search-a-2d-matrix-ii/](https://leetcode.cn/problems/search-a-2d-matrix-ii/)  
> 难度：中等  
> 标签：数组、二分查找、分治、矩阵

---

## 1. 题目描述

给定一个 $m \times n$ 的整数矩阵 `matrix`，它满足两条性质：

- **每行**元素从左到右升序排列；
- **每列**元素从上到下升序排列。

再给定一个目标值 `target`，判断它是否出现在矩阵中。注意行与行之间**没有**大小关系约束（第 $i$ 行的元素不一定都比第 $i+1$ 行的小），这与 74 题"每行首元素大于上一行尾元素"的强条件不同。

**数据范围：**

- $1 \le m, n \le 300$
- $-10^9 \le matrix[i][j] \le 10^9$
- $-10^9 \le target \le 10^9$

**示例：**

```
matrix = [[1 , 4 , 7 , 11, 15],
          [2 , 5 , 8 , 12, 19],
          [3 , 6 , 9 , 16, 22],
          [10, 13, 14, 17, 24],
          [18, 21, 23, 26, 30]]

target = 5  → true   （在下标 (1,1) 处）
target = 20 → false
```

---

## 2. 思路分析

### 2.1 暴力：全表扫描

逐个元素比较，$O(mn)$。最坏 $300 \times 300 = 9 \times 10^4$ 次，数据规模下其实能过，但完全没用到"行列有序"的性质——面试里这只是 baseline。

### 2.2 用上一半有序：逐行二分

每行内部是有序的，对每行做二分查找 (binary search)，总时间 $O(m \log n)$；也可以对每列二分得 $O(n \log m)$，聪明的做法是取两者较优：$O(\min(m \log n, n \log m))$。

还能更彻底地利用"双方向有序"吗？能——但不是把整个矩阵拍平成一个有序数组（行间无序关系，做不到，见第 5 节），而是找一个**站在特殊位置、每次比较都能排除一整行或一整列**的出发点。

### 2.3 阶梯搜索 (staircase search)：从右上角出发

考察右上角的元素 $x = matrix[0][n-1]$，它有个独一无二的身份：

- 在**它所在行**里它是**最大**的（行升序，它在最右）；
- 在**它所在列**里它是**最小**的（列升序，它在最上）。

于是拿 `target` 与 $x$ 比较，**无论结果如何都能删掉一行或一列**：

| 比较 | 结论 | 动作 |
|------|------|------|
| $x = target$ | 找到 | 返回 `true` |
| $x > target$ | 该列往下更大，整列无望 | 删除这一列（`j--`） |
| $x < target$ | 该行往左更小，整行无望 | 删除这一行（`i++`） |

每步让搜索范围的长宽之和严格减 1，最多 $m + n - 1$ 步收敛。左下角对称（所在行最小、所在列最大）同样可行；而左上角（行最小、列也最小）和右下角（行最大、列也最大）两个方向都"同好同坏"，一次比较无法排除任何一方，不能作为起点。

### 2.4 操作流程（以示例矩阵演示）

`target = 5`，从右上角 $(0, 4)$ 出发，值 15：

| 步 | 位置 (i, j) | 值 | 与 5 比较 | 动作 | 剩余范围 |
|----|------------|-----|-----------|------|----------|
| 1 | $(0, 4)$ | 15 | 大于 | 删第 4 列 | 第 $0 \sim 4$ 行 $\times$ 第 $0 \sim 3$ 列 |
| 2 | $(0, 3)$ | 11 | 大于 | 删第 3 列 | 同上少一列 |
| 3 | $(0, 2)$ | 7 | 大于 | 删第 2 列 | 第 $0 \sim 2$ 列 |
| 4 | $(0, 1)$ | 4 | 小于 | 删第 0 行 | 第 $1 \sim 4$ 行 $\times$ 第 $0 \sim 1$ 列 |
| 5 | $(1, 1)$ | 5 | **相等** | 返回 `true` | — |

再看 `target = 20`：$15 \to 11 \to 7 \to 4$（删第 0 行）$\to 5 \to 8 \to 12 \to 19$（小于，下移）$\to 22$（大于，左移）$\to 16 \to 14 \to 13 \to 10$（均大于，一路删列）$\to$ 越出左边界（$j < 0$），循环终止，返回 `false`。路径像沿阶梯下行，故名阶梯搜索。

## 3. 代码实现

```cpp
class Solution {
public:
    bool searchMatrix(vector<vector<int>>& matrix, int target) {
        int m = matrix.size(), n = matrix[0].size();
        int i = 0, j = n - 1;               // 从右上角出发
        while (i < m && j >= 0) {
            int x = matrix[i][j];
            if (x == target) return true;
            if (x > target) j--;            // x 是所在列的最小值，整列都 > target
            else             i++;           // x 是所在行的最大值，整行都 < target
        }
        return false;                        // 走出边界仍未命中
    }
};
```

几个实现细节：

1. **循环条件 `i < m && j >= 0`**：向两个方向都可能越界（下移越下界、左移越左界），必须同时看住。
2. **两个分支删除的都是"确定不含 target 的整行/整列"**，正确性不依赖行列长度关系，$m \ne n$、甚至退化为单行单列都自动成立。
3. 从**左下角** $(m-1, 0)$ 出发完全对称：值大于 target 上移（`i--`），小于则右移（`j++`）。

## 4. 复杂度分析

- **时间复杂度**：$O(m + n)$。每步比较后 $i$ 增 1 或 $j$ 减 1，两者合计最多变化 $m + n - 1$ 次，循环即终止。本题 $m, n \le 300$，至多约 600 次比较。
- **空间复杂度**：$O(1)$。只用了两个下标变量。

与逐行二分 $O(m \log n)$ 的比较并非一边倒：当 $n$ 巨大而 $m$ 很小时（如 $2 \times 10^9$ 的"矮宽"矩阵），$m \log n$ 可能优于 $m + n$。本题规模下两者都绰绰有余；数据范围不设限时，一般约定 $O(m + n)$ 为该模型的最优界。

## 5. 常见疑问

**疑问一：为什么不能像 74 题那样把矩阵拍平成有序一维数组二分？**

74 题额外保证"下一行首元素大于上一行尾元素"，因此按行拼接后整体单调，能把 $(i,j)$ 映射为一维下标 $k = i \cdot n + j$ 直接二分，$O(\log mn)$。本题行间无此约束：第 0 行的 15 大于第 1 行的 2，拼接后 `[1,4,7,11,15,2,...]` 并不单调，一维二分的前提崩塌。**矩阵搜索的复杂度差别完全取决于"有序"的强度**：行单调（+行间链）$\Rightarrow O(\log mn)$；行列双单调 $\Rightarrow O(m+n)$；无序 $\Rightarrow O(mn)$。

**疑问二：分治（四象限切分）是怎么回事，值不值得写？**

官方题解给出过一种分治：取中点元素，把矩阵划成四个象限，由中点值与 target 的大小关系可删掉一个象限，递归搜剩下三个。递推式 $T(n) = 3T(n/2) + O(1)$（方形时按对角计），解得约 $O(n^{1.58})$，即 $O((mn)^{0.79})$ 量级。它在理论上不如 $O(m+n)$（$m = n$ 时 $m + n = 2n$），实现却复杂得多——属于"能做、但不值得"的路线，了解思想即可：**分治的本质也是每层舍弃确定无解的区域**，与阶梯搜索是同一思想的不同切法。

**疑问三：起点选左上角或右下角为什么不行？**

左上角 $matrix[0][0]$ 既是所在行的最小值、又是所在列的最小值。若它小于 target，行和列**两边都可能有解**，无法二选一删除；大于 target 时倒是能直接判定全矩阵无解（所有元素 $\ge$ 它），但这种一次性的运气帮不上平均情形。右下角对称。只有右上角/左下角这种"一行之最与一列之最身份相反"的位置，才能保证**每次比较必然淘汰一行或一列**。面试遇到此类矩阵，先找"角上元素具有方向相反的两个最值身份"的位置。

## 6. 相关题目与模板

**可复用模板**（行列双单调矩阵的搜索骨架）：

```cpp
// 右上角出发；条件反过来（< / >）或换左下角即可适配变体
int i = 0, j = n - 1;
while (i < m && j >= 0) {
    if (matrix[i][j] == target) return true;
    matrix[i][j] > target ? j-- : i++;
}
return false;
```

**方法论总结**：在"部分有序"的结构里搜索，关键是**找到一个判据，让每次比较都能安全地扔掉一块确定无解的区域**。本题右上角的"行最大 + 列最小"双重身份就是这样的判据；同样思想在别处反复出现——旋转有序数组二分（扔掉有序的一半）、240 的分治解法（扔掉一个象限）、169 多数元素（摩尔投票的抵消）。
