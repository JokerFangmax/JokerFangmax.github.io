# LeetCode 131. 分割回文串

> 题目链接：[https://leetcode.cn/problems/palindrome-partitioning/](https://leetcode.cn/problems/palindrome-partitioning/)  
> 难度：中等  
> 标签：字符串、动态规划、回溯

---

## 1. 题目描述

给定一个字符串 `s`，请将 `s` **分割**成若干子串，使每个子串都是**回文串**。返回 `s` 所有可能的分割方案。答案中可以按任意顺序返回，每个子串都必须是 `s` 中**连续**的一段。

例如 `s = "aab"` 可以分割成 `["aa","b"]` 或 `["a","a","b"]`，两者都满足每段皆回文；但 `["a","ab"]` 不行——`"ab"` 不是回文。

**数据范围：**

- $1 \le s.length \le 16$
- `s` 仅由小写英文字母组成

**示例：**

```
输入：s = "aab"
输出：[["a","a","b"],["aa","b"]]

输入：s = "a"
输出：[["a"]]
```

---

## 2. 思路分析

### 2.1 建模：分割就是"在缝隙上做决策"

长度为 $n$ 的串有 $n - 1$ 个相邻缝隙，每个缝隙"切"或"不切"，因此全部分割方式共 $2^{n-1}$ 种。把分割看成决策过程：从下标 $0$ 出发，选定第一段长度，段尾必须是某个下标 $j$（且 $s[0..j]$ 是回文），然后从 $j+1$ 继续决定第二段……直到下标越过 $n-1$。

又是熟悉的**回溯 (backtracking)** 形状：路径是已切出的段，每一步的候选是"下一个切到哪里"。与组合总和不同的是，这里的约束不是"和等于 target"，而是**每一段必须回文**——不回文的切法当场剪掉。

### 2.2 版本一：现切现判，回文检查拖了后腿

最直接的写法：递归里枚举段尾 $j$，用双指针 $O(n)$ 判断 `s[i..j]` 是否回文，是则切段递归。问题在于同一个子串会被反复检查——`"aaa...a"` 这种数据下，区间 $[i, j]$ 在不同路径里被反复询问，单次 $O(n)$ 的判断乘上指数级路径数，浪费明显。

### 2.3 版本二：动态规划预处理，回文判断降到 $O(1)$

注意到**"s[i..j] 是否回文"这一事实与切分路径无关**——它是字符串的静态属性，总共只有 $O(n^2)$ 个区间。静态、可复用、有递推结构，正是**动态规划 (dynamic programming)** 预处理的适用信号。

递推式（中心扩展的区间版本）：

$$isPal[i][j] = \big(s[i] = s[j]\big) \wedge \big(j - i < 3 \ \vee\ isPal[i+1][j-1]\big)$$

含义：两端字符相等，且（段长 $\le 3$，此时中间至多一个字符，天然成立；或）去掉两端后仍是回文。计算顺序按**区间长度从小到大**，保证查 $isPal[i+1][j-1]$ 时它已算好。

以 `s = "aabba"` 为例（`T`/`F` 表示回文与否）：

| 区间 | 长度 | 两端相等？ | 依赖的内部区间 | 结论 |
|------|------|-----------|---------------|------|
| `[a,a]` (0..1) | 2 | 是 | —（长度 $\le 3$ 免查） | T |
| `[a,b]` (1..2) | 2 | 否 | — | F |
| `[a,b]` (0..2) | 3 | 否（`s[0]='a'` vs `s[2]='b'`） | — | F |
| `[b,b]` (2..3) | 2 | 是 | — | T |
| `[a,a]` (1..4) `"abba"` | 4 | 是 | `[b,b]` (2..3) = T | T |
| `[a,a]` (0..4) `"aabba"` | 5 | 是 | `[a,b]` (1..3) = F | F |

之后递归中任何"这段是不是回文"的询问都只是一次数组下标访问。

### 2.4 逐步走一遍：s = "aab"（用预处理表）

预处理结论：`"a"`、`"a"`、`"b"`、`"aa"` 是回文，`"ab"`、`"aab"` 不是。

```
dfs(0)                          ← 从下标 0 出发切第一段
├─ j=0：s[0..0]="a" 回文 ✓     path=["a"]
│   └─ dfs(1)
│       ├─ j=1："a" ✓          path=["a","a"]
│       │   └─ dfs(2)
│       │       └─ j=2："b" ✓  path=["a","a","b"] → 到末尾，收集 ✓
│       └─ j=2："ab" ✗ 剪掉
├─ j=1：s[0..1]="aa" 回文 ✓    path=["aa"]
│   └─ dfs(2)
│       └─ j=2："b" ✓          path=["aa","b"] → 收集 ✓
└─ j=2：s[0..2]="aab" ✗ 剪掉
```

两条活路径收获 `["a","a","b"]` 与 `["aa","b"]`，与示例输出一致。注意剪枝的意义：`j=2` 的分支在第一层就被表查杀，它下面挂着的整棵子树（比如把 `"ab"` 再切出的所有后续）无需考虑。

## 3. 代码实现

```cpp
class Solution {
    vector<vector<string>> ans;
    vector<string> path;
    vector<vector<bool>> isPal;

    void dfs(const string& s, int i) {
        if (i == (int)s.size()) {          // 切完整串，收获一种方案
            ans.push_back(path);
            return;
        }
        for (int j = i; j < (int)s.size(); j++) {
            if (!isPal[i][j]) continue;    // 非回文的段尾，剪掉
            path.push_back(s.substr(i, j - i + 1));   // 切出 s[i..j]
            dfs(s, j + 1);                 // 从下一段继续切
            path.pop_back();               // 撤销，换下一个段尾
        }
    }

public:
    vector<vector<string>> partition(string s) {
        int n = s.size();
        isPal.assign(n, vector<bool>(n, false));
        for (int len = 1; len <= n; len++)             // 按区间长度递推
            for (int i = 0; i + len - 1 < n; i++) {
                int j = i + len - 1;
                isPal[i][j] = (s[i] == s[j]) &&
                              (j - i < 3 || isPal[i + 1][j - 1]);
            }
        dfs(s, 0);
        return ans;
    }
};
```

三个细节：

1. **递推按 `len` 从小到大**：$isPal[i][j]$ 依赖更短的区间 $isPal[i+1][j-1]$，长度循环在外层保证依赖先算好；`j - i < 3`（长度 $\le 3$）时中间至多一个字符，两端相等即可下结论，避免 $i+1 > j-1$ 的无效下标；
2. **回溯里的段用 `substr(i, j-i+1)` 现取**：$n \le 16$，段长很小，没必要存下标最后再统一展开；
3. `dfs` 的参数是起点 $i$ 而不是携带剩余字符串——传下标让 `path` 与递归栈一一对应，也方便查 $isPal[i][j]$。

## 4. 复杂度分析

- **时间复杂度**：$O(n \cdot 2^n)$。分割方式至多 $2^{n-1}$ 种，每种方案切满 $n$ 个单字符段时路径最长，拷贝答案还要 $O(n)$；预处理 $O(n^2)$ 完全被吞没。回文判断若不预处理，最坏会多乘一个 $n$ 变成 $O(n^2 \cdot 2^n)$。
- **空间复杂度**：$O(n^2)$（不计输出）。$isPal$ 表占 $n^2$；递归深度与 `path` 长度之和不超过 $n$。

## 5. 常见疑问

**Q1：为什么不用 DP 直接"算出"所有方案？**

动态规划擅长的是**最值与计数**——比如本题的姊妹题 132（分割回文串的最少切割次数），$O(n^2)$ 就能出答案。但本题要求**列出所有方案**，方案总数本身就是 $2^{n-1}$ 级别，谁来算都逃不开把每个方案写出来一遍，指数是**解空间的天花板**而不是算法的锅。所以正确的分工是：**预处理用 DP（区间回文表），枚举用回溯**——DP 负责把"查询"变便宜，回溯负责把"路径"走出来。

**Q2：递推式里 `j - i < 3` 是什么意思，为什么不是 `j - i < 2`？**

`j - i` 是区间长度减一。$j - i < 3$ 即长度 $\le 3$：长度 1 是单字符，恒回文；长度 2 两端相等即回文；长度 3 两端相等、中间单字符随便，也必回文。这三种情形都不必依赖更短的区间——更关键的是，长度 1、2 时内部区间 $[i+1, j-1]$ 根本不存在（$i + 1 > j - 1$），去查它会下标越界，必须短路保护。从长度 4 起内部区间非空且已算好，才真正用上 $isPal[i+1][j-1]$。写成 `j - i < 2` 会让长度 3 的区间去查单字符的 $isPal[i+1][i+1]$——碰巧也正确（单字符必为真），但多一次查表且初学者容易忽略下标交叉的隐患。

**Q3：回溯枚举段尾 $j$ 时，"剪掉一个 $j$"到底剪掉了多少？**

剪的是**以 $s[0..j]$ 为第一段的一切延续**——子树整棵，而不是一条边。例如 2.4 中 `s[0..2]="aab"` 不是回文，第一段若是它就没有任何合法方案，它下面可能挂着的所有后续切法全部作废。这正是"构造时约束"（对照生成后过滤）的价值：非法的前缀越早识别，省下的搜索量越大。极端好数据（如全同字符）所有前缀皆回文、剪枝不省事，但答案数本身也到达上界。

## 6. 相关题目与模板

**可复用模板**（区间回文表 + 分割回溯）：

```cpp
// 1. DP 预处理：isPal[i][j] 表示 s[i..j] 是否回文
for (int len = 1; len <= n; len++)
    for (int i = 0; i + len - 1 < n; i++) {
        int j = i + len - 1;
        isPal[i][j] = (s[i] == s[j]) && (j - i < 3 || isPal[i+1][j-1]);
    }

// 2. 回溯枚举分割
void dfs(int i) {
    if (i == n) { ans.push_back(path); return; }
    for (int j = i; j < n; j++) {
        if (!isPal[i][j]) continue;      // 段必须回文
        path.push_back(s.substr(i, j - i + 1));
        dfs(j + 1);
        path.pop_back();
    }
}
```

`isPal` 表可复用于一切"回文 + 区间"题：最少切割、最长回文子串（改中心扩展）、回文分割 IV（分成三段）都直接查表。

**同类题目：**

- [LeetCode 132. 分割回文串 II](https://leetcode.cn/problems/palindrome-partitioning-ii/)：同一张 $isPal$ 表，只问最少切几刀——回溯换 DP 的典型，可对照 Q1
- [LeetCode 5. 最长回文子串](https://leetcode.cn/problems/longest-palindromic-substring/)：区间 DP / 中心扩展求最值
- [LeetCode 93. 复原 IP 地址](https://leetcode.cn/problems/restore-ip-addresses/)：同为"枚举切点 + 段约束"的回溯，约束从回文换成 IP 格式
- [LeetCode 139. 单词拆分](https://leetcode.cn/problems/word-break/)：分割 + 字典判定，只问可行性，是 DP 的主场

**一句话总结**：这道题是 **DP 与回溯的分工样本**——静态的区间回文交给动态规划 $O(n^2)$ 离线算好，动态的方案枚举交给回溯走树，两者组合把指数只花在真正不可省的解空间上。
