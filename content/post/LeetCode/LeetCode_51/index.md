# LeetCode 51. N 皇后

> 题目链接：[https://leetcode.cn/problems/n-queens/](https://leetcode.cn/problems/n-queens/)  
> 难度：困难  
> 标签：数组、回溯

---

## 1. 题目描述

按照国际象棋规则，皇后可以攻击与它**同行**、**同列**以及**同一对角线**上的任意棋子。现在要在 $n \times n$ 的棋盘上放 $n$ 个皇后，使得她们两两互不攻击，返回**所有可行的摆放方案**。

每个方案用一个长度为 $n$ 的字符串数组表示，第 $i$ 行的字符串里只有第 $queens[i]$ 列是 `Q`，其余是 `.`。

**数据范围：**

- $1 \le n \le 9$

**示例：**

```
输入：n = 4

输出：[[".Q..","...Q","Q...","..Q."],
       ["..Q.","Q...","...Q",".Q.."]]

解释：4 皇后恰好有 2 个解。第 1 个解的皇后坐标为
      (0,1), (1,3), (2,0), (3,2)，
      任意两个皇后都不同行、不同列、不同对角线。
```

---

## 2. 思路分析

### 2.1 暴力：枚举每一行的所有摆法

$n$ 行棋盘，每行有 $n$ 种列选择，朴素枚举是 $n^n$ 种组合，再对每种组合做 $O(n^2)$ 的两两冲突检查。$n = 9$ 时 $9^9 \approx 3.9 \times 10^8$，加上检查开销必然超时。

但暴力里藏着两个关键的观察：

1. **同一行不可能有两个皇后**（否则立即互相攻击）。既然每行恰好放一个，解的形态天然是"第 $i$ 行的列号 $queens[i]$"——枚举空间从 $n^n$ 个格子选择压缩成"每行选一列"；
2. 大量组合在**前几行就已经冲突**，却仍被完整枚举到最后一行——这是纯粹的浪费。

### 2.2 回溯：冲突出现的那一刻就掉头

**回溯 (backtracking)** 的思路由此自然浮现：按行从上到下决策，在第 $i$ 行尝试第 $c$ 列时，如果与前面已放的皇后冲突，就**立即放弃这一整棵子树**，换下一列尝试。这相当于把暴力枚举剪掉了一大截——不在冲突状态上继续浪费任何一步。

递归树长这样（$n = 4$，只展开前两层）：

```
第 0 行选列 0 ── 第 1 行选列 2 ── 第 2 行选列 ? ── ... （继续）
            └─ 第 1 行选列 3 ── 与后续组合后发现无解，回溯
第 0 行选列 1 ── ...（最终产生一个完整解）
第 0 行选列 2 ── ...
第 0 行选列 3 ── ...
```

**放置合法性的判定**是本题的核心。设已放的皇后坐标为 $(r_1, c_1)$，新皇后放在 $(r, c)$：

| 冲突类型 | 判定条件 | 说明 |
|---------|---------|------|
| 同列 | $c_1 = c$ | 每行只放一个，同列冲突是回溯中唯一可能的行列类冲突 |
| 主对角线 (\) | $r - c = r_1 - c_1$ | 同一条 "\" 方向对角线上，行号减列号是常数 |
| 副对角线 (/) | $r + c = r_1 + c_1$ | 同一条 "/" 方向对角线上，行号加列号是常数 |

同列可以简单地把已用列记成布尔数组；对角线如果每次都去遍历前面所有行，判定是 $O(n)$ 的——能过，但可以更快。

### 2.3 用三个布尔数组把判定降到 $O(1)$

对角线的两个不变量是关键： "\" 对角线由 $r - c$ 唯一确定，"/" 对角线由 $r + c$ 唯一确定。于是开三个标记数组：

- `col[c]`：第 $c$ 列是否已有皇后；
- `diag1[r - c + n - 1]`：编号为 $r - c$ 的 "\" 对角线是否被占（加上 $n-1$ 是为了把值域 $[-(n-1), n-1]$ 平移到非负下标）；
- `diag2[r + c]`：编号为 $r + c$ 的 "/" 对角线是否被占。

放置 $(r, c)$ 前查三个数组，全部为 false 才放，放置时置 true，回溯时还原为 false。判定从"扫一遍前面所有行"变成三次数组访问。

### 2.4 以 $n = 4$ 走一遍关键步骤

只展示通向第一个解 `[".Q..","...Q","Q...","..Q."]` 的路径：

| 行 $r$ | 尝试的列 $c$ | col/diag1/diag2 检查 | 结果 |
|-------|-------------|---------------------|------|
| 0 | 0 | 通过，放置 (0,0) | 但后续全部失败，最终回溯 |
| 0 | 1 | 通过，放置 (0,1) | 进入第 1 行 |
| 1 | 0 | col[0] 闲但 diag2[1] 被 (0,1) 占 | 冲突，跳过 |
| 1 | 1 | col[1] 已占 | 冲突，跳过 |
| 1 | 2 | diag2[3] 被 (0,1) 占（$0+1 = 1+2$） | 冲突，跳过 |
| 1 | 3 | 三项全闲 | 放置 (1,3)，进入第 2 行 |
| 2 | 0 | 三项全闲 | 放置 (2,0)，进入第 3 行 |
| 3 | 0,1 | 冲突 | 跳过 |
| 3 | 2 | 三项全闲 | 放置 (3,2)，$r = n$，收集一个解 |

收集后逐层撤销，继续尝试其他分支，最终得到 2 个解。

## 3. 代码实现

```cpp
class Solution {
    vector<vector<string>> ans;
    vector<int> queens;          // queens[r] = 第 r 行皇后所在列
    vector<bool> col, diag1, diag2;

    void backtrack(int r, int n) {
        if (r == n) {            // 所有行都成功放置，收集一个解
            vector<string> board(n, string(n, '.'));
            for (int i = 0; i < n; i++) board[i][queens[i]] = 'Q';
            ans.push_back(board);
            return;
        }
        for (int c = 0; c < n; c++) {
            int d1 = r - c + n - 1, d2 = r + c;
            if (col[c] || diag1[d1] || diag2[d2]) continue;  // O(1) 冲突判定
            // 放置
            queens[r] = c;
            col[c] = diag1[d1] = diag2[d2] = true;
            backtrack(r + 1, n);
            // 撤销（回溯的"回"就体现在这里）
            col[c] = diag1[d1] = diag2[d2] = false;
        }
    }

public:
    vector<vector<string>> solveNQueens(int n) {
        queens.assign(n, 0);
        col.assign(n, false);
        diag1.assign(2 * n - 1, false);   // r - c + n - 1 的范围是 [0, 2n-2]
        diag2.assign(2 * n - 1, false);   // r + c 的范围是 [0, 2n-2]
        backtrack(0, n);
        return ans;
    }
};
```

几个实现细节：

1. **按行递归天然保证了不同行**，所以冲突判定里根本不需要检查"同行"——这是选择按行搜索维度免费换来的简化；
2. **对角线数组开 $2n - 1$ 长度**。$r - c$ 的值域是 $[-(n-1), n-1]$，平移后 $r - c + n - 1$ 落在 $[0, 2n-2]$；$r + c$ 本身就在 $[0, 2n-2]$；
3. **撤销必须与放置严格对称**。写对称式代码（放置一行、撤销一行）是最不容易漏的方式。

## 4. 复杂度分析

- **时间复杂度**：上界 $O(n!)$（第一行 $n$ 列可选，第二行至多 $n-1$ 列不冲突，依此类推）。实际的解数量增长远慢于阶乘（$n = 8$ 时解只有 92 个，而 $8! = 40320$），剪枝把绝大部分分支拦在了浅层。构造每个解的字符串另花 $O(n^2)$。
- **空间复杂度**：$O(n)$（递归栈深度、`queens` 与三个标记数组；不计输出）。输出最坏要存 $O(n!)$ 个方案，每个 $O(n^2)$ 字符。

对比：朴素枚举 $n^n$ → 逐行回溯 $O(n!)$ 级别 → 本实现带 $O(1)$ 冲突判定，是工程上能做到的实用最优（N 皇后不存在多项式算法枚举所有解，因为解的数量本身就可以是指数级的）。

## 5. 常见疑问

**疑问一：为什么对角线可以用 $r - c$ 和 $r + c$ 编号？**

把 "\" 方向上的格子列出来：$(0,0), (1,1), (2,2)$——每个格子 $r = c$；再看 $(0,2), (1,3), (2,4)$——每个格子 $r - c = -2$。同一条 "\" 对角线上行号每加 1、列号也加 1，所以 $r - c$ 不变。"/" 方向同理，行号加 1、列号减 1，$r + c$ 不变。反过来，$r - c$ 相同的两个格子一定在同一条 "\" 对角线上，所以这个量可以当对角线的"身份证"用。

**疑问二：为什么不用一个 `set` 或者每次循环检查前面的行？**

可以，也能通过本题（$n \le 9$ 太小了）。但循环检查的判定是 $O(r)$，哈希 `set` 是 $O(1)$ 但常数大。三个布尔数组是最快的写法，更重要的是它**把"冲突"这个概念显式地拆成了三个独立维度**，代码想错都难——面试里清晰的维度拆分比抠那点常数更有价值。

**疑问三：回溯的"撤销"忘了写会怎样？**

症状是解的数量**变少**而不是变多：某条分支放置后标记没还原，后续兄弟分支会被误判为冲突，整个子树被错误剪掉。这是回溯题最隐蔽的 bug——程序不崩溃、不报错，只是答案悄悄不对。对称式地写"放置三行、撤销三行"可以最大程度避免。

## 6. 相关题目与模板

**可复用模板**（回溯三板凳：选择、递归、撤销）：

```cpp
// 通用骨架：在每层枚举"当前还可以做的选择"
void backtrack(状态) {
    if (满足结束条件) { 收集结果; return; }
    for (auto& 选择 : 当前可选列表) {
        做选择;          // 修改状态（本题：三个标记置 true）
        backtrack(下一状态);
        撤销选择;        // 精确还原状态
    }
}
```
