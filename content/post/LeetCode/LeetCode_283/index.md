# LeetCode 283. 移动零

> 题目链接：[https://leetcode.cn/problems/move-zeroes/](https://leetcode.cn/problems/move-zeroes/)  
> 难度：简单  
> 标签：数组、双指针

---

## 1. 题目描述

给定一个整数数组 `nums`，编写函数将**所有 `0` 移动到数组的末尾**，同时保持**非零元素的相对顺序**。

要求：

1. **原地 (in-place)** 操作——不能拷贝数组，空间 $O(1)$；
2. 最小化操作次数（指元素写入/交换的总次数）。

**数据范围：**

- $1 \le nums.length \le 10^4$
- $-2^{31} \le nums[i] \le 2^{31} - 1$

**示例：**

```
输入：nums = [0,1,0,3,12]
输出：[1,3,12,0,0]

输入：nums = [0]
输出：[0]
```

注意负数也是非零元素，同样要保持相对顺序；数组里也可能一个零都没有。

---

## 2. 思路分析

### 2.1 暴力：开新数组

最容易想到的做法：扫一遍，把非零元素按序写进新数组，末尾补零，再拷回去。时间 $O(n)$，正确性显然——但它**不满足原地要求**，$O(n)$ 的辅助空间直接违反了题目约束。

不过这个暴力里藏着一个重要观察：**输出的前半段就是"非零元素按原相对顺序排好"，后半段全是零**。既然结构这么规整，值得追问：非零元素能不能在原数组上"就地归位"？

### 2.2 归位的本质：把非零元素前移，零自然沉底

换个视角看这道题：它其实是一次**划分 (partition)**——把数组划分成"非零区"和"零区"两段，且非零区内保持稳定。这和快排的 partition 像极了，区别在于快排划分不要求稳定，而这里要求非零元素**相对顺序不变**。

于是自然的想法：**用一个写指针维护"已就位的非零区"的边界**——

- `slow`：永远指向"下一个非零元素应该放的位置"，即 $[0, slow)$ 是已就位的非零区；
- `fast`：向后扫描寻找非零元素。

`fast` 每遇到一个非零元素，就把它写到 `slow` 位置，`slow++`。扫完后 $[slow, n)$ 全部置零即可。

### 2.3 为什么零不用刻意"搬"？——雪球法与交换法的等价性

上面的做法分两步：先搬运非零元素，再统一填零。还有一种一步到位的**交换 (swap) 写法**：`fast` 遇到非零元素时直接 `swap(nums[slow++], nums[fast])`，把挡路的零换到后面去。

两种写法为什么等价？关键在于：**当 `fast` 遇到非零元素时，若 $[slow, fast)$ 之间存在零，`nums[slow]` 一定是个零**（否则它早就被搬到 `slow` 之前了）；若中间没有零，则 $slow = fast$，交换是自己和自己换，无副作用。所以每次交换都精确地把一个零往后挪、一个非零元素往前挪。

用 `nums = [0,1,0,3,12]` 走一遍交换法：

| fast | nums[fast] | 动作 | 数组状态 | slow |
|------|-----------|------|--------------------------|------|
| 0    | 0         | 跳过 | [0,1,0,3,12]             | 0    |
| 1    | 1         | 换 0↔1 | [1,0,0,3,12]            | 1    |
| 2    | 0         | 跳过 | [1,0,0,3,12]             | 1    |
| 3    | 3         | 换 0↔3 | [1,3,0,0,12]            | 2    |
| 4    | 12        | 换 0↔12 | [1,3,12,0,0]           | 3    |

结束时 $[0, 3)$ 是非零区 `[1,3,12]`（相对顺序保持），$[3, 5)$ 是零区，答案正确。

**两种写法的取舍**：

| 写法 | 写入次数（最坏） | 优点 | 缺点 |
|------|------------------|------|------|
| 覆盖 + 尾部填零 | 非零各写 1 次 + 零各填 1 次 | 思路直白 | 扫完后还要补一轮置零 |
| 交换法 | 每个非零元素 1 次交换（3 次赋值） | 一趟完成，无补零 | 零很少时做了大量"自交" |

最坏情况下（全是非零），覆盖法写 $n$ 次，交换法做 $n$ 次自交（$3n$ 次赋值），覆盖法更省写操作；但交换法代码更短、一遍循环。$n \le 10^4$ 规模下两者都远在时限内，按口味选即可。

## 3. 代码实现

```cpp
// 写法一: 交换法（两个 class Solution 二选一提交）
class Solution {
public:
    void moveZeroes(vector<int>& nums) {
        int slow = 0;                          // [0, slow) 是已就位的非零区
        for (int fast = 0; fast < (int)nums.size(); fast++) {
            if (nums[fast] != 0) {
                if (fast != slow) {            // 有零挡路才需要真的交换
                    swap(nums[slow], nums[fast]);
                }
                slow++;                        // 非零区右扩一格
            }
        }
    }
};

// 写法二: 覆盖 + 尾部填零
// class Solution {
// public:
//     void moveZeroes(vector<int>& nums) {
//         int slow = 0;
//         for (int x : nums)
//             if (x != 0) nums[slow++] = x;    // 非零元素依次前移
//         while (slow < (int)nums.size())
//             nums[slow++] = 0;                // 尾部统一填零
//     }
// };
```

几个实现细节：

1. **`if (fast != slow)` 的守卫**：零很少（或开头一段全非零）时 `fast == slow`，交换是白做的。加上判断后，只有"真的搬零"才动手，最坏写入次数从 $3n$ 降到必要操作数。
2. **稳定性自动保持**：非零元素按 `fast` 从小到大的顺序依次写入 `slow` 位置，先后关系不会被破坏——这正是与快排 partition 的本质区别。
3. `(int)nums.size()`：避免有符号/无符号比较的编译警告，纯习惯。
4. **写法二（注释掉的第二版）**更直白：非零元素依次前移覆盖，扫完后 $[slow, n)$ 统一置零。两法复杂度相同，按口味选。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。`fast` 单趟扫描，`slow` 单调右移，每个元素至多被读写常数次。
- **空间复杂度**：$O(1)$。只用了两个下标，原地完成。

这已经是理论最优：每个元素至少要看一眼才能判断是否为零，$\Omega(n)$ 的时间下界摆在那里。

## 5. 常见疑问

**疑问一：能不能用稳定排序做？** 可以——自定义比较器"零视为最大，其余保持原序"，用 `stable_sort` 一行也能过。但稳定排序是 $O(n \log n)$，且引入"把零当成大元素"的思维绕路，远不如双指针干净。面试中这样答会被追问稳定性从哪来，不如直接讲写指针。

**疑问二：为什么 `fast` 遇到非零元素时 `nums[slow]` 要么是零、要么就是它自己？** 归纳一下：`slow` 只在写入非零元素后自增，所以 $[slow, fast)$ 这段里被跳过的元素全是零。若这段长度为 0，则 $slow = fast$（自交）；否则 `nums[slow]` 是这段零的第一个（交换有效）。这也解释了为什么交换法**天然不会打乱顺序**：非零元素被写入的顺序就是它们被 `fast` 发现的顺序。

**疑问三：如果题目改成"把奇数移到前面、偶数移到后面，不要求稳定"呢？** 那就退化成经典的双路 partition（头尾指针对撞，见 [LeetCode 977](https://leetcode.cn/problems/squares-of-a-sorted-array/)、[75. 颜色分类](https://leetcode.cn/problems/sort-colors/)）。**"要求保持相对顺序"恰恰是本题必须用快慢指针 (fast-slow pointers)、不能用对撞指针的原因**——对撞指针会颠倒一侧元素的顺序。

## 6. 相关题目与模板

**可复用模板**（快慢双指针原地划分骨架）：

```cpp
// 把满足谓词 p 的元素稳定地移到数组前段
int slow = 0;
for (int fast = 0; fast < n; fast++) {
    if (p(nums[fast])) {
        swap(nums[slow], nums[fast]);   // 快慢重合时是无害的自交
        slow++;
    }
}
// [0, slow) 即为满足条件的稳定前缀
```

这个骨架的适用信号：**"原地 + 保持相对顺序 + 把元素分成两类"**。

**同类题目：**

- [LeetCode 26. 删除有序数组中的重复项](https://leetcode.cn/problems/remove-duplicates-from-sorted-array/)：同款快慢指针，`slow` 维护"无重复区"边界，本题可视为它的变体（把"删除"变成"沉底"）
- [LeetCode 27. 移除元素](https://leetcode.cn/problems/remove-element/)：删除所有值为 `val` 的元素——就是本题去掉"尾部补零"的裸版
- [LeetCode 80. 删除有序数组中的重复项 II](https://leetcode.cn/problems/remove-duplicates-from-sorted-array-ii/)：允许重复两次的版本，写指针思想不变
- [LeetCode 905. 按奇偶排序数组](https://leetcode.cn/problems/sort-array-by-parity/)：不要求稳定时可用对撞双指针对比理解

**一句话总结**：移动零的本质是**稳定划分**——用一个写指针圈住"已就位的非零区"，读指针扫到的每个非零元素都被送进圈内，零自然全部沉底。
