# LeetCode 55. 跳跃游戏

> 题目链接：[https://leetcode.cn/problems/jump-game/](https://leetcode.cn/problems/jump-game/)  
> 难度：中等  
> 标签：贪心、数组

---

## 1. 题目描述

给你一个非负整数数组 `nums`，最初位于第一个下标。数组中每个元素代表在该位置可以跳跃的**最大**长度（可以少跳，跳 1 到 `nums[i]` 步都行）。判断你是否能够到达最后一个下标。

**数据范围：**

- $1 \le nums.length \le 10^4$
- $0 \le nums[i] \le 10^5$

**示例：**

```
输入：nums = [2,3,1,1,4]
输出：true
解释：先跳 1 步到下标 1，再跳 3 步到下标 4（最后一个下标）。

输入：nums = [3,2,1,0,4]
输出：false
解释：无论怎么跳，最多只能到达下标 3（值为 0，无法继续），永远到不了下标 4。
```

---

## 2. 思路分析

### 2.1 暴力：从每个位置向后连边，图上搜索

把每个下标看成点，从 $i$ 向 $i+1, \dots, i + nums[i]$ 各连一条有向边，问题变成：从 $0$ 出发能否到达 $n - 1$。深度优先搜索或广度优先搜索均可，但边数最坏 $O(n^2)$ 条（如 `nums[i]` 都很大时），$n = 10^4$ 意味着上亿条边，太慢；朴素 DFS 还会重复访问同一状态，需要记忆化。

换个角度想：我们其实不关心"走哪条路"，只关心"最远能走多远"。

### 2.2 关键观察：可达集合是一段连续区间

若当前已知可达区间是 $[0, R]$，那么从区间内任一点 $i$ 出发，可达范围立刻扩展为 $[0, \max(R,\; i + nums[i])]$——注意中间没有任何空洞，因为从 $i$ 可以跳 $1, 2, \dots, nums[i]$ 步中的任意步数，覆盖了 $i$ 到 $i + nums[i]$ 的**每一个**下标。

于是维护一个变量 `farthest`（最远可达下标），从左往右扫描：

- 若当前下标 $i > \text{farthest}$：$i$ 本身不可达，它后面的更无从谈起，直接返回 `false`；
- 否则用 $i + nums[i]$ 更新 `farthest`；
- 若 `farthest >= n - 1`，提前返回 `true`。

这就是**贪心 (greedy)**：不记录路径、不区分走法，只保留唯一的聚合信息"最远能到哪"。

### 2.3 贪心为什么是对的

需要证明"维护 `farthest` 的判定"与"真实可达性"等价。

- **可行性传递（不会误报 true）**：`farthest` 的每次扩张都来自某个可达点的跳跃，归纳可知 $[0, \text{farthest}]$ 内每个下标确实可达；所以 `farthest >= n - 1` 蕴含终点可达。
- **不会漏报（不会误报 false）**：反设算法在 $i > \text{farthest}$ 时判 `false`，但终点其实可达。那么从 $0$ 到 $n-1$ 的任一条可达路径必然经过某个 $j > \text{farthest}$ 的下标，且该点从某个 $\le \text{farthest}$ 的点跳来——但那样 `farthest` 就应该覆盖 $j$，矛盾。故 `farthest` 停住即真不可达。

另外，由于可达区间连续，这道题也能用动态规划 $O(n^2)$ 做（`dp[i]` 表示 $i$ 是否可达），但贪心把整段区间的信息压缩成一个数，做到 $O(n)$——**贪心可行往往正是因为问题具有这种"区间连续、可以合并"的单调结构**。

### 2.4 手动模拟（两个示例各走一遍）

`nums = [2,3,1,1,4]`：

| $i$ | $nums[i]$ | $i + nums[i]$ | 更新前 farthest | 更新后 farthest | 说明 |
|---|---|---|---|---|---|
| 0 | 2 | 2 | 0 | **2** | 从 0 可到 1、2 |
| 1 | 3 | 4 | 2 | **4** | 从 1 可到 2、3、4 |
| — | — | — | 4 | — | $4 \ge n-1 = 4$，返回 true |

`nums = [3,2,1,0,4]`：

| $i$ | $nums[i]$ | $i + nums[i]$ | 更新前 farthest | 更新后 farthest | 说明 |
|---|---|---|---|---|---|
| 0 | 3 | 3 | 0 | **3** | 可到 1、2、3 |
| 1 | 2 | 3 | 3 | 3 | 没有超越 3 |
| 2 | 1 | 3 | 3 | 3 | 仍然停在 3 |
| 3 | 0 | 3 | 3 | 3 | 下标 3 是"坑"，值为 0 |
| 4 | — | — | 3 | — | $4 > 3$，不可达，返回 false |

## 3. 代码实现

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int n = nums.size();
        int farthest = 0;              // 当前已确认可达的最远下标
        for (int i = 0; i < n; i++) {
            if (i > farthest)          // 扫描指针已越过可达边界：
                return false;          //   i 本身到不了，后面全部失守
            farthest = max(farthest, i + nums[i]);   // 尝试扩张边界
            if (farthest >= n - 1)     // 边界已罩住终点，提前成功
                return true;
        }
        return true;                   // n == 1 时起点即终点
    }
};
```

实现细节：

1. **先判 `i > farthest` 再更新**。顺序颠倒的话，不可达的 $i$ 会用自己的 `nums[i]` 虚假扩张边界——一个到不了的位置怎么能往外跳呢？
2. **循环内的提前返回**只是加速；即使删掉 `farthest >= n - 1` 的判断、靠循环结束返回 `true`，正确性也不受影响（因为 `farthest >= n - 1` 时全程不会有 `i > farthest`）。保留它是 $O(1)$ 的好习惯。
3. $n = 1$ 时起点就是终点，`farthest = 0` 已覆盖，循环第一轮即返回 `true`，无需特判。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。单层扫描，每个下标常数次操作；多数用例会在中途提前返回。
- **空间复杂度**：$O(1)$。只有 `farthest` 一个核心变量。

对比：图搜索 / DP $O(n^2)$ → 贪心 $O(n)$。信息从"每个点是否可达"压缩为"最远可达下标"，是典型的以问题结构换复杂度。

## 5. 常见疑问

**Q1：为什么遇到 `nums[i] == 0` 不用特判？**

很多人第一反应是"遇到 0 就死"。但 0 是否致命取决于**它前面能把边界推多远**：`[3,0,2]` 中下标 1 是 0，可下标 0 一步就能直接跨到 2，0 只是路过。真正致命的情形是"$0$ 后面的所有点都推不动边界"，而这种情况被统一表达为 `i > farthest`——特判 0 反而画蛇添足且容易漏。

**Q2：倒着扫（从终点往前找"能一步跳到终点的最近点"）为什么也行？**

倒序维护"目标位置 `last`"：若 $i + nums[i] \ge last$，则 $i$ 也能作为新目标，`last = i`；最终 `last == 0` 即 true。正确性与正序同理，只是把"最远可达"换成了"最近起点"。两种写法都是 $O(n)$，正序版本更容易推广到 [LeetCode 45](https://leetcode.cn/problems/jump-game-ii/)（求最少步数），建议以正序为主。

**Q3：如果 `nums[i]` 可能为负呢？**

那本题的"区间连续"性质就塌了——负跳跃会产生回头路，可达集合不再是一段前缀区间，贪心失效，只能回到图搜索（此时还要小心负权导致的循环）。幸运的是题目保证 $0 \le nums[i]$，扫描一遍即可。这个思考的价值在于提醒自己：**贪心的成立依赖输入满足的前提**，抄解法前先确认前提还在。

// 维护最远可达边界；改成"最少步数"版本见 LeetCode 45

    if (i > farthest) return false;              // 断层
