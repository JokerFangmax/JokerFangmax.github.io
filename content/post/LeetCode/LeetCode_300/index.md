# LeetCode 300. 最长递增子序列

> 题目链接：[https://leetcode.cn/problems/longest-increasing-subsequence/](https://leetcode.cn/problems/longest-increasing-subsequence/)  
> 难度：中等  
> 标签：数组、二分查找、动态规划

---

## 1. 题目描述

给你一个整数数组 `nums`，找出其中**最长严格递增子序列**（longest increasing subsequence, LIS）的长度。

子序列（subsequence）不要求连续：可以从数组中删除若干元素（也可以不删），剩下的元素保持原有相对顺序。注意本题要求**严格**递增，即相邻两个元素不能相等。

**数据范围：**

- $1 \le nums.length \le 2500$
- $-10^4 \le nums[i] \le 10^4$

**进阶：** 能否将算法的时间复杂度降到 $O(n \log n)$？

**示例：**

```
输入：nums = [10,9,2,5,3,7,101,18]
输出：4
解释：最长递增子序列是 [2,3,7,101]（或 [2,3,7,18]），长度为 4。

输入：nums = [0,1,0,3,2,3]
输出：4
解释：最长递增子序列是 [0,1,2,3]，长度为 4。
```

---

## 2. 思路分析

### 2.1 暴力：枚举所有子序列

每个元素有"选"或"不选"两个状态，枚举全部 $2^n$ 个子序列、逐一检查是否严格递增，代价 $O(2^n \cdot n)$。$n = 2500$ 时天文数字，不可行。

问题的难点在于子序列**不连续**，无法像子数组那样用滑动窗口；但"以谁结尾"是一个可以传递信息的锚点，这提示我们考虑动态规划（dynamic programming, DP）。

### 2.2 动态规划：$O(n^2)$

定义 $dp[i]$ 为**以 $nums[i]$ 结尾**的最长严格递增子序列的长度。之所以要"以 $i$ 结尾"，是因为子序列扩展时只能接在比它小的元素后面——结尾元素是这个状态的全部外部接口。

转移方程：

$$dp[i] = \max_{j < i,\ nums[j] < nums[i]} dp[j] + 1$$

若不存在这样的 $j$，则 $dp[i] = 1$（自己单独成序列）。最终答案是 $\max_i dp[i]$——注意不是 $dp[n-1]$，因为最优子序列可以结束在任何位置。

以 `nums = [10,9,2,5,3,7,101,18]` 走一遍：

| $i$ | $nums[i]$ | 可接续的 $j$（$nums[j] < nums[i]$） | $dp[i]$ | 对应子序列 |
|---|---|---|---|---|
| 0 | 10  | —      | 1 | [10] |
| 1 | 9   | —      | 1 | [9] |
| 2 | 2   | —      | 1 | [2] |
| 3 | 5   | 2      | 2 | [2,5] |
| 4 | 3   | 2      | 2 | [2,3] |
| 5 | 7   | 2,3,4  | 3 | [2,3,7] |
| 6 | 101 | 0..5 全部 | 4 | [2,3,7,101] |
| 7 | 18  | 0..5   | 4 | [2,3,7,18] |

答案为 $4$。$n = 2500$ 时 $O(n^2) \approx 6.25 \times 10^6$，完全可以通过。

### 2.3 贪心 + 二分：$O(n \log n)$

$O(n^2)$ 里每个 $i$ 都要线性扫一遍前面的 $j$。想提速，得问：**转移时我们到底需要前面的什么信息？**

只需要"结尾值小于 $nums[i]$ 的那些子序列中，最长的有多长"。按长度归类，立刻得到一个关键观察：

> 长度相同的一批递增子序列中，**结尾值越小越有潜力**——后面任何元素能接在"结尾值大的"后面，就必然能接在"结尾值小的"后面。

于是维护数组 $tails$，$tails[k]$ 表示**长度为 $k+1$ 的所有递增子序列中最小的结尾值**。逐个处理元素，规则是：

- 若 $nums[i] > tails$ 的末尾元素：直接**追加**，最长长度 +1；
- 否则用 $nums[i]$ **替换** $tails$ 中第一个 $\ge nums[i]$ 的元素（`lower_bound`），即"把某个长度的最小结尾值再压小一点"。

$nums = [10,9,2,5,3,7,101,18]$ 的完整过程：

| 处理元素 | 操作 | $tails$ | 说明 |
|---|---|---|---|
| 10 | 追加 | [10] | 长度 1 的最小结尾是 10 |
| 9  | 替换 10 | [9]  | 长度 1 的最小结尾压小为 9 |
| 2  | 替换 9  | [2]  | 同上 |
| 5  | 追加 | [2,5] | 5 > 2，得到长度 2 |
| 3  | 替换 5  | [2,3] | 长度 2 的最小结尾从 5 压到 3 |
| 7  | 追加 | [2,3,7] | 长度 3 |
| 101 | 追加 | [2,3,7,101] | 长度 4 |
| 18 | 替换 101 | [2,3,7,18] | 长度 4 的最小结尾压小 |

最终 $tails$ 长度为 4，即 LIS 长度。（注意 $[2,3,7,18]$ 恰好是一个真实 LIS，但这只是巧合，见第 5 节。）

$tails$ 始终严格递增——可用归纳法证明：追加时新元素大于末尾；替换时只把某个值变小到仍大于其前驱，单调性不破坏。严格递增保证了 `lower_bound` 的正确性，每步 $O(\log n)$。

## 3. 代码实现

```cpp
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> tails;              // tails[k] = 长度 k+1 的子序列的最小可能结尾
        for (int x : nums) {
            // 找第一个 >= x 的位置：x 能把该长度的最小结尾压小
            auto it = lower_bound(tails.begin(), tails.end(), x);
            if (it == tails.end())
                tails.push_back(x);     // x 比所有结尾都大，LIS 长度 +1
            else
                *it = x;                // 只替换，长度不变，为未来留更小的接口
        }
        return tails.size();
    }
};
```

两个实现细节：

1. **用 `lower_bound`（第一个 $\ge x$）而不是 `upper_bound`（第一个 $> x$）**。本题要求严格递增：若 $x$ 已在 $tails$ 中，`upper_bound` 会把 $x$ 追加到后面，得到长度相同、结尾相等的"伪递增"序列。`lower_bound` 定位到 $x$ 自身并原值覆盖，等价于跳过。
2. **替换操作不改变 $tails$ 长度**，所以最终答案就是 `tails.size()`，无需额外变量。

## 4. 复杂度分析

- **时间复杂度**：$O(n \log n)$。每个元素做一次二分查找，$O(\log n)$；总元素 $n$ 个。
- **空间复杂度**：$O(n)$。$tails$ 最长为 $n$（整个数组严格递增时）。

对比演进路线：暴力 $O(2^n \cdot n)$ → DP $O(n^2)$ → 贪心 + 二分 $O(n \log n)$。对 $n = 2500$ 的本题主数据 DP 已够，但 $n$ 放大到 $10^5$ 级别（如第 5 节提到的信封问题加强版）就必须二分了。

## 5. 常见疑问

**疑问一：$tails$ 是不是就是一个 LIS？**

不是。$tails$ 只保证"每个长度类别的最小结尾"，各元素可能来自不同的子序列。反例：`nums = [3,5,1,2]`。处理完 3、5 后 $tails = [3,5]$；处理 1 替换得 $[1,5]$；处理 2 替换得 $[1,2]$。$[1,2]$ 恰是 LIS 所以这里对了；但换 `nums = [4,5,1,2,3]`：过程为 $[4] \to [4,5] \to [1,5] \to [1,2] \to [1,2,3]$，看似也对——真正的坑在 `nums = [1,3,5,2]`：$[1] \to [1,3] \to [1,3,5] \to [1,2,5]$，而 $[1,2,5]$ 并不是一个真实子序列（2 在 5 之后出现）。**$tails$ 只能回答长度，要还原具体序列需额外记录前驱，通常用 $O(n^2)$ DP 或在二分时记录每个元素接在哪个位置之后。**

**疑问二：为什么替换不会破坏已有信息？**

替换发生在"第一个 $\ge x$"的位置 $k$。替换后 $tails[k]$ 变小，长度为 $k+1$ 的子序列接口变得更"友好"——任何原先能接在旧 $tails[k]$ 后面的元素，必然也能接在新值（$= x \le$ 旧值）后面。而 $tails[k]$ 之前的部分没有动，长度 $k$ 及更短的信息全部保留。这正是贪心不丢解的原因。

**疑问三：能求"最长不下降子序列"（允许相等）吗？**

可以，把 `lower_bound` 换成 `upper_bound` 即可：相等的元素允许接在相等结尾之后，所以定位到第一个"严格大于"的位置替换或追加。

## 6. 相关题目与模板

**可复用模板**（LIS 长度，严格递增版）：

```cpp
vector<int> tails;
for (int x : nums) {
    auto it = lower_bound(tails.begin(), tails.end(), x);
    if (it == tails.end()) tails.push_back(x);
    else *it = x;
}
int lisLen = tails.size();   // 不下降版把 lower_bound 换成 upper_bound
```

**方法论总结**：LIS 优化分三档——

| 档位 | 做法 | 复杂度 | 能否还原方案 |
|---|---|---|---|
| 1 | 枚举子序列 | $O(2^n \cdot n)$ | 能 |
| 2 | DP，$dp[i]$ 以 $i$ 结尾 | $O(n^2)$ | 容易（记前驱） |
| 3 | 贪心 + 二分，维护 $tails$ | $O(n \log n)$ | 需额外记录 |

**一句话总结**：LIS 的贪心本质是"**同样长度，结尾越小越好**"——把每个长度的最优结尾压到最小，新元素能否延长序列只取决于这个最小结尾。
