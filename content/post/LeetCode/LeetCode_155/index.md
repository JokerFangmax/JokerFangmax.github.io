# LeetCode 155. 最小栈

> 题目链接：[https://leetcode.cn/problems/min-stack/](https://leetcode.cn/problems/min-stack/)  
> 难度：中等  
> 标签：栈、设计

---

## 1. 题目描述

设计一个支持 `push`、`pop`、`top` 操作，并能在**常数时间** $O(1)$ 内检索到栈中最小元素的栈：

- `MinStack()` 初始化堆栈对象；
- `void push(int val)` 将元素 `val` 压入栈；
- `void pop()` 删除栈顶元素（题目保证此时栈非空）；
- `int top()` 获取栈顶元素（栈非空）；
- `int getMin()` 获取栈中的最小元素（栈非空）。

要求每个函数的时间复杂度都是 $O(1)$。

**数据范围：**

- $-2^{31} \le val \le 2^{31} - 1$
- `pop`、`top`、`getMin` 只在**栈非空**时调用
- `push`、`pop`、`top`、`getMin` 的总调用次数不超过 $3 \times 10^4$

**示例：**

```
输入：
["MinStack","push","push","push","getMin","pop","top","getMin"]
[[],[-2],[0],[-3],[],[],[],[]]

输出：
[null,null,null,null,-3,null,0,-2]

解释：
MinStack minStack = new MinStack();
minStack.push(-2);
minStack.push(0);
minStack.push(-3);
minStack.getMin();   // 返回 -3
minStack.pop();
minStack.top();      // 返回 0
minStack.getMin();   // 返回 -2
```

## 2. 思路分析

### 2.1 朴素方案：一个变量记最小值，为什么不够

最直接的想法：维护一个变量 `mn`，`push` 时 `mn = min(mn, val)`，`getMin` 返回 `mn`——$O(1)$，成了？

**`pop` 会把它击碎。** 栈是 `[−2, 0, −3]`，`mn = −3`；此时 `pop` 掉 −3，最小值应回到 −2，但 `mn` 不知道——**它只记得历史最小，忘了"第二小"**。要恢复就得扫一遍整个栈，$O(n)$，违背 $O(1)$ 要求。

问题的本质：**栈的"当前最小值"是随弹出而回退的**，一个标量只保存一个时刻的状态，无法回答"回到上一步时最小值是多少"。我们需要的是**每个栈状态各自的最小值**——也就是最小值的"历史"。

### 2.2 想法一：辅助栈 (auxiliary stack)——最小值也走一遍栈的历史

既然主栈记录了"元素的历史"，那就再开一个栈 `minSt`，**与主栈同步进退**，`minSt` 的栈顶永远是"当前栈状态的最小值"：

- `push(val)`：主栈压 `val`；`minSt` 压 `min(val, minSt.top())`——新状态的最小值要么是新元素，要么是旧状态的最小值；
- `pop()`：两栈同弹——状态回退，最小值随之回退；
- `getMin()`：返回 `minSt.top()`。

最小值的回退不再需要"算回来"，因为**每个历史状态的最小值都被存了下来**。这是典型的"用 $O(n)$ 额外空间换取 $O(1)$ 查询"。

一个常见的小优化：`push` 时只有 `val <= minSt.top()` 才压 `minSt`，`pop` 时只有主栈顶等于 `minSt` 顶才弹。能省空间，但**必须用 `<=` 而不是 `<`**（值相同的最小元素可能有多个，弹掉一个还剩一个时，`minSt` 里必须还有一份）——见第 5 节。基础版两栈完全同步，简单不易错，是更推荐的写法。

### 2.3 想法二：单栈存"差值"——把历史编码进元素里

不开第二个栈，主栈里不存 `val`，而存 `val − 当前最小值`（再加一个单独的 `mn` 变量）：

- 压入时若差值 $\ge 0$，说明最小值没变；若差值 $< 0$，说明新元素刷新了最小值（此时旧栈顶的差值是相对旧最小值算的）；
- 弹出时若栈顶差值 $< 0$，说明弹掉的正是"当前最小值"，用 $mn_{\text{new}} = mn_{\text{old}} − \text{差值}$ 倒推出上一代最小值。

空间从"两个栈"变成"一个栈 + 一个变量"。但两个代价：`val` 达到 $-2^{31}$ 时差值会溢出 `int`，需要 `long long`；差值的意义不直观，可读性差。**面试中先写对辅助栈版，再口头给出差值版**是更稳妥的策略。

### 2.4 用具体例子走一遍（辅助栈版）

按示例操作，表格每行展示一次操作后的两个栈（左侧为栈底）：

| 操作 | 主栈 | minSt | getMin 结果 |
|------|------|-------|-------------|
| `push(-2)` | `-2` | `-2` | — |
| `push(0)` | `-2, 0` | `-2, -2` | — |
| `push(-3)` | `-2, 0, -3` | `-2, -2, -3` | — |
| `getMin()` | | | **-3**（minSt 顶） |
| `pop()` | `-2, 0` | `-2, -2` | — |
| `top()` | | | 返回 `0` |
| `getMin()` | | | **-2**（回退自动完成） |

关键看最后两行：弹掉 $-3$ 后，`minSt` 同步弹掉 $-3$，栈顶露出 $-2$——**上一代最小值不需要任何计算，它一直在那儿等着**。再压入一个更小的，比如 `push(-5)`，则 `minSt` 压 $\min(-5, -2) = -5$；之后连 pop 三次，`minSt` 依次露出 $-2, -2, -2$，每次 `getMin` 都即时正确。

## 3. 代码实现

```cpp
class MinStack {
    stack<int> st;      // 主栈：正常进出
    stack<int> minSt;   // 辅助栈：与主栈同步，栈顶 = 当前最小值

public:
    MinStack() {}

    void push(int val) {
        st.push(val);
        // 新状态的最小值 = min(新元素, 上一状态的最小值)；minSt 为空时就是 val 自己
        if (minSt.empty() || val < minSt.top())
            minSt.push(val);
        else
            minSt.push(minSt.top());
    }

    void pop() {
        st.pop();
        minSt.pop();    // 两栈同步弹，最小值随状态回退
    }

    int top() {
        return st.top();
    }

    int getMin() {
        return minSt.top();
    }
};
```

三个实现细节：

1. **`push` 里对空 `minSt` 的分支不可省**。第一个元素没有"上一状态最小值"可比，直接压自身。（写成 `min(minSt.empty() ? val : minSt.top(), val)` 也可以，分支更显眼。）
2. **两栈长度永远相等**，这是不变式 (invariant)：任何时刻 `minSt.top()` 恰是 `st` 当前状态的最小值。所有操作都维护它，`getMin` 才敢直接返回。
3. 本题 `val` 范围是完整 `int`，若改用 2.3 节差值法，差值必须存 `long long` 防溢出。

## 4. 复杂度分析

- **时间复杂度**：每个操作 $O(1)$。`push` 一次比较、两次压栈；`pop` 两次弹栈；`top` / `getMin` 各一次读栈顶——全是常数操作。
- **空间复杂度**：$O(n)$。`minSt` 与主栈等长（$n$ 为历史最大深度）。

若采用"小于等于才压"的共享优化，`minSt` 长度为"最小值刷新次数"，最坏（严格递减输入）仍是 $O(n)$，最好（递增输入）为 $O(1)$——**渐进不变，常数更优**。

## 5. 常见疑问

**疑问一：为什么"只压更小值"的省空间版必须用 `<=` 而不是 `<`？**

反例：依次 `push(2), push(2)`，然后 `pop()` 一次、`getMin()`。
用 `<`：第二个 2 不压入 `minSt`（$2 < 2$ 不成立），`minSt = [2]`；pop 时主栈弹掉一个 2，若同步弹 `minSt`（两个 2 相等，无法区分是不是"最小值被弹了"），`minSt` 变空或提前露底，`getMin` 出错。
用 `<=`：两个 2 各占一格 `minSt = [2, 2]`，弹一个剩一个，正确。**多个并列最小时，"最小值还活着"这件事计数了才知道**——`<=` 正是让 `minSt` 承担计数职责。

**疑问二：`pop` 时为什么不用检查主栈顶是否等于 `minSt` 顶？**

因为本文采用**完全同步**的双栈写法：`minSt` 每格记录的是"主栈到该深度为止的最小值"，与主栈一一对应，pop 必然同弹，不存在"要不要弹"的决策。只有"小于等于才压"的省空间版才需要那个检查——它省下的空间换来的是更多需要小心的分支。两种写法的取舍：

| 写法 | minSt 深度 | push 逻辑 | pop 逻辑 | 易错点 |
|------|-----------|-----------|----------|--------|
| 完全同步 | 恒等于主栈深度 | 总是压 | 总是弹 | 几乎没有 |
| 条件压入 | 最小值刷新次数 | 比较后决定 | 比较后决定 | `<` 与 `<=`、相等判断 |

**疑问三：为什么不用 `multiset` / 堆 / 前缀最小值数组？**

- `multiset`：插入删除 $O(\log n)$，且删除时要把迭代器定位到那个具体元素，违反 $O(1)$；
- 堆：**不支持删除任意元素**，弹出栈顶时堆里那个元素成了僵尸；
- 前缀最小值数组：$getMin$ 时刻的"当前"对应数组哪个下标？其实可行（`preMin[depth]`），但那正是辅助栈——数组换了个名字而已，而栈天然只暴露 $O(1)$ 的顶端操作，语义更贴合。

## 6. 相关题目与模板

**可复用模板**（"带历史的最值查询"骨架，栈/队列版通用）：

```cpp
// 维护一个结构，支持 push / pop / 查当前最值，全部 O(1)：
// 核心 = "新状态的最值 = min(新元素, 上一状态的最值)"，把状态历史存下来
if (minSt.empty() || val < minSt.top()) minSt.push(val);
else minSt.push(minSt.top());   // 同步版；队列场景见单调队列
```

> 📚 "每个状态配一个最值"的思想与单调结构同源，系统笔记见 [单调队列：滑动窗口最值](../../algorithms/monotonic_queue/)——区别在单调队列还要淘汰过期元素，本题不会。

**同类题目：**

- [LeetCode 716. 最大栈](https://leetcode.cn/problems/max-stack/)：把 `getMin` 换成 `popMax`（弹出最大值），纯 $O(1)$ 做不到，双栈 + 平衡查找的经典矛盾点
- [LeetCode 895. 最大频率栈](https://leetcode.cn/problems/maximum-frequency-stack/)：按频率分桶的栈组，"弹出谁由结构内部决定"的设计题进阶
- [LeetCode 239. 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/)：窗口场景下的最值维护，单调队列解法（同系列已发：[LeetCode 239](../LeetCode_239/)）
- [LeetCode 394. 字符串解码](https://leetcode.cn/problems/decode-string/)：同样是双栈配合，一个存数、一个存串

**一句话总结**：最小栈的题眼不在"栈"，而在"**历史**"——标量只记得此刻，栈记得每一层状态；让辅助栈与主栈同步进退，"回退后的最小值"就从一道计算题变成一次查表。
