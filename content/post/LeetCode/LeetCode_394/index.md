# LeetCode 394. 字符串解码

> 题目链接：[https://leetcode.cn/problems/decode-string/](https://leetcode.cn/problems/decode-string/)  
> 难度：中等  
> 标签：栈、字符串

---

## 1. 题目描述

给定一个经过编码的字符串，返回解码后的字符串。编码规则为 `k[encoded_string]`，表示方括号内的 `encoded_string` **重复 $k$ 次**。注意 $k$ **保证是正整数**。

例如 `3[a]` 解码为 `aaa`，`2[bc]` 解码为 `bcbc`，`3[a2[c]]` 解码为 `accaccacc`（方括号可以**嵌套**）。

**数据范围：**

- $1 \le s.length \le 30$
- $s$ 由小写英文字母、数字和方括号 `[]` 组成
- 题目保证输入是**合法编码**：$k$ 总在方括号前、取值范围 $1 \le k \le 300$；输入中不会有额外空格；方括号总是成对且格式合法
- 保证解码后字符串的长度不超过 $10^5$

**示例：**

```
输入：s = "3[a]2[bc]"
输出："aaabcbc"

输入：s = "3[a2[c]]"
输出："accaccacc"

输入：s = "abc3[cd]xyz"
输出："abccdcdcdxyz"
```

## 2. 思路分析

### 2.1 暴力的困境：为什么不能"边扫边展开"

最朴素的冲动：线性扫描，读到数字 $k$ 和 `[`，就找到匹配的 `]`，把中间重复 $k$ 次拼进结果。问题出在**嵌套**：`3[a2[c]]` 的内层 `2[c]` 自己还没展开，外层的 $3$ 份里每一份都得包含展开后的内层。要做对就得递归下降、或者对每个 `]` 反复回扫匹配括号，实现又碎又乱。

症结在于：**展开外层之前必须先展开内层**——这和括号匹配里"最近的左括号最先闭合"是同一个结构：**内层后读、先完成**，后进先出。既然如此，就该用栈。

### 2.2 两个栈：把"现场"存起来再进去

顺着这个思路设计：扫描中维护**当前正在拼的字符串** `cur` 和**当前乘数** `num`。遇到三种情况分流：

| 读到 | 动作 | 为什么 |
|------|------|--------|
| 数字 | `num = num*10 + d` | 多位数字（如 `12[ab]`）要逐位累积 |
| `[` | **保存现场**：数字栈压 `num`，字符串栈压 `cur`，然后 `num=0, cur=""` | 进入新一层，旧层挂起 |
| 字母 | `cur += c` | 正常累积 |
| `]` | **恢复现场**：弹出 `last` 与 `k`，`cur = last + k 个 cur` | 内层拼完了，回到外层并把成果接上 |

`k 个 cur` 的小实现：`string t = cur; for (k-1 次) cur += t;`（$k=1$ 时不追加）。

为什么这一套是自洽的？因为 `]` 到来时，`cur` 恰好是**刚闭合的那一层**的完整内容（内层更早的 `]` 已经把它消化掉了），字符串栈顶恰是**它的外层已拼前缀**——栈的顺序天然与嵌套层级对齐。每对 `[]` 恰好经历一次"压现场 / 弹现场"，扫描结束时 `cur` 就是全局答案（最外层没有 `]`，不再有挂起的现场）。

### 2.3 换个视角：这其实是一个手动递归

用递归来写也完全可行：`decode(s)` 从下标 $i$ 扫起，遇 `]` 返回；遇 `k[` 则递归取内层结果，重复 $k$ 次接上。递归深度 = 嵌套深度，系统调用栈做的就是"字符串栈"做的事——**双栈解法就是显式展开的递归**。两版对比：

| | 递归版 | 双栈版 |
|---|--------|--------|
| 现场保存 | 系统调用栈自动 | 两个显式栈 |
| 括号匹配 | 靠递归返回时机 | 靠 `]` 触发弹栈 |
| 何时必须用 | 树/图等天然递归结构 | 不能用递归（深度不可控）或想统一迭代时 |

本题嵌套极浅（串长 30），两版皆可；掌握双栈版的价值在于它是"递归转迭代"的最小范例。

### 2.4 用具体例子走一遍

`s = "3[a2[c]]"`，记 `numSt` 为数字栈、`strSt` 为字符串栈：

| 读到 | 动作 | `num` | `cur` | `numSt` | `strSt` |
|------|------|-------|-------|---------|---------|
| `3` | 累积数字 | 3 | `""` | 空 | 空 |
| `[` | 压现场 3 与 `""`，清空 | 0 | `""` | `[3]` | `[""]` |
| `a` | 拼入 | 0 | `a` | `[3]` | `[""]` |
| `2` | 累积数字 | 2 | `a` | `[3]` | `[""]` |
| `[` | 压现场 2 与 `a`，清空 | 0 | `""` | `[3,2]` | `["", "a"]` |
| `c` | 拼入 | 0 | `c` | `[3,2]` | `["", "a"]` |
| `]` | 弹 2、`a`：`cur = a + c×2 = "acc"` | 0 | `acc` | `[3]` | `[""]` |
| `]` | 弹 3、`""`：`cur = "" + acc×3 = "accaccacc"` | 0 | `accaccacc` | 空 | 空 |

扫完，答案 `accaccacc`。注意两个 `]` 的处理顺序：**内层先闭合**（第一次 `]` 消化 `2[c]`），它的成果 `acc` 成为外层现场的一部分，第二次 `]` 才把整体重复 3 次——这正是"后进先出"在嵌套展开中的体现。

## 3. 代码实现

```cpp
class Solution {
public:
    string decodeString(string s) {
        stack<int> numSt;        // 每层的重复次数
        stack<string> strSt;     // 每层进入前已拼好的前缀
        string cur;              // 当前层正在拼的串
        int num = 0;             // 当前正在累积的乘数

        for (char c : s) {
            if (isdigit(c)) {
                num = num * 10 + (c - '0');      // 多位数字逐位累积
            } else if (c == '[') {
                numSt.push(num);                 // 保存现场，进入内层
                strSt.push(cur);
                num = 0;
                cur.clear();
            } else if (c == ']') {
                int k = numSt.top(); numSt.pop();
                string last = strSt.top(); strSt.pop();
                string block = cur;              // 内层成果重复 k 份，接回外层前缀
                for (int t = 1; t < k; t++) cur += block;
                cur = last + cur;
            } else {
                cur += c;                        // 普通字母
            }
        }
        return cur;              // 最外层无 ']'，cur 即最终答案
    }
};
```

四个实现细节：

1. **数字用 `num*10 + d` 累积而不是 `num = d`**。`"12[ab]"` 的 12 是一位一位读进来的；漏乘 10 是本题最经典的错法。遇到 `[` 后必须把 `num` 归零，为下一层做准备。
2. **`[` 处先压栈再清空**，顺序颠倒会把刚清空的空串压进去。
3. **重复 $k$ 份用"复制再追加 $k-1$ 次"**，避免 $k=1$ 时多拼一次；也可以 `res.reserve` 后循环，$10^5$ 的解码长度下不必过度优化。
4. **不需要特判"串里没有括号"**（如 `"abc"`）：全程走字母分支，`cur` 累积成答案，栈始终为空。

## 4. 复杂度分析

- **时间复杂度**：$O(\text{len})$，其中 $\text{len} \le 10^5$ 是**解码后**的串长。每个源字符处理一次是 $O(|s|)$；每个 `]` 展开时拼接的总量恰好等于输出中"由重复产生"的字符数，各层展开的总拼接代价与输出长度同阶。
- **空间复杂度**：$O(\text{len})$。输出串本身占 $O(\text{len})$；两个栈在嵌套最深时存的是各层前缀，总量不超过源串长度 $O(|s|)$。

一个值得注意的点：复杂度必须按**输出规模**计，而不是输入规模——$300[300[300[a]]]$ 这类输入，30 个字符就能生产约 $2.7 \times 10^7$ 字符（本题数据范围刻意排除了它，但复杂度表述上要自觉）。

## 5. 常见疑问

**疑问一：`num` 为什么要归零？不归零会怎样？**

`num` 的语义是"**当前层**未读完的乘数"。进层归零后，内层读到的数字才属于内层。反例 `"3[a2[c]]"`：若进层后 `num` 仍是 3，读到 `2` 时变成 $3 \times 10 + 2 = 32$，内层错误地重复 32 次。所有"逐位累积数字"的题（表达式求值、[LeetCode 8]atoi 等）都有同一条纪律：**数字结束（或进入新语境）时立即封口**。

**疑问二：`k` 份重复为什么不能在遇到 `k[` 时就把后面的内容复制 $k$ 遍？**

因为那时**还不知道内层是什么**。`3[a2[c]]` 的 `3[` 后面跟着的不是纯文本而是又一个待展开的表达式。能提前复制的只有"内层已经完全展开"的串——这只能发生在内层闭合（`]`）之后。换句话说：**展开的时机必须在最内层先完成**，栈的进出顺序正是把"时机"安排对了。

**疑问三：为什么输入保证合法这件事很重要？**

合法保证让代码免除三类防御：`k` 一定在 `[` 前且 $\ge 1$（不会除零/乘零）、`[` 与 `]` 一定配对（栈不会弹空或残留）、解码长度有上界（不会内存爆炸）。如果没有这些保证，`numSt.top()` 前要判空、残留的 `strSt` 要决定抛错还是忽略，代码会胖一圈。**设计题里"利用好题目给的约定"与写出正确代码同等重要**。

## 6. 相关题目与模板

**可复用模板**（双栈"保存现场"骨架，一切嵌套展开/表达式求值的底座）：

```cpp
stack<int> numSt;      // 语境 1：数字/状态
stack<string> strSt;   // 语境 2：已构建的前缀
for (char c : s) {
    if (isdigit(c)) num = num * 10 + c - '0';
    else if (c == '[') { numSt.push(num); strSt.push(cur); num = 0; cur.clear(); }
    else if (c == ']') { /* 弹现场，合成，写回 cur */ }
    else cur += c;
}
```

把 `[` `]` 换成 `(` `)`、把"重复拼接"换成"按运算符合并"，同一骨架就变成中缀表达式求值。

- [LeetCode 880. 索引处的解码字符串](https://leetcode.cn/problems/decoded-string-at-index/)：逆向思维姊妹题——不展开，而是把下标一步步"缩"回源串
- [LeetCode 726. 原子的数量](https://leetcode.cn/problems/number-of-atoms/)：嵌套化学式计数，"现场"从字符串换成哈希表，骨架不变

**一句话总结**：嵌套展开的次序是**内层先完成、外层后收割**——遇到 `[` 把外层现场压栈挂起，遇到 `]` 弹栈接回，两个栈让递归的调用顺序变成一次从左到右的线性扫描。
