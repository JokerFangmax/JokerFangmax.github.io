# LeetCode 20. 有效的括号

> 题目链接：[https://leetcode.cn/problems/valid-parentheses/](https://leetcode.cn/problems/valid-parentheses/)  
> 难度：简单  
> 标签：栈、字符串

---

## 1. 题目描述

给定一个只包含 `'('`、`')'`、`'{'`、`'}'`、`'['`、`']'` 的字符串 `s`，判断它是否**有效**。

有效字符串需满足：

1. 左括号必须用**相同类型**的右括号闭合（`'('` 配 `')'`，不能配 `']'`）；
2. 左括号必须以**正确的顺序**闭合（先开的必须先关，像洋葱一样层层嵌套）。

**数据范围：**

- $1 \le s.length \le 10^4$
- `s` 仅由括号字符 `'()[]{}'` 组成

**示例：**

```
输入：s = "()[]{}"
输出：true

输入：s = "(]"
输出：false    // 类型不匹配

输入：s = "([)]"
输出：false    // 顺序错误：'[' 还没关，')' 先来关 '(' 了

输入：s = "{[]}"
输出：true     // 正确嵌套
```

## 2. 思路分析

### 2.1 暴力：反复消去相邻配对

观察：有效串里一定存在至少一处**相邻的配对括号** `()`、`[]`、`{}`（最内层那对）。于是可以不断把相邻配对替换成空串，最后串空则有效。每轮消去要 $O(n)$ 扫描，最坏嵌套 $n/2$ 层，总计 $O(n^2)$。$n = 10^4$ 时约 $5 \times 10^7$，勉强能过，但不优雅，而且"每轮从头扫描"浪费了上一轮的信息。

反向想想：这个"消去相邻配对"的过程，等价于**一边扫描一边消**——遇到右括号时，若它恰好能闭合"最近的、尚未闭合的左括号"，就地消掉这一对，后面的字符就成了新的"相邻"。

### 2.2 为什么是栈：括号的嵌套是 LIFO 的

"最近尚未闭合的左括号"——这句话就是数据结构的选型说明书：

- 左括号**先出现、后闭合**（后进先出，LIFO）；
- 每个**右括号**到来时，必须与**最后那个未闭合**的左括号配对。

这正好是**栈 (stack)** 的行为：左括号压栈；右括号到时弹栈顶，弹出的必须是与它同类型的左括号。

从"匹配失败"的角度看，无效串只有三种死法，栈能把三种全部抓住：

| 失败模式 | 例子 | 栈的表现 |
|----------|------|----------|
| 右括号多了 | `(()` 之后再来个 `)` → `"(()))"` 或 `")("` 开头 | 弹栈时栈已空 |
| 类型不匹配 | `"(]"` | 弹出的 `'('` 与 `']'` 不是同类 |
| 左括号多了 | `"((("` | 扫完后栈非空 |

**任何一种都不需要特判**——统一的扫描规则自然覆盖。反过来说，若扫完时"从未触发失败且栈恰好清空"，串必然有效：每个右括号都闭掉了最近的同类左括号，归纳可证整串配对完全。

### 2.3 一个小技巧：左括号入栈时直接存"期待的右括号"

压栈时做一次翻译：遇 `'('` 压 `')'`，遇 `'['` 压 `']'`，遇 `'{'` 压 `'}'`。之后遇到右括号 $c$，只需检查 `栈顶 == c`，一条比较搞定，免去"查配对表再比"的两步。

### 2.4 用具体例子走一遍

`s = "{[()()]}"`，栈从底到顶用竖线分隔：

| 读到 | 动作 | 栈（底→顶） |
|------|------|-------------|
| `{` | 压 `}` | `}` |
| `[` | 压 `]` | `} ]` |
| `(` | 压 `)` | `} ] )` |
| `)` | 弹栈顶 `)`，匹配 | `} ]` |
| `(` | 压 `)` | `} ] )` |
| `)` | 弹栈顶 `)`，匹配 | `} ]` |
| `]` | 弹栈顶 `]`，匹配 | `}` |
| `}` | 弹栈顶 `}`，匹配 | （空） |

扫完栈空，输出 `true`。

再看失败的 `s = "([)]"`：

| 读到 | 动作 | 栈 |
|------|------|----|
| `(` | 压 `)` | `)` |
| `[` | 压 `]` | `) ]` |
| `)` | 弹出 `]`，与 `)` 不等 | — 失败 |

第 3 个字符就暴露了顺序错误——`'['` 尚未闭合，`')'` 却想来关更早的 `'('`，而栈顶告诉它：现在轮不到你。

## 3. 代码实现

```cpp
class Solution {
public:
    bool isValid(string s) {
        stack<char> st;
        for (char c : s) {
            if (c == '(')      st.push(')');   // 左括号：入栈"期待的右括号"
            else if (c == '[') st.push(']');
            else if (c == '{') st.push('}');
            else {
                // 右括号：必须与栈顶的期待相符，且栈不能为空
                if (st.empty() || st.top() != c) return false;
                st.pop();
            }
        }
        return st.empty();     // 栈非空 = 有左括号没闭合
    }
};
```

三个实现细节：

1. **弹栈前先判空**。`")("` 这类以右括号开头的串，第一个字符就要弹空栈；不判 `st.empty()` 直接 `st.top()` 是未定义行为（常见 RE 来源）。
2. **`||` 的短路顺序不能反**。必须先 `st.empty()` 再 `st.top()`，顺序颠倒在空栈时崩溃。
3. **最后 `return st.empty()` 而非 `return true`**。`"((("` 全程不触发失败，但栈里剩 3 个未闭合的左括号——第三种失败模式在这里被抓到。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。每个字符至多一次压栈、一次弹栈，全部 $O(1)$ 操作。
- **空间复杂度**：$O(n)$。最坏情况全是左括号（`"((((("`），全部滞留栈中。

对比暴力消去法的 $O(n^2)$：栈把"消去相邻配对"的成果**实时保留**在栈里，右括号一到就地对账，无需回头重扫——这是"用空间换重复扫描"的标准案例。

## 5. 常见疑问

**疑问一：`"([)]"` 里每个括号数量都配对，为什么还是无效？**

括号匹配的合法性不只看**数量**，还看**交错顺序**。`"([)]"` 的 `')'` 越过了尚未闭合的 `'['` 去关 `'('`，这违反了"后开先关"。形式化地说，有效串是上下文无关文法 $S \to (S) \mid [S] \mid \{S\} \mid SS \mid \epsilon$ 生成的语言，栈正是识别这类"嵌套对称"语言的标配工具（下推自动机）。数量检查只能排除第一种死法，挡不住交错。

**疑问二：能不能用计数器代替栈——左括号加一、右括号减一，中途不为负、结尾为零？**

对**单一**括号类型（如只含 `()`）可以：不存在类型区分时，"位置合法"等价于"前缀计数非负、总数为零"。但三种括号混合时计数器丢失了**类型信息**：`"(]"` 的计数是完美的一加一减，却无效。栈里存的不只是"有几个没关"，还有"**谁**还没关"——后者才是本题考点。

**疑问三：字符串以右括号开头要不要特判？**

不需要。首字符是右括号时进入 `else` 分支，栈为空，`st.empty()` 条件直接返回 `false`——已经写进统一规则里了。同理"栈里只剩左括号"也不需要特判。这题的所有"边界"都被三种失败模式收编，**好代码的标志是特判数量为零**。

## 6. 相关题目与模板

**可复用模板**（括号匹配骨架，嵌套类问题的通用积木）：

```cpp
stack<char> st;
for (char c : s) {
    if (isLeft(c)) st.push(match(c));      // 压入对应的右括号
    else if (st.empty() || st.top() != c) return false;
    else st.pop();
}
return st.empty();
```

配对表 `match` 可换成 `map<char,char>` 或 `switch`，骨架不变。

**一句话总结**：括号嵌套的本质是**后进先出**——"最近的未闭合"就是栈顶，遇到右括号问一句"你等的是不是我"，三种失败模式（栈空、类型错、栈不空）各归其位，无需任何特判。
