# LeetCode 79. 单词搜索

> 题目链接：[https://leetcode.cn/problems/word-search/](https://leetcode.cn/problems/word-search/)  
> 难度：中等  
> 标签：数组、回溯、矩阵

---

## 1. 题目描述

给定一个 $m \times n$ 的二维字符网格 `board` 和一个字符串单词 `word`。如果 `word` 存在于网格中，返回 `true`；否则返回 `false`。

单词必须按照**字母顺序**，通过**相邻的**单元格内的字母构成（"相邻"指水平相邻或垂直相邻）；同一个单元格内的字母**不允许被重复使用**。

**数据范围：**

- $1 \le m, n \le 6$
- $1 \le word.length \le 15$
- `board` 和 `word` 仅由大小写英文字母组成

**示例：**

```
board = [["A","B","C","E"],
         ["S","F","C","S"],
         ["A","D","E","E"]]

输入：word = "ABCCED"
输出：true   （路径 A(0,0)→B(0,1)→C(0,2)→C(1,2)→E(2,2)→D(2,1)）

输入：word = "SEE"
输出：true   （路径 S(1,3)→E(2,3)→E(2,2)）

输入：word = "ABCB"
输出：false  （B 会被复用，找不到不重复的路径）
```

---

## 2. 思路分析

### 2.1 暴力：起点枚举 + 沿网格走

这道题天然是**搜索**：单词的每个字符对应网格中一步，步与步之间必须四联通相邻。思路按层级自然展开：

1. **起点**：网格里任何等于 `word[0]` 的格子都可能是路径起点，逐个尝试；
2. **延伸**：从起点出发，检查四邻格中哪个等于 `word[1]`，走过去，再找 `word[2]`……；
3. **成功**：下标推进到 `word.length`，说明每个字符都按序踩到了；
4. **失败**：四邻里没有需要的字符，退回来换条路走。

第 2、4 步就是**回溯 (backtracking)**：走一步、递归、走不通就撤销这步。真正要想清楚的是下面两个问题。

### 2.2 关键点一：访问标记——路径不能自交

"同一单元格不能重复使用"意味着**当前路径上已占用的格子要被挡住**。两种等价实现：

| 方案 | 做法 | 恢复方式 |
|------|------|---------|
| `visited[6][6]` 数组 | 进入格子置 `true`，递归返回后置回 `false` | 显式置回 |
| **原地修改** | 进入格子前把 `board[i][j]` 暂存后改成 `'#'`，返回后写回 | 借格子自己当标记 |

原地修改省一个数组，且"标记的生存期恰好等于递归调用"天然不会忘记恢复——但**必须在返回前写回**，否则污染棋盘，起点枚举的后续尝试会错杀。

### 2.3 关键点二：分支因子是 3 不是 4

表面上每步有上下右左 4 个方向可选。但来时的格子刚被标记为 `'#'`（或 `visited`），必然匹配失败——**回头方向是自动剪掉的**。所以除了第一步（从起点出发真有 4 个方向），后续每步有效分支至多 3。这直接把搜索树规模从 $4^L$ 压到 $3^L$：$L = 15$ 时是从 $10^9$ 降到 $10^7$ 的量级差，再乘上 $m \times n \le 36$ 个起点，最坏约 $3.6 \times 10^8$……听着吓人，但实际数据里字符不匹配会砍掉绝大部分分支，LeetCode 的测试下这个解法轻松通过。若要加强，先统计 `board` 字符频率，`word` 中某字符出现次数超过库存直接返回 `false`。

### 2.4 逐步走一遍：word = "SEE"

```
board:
    0    1    2    3
0 [ A ][ B ][ C ][ E ]
1 [ S ][ F ][ C ][ S ]
2 [ A ][ D ][ E ][ E ]
```

找 `word[0] = 'S'`：两个候选 $(1,0)$ 和 $(1,3)$。

| 步骤 | 状态 | 动作 | 结果 |
|------|------|------|------|
| 1 | 起点 $(1,0)$ | 四邻找 `E`：$(0,0)$=A、$(2,0)$=A、$(1,1)$=F | 无 E，回溯，换起点 |
| 2 | 起点 $(1,3)$ | 四邻找 `E`：$(0,3)$=E ✓、$(2,3)$=E ✓，先走 $(0,3)$ | 进入 $(0,3)$，标记 `#` |
| 3 | 在 $(0,3)$ | 找 `word[2] = 'E'`：邻格 $(0,2)$=C、$(1,3)$=`#` | 失败，退回 $(1,3)$，恢复 $(0,3)$ |
| 4 | 回到 $(1,3)$ | 第二个邻格 $(2,3)$=E ✓ | 进入 $(2,3)$，标记 `#` |
| 5 | 在 $(2,3)$ | 找 `word[2] = 'E'`：邻格 $(2,2)$=E ✓ | 进入 $(2,2)$ |
| 6 | 下标到 3 = 长度 | 全部匹配 | 返回 `true` |

路径 $(1,3) \to (0,3)$ 那条在**第 3 步就死掉**、退回来换 $(2,3)$ 才活——这正是"走不通就撤销"的现场。

## 3. 代码实现

```cpp
class Solution {
    int m, n;

    // 从 (i,j) 出发匹配 word[k..]，能否走通
    bool dfs(vector<vector<char>>& board, const string& word,
             int i, int j, int k) {
        if (board[i][j] != word[k]) return false;   // 当前字符对不上
        if (k == (int)word.size() - 1) return true; // 最后一个字符也匹配上了

        board[i][j] = '#';                          // 原地标记：本路径已占用
        bool found = false;
        const int di[4] = {1, 0, -1, 0};
        const int dj[4] = {0, 1, 0, -1};
        for (int d = 0; d < 4 && !found; d++) {
            int ni = i + di[d], nj = j + dj[d];
            if (ni >= 0 && ni < m && nj >= 0 && nj < n)   // 边界内
                found = dfs(board, word, ni, nj, k + 1);
        }
        board[i][j] = word[k];                      // 无论成败，恢复原字符
        return found;
    }

public:
    bool exist(vector<vector<char>>& board, string word) {
        m = board.size();
        n = board[0].size();
        for (int i = 0; i < m; i++)
            for (int j = 0; j < n; j++)
                if (dfs(board, word, i, j, 0))
                    return true;
        return false;
    }
};
```

四个细节：

1. **字符比较放在递归开头**：`board[i][j] != word[k]` 一票否决，使得调用方不必预检查邻格字符，代码短且失败得最快；
2. **先标记、后恢复，`return` 前必经恢复语句**——把递归结果存进 `found` 再统一返回，就是为了不在多个 `return` 处漏掉恢复；
3. `k == word.size() - 1` 的判断在标记**之前**：最后一个格子不需要再延伸，提前返回可少做一轮标记/恢复；
4. 四方向写成数组循环而不是手抄四段，`&& !found` 让找到一个就立刻停。

## 4. 复杂度分析

- **时间复杂度**：$O(m \cdot n \cdot 3^L)$，$L = word.length$。起点至多 $mn$ 个；起点那一步 4 个方向，其后每步有效分支至多 3（回头格已被标记），树深 $L$。字符失配的剪枝让实际运行远快于此上界。
- **空间复杂度**：$O(L)$（不计输入）。递归深度不超过 $L \le 15$；原地修改取代了 `visited` 数组，没有额外网格。

## 5. 常见疑问

**Q1：标记为什么"进入时改、返回时恢复"，而不是搜索完一条路径后统一清除？**

标记的**生存期**必须是"当前路径正在占用"，而不是"曾经走过"。假如标记不随回溯撤销，被一条失败路径踩过的格子会永久变灰——它本可以被另一条路径（甚至同一路径的兄弟分支）以不同的顺序合法使用。统一清除相当于把"占用"误当成"报废"，会漏解导致 `false` 错判。这也解释了为什么不能用一次性的 `visited` 集合做"全局去重"。

**Q2：为什么分支因子是 3，不是 4？**

来时方向的格子刚被标成 `'#'`，下一步去试探它时 `board[i][j] != word[k]` 立刻失败，等价于这个方向被剪掉。所以**第一步 4 分支、其余每步至多 3 分支**，复杂度写成 $4 \cdot 3^{L-1}$，习惯上记 $O(3^L)$。这个"回头路自动断"的性质依赖于"标记在递归期间生效"，又回到 Q1 的生存期问题——两个细节是同一件事的两面。

**Q3：`exist` 参数里的 `board` 为什么必须按引用传、还要是非 const 引用？**

因为原地修改要写 `board`。有同学嫌破坏输入而复制一份，$6 \times 6$ 的规模无所谓，但复制会把"原地标记"的最大优点（零额外状态、标记与递归同生共死）丢掉。工程上若不能改输入，就老实用 `visited` 数组——两种写法在这一题的数据范围下没有性能差异，选哪个看可读性偏好。

## 6. 相关题目与模板

**可复用模板**（网格回溯通用骨架）：

```cpp
bool dfs(Grid& g, int i, int j, int k) {          // 匹配/收集第 k 步
    if (越界 || 不满足条件) return false;
    if (到达终态) return true;
    g[i][j] = VISITED;                            // 占用
    for (auto [di, dj] : {四个方向})
        if (dfs(g, i + di, j + dj, k + 1)) { ... }
    g[i][j] = 原值;                               // 撤销占用
    ...
}
```

网格回溯三板斧：**越界检查、占用标记、四向扩展**。三角形拓扑（方向数组）、标记生存期这两件事想清楚，绝大多数网格搜索题都是这套骨架的变形。

**同类题目：**

- [LeetCode 212. 单词搜索 II](https://leetcode.cn/problems/word-search-ii/)：一次搜几百个单词，逐个跑本题解法会超时，用 **Trie（前缀树）** 把所有单词的公共前缀合并进搜索树
- [LeetCode 695. 岛屿的最大面积](https://leetcode.cn/problems/max-area-of-island/)：只染色不回溯（Flood Fill），对照可见"标记恢复与否"取决于路径是否会分叉复用
- [LeetCode 489. 扫地机器人](https://leetcode.cn/problems/robot-room-cleaner/)：回溯 + 状态标记的进阶综合题
- [LeetCode 51. N 皇后](https://leetcode.cn/problems/n-queens/)：同样是"占用—递归—释放"，约束从四联通换成三条攻击线

**一句话总结**：网格搜索 = **起点枚举 + 四向回溯**，成败全在标记的生存期——占用与释放必须严格包裹住那一次递归调用。
