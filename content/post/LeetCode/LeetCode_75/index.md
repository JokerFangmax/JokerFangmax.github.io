# LeetCode 75. 颜色分类

> 题目链接：[https://leetcode.cn/problems/sort-colors/](https://leetcode.cn/problems/sort-colors/)  
> 难度：中等  
> 标签：数组、双指针、排序

---

## 1. 题目描述

给定一个包含红色、白色和蓝色（共 $n$ 个元素）的数组 `nums`，原地**对它们进行排序**，使得相同颜色的元素相邻，并按照红色、白色、蓝色的顺序排列。

用整数 $0$、$1$、$2$ 分别表示红色、白色和蓝色。必须在不使用库内置的 `sort` 函数、**不使用额外空间**（$O(1)$ 空间）的情况下解决这个问题。

**进阶要求：** 能否只扫描一遍（一趟）完成？

**数据范围：**

- $n = nums.length$
- $1 \le n \le 300$
- $nums[i] \in \{0, 1, 2\}$

**示例：**

```
输入：nums = [2,0,2,1,1,0]
输出：[0,0,1,1,2,2]

输入：nums = [2,0,1]
输出：[0,1,2]
```

元素只有三种取值，这是**值域极小的排序**——通用的比较排序（$O(n \log n)$）在这里是杀鸡用牛刀，值域小的信息值得专门利用。

---

## 2. 思路分析

### 2.1 暴力：直接快排

最省事的做法是调用 `sort`，$O(n \log n)$ 时间、$O(\log n)$ 递归栈空间。但题目明确禁止用内置排序，且完全没利用"只有 0/1/2 三种值"这个关键条件。

### 2.2 计数排序：两趟扫描

值域只有 $\{0,1,2\}$，那就数一数各有多少个，再按数量回填：

1. 第一趟统计：$cnt[0]$、$cnt[1]$、$cnt[2]$；
2. 第二趟回填：先写 $cnt[0]$ 个 $0$，再写 $cnt[1]$ 个 $1$，最后写 $cnt[2]$ 个 $2$。

这就是**计数排序 (counting sort)** 的最简形式，时间 $O(n)$（其实是 $O(n + k)$，$k$ 为值域大小），空间 $O(1)$（只用了 3 个计数器）。两趟扫描，已经满足了时间与空间要求——但进阶问的是**一趟**。

一趟的难点在于：第二趟回填时我们"提前知道"了每种颜色该占的区间，而一趟扫描时信息是**逐渐到来**的。如果来一个 0 就往当前位置写，数组左端会被后到的 0 挤占已写好的位置。我们需要在写入时**腾挪**已经放好的元素——这就是双指针要做的事。

### 2.3 三指针：一趟荷兰国旗

维护三个区间，让数组在扫描过程中始终保持**分区不变量**：

```
[0 .. p0-1]  全是 0   （红色区，已定稿）
[p0 .. i-1]  全是 1   （白色区，已定稿）
[i .. p2]    未扫描
[p2+1 .. n-1] 全是 2  （蓝色区，已定稿）
```

指针 $i$ 从左往右扫，$p0$ 指向"下一个 0 应放的位置"，$p2$ 指向"下一个 2 应放的位置"：

- 遇到 $1$：不用动，它天然属于中段，`i++` 继续扫；
- 遇到 $0$：与 `nums[p0]` 交换，`p0++`。由于 `p0 <= i`，换回来的要么是 $1$（来自已定稿的白色区）要么与 `nums[i]` 相同（$p0 = i$ 时），两种情况换回来的位置都已检查过或无需再查，`i++`；
- 遇到 $2$：与 `nums[p2]` 交换，`p2--`。**但 `i` 不能动**——从 `p2` 换过来的元素来自**未扫描区**，它可能是 $0$、$1$、$2$ 中任何一个，必须留在原地等下一轮判断。

这个"交换后 `i` 动不动"的不对称正是本题最经典的坑，第 5 节详细展开。该算法因由 Dijkstra 提出而被称为**荷兰国旗问题 (Dutch National Flag problem)**。

用 `nums = [2,0,2,1,1,0]` 走一遍（初始 $p0 = 0$，$i = 0$，$p2 = 5$）：

| 步 | nums[i] | 操作 | 数组状态 | p0 | i | p2 |
|----|---------|------|----------|----|----|----|
| 1 | 2 | 与 nums[5]=0 交换，p2-- | [0,0,2,1,1,2] | 0 | 0 | 4 |
| 2 | 0 | 与 nums[0] 自换，p0++，i++ | [0,0,2,1,1,2] | 1 | 1 | 4 |
| 3 | 0 | 与 nums[1] 自换，p0++，i++ | [0,0,2,1,1,2] | 2 | 2 | 4 |
| 4 | 2 | 与 nums[4]=1 交换，p2-- | [0,0,1,1,2,2] | 2 | 2 | 3 |
| 5 | 1 | 属于中段，i++ | [0,0,1,1,2,2] | 2 | 3 | 3 |
| 6 | i > p2 | 循环结束 | **[0,0,1,1,2,2]** | 2 | 3 | 3 |

得到 `[0,0,1,1,2,2]`，与期望一致。注意第 1 步和第 4 步：与 `p2` 侧交换后 `i` 原地不动。第 1 步换回来的 $0$ 恰好需要下一轮处理（第 2 步才把它归位），而第 4 步换回来的 $1$ 只是被 `i` 原地"再确认"了一遍——两种情况 `i` 都不能前进，否则就会漏判一个来自未扫描区的值。

## 3. 代码实现

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int n = nums.size();
        int p0 = 0;          // 下一个 0 的落点：[0, p0) 全是 0
        int p2 = n - 1;      // 下一个 2 的落点：[p2+1, n) 全是 2
        int i = 0;           // 扫描指针：[p0, i) 全是 1，[i, p2] 待扫
        while (i <= p2) {
            if (nums[i] == 0) {
                swap(nums[i], nums[p0]);   // nums[p0] 只能是 1 或自己
                p0++;
                i++;                       // 换回的值已检查过，可以前进
            } else if (nums[i] == 2) {
                swap(nums[i], nums[p2]);   // nums[p2] 来自未扫描区
                p2--;                      // i 不动，下一轮重新判断换来的值
            } else {
                i++;                       // 1 留在中段原地
            }
        }
    }
};
```

两个实现细节：

1. **循环条件是 `i <= p2` 而不是 `i < n`**：`p2` 右侧是已定稿的蓝色区，扫过它没有任何意义，还可能把已经归位的 2 又换出来破坏不变量。
2. **遇到 0 时可以放心 `i++`**：因为 $p0 \le i$ 恒成立，`nums[p0]` 要么是 $1$（已扫描），要么就是 `nums[i]` 本身（$p0 = i$ 时自换），不存在"换回一个没见过的值"。

## 4. 复杂度分析

| 解法 | 时间 | 空间 | 趟数 |
|------|------|------|------|
| 快排 | $O(n \log n)$ | $O(\log n)$ | — |
| 计数排序 | $O(n)$ | $O(1)$ | 两趟 |
| **三指针** | $O(n)$ | $O(1)$ | **一趟** |

- **时间**：指针 $i$ 与 $p2$ 相向而行，每轮循环要么 $i$ 前进、要么 $p2$ 后退，最多共 $n$ 轮，每轮 $O(1)$，总计 $O(n)$。
- **空间**：只用了 $p0, i, p2$ 三个下标变量和 $O(1)$ 次交换，原地完成。

## 5. 常见疑问

**疑问一：为什么遇 2 交换后 `i` 不能 `++`，遇 0 却可以？**

这是本题最核心的差一 (off-by-one) 陷阱。看反例 `nums = [1, 2, 0]`，$i = 1$ 时遇到 2，与 `nums[2] = 0` 交换得到 `[1, 0, 2]`。如果此时 `i++` 到 2，那个换回来的 $0$ 就被跳过了，最终输出 `[1, 0, 2]`——错误。

根源在于交换的两个来源不同：

- 与 `nums[p0]` 交换：$p0 \le i$，那一格属于**已扫描的白色区**，值必然是 $1$（或 $p0=i$ 时是自身），换回来无需再判断；
- 与 `nums[p2]` 交换：那一格属于**未扫描区**，换回来的值是未知的，`i` 必须停在原地再判一次。

**疑问二：为什么遇到 0 不用像遇到 2 那样用 `while` 循环？**

因为 `nums[p0]` 的可能取值被不变量锁死了（只能是 $1$ 或自身），换一次就干净；而 `nums[p2]` 理论上可能连续多个都是 $2$（如 `[1, 2, 2, 2, 0]` 扫到 $i=1$ 时），我们靠"不动 `i`"让下一轮循环自然地继续处理，效果等价于 `while`，代码反而更简洁。

**疑问三：能不能用快排的 partition 思路，先分 0 与非 0，再分 1 与 2？**

可以，两趟 partition 也满足 $O(n)$ 时间、$O(1)$ 空间，思路完全正确。但每趟都要扫全数组，共两趟；荷兰国旗一趟做完，把"三分类"整合进了一轮循环。两者都值得掌握：一趟版本是把快排 partition 的"两分类"推广到"多分类"的通用技巧，快排面对大量重复元素时也用它优化（三路快排）。

## 6. 相关题目与模板

**可复用模板**（三路 partition，可推广到三路快排的 partition 步骤）：

```cpp
// 荷兰国旗骨架：把区间按 <pivot / ==pivot / >pivot 三分
// 本题即 pivot = 1 的特例：0 走左区，2 走右区
int p0 = l, i = l, p2 = r;
while (i <= p2) {
    if (nums[i] < pivot)      swap(nums[i++], nums[p0++]);
    else if (nums[i] > pivot) swap(nums[i], nums[p2--]);
    else                      i++;
}
```

把这个骨架放进快排的递归里，就得到**三路快排**：等于 pivot 的中段不再参与递归，专门治"大量重复元素"的退化。

- [LeetCode 283. 移动零](https://leetcode.cn/problems/move-zeroes/)：同系列双指针交换入门，相当于只分两类（见本博客 [LeetCode 283](../LeetCode_283/)）
- [LeetCode 215. 数组中的第 K 个最大元素](https://leetcode.cn/problems/kth-largest-element-in-an-array/)：快速选择 + 三路 partition 应对重复元素
- [LeetCode 324. 摆动排序 II](https://leetcode.cn/problems/wiggle-sort-ii/)：同样值域受限 + 原地重排的进阶版
- [LeetCode 905. 按奇偶排序数组](https://leetcode.cn/problems/sort-array-by-parity/)：两分类 partition 的直接练习
- [洛谷 P1177 快速排序](https://www.luogu.com.cn/problem/P1177)：在大量重复数据下体会三路 partition 的必要性

**一句话总结**：三指针各自守住一个已定稿区间，`i` 是"未知区"的边界——遇到 0 靠左站、遇到 2 靠右站、遇到 1 原地不动，一趟就把国旗染成了三色。
