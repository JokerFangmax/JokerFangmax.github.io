# LeetCode 295. 数据流的中位数

> 题目链接：[https://leetcode.cn/problems/find-median-from-data-stream/](https://leetcode.cn/problems/find-median-from-data-stream/)  
> 难度：困难  
> 标签：双指针、数据流、堆

---

## 1. 题目描述

**中位数 (median)** 是有序整数列表的中间值。若列表长度为奇数，中位数是中间那个数；若长度为偶数，中位数是中间两个数的平均值。

实现 `MedianFinder` 类：

- `MedianFinder()` 初始化；
- `void addNum(int num)` 从数据流中接收一个整数；
- `double findMedian()` 返回目前所有元素的中位数。

**数据范围：**

- $-10^5 \le num \le 10^5$
- 最多调用 $5 \times 10^4$ 次 `addNum` 和 `findMedian`
- `findMedian` 只在至少插入一个数之后被调用

**示例：**

```
输入：
["MedianFinder", "addNum", "addNum", "findMedian", "addNum", "findMedian"]
[[],           [1],      [2],      [],            [3],      []        ]
输出：[null, null, null, 1.5, null, 2.0]

解释：
addNum(1)、addNum(2) 后数据为 [1,2]，中位数 (1+2)/2 = 1.5；
addNum(3) 后数据为 [1,2,3]，中位数为 2。
```

## 2. 思路分析

### 2.1 暴力：每次查询时现算

两种朴素方案：

| 方案 | addNum | findMedian | 问题 |
|------|--------|------------|------|
| 无序数组 + 每次查询 `nth_element` | $O(1)$ | $O(n)$ | 查询太慢 |
| 有序数组 + 二分插入 | $O(\log n)$ 查找 + $O(n)$ 搬移 | $O(1)$ | 插入太慢 |

$5 \times 10^4$ 次调用时两种都是 $O(n^2)$ 总量级（约 $2.5 \times 10^9$ 次元素搬移/比较），危险。根源和[LeetCode 239](../LeetCode_239/) 一样：**每次操作都从全局视角重算，而数据其实只变了一个元素**。

### 2.2 中位数到底需要哪些信息

追问一句：查询中位数，真的需要整个数组有序吗？**不需要**——只需要两个数：

- 长度为奇数 $n$ 时：第 $\frac{n+1}{2}$ 小的那个数（下半部分的最大值）；
- 长度为偶数 $n$ 时：第 $\frac{n}{2}$ 小与第 $\frac{n}{2}+1$ 小的平均（下半部分最大值 + 上半部分最小值）。

于是把数据**劈成两半**：

> 较小的一半放进**大根堆 (max-heap)** `lo`，较大的一半放进**小根堆 (min-heap)** `hi`。中位数只由 `lo` 的堆顶和 `hi` 的堆顶决定。

这叫**对顶堆**。它精确维护"中间的两个数"，其余元素**只需要知道自己属于哪一半**，内部次序完全交给堆的偏序结构，谁也不会被真正排序。

### 2.3 平衡规则与操作流程

两半的规模必须受控，否则中位数位置就漂了。约定**不变量 (invariant)**：

- $lo.size() = hi.size() + 1$（总数奇数）或 $lo.size() = hi.size()$（总数偶数）；
- `lo` 中所有元素 $\le$ `hi` 中所有元素。

插入一个数要同时满足两条。最省心的写法是"**先过一道流水线**"：新数先进 `lo`，立刻把 `lo` 的堆顶（当前下半部分最大者）转送给 `hi`，再在 `hi` 偏大时把 `hi` 的堆顶退回 `lo`。两次转手天然保证"左小右大"，且奇偶两种情况统一处理，不用写分支。

**用示例走一遍**（依次 `addNum(1)`, `addNum(2)`, `addNum(3)`, `addNum(0)`）：

| 操作 | lo（大根堆，下半） | hi（小根堆，上半） | findMedian |
|------|--------------------|--------------------|------------|
| addNum(1)：入 lo → 顶 1 送 hi → 顶 1 退回 lo | {1} | {} | — |
| addNum(2)：入 lo → 顶 2 送 hi | {1} | {2} | $(1+2)/2 = 1.5$ |
| addNum(3)：入 lo → 顶 3 送 hi → 顶 2 退回 lo | {1,2} | {3} | $2$ |
| addNum(0)：入 lo → 顶 2 送 hi | {0,1} | {2,3} | $(1+2)/2 = 1.5$ |

每步验证：`lo` 的最大值始终 $\le$ `hi` 的最小值，两堆大小差始终 $\le 1$；四个数 $[0,1,2,3]$ 的中位数 $(1+2)/2 = 1.5$，正确。注意第 3 步：3 进来后先到 `lo` 又被顶到 `hi`，最后退回 `lo` 的反而是 2——**流水线自动把该沉下去的沉下去、该浮上来的浮上来**，这正是两条不变量被维护的过程。

## 3. 代码实现

```cpp
class MedianFinder {
    priority_queue<int> lo;                            // 大根堆：较小的一半
    priority_queue<int, vector<int>, greater<int>> hi; // 小根堆：较大的一半

public:
    void addNum(int num) {
        lo.push(num);              // 1. 先进下半
        hi.push(lo.top());         // 2. 下半的最大者上缴，保证 lo <= hi
        lo.pop();
        if (hi.size() > lo.size()) {   // 3. 上半多了，把最小者退回下半
            lo.push(hi.top());
            hi.pop();
        }
    }

    double findMedian() {
        return lo.size() > hi.size()
             ? (double)lo.top()                  // 奇数：下半的堆顶
             : (lo.top() + hi.top()) / 2.0;      // 偶数：两堆顶平均
    }
};
```

几个实现细节：

1. **三步流水线代替 if-else 分类讨论**。经典写法是"若 $num \le lo.top()$ 入 `lo` 否则入 `hi`，再比较两堆大小互相搬一个"，要分四种情况；"先入 lo、上缴、按需退回"的流水线把所有情况压进一条路径，无论 $num$ 多大多小都正确——它多做了 $O(\log n)$ 的常数次堆操作，换来的是**不可能写错的分支结构**。
2. **奇数时中位数在 `lo`**。由不变量 $lo = hi$ 或 $lo = hi + 1$，总数为奇数时多出的那一个落在下半，即 `lo.top()`。
3. **除法必须用 `2.0`**。`int + int` 再 `/ 2` 是整除截断，`/ 2.0` 才走浮点；两堆顶之和至多 $2 \times 10^5$，`double`（53 位尾数）可精确表示，无精度问题。

## 4. 复杂度分析

| 方案 | addNum | findMedian | 总量级（$q$ 次操作） |
|------|--------|------------|----------------------|
| 无序数组 + 查询时选择 | $O(1)$ | $O(n)$ | $O(nq)$ |
| 有序数组 + 二分插入 | $O(n)$ | $O(1)$ | $O(nq)$ |
| 有序 multiset + 双指针 | $O(\log n)$ | $O(1)$* | $O(q \log n)$ |
| **对顶堆** | $O(\log n)$ | $O(1)$ | $O(q \log n)$ |

- **对顶堆**：`addNum` 固定做 3 次堆操作，每次 $O(\log n)$；`findMedian` 只读两个堆顶，$O(1)$。$q = 5 \times 10^4$ 时总量级约 $5 \times 10^4 \times 17 \approx 10^6$，轻松通过。
- multiset 方案见第 5 节疑问三：插入 $O(\log n)$、查询 $O(1)$，但指针维护代码量大，且 C++ 的 `multiset` 删除/移动迭代器极易写错，面试中堆方案几乎总是更好的选择。
- 空间复杂度 $O(n)$：两堆合计存全部元素。

## 5. 常见疑问

**疑问一：为什么必须两个堆，一个大根一个小根？**

中位数是"下半的最大值"和"上半的最小值"——恰好是**两个方向的最值**。大根堆只擅长回答"这批数里谁最大"，小根堆只擅长"谁最小"；把数据劈成两半各问所长，两个堆顶正好就是中位数邻居。单用一个堆（比如只维护前一半的最大值）无法知道上半的最小值，反之亦然。**对顶堆的本质是：与其维护全序，不如只维护"中间那道分界线两侧的局部最值"**。

**疑问二：如果允许删除元素，对顶堆还撑得住吗？**

撑不太住。堆不支持删除任意元素，标准对策是**延迟删除**：用一个哈希表记录"待删除的数及次数"，查询或调整时发现堆顶是待删元素就弹掉重试——LeetCode 480（滑动窗口中位数）就是这套机制的完整演练，代码复杂度直接翻倍。通用结论：**只有插入的数据流用裸对顶堆；带删除的窗口问题要么延迟删除，要么换有序 multiset + 双指针**。

**疑问三：题目标签里的"双指针"对应什么做法？**

对应 multiset 方案：把元素全部插进有序多重集合 `multiset<int>`，再维护**两个迭代器** `it1`、`it2` 分别指向"下中位"与"上中位"的位置——总数奇数时两者重合，偶数时相邻。每次插入后按新元素与中位数的相对大小、总数的奇偶性，把两个指针各向前或向后挪至多一步，`findMedian` 就是 `(*it1 + *it2) / 2.0`。插入 $O(\log n)$、查询 $O(1)$，与对顶堆同级；代价是插入后迭代器可能因**等值元素插入位置**而失效（C++ `multiset` 相等元素插入位置不确定），必须用 `insert` 返回值或比较后重定位指针，边界极多。理解思想即可，实战选堆。

## 6. 相关题目与模板

**可复用模板**（对顶堆骨架，"动态中位数"通用）：

```cpp
priority_queue<int> lo;                             // 大根堆：较小一半，可多存 1 个
priority_queue<int, vector<int>, greater<int>> hi;  // 小根堆：较大一半

void insert(int x) {                 // 不变量：lo.size() - hi.size() ∈ {0, 1}
    lo.push(x);
    hi.push(lo.top()); lo.pop();     // 下半上缴最大者
    if (hi.size() > lo.size()) {     // 上半偏大，退回最小者
        lo.push(hi.top()); hi.pop();
    }
}
// 奇数中位数 = lo.top()；偶数 = (lo.top() + hi.top()) / 2.0
```

同一骨架换个"顶"还能做别的：求**第 k 大**（`lo` 容量固定为 $k$，堆顶即答案，见 [LeetCode 703](https://leetcode.cn/problems/kth-largest-element-in-a-stream/)）；**滑动窗口中位数**（对顶堆 + 延迟删除，LeetCode 480）；**两端优先队列**（LeetCode 502 IPO 同时取全局最大与按序偿还）。

**方法论总结**：

1. 先问"查询真正需要哪些信息"——中位数只需要分界线两侧各一个数；
2. 每个局部最值配一个对应方向的堆，数据劈半、各司其职；
3. 带删除就把堆升级为"堆 + 延迟删除哈希"，或改用有序结构 + 双指针。

**同类题目：**

- [LeetCode 480. 滑动窗口中位数](https://leetcode.cn/problems/sliding-window-median/)：本题 + 滑动窗口过期删除（延迟删除模板题）
- [LeetCode 502. IPO](https://leetcode.cn/problems/ipo/)：双堆按序配对（小根堆做候选池、大根堆取当前最优）
- [LeetCode 703. 数据流中的第 K 大元素](https://leetcode.cn/problems/kth-largest-element-in-a-stream/)：固定容量单堆，对顶堆的退化版
- [LeetCode 295 剑指 Offer 41 同款](https://leetcode.cn/problems/shu-ju-liu-zhong-de-zhong-wei-shu-lcof/)：中文站同题，数据范围更小
- [LeetCode 215. 数组中的第K个最大元素](https://leetcode.cn/problems/kth-largest-element-in-an-array/)：离线一次性版本，见[本系列](../LeetCode_215/)

**一句话总结**：对顶堆把数据劈成两半、各配一个方向相反的堆——**中位数不关心全序，只关心分界线两侧的两个局部最值**，$O(\log n)$ 插入、$O(1)$ 查询。
