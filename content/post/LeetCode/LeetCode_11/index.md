# LeetCode 11. 盛最多水的容器

> 题目链接：[https://leetcode.cn/problems/container-with-most-water/](https://leetcode.cn/problems/container-with-most-water/)  
> 难度：中等  
> 标签：数组、双指针

---

## 1. 题目描述

给定一个长度为 $n$ 的整数数组 `height`，第 $i$ 条垂线的长度为 $height[i]$。从中选出**两条**垂线 $i$ 和 $j$（$i \ne j$），它们与横轴共同构成容器，求容器能盛的最大水量。

容器的容量由两个因素决定：

$$capacity(i, j) = \min(height[i], height[j]) \times |j - i|$$

即**短板高度 × 底宽**。倾斜容器是不允许的，水一旦超过较短的那条线就会溢出。

**数据范围：**

- $2 \le n \le 10^5$
- $0 \le height[i] \le 10^4$

**示例：**

```
输入：height = [1,8,6,2,5,4,8,3,7]
输出：49
解释：选下标 1 和 8（值 8 和 7），
      容量 = min(8,7) * (8-1) = 7 * 7 = 49。

输入：height = [1,1]
输出：1
```

## 2. 思路分析

### 2.1 暴力：枚举所有线对

枚举全部 $\binom{n}{2} \approx \frac{n^2}{2}$ 个组合，每个组合 $O(1)$ 计算容量，总时间 $O(n^2)$。$n = 10^5$ 时约 $5 \times 10^9$ 次运算，必然超时。

问题出在**把每条线对的地位看成平等的**——事实上绝大多数线对从一开始就没有竞争力。双指针的做法正是先证明"一整类线对可以集体排除"，再让搜索空间从平方级坍缩到线性级。

### 2.2 关键观察：短板决定命运，谁短谁该走

初始时取最宽的底：左指针 $l = 0$、右指针 $r = n-1$，此时容量是 $\min(height[l], height[r]) \times (n-1)$——**底已经是全场最大**，接下来只有可能"牺牲底宽换取更高的短板"。

假设当前 $height[l] \le height[r]$（左边是短板），考察所有以 $l$ 为左端点的候选：

| 候选 | 短板 | 底宽 | 与当前容器比较 |
|------|------|------|----------------|
| $(l, r)$（当前） | $height[l]$ | $r - l$ | 基准 |
| $(l, k)$，$l < k < r$ | $\le height[l]$ | $< r - l$ | **两项都不占优，必败** |

为什么 $(l, k)$ 的短板 $\le height[l]$？分两种情况：若 $height[k] \ge height[l]$，短板仍是 $height[l]$，但底更窄；若 $height[k] < height[l]$，短板更矮、底也更窄。**无论 $k$ 是谁，容器 $(l,k)$ 都不可能比 $(l,r)$ 更大。**

结论：**以较短的那条线为端点的所有其他组合，可以一次性全部排除**。于是短板一方完成了使命，可以放心地移动它（$l$ 右移一步）——这就是"谁短谁走"的贪心规则。移动后底宽变小了，但短板有可能变高，仍有机会找到更大的容器。

### 2.3 为什么这样不会漏掉最优解？

把上面的排除论证形式化。设最优解为 $(l^*, r^*)$，只需证明**双指针的移动过程不会把 $l^*$ 或 $r^*$ "错过"**：

- 指针从两端相向移动，只要"还没同时抓住 $l^*$ 和 $r^*$ 时移走的不是它们两个"，最优候选就始终留在剩余区间 $[l, r]$ 内；
- 假设当前 $l = l^*$、$r > r^*$（对称情况同理），分两种情况。若 $height[l^*] \le height[r]$，按规则该移的是 $l$，这看似会错过 $(l^*, r^*)$——其实不会损失：此时 $(l^*, r)$ 的容量为 $height[l^*] \times (r - l^*) \ge \min(height[l^*], height[r^*]) \times (r^* - l^*)$，即 $(l^*, r)$ 不劣于 $(l^*, r^*)$，而 $(l^*, r)$ 正是本轮**移动前刚记录**的候选，最优值已被追平；若 $height[l^*] > height[r]$，按规则移动的是 $r$ 而不是 $l^*$，$l^*$ 安全。

两种情况都无损失，归纳可知每个中间状态的最优候选都保留在了剩余区间里。**排除的是必败组合，保留的是全部潜在最优组合。**

### 2.4 执行过程演示

`height = [1,8,6,2,5,4,8,3,7]`，下标 0-8：

| 步 | l | r | 短板 | 容量 | 答案 | 动作 |
|----|---|---|------|------|------|------|
| 1  | 0 | 8 | 1   | $1 \times 8 = 8$   | 8  | 左短，l++ |
| 2  | 1 | 8 | 7   | $7 \times 7 = 49$  | **49** | 右短，r-- |
| 3  | 1 | 7 | 3   | $3 \times 6 = 18$  | 49 | 右短，r-- |
| 4  | 1 | 6 | 8   | $8 \times 5 = 40$  | 49 | 两端等高（8 与 8），l++ |
| 5  | 2 | 6 | 6   | $6 \times 4 = 24$  | 49 | 左短，l++ |
| 6  | 3 | 6 | 2   | $2 \times 3 = 6$   | 49 | 左短，l++ |
| 7  | 4 | 6 | 5   | $5 \times 2 = 10$  | 49 | 左短，l++ |
| 8  | 5 | 6 | 4   | $4 \times 1 = 4$   | 49 | l++ 后相遇，结束 |

最终答案 $49$。全程只有 $n - 1 = 8$ 次决策，每步淘汰一整列候选组合。

值得注意第 4 步：`height[1] = height[6] = 8` 左右等高时，**移动哪边都不影响正确性**——两边都是短板，任何一边的其余组合都已可排除（代码里 `<=` 统一走左移分支）。

## 3. 代码实现

```cpp
class Solution {
public:
    int maxArea(vector<int>& height) {
        int n = height.size();
        int l = 0, r = n - 1;
        int ans = 0;
        while (l < r) {
            // 短板决定容量；先算再移，避免遗漏当前状态
            int cap = min(height[l], height[r]) * (r - l);
            ans = max(ans, cap);
            if (height[l] <= height[r])
                l++;                 // 左边是短板：以 l 为端点的其余组合必败，弃 l
            else
                r--;                 // 右边是短板：对称地弃 r
        }
        return ans;
    }
};
```

几个实现细节：

1. **先计算容量、后移动指针**。当前 $(l, r)$ 本身就是一个合法候选，必须在移动前记录；先移后算会漏掉初始状态（例如 $n = 2$ 时直接漏掉唯一答案）。
2. **等高时移哪边都对**，用 `<=` 统一处理即可，不必纠结。
3. 溢出检查：容量上界 $\le 10^4 \times 10^5 = 10^9$，恰好卡在 `int` 边界内（$< 2^{31} - 1 \approx 2.1 \times 10^9$），本题不需要 `long long`。但这是个要主动核对的点，不是想当然。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。每轮循环 $l$ 与 $r$ 中恰有一个向另一个靠近 1，合计至多 $n - 1$ 轮。
- **空间复杂度**：$O(1)$。两个下标加一个答案变量。

对比：暴力 $O(n^2)$ → 对撞双指针 $O(n)$。加速的来源不是数据结构，而是**每一步用数学论证批量淘汰候选**——这类"对撞双指针 + 交换论证"的模式在有序数组类问题中反复出现。

## 5. 常见疑问

**疑问一：为什么不能移动较长的一边？** 假设 $height[l] \le height[r]$ 却移走 $r$：新容器 $(l, r-1)$ 的短板仍然 $\le height[l]$（短板被左侧锁死），底还变窄了，**两个因子同时不增**，容量必不大于当前值——这一步没有排除掉任何必败组合，纯属浪费指针预算。更严重的是会漏解：考察 `height = [2,5,2,2,5,2]`，最优解是下标 $(1, 4)$，容量 $5 \times 3 = 15$。当 $l = 1$（高 5）、$r = 5$（高 2）时，若规则是"移长边"，$l$ 这条**未来最优解的左端点**会被提前移掉，此后再无机会与下标 4 配对，全程最大只记到 10。移长边既不安全又漏解，必须移短边。

**疑问二：贪心会不会只找到局部最优？** "贪心"一词在这里容易误导。本题的双指针不是"每步取当前最优选择"的贪心，而是"每步**安全排除**一批不可能最优的组合"的搜索空间收缩——被排除的组合被**证明**不可能超过已见过的答案，所以最终剩下的最大值就是全局最大值。正确性来自排除论证，不来自贪心直觉。

**疑问三：与 LeetCode 42 接雨水有什么区别？** 两者都涉及"短板"和双指针，但完全不同题：

| | LC 11 盛最多水 | LC 42 接雨水 |
|---|---|---|
| 结构 | 选**两条**线 | **每根**线各自算积水 |
| 短板含义 | 两端点的较小值 | 左右两侧最大值的较小值 |
| 目标 | 单个最大容量 | 所有位置积水求和 |
| 双指针用途 | 排除候选端点 | 同步维护两侧前缀最大 |

## 6. 相关题目与模板

**可复用模板**（对撞双指针求最值骨架）：

```cpp
int l = 0, r = n - 1;
while (l < r) {
    // 用 (l, r) 更新答案 —— 必须在移动之前
    if (/* 左侧可以安全排除 */)
        l++;
    else
        r--;
}
```

适用信号：**候选是"一对端点"、且能证明移动某一端不丢失最优解**。证明的核心句式是"另一端固定时，被移走的这端已无法产生更优组合"。

**同类题目：**

- [LeetCode 42. 接雨水](https://leetcode.cn/problems/trapping-rain-water/)：同样是"短板"思想，但按列求和，双指针的用法不同（见上面对比表）
- [LeetCode 167. 两数之和 II](https://leetcode.cn/problems/two-sum-ii-input-array-is-sorted/)：有序数组上对撞双指针的入门题，排除论证更简单（和偏大移右、偏小移左）
- [LeetCode 15. 三数之和](https://leetcode.cn/problems/3sum/)：排序后"固定一个 + 对撞双指针"，是本题排除思想的进阶版
- [LeetCode 977. 有序数组的平方](https://leetcode.cn/problems/squares-of-a-sorted-array/)：非最值的对撞双指针练习

**一句话总结**：盛最多水的容器靠一个反直觉却严格成立的观察制胜——**短板一方的所有其他配对都已注定失败，所以谁短谁走**；$O(n^2)$ 的候选空间就这样被逐步挤压成 $O(n)$。
