# LeetCode 215. 数组中的第K个最大元素

> 题目链接：[https://leetcode.cn/problems/kth-largest-element-in-an-array/](https://leetcode.cn/problems/kth-largest-element-in-an-array/)  
> 难度：中等  
> 标签：数组、分治、快速选择、堆

---

## 1. 题目描述

给定整数数组 `nums` 和整数 `k`，返回数组中**第 `k` 个最大的元素**。

注意：是排序后的第 `k` 个最大元素，**不是第 `k` 个互不相同的元素**。例如 `[3,2,3,1,2,4,5,5,6]` 的第 4 大是 `4`——虽然有两个并列第 2 的 `5`，重复元素照常占位。

**数据范围：**

- $1 \le k \le nums.length \le 10^5$
- $-10^4 \le nums[i] \le 10^4$

**示例：**

```
输入：nums = [3,2,1,5,6,4], k = 2
输出：5

解释：排序得 [1,2,3,4,5,6]，第 2 大的元素是 5。

输入：nums = [3,2,3,1,2,4,5,5,6], k = 4
输出：4
```

---

## 2. 思路分析

### 2.1 暴力：整个数组排序

`sort` 一把梭，取 `nums[n-k]`，$O(n \log n)$ 时间、$O(\log n)$ 栈空间。$n = 10^5$ 时毫无压力，能过。

但排序做了大量**与问题无关的工作**：题目只要"第 $k$ 大"这一个数，排序却把所有元素的相对次序都排好了。就像查一个单词却把整本词典背下来——我们要问：**能不能只对"包含答案的那一半"下功夫？**

### 2.2 堆：只维护前 k 个候选

求第 $k$ 大，本质是维护一个"目前见过的前 $k$ 大"集合：

- 用**容量为 $k$ 的小根堆 (min-heap)**：新元素比堆顶大就替换，否则丢弃；
- 扫描结束后，堆顶恰好是"第 $k$ 大"——堆里是最大的 $k$ 个数，其中最小者就是第 $k$ 大。

时间 $O(n \log k)$，空间 $O(k)$。$k$ 很小时接近线性，但 $k = n$ 时退化为 $O(n \log n)$。这是**流式/在线**场景的标准解（数据一个一个来时，快排选不了，堆还能用，见第 6 节的 LeetCode 703）。

### 2.3 快速选择：排序只递归一半

回到分治。快速排序的**划分 (partition)** 会把基准放到它最终的正确位置 $p$：左边都 $\le$ 它、右边都 $\ge$ 它。也就是说，**划分一次，就有一个元素的最终排名被确定了**。

- 若 $p$ 恰好是目标下标 $n - k$（升序下第 $k$ 大即第 $n-k$ 小，0 起始），答案就是它；
- 否则目标只可能在**其中一侧**——另一侧的所有元素排名已定、与答案无关，整块丢弃。

这与二分查找同构：每轮期望扔掉一半元素，期望复杂度

$$
T(n) = T(n/2) + O(n) \implies T(n) = O(n)
$$

这就是**快速选择 (quickselect)**：快速排序的骨架 + 二分的"只走一边"。

**用示例走一遍**：`nums = [3,2,1,5,6,4]`，$k = 2$，目标下标 $target = 6 - 2 = 4$。

| 轮次 | 处理范围 | 随机基准 | 划分结果（基准归位处标 \*） | 与 target=4 比较 |
|------|---------|---------|------------------------------|------------------|
| 1 | `[3,2,1,5,6,4]` | 4 | `[3,2,1, 4*, 6, 5]`，$p = 3$ | $p < 4$，去右侧 |
| 2 | `[6, 5]` | 5 | `[6, 5*]`（实际下标 4 处归位） | $p = 4$ 命中，返回 5 |

仅两轮划分就锁定答案，比较次数远小于完整排序。最坏情况（每轮基准都选到边界）退化为 $O(n^2)$，**随机选基准**后，任何固定输入被卡死的概率都微乎其微。

## 3. 代码实现

```cpp
class Solution {
    mt19937 rng{random_device{}()};

    // Lomuto 划分：随机选基准换到末尾，返回基准归位后的下标
    int partition(vector<int>& a, int lo, int hi) {
        uniform_int_distribution<int> pick(lo, hi);
        swap(a[pick(rng)], a[hi]);        // 随机基准，规避恶意输入
        int pivot = a[hi], i = lo;        // 不变量：a[lo..i-1] < pivot
        for (int j = lo; j < hi; j++)
            if (a[j] < pivot) swap(a[i++], a[j]);
        swap(a[i], a[hi]);                // 基准归位：左边 < pivot，右边 >= pivot
        return i;
    }

public:
    int findKthLargest(vector<int>& nums, int k) {
        int n = nums.size(), target = n - k;   // 升序下第 n-k 位即第 k 大
        int lo = 0, hi = n - 1;
        while (true) {
            int p = partition(nums, lo, hi);
            if (p == target) return nums[p];
            p < target ? lo = p + 1 : hi = p - 1;   // 只递归目标所在的一侧
        }
    }
};
```

几个实现细节：

1. **`target = n - k`**：第 $k$ 大 = 升序第 $n-k$ 位（0 起始）。这一步的差一错误是本题最高频的 WA 来源。
2. **随机基准**：`pick(rng)` 均匀选下标与末尾交换。固定取 `a[hi]` 时，面对有序输入每轮只排除 1 个元素，$O(n^2)$ 必超时；随机化后期望 $O(n)$。
3. **迭代代替递归**：每轮只需向一侧收缩，用 `while (true)` + 收缩 `lo/hi` 即可，避免递归栈开销，也顺便规避了最坏情况的栈深度问题。
4. 若追求工程简洁，标准库 `nth_element(nums.begin(), nums.begin() + n - k, nums.end())` 一行等价（Introselect：快选 + 堆排兜底，最坏 $O(n)$）。

## 4. 复杂度分析

| 做法 | 时间 | 空间 | 备注 |
|------|------|------|------|
| 全排序 | $O(n \log n)$ | $O(\log n)$ | 代码最短，与问题不匹配 |
| 计数排序（利用值域） | $O(n + V)$ | $O(V)$ | $V = 2 \times 10^4 + 1$，本题也可行 |
| 小根堆（容量 $k$） | $O(n \log k)$ | $O(k)$ | 在线可用的唯一选择 |
| 快速选择（随机） | 期望 $O(n)$，最坏 $O(n^2)$ | $O(1)$ 额外 | **本题最优** |

- **快速选择期望 $O(n)$**：随机基准下每轮期望保留 $\le \frac{3}{4}$ 的元素，总代价为等比级数 $\sum n \cdot (3/4)^i = O(n)$；更精细的论证可得期望比较次数约 $2n + o(n)$，**比堆的 $O(n \log k)$ 更快且不需额外空间**。
- 计数排序值得一提：值域只有 $[-10^4, 10^4]$ 共 $2 \times 10^4 + 1$ 个取值，从大到小累加计数即可，$O(n + V)$ 严格线性——但它依赖**值域小**这个巧合，值域一大空间就爆炸。

## 5. 常见疑问

**疑问一：为什么随机化就能避免 $O(n^2)$？它不是还有最坏情况吗？**

有，但"最坏情况"从**确定的输入**变成了**极小概率的事件**。固定取 `a[hi]` 为基准时，出题人塞一个有序数组就能构造每轮只排除 1 个元素的最坏划分；随机选基准后，划分质量取决于算法自己的随机数，与输入无关——**任何输入**连续 $\log n$ 轮都切到 $1/10$ 以下区域的概率是指数级小的。工程上还有兜底方案 Introselect（退化到一定程度切换中位数的中位数选基准，保证最坏 $O(n)$）。

**疑问二：大量重复元素会不会破坏划分？**

Lomuto 划分把与基准相等的元素全放到右侧，重复元素极多时（如全数组只有 3 种值）划分可能极度不均，退化到 $O(n \log n)$ 甚至 $O(n^2)$。对策是**三路划分**：一轮把数组分成 `< pivot / == pivot / > pivot` 三段，等于基准的整段直接定位排名区间，若 `target` 落在其中即刻返回。本题数据下随机 Lomuto 足够通过，但面试中主动提到三路划分是加分项。

**疑问三：快速选择会修改原数组，怎么办？**

本题允许原地操作。若调用方不允许改动，要么拷贝一份（$O(n)$ 额外空间，堆解法 $O(k)$ 反而更省），要么用堆。这也是"离线快选、在线堆"这条选型准则的另一面：**能看全数据且能改动 → 快选；只能流式到达或不许动原数组 → 堆**。

## 6. 相关题目与模板

**可复用模板**（快速选择骨架，求"第 idx 小"通用）：

```cpp
// 循环不变量：target 始终在 [lo, hi] 内
int lo = 0, hi = n - 1;
while (true) {
    int p = partition(a, lo, hi);         // 随机基准的 Lomuto/三路划分
    if (p == target) return a[p];
    p < target ? lo = p + 1 : hi = p - 1;
}
```

配套的**容量为 k 的小根堆**模板（第 $k$ 大 / 前 $k$ 大的在线版本）：

```cpp
priority_queue<int, vector<int>, greater<int>> pq;   // 小根堆
for (int x : nums) {
    pq.push(x);
    if ((int)pq.size() > k) pq.pop();   // 弹掉最小的，堆里永远留着最大的 k 个
}
// pq.top() 即第 k 大
```

**选型方法论**：

1. 允许改动数组、一次性给全 → 随机快速选择，期望 $O(n)$；
2. 数据流式到达、或要求 $O(k)$ 额外空间 → 容量 $k$ 的堆，$O(n \log k)$；
3. 值域小 → 计数排序，严格 $O(n + V)$。

**一句话总结**：快速选择的本质是**划分一次确定一个元素的最终排名，然后像二分一样只保留包含答案的那一半**——排序的知识只学要用的一半。
