# LeetCode 17. 电话号码的字母组合

> 题目链接：[https://leetcode.cn/problems/letter-combinations-of-a-phone-number/](https://leetcode.cn/problems/letter-combinations-of-a-phone-number/)  
> 难度：中等  
> 标签：哈希表、字符串、回溯

---

## 1. 题目描述

老式手机九宫格键盘上，数字 $2$ 到 $9$ 各对应着若干个英文字母（$2 \to abc$、$3 \to def$、……、$9 \to wxyz$）。给定一个仅包含数字 $2$ 到 $9$ 的字符串 `digits`，返回它能表示的**所有字母组合**，组合顺序任意。

**数据范围：**

- $0 \le digits.length \le 4$
- `digits[i]` 是 $2$ 到 $9$ 之间的数字

**示例：**

```
输入：digits = "23"
输出：["ad","ae","af","bd","be","bf","cd","ce","cf"]

输入：digits = ""
输出：[]

输入：digits = "2"
输出：["a","b","c"]
```

注意 $7$ 和 $9$ 各对应 $4$ 个字母，其余数字对应 $3$ 个——这决定了答案规模的上界是 $4^4 = 256$ 个。

---

## 2. 思路分析

### 2.1 暴力：多重循环的尴尬

组合的总数是每个数字的字母个数连乘。最直白的做法是写循环：第一个数字选一个字母，第二个数字选一个字母……拼起来。问题是 `digits` 长度可变——长度为 2 要两层 `for`，长度为 4 要四层，**循环层数无法在写代码时确定**。

一个躲开"层数不定"的办法是**迭代累乘**：维护当前答案列表，每处理一个新数字，就把列表里每个串分别拼上该数字的每个字母：

| 处理到 | 原列表 | 拼接后 |
|--------|--------|--------|
| `"2"` | `[]`（视为空串） | `["a","b","c"]` |
| `"23"` | `["a","b","c"]` | `["ad","ae","af","bd","be","bf","cd","ce","cf"]` |

这本质是**广度优先**地按层展开笛卡尔积，完全可行。但它每层都要复制整个列表，且不太好推广到"每一步带约束需要回退"的场景。

### 2.2 回溯：把"选字母"想成一棵树

换个视角：处理第 $i$ 位数字时，面前有 $3$ 或 $4$ 个分支，选一个字母进入下一层，处理完所有位就得到一个组合。这是一个**隐式的多叉树**，深度恰好是 `digits` 的长度，叶子节点就是答案。

**回溯 (backtracking)** 的骨架是"选择—递归—撤销"：

1. 若当前位置 $i = n$，说明每个数字都配了字母，收集路径；
2. 否则取出 `digits[i]` 对应的字母表，枚举其中**每一个**字母：拼到路径末尾 → 递归处理 $i+1$ → 弹掉末尾恢复现场。

"撤销"这一步在本题里看似多余（拼上再弹掉，其他分支反正会覆盖），但它是回溯的标准动作——一旦题目加上约束（比如不允许某个字母出现两次），路径就是必须保护的共享状态。用 `string path` 而不是每层新建字符串，也是为了让撤销变成 $O(1)$ 的 `pop_back()`。

### 2.3 数字到字母的映射：用数组而不是哈希表

映射本身可以用 `unordered_map<char, string>`，但键只有 `2`~`9` 八个、且是连续的小整数，**用下标直接寻址的数组更快也更短**：

```cpp
const string MAP[10] = {"", "", "abc", "def", "ghi", "jkl",
                        "mno", "pqrs", "tuv", "wxyz"};
```

这是哈希表思想的退化版：键域小而稠密时，数组就是最完美的哈希表，$O(1)$ 且零冲突（哈希表的应用模式可参见[哈希表模板笔记](../../algorithms/hash_table/)）。

### 2.4 逐步走一遍：digits = "23"

递归树（`path` 用栈式拼接）：

```
                        ""            ← i=0，处理 '2'
              ┌─────────┼─────────┐
             'a'       'b'       'c'        ← i=1，处理 '3'
           ┌──┼──┐  ┌──┼──┐  ┌──┼──┐
          ad  ae  af bd  be  bf  cd  ce  cf   ← i=2 = n，收集
```

| 步骤 | path | 动作 |
|------|------|------|
| 递归 $i=0$ | `""` | 选 `'a'`，path = `"a"` |
| 递归 $i=1$ | `"a"` | 选 `'d'`，path = `"ad"` |
| 递归 $i=2$ | `"ad"` | $i = n$，收集 `"ad"`，返回 |
| 回溯 | `"a"` | 弹掉 `'d'`，选 `'e'`…… |
| …… | …… | 依次得到 `"ae","af"`，回到 $i=0$ 换 `'b'` |

共 $3 \times 3 = 9$ 个组合，与示例输出一致。

## 3. 代码实现

```cpp
class Solution {
    const string MAP[10] = {"", "", "abc", "def", "ghi", "jkl",
                            "mno", "pqrs", "tuv", "wxyz"};
    vector<string> ans;
    string path;

    void dfs(const string& digits, int i) {
        if (i == (int)digits.size()) {          // 每个数字都已配上字母
            ans.push_back(path);                // 此时 path 必非空（见下）
            return;
        }
        for (char c : MAP[digits[i] - '0']) {   // 枚举该数字的所有字母
            path.push_back(c);                  // 做选择
            dfs(digits, i + 1);                 // 处理下一位数字
            path.pop_back();                    // 撤销选择
        }
    }

public:
    vector<string> letterCombinations(string digits) {
        if (digits.empty()) return {};          // 特判：空输入没有组合
        dfs(digits, 0);
        return ans;
    }
};
```

三个细节：

1. **空输入返回空列表**，且必须在递归前拦下——若不特判，`i == n == 0` 会在第一步就成立，返回 `[""]`（一个空字符串）而不是 `[]`，这是本题最经典的 WA。
2. `MAP` 用成员数组初始化，键是 `digits[i] - '0'`，避开每次查 `unordered_map` 的哈希开销。
3. `path.pop_back()` 与 `push_back` 严格配对，保证回到上一层时路径与来时相同。

## 4. 复杂度分析

设 $n = digits.length$。

- **时间复杂度**：$O(4^n \cdot n)$。答案总数是各数字字母数的乘积，上界为 $4^n$（每位都是 7 或 9）；每条路径收集答案时要复制一次 `path`，代价 $O(n)$。$n \le 4$ 时最多 $256 \times 4 \approx 10^3$ 级别，瞬间跑完。
- **空间复杂度**：$O(n)$（不计输出）。递归深度与 `path` 长度都是 $n$；`MAP` 是常数大小。

## 5. 常见疑问

**Q1：空串为什么返回 `[]` 而不是 `[""]`？**

这是语义问题：`""` 表示"没有按键"，没有按键就没有任何组合；而"由零个字母构成的组合"——即一个空字符串——只在"有按键但都对应零个字母"这种本题不存在的情况下才说得通。测试用例明确要求 `digits = ""` 时输出 `[]`，所以必须在入口特判，靠递归终止条件会得到 `[""]`。

**Q2：为什么这题的回溯不需要"剪枝"？**

剪枝 (pruning) 的前提是**约束**——某些分支注定违反条件，提前砍掉。本题只要求"枚举全部组合"，树上每条从根到叶的路径都是合法答案，一个分支都不用砍。所以本题是回溯的**纯枚举形态**，最适合用来理解"选择—递归—撤销"骨架本身；后续的组合总和、括号生成就会看到约束如何带来剪枝。

**Q3：迭代法和回溯法哪个好？**

迭代累乘每层要重建整个列表，总拷贝量与 $4^n \cdot n$ 同阶，渐近上不占便宜；回溯共享一个 `path`，撤销是 $O(1)$。更重要的是回溯框架可扩展——若题目改成"字母不能重复使用"或"按字典序输出前 k 个"，回溯只需在循环里加判断或提前 return，迭代法则要推翻重写。

## 6. 相关题目与模板

**可复用模板**（无约束全枚举回溯骨架）：

```cpp
void dfs(int i) {                  // i：当前决策到第几层
    if (i == n) { ans.push_back(path); return; }
    for (auto& choice : candidatesOf(i)) {
        path.push_back(choice);    // 选择
        dfs(i + 1);                // 下一层
        path.pop_back();           // 撤销
    }
}
```
