# LeetCode 76. 最小覆盖子串

> 题目链接：[https://leetcode.cn/problems/minimum-window-substring/](https://leetcode.cn/problems/minimum-window-substring/)  
> 难度：困难  
> 标签：哈希表、字符串、滑动窗口

---

## 1. 题目描述

给你一个字符串 `s` 和一个字符串 `t`，返回 `s` 中涵盖 `t` 所有字符（**含重复字符**）的最短子串。如果 `s` 中不存在涵盖 `t` 所有字符的子串，返回空字符串 `""`。

**数据范围：**

- $1 \le s.length, t.length \le 10^5$
- `s` 和 `t` 由英文字母组成（含大小写）

**示例：**

```
输入：s = "ADOBECODEBANC", t = "ABC"
输出："BANC"

输入：s = "a", t = "a"
输出："a"

输入：s = "a", t = "aa"
输出：""     // t 有两个 a，s 只有一个，覆盖不了
```

---

## 2. 思路分析

### 2.1 问题的结构：要求"包含"，且要"最短"

先确认两件事：

1. **子串（连续）**，不是子序列；
2. t 中的**重复字符要按次数覆盖**——`t = "aa"` 要求子串里至少有两个 `a`。

"是否覆盖"是一个关于**字符频次**的条件：窗口 `win` 覆盖 `t` 当且仅当对每个字符 $c$，`win` 中 $c$ 的个数 $\ge$ `t` 中 $c$ 的个数。

### 2.2 暴力与 $O(n^2)$ 优化

暴力：枚举所有 $O(n^2)$ 个子串，每个窗口重新数一遍字符，$O(n^3)$。枚举起点向右扩展、边扩展边更新计数，可以做到 $O(n^2 \cdot |\Sigma|)$——$n = 10^5$ 时仍然超时。

### 2.3 关键性质：窗口的"可满足性"随扩张/收缩单调

这是滑动窗口能用的**根本前提**。定义谓词：

> $P(l, r)$ = 子串 $s[l..r]$ 覆盖 `t`。

两条单调性（覆盖只看数量，加字符只会更多、删字符只会更少）：

1. **扩张保真**：若 $P(l, r)$ 成立，则向**任一端**扩张后仍成立——$P(l, r')$ 对 $r' \ge r$ 成立，$P(l', r)$ 对 $l' \le l$ 也成立；
2. **收缩保假**（第 1 条的逆否）：若 $P(l, r)$ 不成立，则向**任一端**收缩后仍不成立——子窗口的字符集是原窗口的子集，只会更少。

> ⚠️ 方向别写反："不成立 ⟹ 左扩后也不成立"是**错的**——窗口变大、字符变多，原本不覆盖的可能变得覆盖（反例：`s = "AB", t = "AB"`，窗口 `"B"` 不覆盖，左扩成 `"AB"` 就覆盖了）。能传递给更大窗口的是"成立"，能传递给更小窗口的是"不成立"。

这两条性质如何支撑双指针：

- 由**左端扩张保真**：对固定 $r$，满足 $P$ 的 $l$ 构成前缀 $[0, l_{\max}(r)]$，以 $r$ 结尾的最短覆盖窗口就是 $l = l_{\max}(r)$，收缩到它即停；
- 由**右端扩张保真**：$r$ 增大时 $l_{\max}(r)$ 单调不减（旧的合法 $l$ 在新 $r$ 下依然合法），所以**左指针永远不需要向左回退**。

于是存在经典的**双指针不回退**结构：

- 右指针 `r` 只往右走，负责**扩张**直到覆盖；
- 左指针 `l` 只往右走，负责**收缩**直到恰好不覆盖；
- 每个"覆盖 → 收缩到不能再缩 → 记录答案 → 再扩张"的循环中，`l` 和 `r` 各自单调右移，总移动次数各 $\le n$。

**为什么这一题能用滑动窗口而 LC 560 不能？** 因为这里的窗口条件（字符频次比较）**对扩张和收缩都单调**——多加字符永远不坏、多删字符永远不好。LC 560 的条件是"和恰好等于 k"，加负数会让和变小，双向都不单调，窗口没有"该进则进、该退则退"的判断依据。**滑动窗口的适用判据是条件的单调性，不是"题目长得像窗口"。**

### 2.4 覆盖性的 $O(1)$ 判断：欠账计数

扩张/收缩各发生 $O(n)$ 次，若每次都遍历 52 个字母比较 `need[c]` 与 `win[c]`，总代价 $O(52n)$ 也能过，但有个更优雅的 $O(1)$ 维护法——**只维护"欠账"**：

- 变量 `less` = 还有**几种**字符存在缺口（即满足 `win[c] < need[c]` 的字符种类数），初始为 `t` 中不同字符的种类数；
- 扩张纳入字符 `c` 时：`win[c]++` 之后若恰好**等于** `need[c]`，该种类的缺口被补满，`less--`（注意是"等于"而不是"小于"——缺口需要 3 个 `a`、只来了 2 个时缺口仍在，不能提前减）；
- 收缩丢弃字符 `c` 时：`win[c]--` 之后若**恰好等于** `need[c] - 1`，该种类从"刚好够"跌回"有缺口"，`less++`；
- **`less == 0` ⟺ 每个种类都补满 ⟺ 覆盖**。

这样"是否覆盖"变成整型比较，代价 $O(1)$。

### 2.5 执行过程演示

`s = "ADOBECODEBANC"`，`t = "ABC"`。

**记号**：代码块第一行用 `[ ... ]` 括住当前窗口；`need = {A:1, B:1, C:1}`；`less` = 还有几种字符存在缺口，**`less = 0` 即覆盖**。

代码每轮的固定动作顺序：**纳入 `s[r]` 更新计数 → 若覆盖则进入收缩循环（记录答案 → 弹 `s[l]`）**。下面按轮走查，无事件的轮次合并。

---

**r = 0..4，纳入 `A D O B E`**

```
[ A D O B E ] C O D E B A N C

A: 0→1，恰好等于 need → less: 3→2     （A 的缺口补满）
B: 0→1，恰好等于 need → less: 2→1     （B 的缺口补满）
D、O、E: need = 0，无关字符，less 不动
覆盖? 否（less=1，还缺 C）→ 右指针继续
```

**r = 5，纳入 `C` —— 第一次覆盖**

```
[ A D O B E C ] O D E B A N C

C: 0→1，恰好等于 need → less: 1→0     ✓ 覆盖成立！
收缩循环:
  窗口 ADOBEC 长 6 → 记录 best = "ADOBEC"
  弹 A → A: 1→0，跌回缺口 → less = 1，覆盖打破，收缩急停
```

> **急停位置**是关键：弹 `A` 的那一步让 `less` 从 0 变 1，`while` 条件立即失效。于是 `l` 停在 1，窗口 `DOBEC` 是"以 r=5 结尾、弹出 A 之前"的最后一个合法状态——这正是"以当前 r 结尾的最短覆盖"。

**r = 6..9，纳入 `O D E B`**（窗口从 `DOBEC` 右端继续加长）

```
  D O B E C O D E [ B ] A N C
  ~~~~~~~~~~~~~~~~        （l 停在 1，窗口 = DOBECODEB）

B: 1→2，已超过 need，不跨越 need 线 → less 不动（仍缺 A）
覆盖? 否 → 右指针继续
```

> 注意 `less` 的增减**只在"恰好跨过 need 线"的瞬间发生**：B 从 1 到 2 在线的上方，无关痛痒。

**r = 10，纳入 `A` —— 第二次覆盖**

```
  D O B E C O D E B [ A ] N C
  ~~~~~~~~~~~~~~~~~~          （窗口 = DOBECODEBA）

A: 0→1，恰好等于 need → less: 1→0     ✓ 覆盖成立！
收缩循环:
  窗口 DOBECODEBA 长 10 > 6，不记录 → 弹 D（无关，less 不动）
  窗口 OBECODEBA  长 9  > 6，不记录 → 弹 O（无关，less 不动）
  窗口 BECODEBA   长 8  > 6，不记录 → 弹 B（B: 2→1，仍 ≥ need，不跌缺口！）
  窗口 ECODEBA    长 7  > 6，不记录 → 弹 E（无关，less 不动）
  窗口 CODEBA     长 6，不优于 6，不记录 → 弹 C（C: 1→0，跌回缺口）
  → less = 1，急停。l 停在 6，窗口 ODEBA
```

> 这一轮有两个值得盯住的点：**重复字符**（B 有 2 个）弹掉一个后仍在线上，`less` 纹丝不动；收缩一路上弹了 5 个字符，`less` 只在最后弹 `C` 时 +1。

**r = 11，纳入 `N`**

```
  O D E B A N [ C ]   →  覆盖? 否（less=1，缺 C——上一轮刚弹掉）
```

**r = 12，纳入 `C` —— 第三次覆盖，也是最后一轮**

```
  O D E B A N C
              （r=11 已纳入 N；r=12 纳入 C 后窗口 = ODEBANC）

C: 1→2？不——C 上一轮被弹光了，此处 0→1，恰好等于 need → less: 1→0   ✓ 覆盖！
收缩循环:
  窗口 ODEBANC 长 7 > 6，不记录 → 弹 O（无关）
  窗口 DEBANC  长 6，不优于 6，不记录 → 弹 D（无关）
  窗口 EBANC   长 5 < 6 → 记录 best = "EBANC" → 弹 E（无关）
  窗口 BANC    长 4 < 6 → 记录 best = "BANC"  → 弹 B（B: 1→0，跌回缺口）
  → less = 1，急停。r 已到末尾，算法结束
```

**最终答案 `BANC`**（长 4）。

---

回看全程，值得带走的三个观察：

1. **`less` 只在"跨线"瞬间变化**：纳入时从 `need−1` 跨到 `need` 才 −1，弹出时从 `need` 跌回 `need−1` 才 +1。超量纳入（B 的第 2 个）、无关字符（D/O/E/N）都纹丝不动——这就是它能 $O(1)$ 判断覆盖的原因。
2. **收缩在"恰好打破覆盖"处急停**：急停前的最后一个合法窗口 = 以当前 `r` 结尾的最短覆盖，所以答案必须在收缩循环**内部**、弹字符**之前**记录（r=12 轮里 `EBANC` 和 `BANC` 都是边缩边记的）。
3. **两指针各只走一遍**：`r` 从 0 走到 12 单调右移，`l` 从 0 走到 10 单调右移，合计 13 + 10 步——"指针不回退"就是 $O(n)$ 复杂度的全部来源。

## 3. 代码实现

```cpp
class Solution {
public:
    string minWindow(string s, string t) {
        int need[128] = {}, win[128] = {};
        for (char c : t) need[(unsigned char)c]++;

        int less = 0;                       // 欠账：win[c] < need[c] 的缺口总数
        for (int c = 0; c < 128; c++)
            if (need[c] > 0) less++;

        int n = s.size();
        int bestLen = INT_MAX, bestL = 0;
        for (int l = 0, r = 0; r < n; r++) {
            unsigned char c = s[r];
            win[c]++;
            if (need[c] > 0 && win[c] == need[c]) less--;  // 恰好补满该种类的缺口
            while (less == 0) {              // 覆盖成立，收缩到极限
                if (r - l + 1 < bestLen) {
                    bestLen = r - l + 1;
                    bestL = l;
                }
                unsigned char d = s[l++];
                win[d]--;
                if (need[d] > 0 && win[d] == need[d] - 1) less++;  // 该种类重新出现缺口
            }
        }
        return bestLen == INT_MAX ? "" : s.substr(bestL, bestLen);
    }
};
```

几个实现细节：

1. **数组代替 `unordered_map`**：字符集只有 ASCII 128 个，`int need[128]` 比 `unordered_map<char,int>` 快好几倍且无需哈希开销。这是[哈希表模板](../../algorithms/hash_table/)里"能用数组别用哈希"原则的直接应用。
2. **`less` 初始化为"有需求的字符种类数"**，不是 `t` 的长度——它数的是**种类级的缺口**（每个 $c$ 最多贡献 1 个缺口），不是字符个数。
3. **`less` 的更新时机是"增减之后再判断"**：扩张时 `win[c]++` 之后若恰好**等于** `need[c]`，该种类的缺口才算补满，才 `less--`。这是一个容易写错的点：若写成"纳入前 `win[c] < need[c]` 就 `less--`"，在 `t = "aa"`、窗口里只进来 1 个 `a` 时就会提前宣告覆盖（缺口需要 2 个、只补了 1 个），`s = "a", t = "aa"` 会错误地返回 `"a"` 而非空串。
4. **答案在收缩过程中记录**：覆盖成立后每收缩一步都可能是"最短覆盖"，所以在 `while (less == 0)` 循环内部、`l++` 之前记录。
5. `(unsigned char)` 强转：`char` 可能是有符号的，直接当下标用负数索引是 UB。

## 4. 复杂度分析

- **时间复杂度**：$O(n + m)$，$n = |s|, m = |t|$。左指针和右指针各自最多前进 $n$ 步，永不回退；每步的窗口更新和覆盖判断都是 $O(1)$（欠账计数）。
- **空间复杂度**：$O(|\Sigma|) = O(128)$，两个定长计数数组。

注意双指针的总代价是"两指针移动总步数"，不是"窗口数量 × 窗口长度"——**指针不回退**是滑动窗口区别于暴力枚举的本质，也是均摊分析的另一个标准例子（和单调队列"每个元素最多进出队一次"同构）。

## 5. 滑动窗口的适用判据（重要总结）

以本题为契机，把"什么时候能用滑动窗口"说透。滑动窗口可行当且仅当窗口的**可满足性谓词** $P(l, r)$ 具有双向单调性：

> $P$ 对扩张封闭（窗口变大概率不假）、对收缩封闭（窗口变小概率不真）。

对照三道题：

| 题 | 条件 | 单调性 | 做法 |
|----|------|--------|------|
| **LC 76**（本题）| 窗口覆盖 `t` 的频次 | ✅ 加字符只会更好 | 滑动窗口 $O(n)$ |
| **LC 560** | 子数组和**恰好**为 `k` | ❌ 有负数，加/删不单调 | 前缀和 + 哈希表 |
| **LC 239** | 问窗口**最值** | 与单调性无关 | 单调队列 |

更细的判定：

- 求指标恰好等于某值 → 滑窗失效，考虑前缀和 + 哈希；
- 求指标 ≥ / ≤ 某阈值的最长/最短窗口 → 大概率滑窗（"至少/至多"型条件天然单调）；
- 窗口内维护的是**最值**且元素符号不定 → 单调队列。

**一句话判据：把"扩张"和"收缩"两个动作代入条件，若两边都不产生反例，滑窗成立；任何一边出现反例，立即换思路。**
