# LeetCode 25. K 个一组翻转链表

> 题目链接：[https://leetcode.cn/problems/reverse-nodes-in-k-group/](https://leetcode.cn/problems/reverse-nodes-in-k-group/)  
> 难度：困难  
> 标签：递归、链表

---

## 1. 题目描述

给你链表的头结点 `head` 和一个整数 $k$，**每 $k$ 个结点一组进行翻转**，请你返回修改后的链表。

$k$ 是一个正整数，它的值小于或等于链表的长度。如果结点总数不是 $k$ 的整数倍，那么请将**最后剩余的结点保持原有顺序**。

你不能只是改变结点内部的值，而是需要**实际进行结点交换**。进阶：你可以设计一个只使用 $O(1)$ 额外空间的算法解决此问题吗？

**数据范围：**

- 链表中的结点数目为 $n$，$1 \le k \le n \le 5000$
- $0 \le Node.val \le 1000$

**示例：**

```
输入：head = [1,2,3,4,5], k = 2
输出：[2,1,4,3,5]

输入：head = [1,2,3,4,5], k = 3
输出：[3,2,1,4,5]
```

第二个示例是本题的全部难点浓缩：$n = 5, k = 3$，第一组 $[1,2,3]$ 翻转成 $[3,2,1]$，剩下的 $[4,5]$ **不足一组，必须原样保留**。

---

## 2. 思路分析

### 2.1 暴力：节点塞进数组再重排

把所有节点指针存进数组，按组翻转下标区间，再按新顺序串回 `next`。正确、好写，时间 $O(n)$——但额外空间 $O(n)$，违反进阶要求；且"翻转"靠的是数组的随机访问，链表指针操作本身一点没练。它还埋了一个坑：串回去时**每组最后一环与下一组的衔接**还是要小心。

更细的暴力变体是"每组攒一个 `vector`，`reverse` 后再接线"，空间 $O(k)$，稍好，但本质相同。

### 2.2 子问题拆解：本题 = LC 206 的组内翻转 + 组间接线

两个子能力，各自都是简单题：

1. **组内翻转**：就是 [LeetCode 206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/) 的三指针循环——`prev` 初始指向"组尾应指向的后继"，逐节点把 `next` 反指；
2. **组间调度**：需要一个指针记住"上一组翻转后的尾"，把翻转好的每组接到它后面——这正是哑节点 + `prev` 推进的骨架（与 LeetCode 24 一脉相承）。

### 2.3 关键边界：先验货，再动手

本题标"困难"的原因不在翻转，而在**尾部不足 $k$ 个的处理**。两种策略对比：

| 策略 | 做法 | 代价 |
|------|------|------|
| 先翻再查 | 先把一组翻完，发现不足 $k$ 个，再翻回去 | 每个节点可能被摸两遍，还要精确回退指针，极易错 |
| **先查再翻** | 探测前方是否凑得够 $k$ 个；够才动手翻 | 每个节点只被摸常数次，尾组天然原样保留 |

显然选后者：**动手之前先数够 $k$ 个**，数不够直接收工——"保持原有顺序"这个要求被探测这一步免费满足了。

### 2.4 组内翻转逐步走（LC 206 的复习）

翻转子链 $1 -> 2 -> 3$（后继 `after = 4`），三指针 `prev`/`cur`/`nxt`：

| 步骤 | prev | cur | 操作 | 链表状态（已断开画在右侧） |
|------|------|-----|------|---------------------------|
| 初始 | 4 | 1 | — | (1 -> 2 -> 3) ，prev = 4 |
| 1 | 4 | 1 | `1->next = 4`，prev=1, cur=2 | (2 -> 3)，1 -> 4 |
| 2 | 1 | 2 | `2->next = 1`，prev=2, cur=3 | (3)，2 -> 1 -> 4 |
| 3 | 2 | 3 | `3->next = 2`，prev=3, cur=4 | 3 -> 2 -> 1 -> 4 |

循环条件 `cur != after`。结束后 `prev` 就是翻转后的组头（原组尾 `3`），原组头 `1` 变成组尾且已指向 `after`——**这一步顺手把组间接线做了一半**。

### 2.5 整体流程走一遍

`head = 1 -> 2 -> 3 -> 4 -> 5`，$k = 3$，哑节点 `d`，`prevGroup` 指向上一组翻转后的尾：

| 轮次 | 探测 | 组内翻转 | 接线 | 链表状态 |
|------|------|---------|------|----------|
| 1 | 从 d 走 3 步到 3，够一组 | 翻 $[1,3]$ 得 $3 -> 2 -> 1$，`after = 4` | `d->3`，prevGroup = 1 | d -> 3 -> 2 -> 1 -> 4 -> 5 |
| 2 | 从 1 走：4、5，第 3 步踩空 | 不动手 | 直接返回 | d -> 3 -> 2 -> 1 -> 4 -> 5 |

返回 `dummy.next`，即 `3 -> 2 -> 1 -> 4 -> 5`，尾组 $[4,5]$ 完好无损。

### 2.6 递归视角

分组调度也能递归 (recursion)：从 `head` 数 $k$ 个，若不足直接返回 `head`；若足够，翻转前 $k$ 个（LC 206 循环），此时原组头成为组尾，让它接住 `reverseKGroup(下一组的头, k)` 的返回值即可。递归深度 $n / k$，本题 $n \le 5000$ 安全。

## 3. 代码实现

```cpp
class Solution {
public:
    ListNode* reverseKGroup(ListNode* head, int k) {
        ListNode dummy(0, head);
        ListNode* prevGroup = &dummy;          // 上一组翻转后的尾

        while (true) {
            // 1. 先验货：前方是否凑得够 k 个节点
            ListNode* end = prevGroup;
            for (int i = 0; i < k && end; i++)
                end = end->next;
            if (!end) return dummy.next;      // 不足 k 个：原样保留，收工

            // 2. 组内翻转 [prevGroup->next ... end]，三指针循环
            ListNode* after = end->next;       // 下一组的头，先存下
            ListNode* prev = after;            // 组尾翻转后应指向 after
            ListNode* cur  = prevGroup->next;
            while (cur != after) {
                ListNode* nxt = cur->next;     // 先存后改，防断链
                cur->next = prev;
                prev = cur;
                cur = nxt;
            }
            // 循环结束：prev = 翻转后的组头（原 end）

            // 3. 接线：上组尾 -> 新组头；原组头变新组尾
            ListNode* oldHead = prevGroup->next;
            prevGroup->next = prev;
            prevGroup = oldHead;               // 原头是下一轮的前驱
        }
    }
};
```

三个不变量值得在面试时口述出来：

1. **`prevGroup` 永远指向"已处理完成的链表的尾"**，所以第 2 步翻转时 `prev` 初始化为 `after`、翻完 `prevGroup->next = prev`，首尾两条接线一次到位；
2. **`after` 在翻转前保存**——它是找到下一组的唯一线索，组内翻转会破坏所有指向它的指针；
3. **探测从 `prevGroup` 出发**，与翻转的起点天然对齐，不需要额外的组头变量。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。每个节点被探测一次、被翻转一次，加上 $O(1)$ 的接线，总计常数次访问。注意探测是"每组从 `prevGroup` 重新数 $k$ 步"，看似双层循环，但每轮探测与翻转消耗的都是**本组自己的** $k$ 个节点，全程没有回头路。
- **空间复杂度**：$O(1)$。哑节点 + 常数个指针，满足进阶要求（递归版为 $O(n/k)$ 调用栈）。

对比：数组重排 $O(n)$ 空间 → 就地三指针 $O(1)$ 空间，时间同为线性——这道"困难"卡的不是复杂度，是实现纪律。

## 5. 常见疑问

**Q1：为什么要"先探测再翻转"，边翻边数不行吗？**

边翻边数的意思是：翻一个数一个，数到 $k$ 收手。听起来对称，但**最后不足 $k$ 个的那组已经翻了一半**——你必须把它再翻回去（又一次指针手术，且此时组的边界指针已被改乱，极易翻错段）。先探测的版本里，尾组从头到尾没被碰过，"保持原有顺序"零成本。这是本题与 [LeetCode 24](https://leetcode.cn/problems/swap-nodes-in-pairs/)（$k = 2$ 且尾组最多剩 1 个，怎么都构不成"翻了一半"的尴尬）的本质区别，也是 24 是中等、25 是困难的主要原因。

**Q2：`prev` 初始化为 `after` 而不是 `nullptr`，这是为什么？**

普通反转整条链表（LC 206）时 `prev = nullptr`，因为翻完后原头指向空。本题翻转的是**链表中段**，原组尾接下来必须指向**下一组的头**，即 `after`。把它当 `prev` 的初值，等价于把"组间接线"合并进组内翻转的第一步——翻完自然就接好了，不需要事后补 `oldHead->next = after` 这一行（容易忘，忘了就是断链）。

**Q3：探测循环写成 `for (i < k && end)`，那个 `&& end` 是防什么的？**

防尾组**踩空指针**。尾组剩余 $r < k$ 个节点时，第 $r + 1$ 步 `end = end->next` 会得到 `nullptr`，没有 `&& end` 就会对空指针解引用。另一种等价写法是先 `if (!end) break;` 的 while 循环。另外提醒：$k = 1$ 时每组"翻转"是恒等操作，代码天然正确，不需要特判——好代码的一个标志就是让平凡情形自动成立。

## 6. 相关题目与模板

**可复用模板**（分组处理骨架，"探测 + 组内手术 + prevGroup 接线"三段式）：

```cpp
ListNode dummy(0, head), *prevGroup = &dummy;
while (true) {
    ListNode* end = prevGroup;
    for (int i = 0; i < k && end; i++) end = end->next;  // 探测
    if (!end) break;                                      // 不够一组，收工
    // ... 对 [prevGroup->next, end] 做任意组内手术 ...
    prevGroup = 本组手术后的新尾;
}
return dummy.next;
```

任何"每 $k$ 个一组做某事、尾组特殊处理"的链表题（翻转、旋转、删除、交换）都可以套这个三段式。

**方法论总结**：本题是链表原地操作的集大成者——LC 206 提供组内翻转，LC 24 的哑节点 + `prev` 提供组间接线，再叠加"先探测后动手"的边界纪律。**把困难题拆成熟悉的子能力**，是比背模板更重要的元能力。

**同类题目：**

- [LeetCode 206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/)：组内翻转的原子操作，本题的前置
- [LeetCode 92. 反转链表 II](https://leetcode.cn/problems/reverse-linked-list-ii/)：只翻一段区间，与"一组"的翻转几乎同构
- [LeetCode 24. 两两交换链表中的节点](https://leetcode.cn/problems/swap-nodes-in-pairs/)：$k = 2$ 的特例，尾组边界更宽松
- [LeetCode 61. 旋转链表](https://leetcode.cn/problems/rotate-list/)：另一种"成段重排"，先成环再断开
- [LeetCode 143. 重排链表](https://leetcode.cn/problems/reorder-list/)：中点 + 反转 + 交错合并三个子能力的综合

**一句话总结**：K 个一组翻转 = 先探测够不够一组（尾组自动幸免）+ 三指针就地翻转（`prev` 初值就是下一组的头）+ `prevGroup` 逐组推进接线——困难题拆开看，每一步都只是中等题。
