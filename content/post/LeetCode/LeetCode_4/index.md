# LeetCode 4. 寻找两个正序数组的中位数

> 题目链接：[https://leetcode.cn/problems/median-of-two-sorted-arrays/](https://leetcode.cn/problems/median-of-two-sorted-arrays/)  
> 难度：困难  
> 标签：数组、二分查找、分治

---

## 1. 题目描述

给定两个大小分别为 $m$ 和 $n$ 的**升序**数组 `nums1` 和 `nums2`，返回这两个数组**合并后**的中位数。要求时间复杂度为 $O(\log(m+n))$。

中位数的定义：合并后长度为 $\text{len}$，若 $\text{len}$ 为奇数，中位数是第 $\lfloor \text{len}/2 \rfloor + 1$ 小的元素；若为偶数，是第 $\text{len}/2$ 小与第 $\text{len}/2 + 1$ 小的平均值。

**数据范围：**

- $0 \le m, n \le 1000$
- $1 \le m + n \le 2000$
- $-10^6 \le nums1[i], nums2[i] \le 10^6$

**示例：**

```
输入：nums1 = [1,3], nums2 = [2]
输出：2.00000
解释：合并数组 = [1,2,3] ，中位数 2。

输入：nums1 = [1,2], nums2 = [3,4]
输出：2.50000
解释：合并数组 = [1,2,3,4] ，中位数 (2+3)/2 = 2.5。
```

---

## 2. 思路分析

### 2.1 暴力：合并后取中位数

归并两个有序数组，$O(m+n)$ 时间、$O(m+n)$ 空间（其实只需扫前半就能停，但仍是线性）。$m+n \le 2000$ 完全能过，可是 $O(\log(m+n))$ 的要求摆在那里——线性算法不达标。

一个稍好的中间方案是**不真正合并，用双指针 $O((m+n)/2)$ 找第 $k$ 小**。这暗示了一个重要转化：**中位数 = 第 $k$ 小问题**。剩下的就是让"找第 $k$ 小"也长出对数复杂度。

### 2.2 转化：中位数 ⟺ 一条"对半切"的分割线

设总长 $\text{len} = m + n$。中位数的本质是把合并后的数组切成**左右两半**，左半有 $\lceil \text{len}/2 \rceil$ 个元素、右半有其余元素，且**左半的最大值 $\le$ 右半的最小值**。

不合并数组也能画这条线：在 `nums1` 的位置 $i$ 处切一刀（左半取 `nums1[0..i-1]` 共 $i$ 个），在 `nums2` 的位置 $j$ 处切一刀（左半取 $j$ 个），只要满足：

$$i + j = \left\lceil \frac{m+n}{2} \right\rceil \qquad \text{且} \qquad nums1[i-1] \le nums2[j] \;\wedge\; nums2[j-1] \le nums1[i]$$

（$nums1[i-1]$ 是左半中来自 `nums1` 的最大值，$nums2[j]$ 是右半中来自 `nums2` 的最小值，另两个对称。）此时：

$$\text{中位数} = \max(nums1[i-1],\; nums2[j-1]) \quad \text{（奇数长取它；偶数长再和 } \min(nums1[i], nums2[j]) \text{ 取平均）}$$

**为什么这个转化是关键的跳跃**：原问题问的是"第 $k$ 小的**值**是多少"，值域上没法直接二分；转化后变成"**分割线的位置**是否合法"，而位置 $i \in [0, m]$ 是个有序的离散区间——一旦固定 $i$，$j$ 由 $i + j = \lceil \text{len}/2 \rceil$ 直接算出，判定"这条线切对没有"只需 $O(1)$。**可二分的前提从来不是"数组有序"，而是"候选空间有序且判定可测"**。

### 2.3 二分分割线：在短数组上找 i

剩下的问题是：$i$ 变大时合法性如何单调变化？观察判定条件 $nums1[i-1] \le nums2[j]$：$i$ 增大 $\Rightarrow$ $nums1[i-1]$ 增大，同时 $j = \text{half} - i$ 减小 $\Rightarrow$ $nums2[j]$ 增大，**两边同时变大**，不单调？不对——真正单调的是**越界方向**：

- 若 $nums1[i-1] > nums2[j]$：`nums1` 左半伸得太长（拿进来一个比 `nums2` 右半最小值还大的元素），$i$ 必须变小；
- 若 $nums2[j-1] > nums1[i]$：`nums2` 左半伸得太长（等价于 `nums1` 左半太短），$i$ 必须变大。

两个条件**不会同时违反**（同时违反意味着 $nums1[i-1] > nums2[j] \ge nums2[j-1] > nums1[i]$，即 $nums1[i-1] > nums1[i]$，矛盾于升序）。于是 $i$ 的候选区间呈"太短 / 恰好 / 太长"三段式，标准的二分搜索形状。**保证在长度较短的数组上二分**（设 $m \le n$），这样 $i$ 的范围 $[0, m]$ 足够小，且可证明 $j = \text{half} - i \in [0, n]$ 恒不越界。

### 2.4 用具体例子走一遍

`nums1 = [1,3], nums2 = [2,4,5]`，$m=2, n=3$，$\text{len}=5$，左半应有 $\lceil 5/2 \rceil = 3$ 个元素。二分 $i \in [0, 2]$，$j = 3 - i$。用 $\pm\infty$ 作为数组边界外的哨兵（见第 5 节）：

| 轮次 | $i$ 范围 | 取 $i$ | $j=3-i$ | 左半（nums1 取 $i$ 个 + nums2 取 $j$ 个） | 检查 | 结论 |
|------|---------|--------|---------|------------------------------------------|------|------|
| 1 | $[0,2]$ | 1 | 2 | `[1]` + `[2,4]` | $nums1[0]=1 \le nums2[2]=5$ ✓；$nums2[1]=4 > nums1[1]=3$ ✗ | nums2 左半太长，$i$ 要变大，转 $[2,2]$ |
| 2 | $[2,2]$ | 2 | 1 | `[1,3]` + `[2]` | $nums1[1]=3 \le nums2[1]=4$ ✓；$nums2[0]=2 \le nums1[2]=+\infty$ ✓ | 合法！ |

左半为 `[1,2,3]`，左半最大值 $\max(3, 2) = 3$；$\text{len}$ 为奇数，中位数 $= 3$。验证：合并后 `[1,2,3,4,5]`，中位数确实是 3。

再看偶数长的例子 `nums1 = [1,2], nums2 = [3,4]`：$m=2,n=2$，左半应有 $\lceil 4/2 \rceil = 2$ 个。二分一次取 $i=1, j=1$：左半 `[1]` + `[3]`，检查 $nums1[0]=1 \le nums2[1]=4$ ✓、$nums2[0]=3 \le nums1[1]=2$ ✗——nums2 左半太长，$i$ 变大为 2。取 $i=2, j=0$：左半 `[1,2]` + 空，检查 $nums1[1]=2 \le nums2[0]=3$ ✓、$nums2[-1]=-\infty \le +\infty$ ✓。左半最大 $2$，右半最小 $\min(+\infty, 3) = 3$，中位数 $(2+3)/2 = 2.5$。

## 3. 代码实现

```cpp
class Solution {
public:
    double findMedianSortedArrays(vector<int>& a, vector<int>& b) {
        // 保证在较短的数组上二分：i 的搜索空间更小，且可证 j 不越界
        if (a.size() > b.size()) return findMedianSortedArrays(b, a);
        int m = a.size(), n = b.size();
        int half = (m + n + 1) / 2;          // 左半应含的元素个数
        int lo = 0, hi = m;
        while (lo <= hi) {
            int i = lo + (hi - lo) / 2;      // a 取前 i 个进左半
            int j = half - i;                // b 取前 j 个进左半
            int aL = (i == 0) ? INT_MIN : a[i - 1];   // 左半中 a 的最大值
            int aR = (i == m) ? INT_MAX : a[i];       // 右半中 a 的最小值
            int bL = (j == 0) ? INT_MIN : b[j - 1];
            int bR = (j == n) ? INT_MAX : b[j];
            if (aL > bR)       hi = i - 1;   // a 左半太长，往左找
            else if (bL > aR)  lo = i + 1;   // a 左半太短，往右找
            else {                            // 分割线合法
                int leftMax  = max(aL, bL);
                int rightMin = min(aR, bR);
                if ((m + n) % 2) return leftMax;             // 奇数长
                return (leftMax + rightMin) / 2.0;           // 偶数长
            }
        }
        return 0.0;   // 不会到达：合法分割线必然存在
    }
};
```

几个实现细节：

1. **递归交换保证 $m \le n$**，二分区间 $[0, m]$ 最短；同时 $j = \text{half} - i$ 落在 $[0, n]$ 内可由不等式验证（这是选短数组二分的第二个理由）。
2. **哨兵用 `INT_MIN` / `INT_MAX`**：切在数组边界（左半不含该数组任何元素，或全含）时，边界比较退化为恒真，免去一堆 `if` 分类。
3. **`(m + n + 1) / 2` 的 `+1`**：奇数长时让左半多一个元素，中位数直接就是 `leftMax`，奇偶分支统一。
4. 除法用 `/ 2.0` 保证浮点结果（元素是整数，平均值可能是 .5）。

## 4. 复杂度分析

- **时间复杂度**：$O(\log(\min(m, n)))$。二分在较短数组的下标区间 $[0, m]$ 上进行（$m \le n$），每轮常数次比较。这比题目要求的 $O(\log(m+n))$ 还要好。
- **空间复杂度**：$O(1)$。不合并、不复制，只动几个下标和变量。

演进链条：合并 $O(m+n)$ → 双指针扫一半 $O((m+n)/2)$ → 二分分割线 $O(\log \min(m,n))$。越往下，越依赖"有序"这个前提提供的信息。

## 5. 常见疑问

**疑问一：为什么 `i` 增大时合法性不会"两头都错"导致二分失效？**

二分依赖的是**候选空间的序**，不是判定函数值的单调。2.3 节证明了两个违规条件互斥（同时成立会与数组各自升序矛盾），所以每个 $i$ 要么"太大"、要么"太小"、要么"恰好"，三个区间沿 $i$ 轴依次排列——这正是可二分的结构。若两条件同时可能成立，就得退回线性扫描。

**疑问二：为什么必须二分较短的数组？**

两个原因。其一，效率：$O(\log \min(m,n))$ 优于 $O(\log \max(m,n))$。其二，正确性：$j = \text{half} - i$ 必须 $\in [0, n]$。若在长数组上二分且 $i$ 取得过大，$j$ 会变负、越界，需要额外处理；而 $m \le n$ 时可以证明 $\text{half} - m \ge 0$ 且 $\text{half} \le n$，$j$ 自动合法。**短数组上每条可行的分割线，都对应长数组上一条可行的分割线**。

**疑问三：哨兵 `INT_MIN`/`INT_MAX` 会不会算出错误的中位数？**

不会，但前提是分清"哨兵参与的是**判定**还是**取值**"。哨兵只出现在越界侧的比较里（让比较恒真/恒假），而最终取值的 `leftMax = max(aL, bL)`、`rightMin = min(aR, bR)`：若哨兵混进了取值——比如左半为空（只在 $m = n = 0$ 时可能，被 $1 \le m+n$ 排除）或右半为空（偶数长且左半占满，此时 `rightMin` 是哨兵但 `leftMax` 来自真实元素，$\max$ 取真实的那个）——**只要哨兵是"必然落败"的方向（MIN 在 max 里、MAX 在 min 里），就永远不会被选中**。这就是哨兵方向不能写反的原因。

**可复用方法论**："有序结构上找第 $k$ 小 / 定位分割点"的通用套路——把"找值"转化为"找分割位置"，再证明判定条件构成三段式（太小/恰好/太大），二分即成。这一招同样适用于：

```cpp
// 两个有序数组找第 k 小（k 从 1 计）——O(log min(m,n)) 的分割线二分
// 思路：在 a 上二分 i ∈ [0, min(k, m)]，b 取 k - i 个，
//       判定与中位数版完全相同，答案为 max(a[i-1], b[j-1])。
```

**一句话总结**：本题的精髓是**把"合并后找第 $k$ 小"翻转成"找一条对半分割线"**——值不可二分，但位置可以；在短数组上二分切口，切口一合法，中位数就是分割线两侧四个数的两极。
