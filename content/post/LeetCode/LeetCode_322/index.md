# LeetCode 322. 零钱兑换

> 题目链接：[https://leetcode.cn/problems/coin-change/](https://leetcode.cn/problems/coin-change/)  
> 难度：中等  
> 标签：广度优先搜索、数组、动态规划

---

## 1. 题目描述

给你一个整数数组 `coins` 表示不同面额的硬币，以及一个整数 `amount` 表示总金额。计算并返回**凑成总金额所需的最少硬币个数**。如果没有任何一种硬币组合能凑出总金额，返回 `-1`。

每种硬币的数量是**无限的**（同种面额可重复使用）。

**数据范围：**

- $1 \le coins.length \le 12$
- $1 \le coins[i] \le 5 \times 10^3$
- $0 \le amount \le 10^4$

**示例：**

```
输入：coins = [1, 2, 5], amount = 11
输出：3
解释：11 = 5 + 5 + 1。
```

```
输入：coins = [2], amount = 3
输出：-1
解释：3 无法被 2 的任何倍数凑出。
```

```
输入：coins = [1], amount = 0
输出：0
```

## 2. 思路分析

### 2.1 贪心为什么错

直觉方案：每次优先用最大面额，剩下的继续贪。反例：

| 案例 | 贪心过程 | 贪心结果 | 最优解 |
|------|----------|----------|--------|
| `coins = [1, 3, 4]`, `amount = 6` | 先拿 4，剩 2 → $1+1$ | 3 枚 | $3 + 3$，**2 枚** |
| `coins = [1, 5, 11]`, `amount = 15` | 先拿 11，剩 4 → $1 \times 4$ | 5 枚 | $5 + 5 + 5$，**3 枚** |

贪心失败的根源：**大面额硬币局部减少枚数，却把余额引向「难凑」的状态**。子问题之间不是独立可分解的，必须系统性地求出**每个金额**的最优值——这就是动态规划 (dynamic programming)。

### 2.2 暴力递归与重叠子问题

定义 $f(x)$ 为凑出金额 $x$ 的最少硬币数，则有自然递归：

$$f(x) = \min_{c \in coins,\, c \le x} f(x - c) + 1, \qquad f(0) = 0$$

即枚举「最后一枚用的是哪种面额」。裸递归是指数级（每层最多 12 个分支），但状态只有 $amount + 1$ 个，大量分支反复求解同一个 $f(x-c)$——重叠子问题 (overlapping subproblems)，加记忆化即可。自底向上写成表就是 DP。

### 2.3 动态规划（完全背包）

设 $dp[j]$ 为凑出金额 $j$ 的最少硬币数，初始化 $dp[0] = 0$，其余为 $+\infty$（表示暂时凑不出）：

$$dp[j] = \min_{c \in coins,\, c \le j} \bigl(dp[j - c] + 1\bigr)$$

这正是完全背包 (unbounded knapsack) 的「恰好装满、最少件数」形态：硬币是可无限次使用的「物品」，金额是「容量」。

**逐步填表：`coins = [1, 2, 5], amount = 11`**

| $j$ | $dp[j-1]+1$ | $dp[j-2]+1$ | $dp[j-5]+1$ | $dp[j]$ |
|-----|-------------|-------------|-------------|---------|
| 1 | $\mathbf{1}$ | — | — | 1 |
| 2 | 2 | $\mathbf{1}$ | — | 1 |
| 3 | 2 | $\mathbf{2}$ | — | 2 |
| 4 | 3 | $\mathbf{2}$ | — | 2 |
| 5 | 3 | 3 | $\mathbf{1}$ | 1 |
| 6 | 2 | 2 | $\mathbf{2}$ | 2 |
| 10 | 3 | 3 | $\mathbf{2}$ | 2 |
| 11 | 3 | 4 | $dp[6]{+}1 = \mathbf{3}$ | 3 |

答案 $dp[11] = 3$：最后一步用 5，退回 $dp[6] = 2$；再一枚 5 退回 $dp[1] = 1$；最后 1 枚面额 1 回到 $dp[0]$——即 $5+5+1$。

### 2.4 BFS 视角：最短路径

把 $0 \dots amount$ 看作节点，从 $j$ 向 $j - c$ 连边（每枚硬币一条边，边权 1），「最少硬币数」就是 $amount$ 到 $0$ 的最短路。无权图最短路用广度优先搜索 (breadth-first search, BFS)：从 $amount$ 出发按层扩展，首次到达 $0$ 时的层数即答案；队列空了还没到 $0$ 则返回 $-1$。BFS 与 DP 的区别只是「扩展顺序」：BFS 按层数扩展，DP 按金额升序填表，两者本质等价，BFS 在答案很小时可以提前终止。

## 3. 代码实现

```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        const int INF = INT_MAX;
        // dp[j]：凑出金额 j 的最少硬币数
        vector<int> dp(amount + 1, INF);
        dp[0] = 0;                        // 边界：金额 0 用 0 枚
        for (int j = 1; j <= amount; j++) {
            for (int c : coins) {
                // 子状态必须已经可达，且 c <= j
                if (c <= j && dp[j - c] != INF)
                    dp[j] = min(dp[j], dp[j - c] + 1);
            }
        }
        return dp[amount] == INF ? -1 : dp[amount];
    }
};
```

三个实现细节：

1. **`dp[0] = 0` 是唯一的合法起点**。「恰好装满」型背包的初始化原则：容量 0 天然合法（代价 0），其余一律 $+\infty$ 表示不可达——这决定了最后 `dp[amount] == INF` 要翻译成 `-1`。
2. **先判 `dp[j-c] != INF` 再 `+1`**。直接对 `INT_MAX` 加一会溢出为负数，`min` 就取到错误值。
3. **两层循环顺序对「最少件数」不敏感**。硬币在外、金额在内（正序）或反过来都能过，因为 $\min$ 对顺序无要求；但对「计数」类问题（518 题）顺序就致命了，见第 5 节。

## 4. 复杂度分析

- **时间复杂度**：$O(amount \times |coins|)$。每个金额 $j$ 枚举一遍硬币面额；最坏 $10^4 \times 12 \approx 1.2 \times 10^5$ 次转移，非常宽裕。
- **空间复杂度**：$O(amount)$。一维 DP 数组（BFS 版本的队列与 `vis` 数组同阶）。

| 解法 | 时间 | 空间 | 备注 |
|------|------|------|------|
| 裸递归 | 指数级 | $O(amount)$ 栈 | 必超时 |
| 记忆化递归 | $O(amount \cdot \|coins\|)$ | $O(amount)$ | 与 DP 同阶 |
| DP / BFS | $O(amount \cdot \|coins\|)$ | $O(amount)$ | 本文推荐 |

## 5. 常见疑问

**疑问一：能不能先对硬币排序、从大到小贪心剪枝？**

排序无助于正确性，贪心路径本身就可能不是最优（见 2.1 的反例）。排序唯一的价值是把「面额大于 $j$」的硬币集中到一处提前 `break`，属于常数优化。**判断一道题该不该贪心，先构造「大面额互相打架」的反例试试**。

**疑问二：完全背包和 0-1 背包的内层循环方向差别？**

以「硬币外层、金额内层」为例：内层**正序**遍历 $j$ 时，$dp[j-c]$ 可能已包含本轮硬币 $c$——即同一硬币被重复使用，这恰好是完全背包的语义；内层**倒序**时 $dp[j-c]$ 还是上一轮（未考虑硬币 $c$）的值，每件物品至多用一次，是 0-1 背包。同一份代码只改遍历方向，语义天差地别，面试高频考点。

**疑问三：这道题和 518「零钱兑换 II」（求方案数）的循环顺序为什么不能混用？**

求**最少件数**时 $\min$ 满足交换律，两种顺序等价。求**组合数**时必须「硬币外层」——先固定考虑了哪些面额，累加的是组合（`{1,2}` 与 `{2,1}` 只算一次）；若「金额外层」，同一组合会按不同顺序被多次计入，得到的是排列数。需要区分组合与排列时（如 [377. 组合总和 IV](https://leetcode.cn/problems/combination-sum-iv/) 恰恰要排列），循环顺序本身就是算法的一部分。

## 6. 相关题目与模板

**可复用模板**（完全背包「恰好装满、最少件数」，同款骨架见 [LeetCode 279 完全平方数](../LeetCode_279/)）：

```cpp
// coins：可无限次使用的面额；amount：目标
vector<int> dp(amount + 1, INF);
dp[0] = 0;                          // 恰好装满型：只有 0 合法
for (int j = 1; j <= amount; j++)
    for (int c : coins)
        if (c <= j && dp[j - c] != INF)
            dp[j] = min(dp[j], dp[j - c] + 1);
```

方法论总结：**「无限使用 + 最少件数」的凑数问题，标准形态是完全背包**；初始化用 $+\infty$ 标记不可达，最后统一翻译成 `-1`。贪心只适用于面额体系有特殊结构的情形（如标准币制 $\{1,5,10,50,100\}$）。

**一句话总结**：零钱兑换是完全背包的教科书题——$dp[j] = \min_c dp[j-c] + 1$，别贪心，别忘 $dp[0]=0$ 与 $+\infty$ 初始化，最后记得把 $+\infty$ 翻译成 $-1$。
