# LeetCode 230. 二叉搜索树中第 K 小的元素

> 题目链接：[https://leetcode.cn/problems/kth-smallest-element-in-a-bst/](https://leetcode.cn/problems/kth-smallest-element-in-a-bst/)  
> 难度：中等  
> 标签：树、深度优先搜索、二叉搜索树

---

## 1. 题目描述

给定一棵二叉搜索树 (Binary Search Tree, BST) 的根节点 `root` 和一个整数 `k`，请你返回树中**第 `k` 小的节点值**（$k$ 从 1 开始计数）。

进阶：如果树经常被修改（插入/删除操作）且需要频繁查找第 $k$ 小的值，你将如何优化算法？

**数据范围：**

- 树中节点数为 $n$，$1 \le n \le 10^4$
- $1 \le k \le n$
- $0 \le Node.val \le 10^4$
- BST 保证有效（中序遍历严格递增）

**示例：**

```
输入：root = [5,3,6,2,4,null,null,1], k = 3

        5
       / \
      3   6
     / \
    2   4
   /
  1

输出：3
解释：中序遍历为 [1,2,3,4,5,6]，第 3 小的是 3。
```

---

## 2. 思路分析

### 2.1 暴力：中序遍历存下全部

最直接的做法：中序遍历整棵树，把 $n$ 个值依序存进数组，返回第 $k$ 个。

正确性来自 BST 的核心性质——**中序遍历 (inorder traversal) 得到的序列严格递增**，即中序的第 $k$ 个恰好是第 $k$ 小。代价是 $O(n)$ 时间 + $O(n)$ 空间。两个可改进点立刻浮现：

1. 只需要第 $k$ 个，前面的 $k-1$ 个**访问过就该扔**，后面 $n - k$ 个**根本不用访问**；
2. 存整个数组没必要，一个计数器就够。

### 2.2 优化：中序遍历 + 计数，到 $k$ 即停

把"存数组"换成"数到 $k$ 立即终止"。中序遍历天然按升序吐出节点，每访问一个节点计数器加一，加到 $k$ 时当前节点值就是答案，整棵遍历就此刹车。

用示例走一遍，$k = 3$：

| 步骤 | 访问节点 | 计数 | 说明 |
|------|---------|------|------|
| 1 | 1 | 1 | 最左下角（一路向左到底） |
| 2 | 2 | 2 | 回溯：1 无右子，弹出 2 |
| 3 | 3 | **3 = k** | 停！返回 3，4、5、6 根本不碰 |

树越"右侧"的节点越可能没被访问到。最好情况（$k = 1$）只走 $O(h)$ 条左链；最坏情况（$k = n$，答案是最右节点）仍是全量 $O(n)$，但空间从 $O(n)$ 降到 $O(h)$（只剩递归栈）。

### 2.3 进阶追问：频繁修改怎么办

若树经常插入/删除且查询高频，每次查询都 $O(n)$ 中序扫一遍不可接受。改进方向有两个层次：

| 方案 | 单次查询 | 插入/删除 | 说明 |
|------|---------|----------|------|
| 中序 + 计数 | $O(h + k)$ | $O(h)$ | 本题主解，简单场景够用 |
| 每个节点维护子树大小 $size$ | $O(h)$ | $O(h)$ | 查第 $k$ 小如"按排名找节点" |
| 平衡树（Treap / 红黑树带 order-statistics） | $O(\log n)$ | $O(\log n)$ | 保证树高，极端数据不退化 |

"每个节点维护子树大小"的思路：若左子树大小 $size_L \ge k$，答案在左子树；若 $size_L + 1 = k$，答案就是当前节点；否则在右子树里找第 $k - size_L - 1$ 小。这与"在有序数组里按下标随机访问"完全同构，只是数组换成了树。C++ 的 `pb_ds` 库就有现成的 `tree` 容器支持 `order_of_key` / `find_by_order`。

### 2.4 中序的迭代写法为什么更"实用"

递归版中序要"整条左链先压栈"，终止时上层递归帧还挂着，提前退出需要靠返回值层层传递（或抛异常）。**迭代版用显式栈**，把"一路向左"和"访问 + 转向右"拆成两段循环，计数到 $k$ 直接 `return`，干净利落——这也是面试中更受青睐的写法。

## 3. 代码实现

```cpp
class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        // 迭代中序：栈模拟，数到第 k 个立即返回
        stack<TreeNode*> stk;
        TreeNode* cur = root;
        while (cur != nullptr || !stk.empty()) {
            // 1. 一路向左压栈：中序先访问最小的
            while (cur != nullptr) {
                stk.push(cur);
                cur = cur->left;
            }
            // 2. 弹栈访问：当前节点是"剩余部分的最小值"
            cur = stk.top();
            stk.pop();
            if (--k == 0) return cur->val;   // 第 k 小，刹车
            // 3. 转向右子树：右子树整体大于当前节点
            cur = cur->right;
        }
        return -1;   // 题目保证 1 <= k <= n，不会走到这里
        // 需要声明 #include <stack>（多数判题环境已含）
    }
};
```

等价的递归版（逻辑更短，靠返回值逐层传出）：

```cpp
class Solution {
    int cnt, ans;
    void inorder(TreeNode* root) {
        if (root == nullptr || cnt == 0) return;   // cnt==0 表示已找到，剪枝
        inorder(root->left);
        if (--cnt == 0) { ans = root->val; return; }
        inorder(root->right);
    }
public:
    int kthSmallest(TreeNode* root, int k) {
        cnt = k;
        inorder(root);
        return ans;
    }
};
```

几个实现细节：

1. **`if (--k == 0) return`**：先减再比，恰好访问第 $k$ 个节点时触发，无差一错误。写成 `k--` 再判断 `k == 0` 语义相同，但 `cnt` 与 `k` 混用容易出 bug。
2. **递归版的 `cnt == 0` 剪枝不可省**。否则即使已找到答案，剩余节点仍会被完整遍历，退回 $O(n)$；加上后右侧未访问的子树被整块跳过。
3. **外层循环条件 `cur != nullptr || !stk.empty()`**：`cur` 非空说明还有左链要压，栈非空说明还有节点没访问，两者都空才真正结束。

## 4. 复杂度分析

- **时间复杂度**：$O(h + k)$。先沿左链下降 $O(h)$，随后每弹出一个节点计数一次，到 $k$ 停止。最坏 $k = n$ 时为 $O(n)$；平衡树且 $k$ 小时接近 $O(\log n)$。
- **空间复杂度**：$O(h)$。显式栈（或递归栈）深度等于树高 $h$，最好 $O(\log n)$，最坏（树退化为链且 $k$ 大）$O(n)$；不再有 $O(n)$ 的数组。

对比暴力：全量中序 $O(n)$ 时间 + $O(n)$ 空间 $\to$ 计数提前停 $O(h + k)$ 时间 + $O(h)$ 空间。若采用 2.3 的子树大小方案，查询进一步降到 $O(h)$ 且与 $k$ 无关。

## 5. 常见疑问

**疑问一：第 $k$ 小为什么一定是中序第 $k$ 个，会不会漏掉或重复？**

中序遍历按"左 - 根 - 右"访问，而 BST 中左子树所有值严格小于根、右子树所有值严格大于根，所以访问顺序恰好是值升序。树中每个节点恰好被访问一次，序列无重复无遗漏，"中序第 $k$ 个"与"第 $k$ 小"是同一个对象的两种说法。这一性质是所有 BST 有序性题目的基石。

**疑问二：为什么不直接按值大小去搜索，比如"往左走还是往右走"？**

这是本题最常见的思维误区：普通 BST **不维护子树大小**，站在节点处不知道左子树有几个节点，无从判断第 $k$ 小在哪一侧，只能老老实实中序数。一旦每个节点额外存了 $size$（2.3 的方案），"按排名走"才成立——信息不是免费的，要么遍历现算，要么维护缓存。

**疑问三：$k$ 是从 0 还是从 1 开始？边界 $k = 1$ 和 $k = n$ 对应什么？**

题目明确 $k$ 从 1 开始：$k = 1$ 是**最小值**（一路向左到底的那个节点），$k = n$ 是**最大值**（一路向右到底）。代码里 `--k == 0` 在访问第 1 个节点时就触发，对应 $k = 1$ 正确；若把 `k` 当 0 起点用，会在第 $k + 1$ 个节点处返回，恰好差一——这类 off-by-one 是本题最常见 WA。

## 6. 相关题目与模板

**可复用模板**（迭代中序骨架，改"访问处"的逻辑即可通吃 BST 有序性题目）：

```cpp
// 中序遍历（迭代版）：升序访问每个节点
stack<TreeNode*> stk;
TreeNode* cur = root;
while (cur != nullptr || !stk.empty()) {
    while (cur != nullptr) { stk.push(cur); cur = cur->left; }
    cur = stk.top(); stk.pop();
    // ---- 在这里处理 cur：计数、比较前驱、累加、找目标 ----
    cur = cur->right;
}
```

**方法论总结**：凡是"BST + 第 k / 众数 / 最小差 / 区间统计"类问题，第一步永远是想到"中序 = 有序序列"，把树上问题降维成序列问题；再根据是否需要频繁修改，决定用遍历现算还是维护子树大小/平衡树。
