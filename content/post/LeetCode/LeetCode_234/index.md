# LeetCode 234. 回文链表

> 题目链接：[https://leetcode.cn/problems/palindrome-linked-list/](https://leetcode.cn/problems/palindrome-linked-list/)  
> 难度：简单  
> 标签：栈、链表、双指针

---

## 1. 题目描述

给你一个单链表的头节点 `head`，请你判断该链表是否为**回文链表 (palindrome)**。如果是，返回 `true`；否则返回 `false`。

回文即"正着读和倒着读一样"：值序列 $a_1, a_2, \dots, a_n$ 满足 $a_i = a_{n+1-i}$ 对所有 $i$ 成立。

进阶：你能否用 $O(n)$ 时间复杂度和 $O(1)$ 空间复杂度解决此题？

**数据范围：**

- 链表中节点数目 $1 \le n \le 10^5$
- $0 \le Node.val \le 9$

**示例：**

```
输入：head = [1,2,2,1]
输出：true

      1 -> 2 -> 2 -> 1 -> null
      正读 1,2,2,1；倒读 1,2,2,1。相同。

输入：head = [1,2]
输出：false

      1 -> 2：正读 1,2；倒读 2,1。不同。
```

---

## 2. 思路分析

### 2.1 暴力：拷进数组再首尾对撞

遍历链表把值拷进数组 `a`，然后用双指针从两端向中间对撞：比较 `a[i]` 与 `a[n-1-i]`，全相等即回文。

- 时间 $O(n)$，空间 $O(n)$——链表最大的不便在此暴露无遗：**单链表只能向后走，无法从尾部"倒着读"**，只好借数组把"倒读"变成"倒着索引"。

### 2.2 栈：把链表"倒着读"抽象成数据结构

数组的"倒着索引"有一个更贴合链表气质的替身——栈 (stack)：一次遍历把所有节点值压栈，第二次遍历时每走一个节点弹一次栈顶比较。栈的"后进先出"恰好就是"倒序遍历"。

一个省一半空间的小优化：配合快慢指针，只把**前半段**压栈，遍历后半段时逐个弹栈比较。但无论如何压栈，空间仍是 $O(n/2) = O(n)$ 量级，进阶的 $O(1)$ 要求没达到。

| 做法 | 时间 | 空间 | 卡点 |
|------|------|------|------|
| 数组 + 对撞双指针 | $O(n)$ | $O(n)$ | 借道数组 |
| 栈 | $O(n)$ | $O(n)$ | 借道栈 |
| ？ | $O(n)$ | $O(1)$ | 需要原地"倒读" |

突破口：回文的判定只需要**后半段倒过来和前半段比**。"倒过来"有一个原地操作——反转链表 (reverse linked list)。剩下的问题只有一个：不数长度，怎么知道后半段从哪开始？

### 2.3 最优解：快慢指针找中点 + 反转后半段 + 双指针比较

三步走：

1. **快慢指针找中点**：`slow` 每次走 1 步、`fast` 每次走 2 步，`fast` 到尾时 `slow` 恰在中点。一次遍历拿到后半段起点，替代"数长度再走一半"。
2. **反转后半段**：沿用反转链表的三指针骨架，把后半段原地掉头。
3. **双指针比较**：一个指针从头（前半段起点）、一个从反转后的后半段起点，同步前进逐一比对，走到后半段 `null` 为止。

用 `[1,2,2,1]`（$n = 4$，偶数）完整走一遍。快慢指针过程（`slow`、`fast` 同起于头）：

| 轮次 | 操作后 slow | 操作后 fast | 说明 |
|------|-------------|-------------|------|
| 初始 | 1 | 1 | 都在头 |
| 1 | 2 | 2 (第二个) | fast 走 2 步 |
| 2 | 2 (第二个) | null | fast 出界，循环结束 |

`slow` 停在第二个 `2`——正是后半段的起点。反转 `[2,1]` 得 `1→2`，然后比较：

| 步数 | p1（前半段） | p2（反转后后半段） | 相等？ |
|------|--------------|--------------------|--------|
| 1 | 1 | 1 | ✓ |
| 2 | 2 | 2 | ✓ |

`p2` 到 `null`，全程相等，是回文。

奇数长度 `[1,2,3,2,1]`（$n = 5$）时 `slow` 停在正中间的 `3`：中间节点跟着后半段一起被反转，比较时它恰好和自己配成一对（必然相等），天然不需要特判——详见第 5 节对初始化的讨论。

## 3. 代码实现

```cpp
class Solution {
public:
    bool isPalindrome(ListNode* head) {
        // 1. 快慢指针：slow 停在前半段末尾（或正中），fast 探路
        ListNode *slow = head, *fast = head;
        while (fast && fast->next) {
            slow = slow->next;
            fast = fast->next->next;
        }

        // 2. 反转后半段（从 slow 开始）
        //    奇数长度时 slow 是正中间节点，从它开始反转后，
        //    比较时中间节点恰好和自己配对（必然相等），无需特判
        ListNode *prev = nullptr, *curr = slow;
        while (curr) {
            ListNode *next = curr->next;   // 先存后继，防止断链
            curr->next = prev;
            prev = curr;
            curr = next;
        }

        // 3. 双指针比较：p1 从头，p2 从反转后的后半段头（原链尾）
        //    prev 同时充当"后半段是否走完"的哨兵：p1 不会越过中点
        ListNode *p1 = head, *p2 = prev;
        while (p2) {
            if (p1->val != p2->val) return false;
            p1 = p1->next;
            p2 = p2->next;
        }
        return true;
    }
};
```

几个实现细节：

1. **比较循环用 `p2` 做条件**。反转后的后半段长度 $\lfloor n/2 \rfloor \le$ 前半段长度，`p2` 先走到 `null`；若用 `p1` 做条件，奇数长度时 `p1` 会多走一步到中间节点——虽然不影响本题正确性（多走不比较），但用 `p2` 语义更干净。
2. **反转从 `slow` 开始，奇偶统一处理**。`n` 偶时 `slow` 是后半段第一个节点；`n` 奇时 `slow` 是中间节点，它跟着后半段一起被反转，比较时和自己的镜像位置配对、必然相等，无需任何特判。
3. **本解法修改了链表结构**（后半段被反转）。题目判题只看返回值，不要求恢复；若面试官要求还原，把第 2 步的反转再对后半段执行一次即可，仍是 $O(n)$。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。三步是串联的：找中点走 $n/2$ 次，反转走 $\lfloor n/2 \rfloor$ 次，比较走 $\lfloor n/2 \rfloor$ 次，总计不超过 $1.5n$ 次指针移动。
- **空间复杂度**：$O(1)$。全程只有常数个指针变量（`slow`、`fast`、`prev`、`curr`、`p1`、`p2`），没有任何与 $n$ 相关的辅助结构——这是三个解法中唯一达到进阶要求的。

对比：数组 $O(n)$ 空间 → 栈 $O(n)$ 空间 → 反转后半段 $O(1)$ 空间。空间的下降来自把"倒读后半段"从"借用外部结构"变成"原地改指针"。

## 5. 常见疑问

**Q1：为什么不能像数组那样，一个指针从头、一个指针从尾往中间走？**

单链表每个节点只有 `next`，**没有前驱指针**：站在尾节点上无法回到前一个节点。数组对撞双指针依赖 $O(1)$ 的双向随机访问，链表只有单向的后继访问。所以"倒着读"必须造出来——要么用栈/数组（$O(n)$ 空间），要么把后半段原地反转（$O(1)$ 空间）。这是链表题里反复出现的主题：**想要"回头"，要么花空间，要么改结构**。

**Q2：`slow` 到底停在哪个节点？快慢指针的初始化为什么重要？**

本题用 `slow = head, fast = head`：

| 初始化 | 循环写法 | $n$ 偶时 slow 停在 | $n$ 奇时 slow 停在 |
|--------|----------|--------------------|---------------------|
| `slow = fast = head` | `while (fast && fast->next)` | 后半段第 1 个（下标 $n/2$） | 正中间（下标 $n/2$ 下取整） |
| `slow = head, fast = head->next` | `while (fast && fast->next)` | 前半段最后 1 个（下标 $n/2 - 1$） | 前半段最后 1 个 |

两种写法都可行，但**后半段的起点不同**（前者是 `slow`，后者是 `slow->next`），配套的反转起点、比较起点都要跟着变。混用两套初始化是本题最常见的 WA 来源——选定一套，贯彻到底。

**Q3：修改链表结构真的没问题吗？**

对 OJ 判题没问题：判题程序在 `isPalindrome` 返回后才检查输出，且每个测试用例都新建链表，前一个用例留下的"反转残骸"不会影响后一个。但两个工程上的注意点值得知道：一是若该链表被其他调用方持有，反转会使他们看到意外的结构，稳妥起见比较完应把后半段反转回来；二是反转后原中点附近会出现"两个指针都指向某节点"的过渡状态，多线程环境下这类原地操作并不安全。

## 6. 相关题目与模板

**可复用模板**（"快慢指针找中点 + 反转后半段"组合拳，链表题的高频子套路）：

```cpp
// 1. 找中点
ListNode *slow = head, *fast = head;
while (fast && fast->next) { slow = slow->next; fast = fast->next->next; }
// 2. 反转 [slow, null)：三指针骨架
ListNode *prev = nullptr, *curr = slow;
while (curr) {
    ListNode *next = curr->next;
    curr->next = prev; prev = curr; curr = next;
}
// 此后 head 指向前半段，prev 指向反转后的后半段头
```

这个组合是"链表上的分半操作"的通用件：拿到"前后两半"之后，可以比较（本题）、可以交错拼接（重排链表）、可以归并排序（排序链表的递归版）。

**同类题目：**

- [LeetCode 206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/)：本题第 2 步的完整版，必先掌握
- [LeetCode 876. 链表的中间结点](https://leetcode.cn/problems/middle-of-the-linked-list/)：本题第 1 步的独立成题版
- [LeetCode 143. 重排链表](https://leetcode.cn/problems/reorder-list/)：同一组合拳，后半段反转后与前半段交错合并
- [LeetCode 125. 验证回文串](https://leetcode.cn/problems/valid-palindrome/)：数组/字符串版回文判定，对撞双指针即可，对照体会链表为什么要绕弯
- [LeetCode 2130. 链表最大孪生和](https://leetcode.cn/problems/maximum-twin-sum-of-a-linked-list/)：把"前半段与倒序的后半段配对"直接变成求 $\max(a_i + a_{n+1-i})$

**一句话总结**：链表不会倒着走，但你可以让它掉头——快慢指针劈成两半、后半段原地反转，$O(1)$ 空间就"倒读"了后半程。
