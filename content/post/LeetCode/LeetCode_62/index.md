# LeetCode 62. 不同路径

> 题目链接：[https://leetcode.cn/problems/unique-paths/](https://leetcode.cn/problems/unique-paths/)  
> 难度：中等  
> 标签：数学、动态规划、组合数学

---

## 1. 题目描述

一个机器人位于 $m \times n$ 网格的**左上角**（起点为下标 $(0,0)$ 的格子）。机器人每次只能**向下**或者**向右**移动一步。问到达网格的**右下角**（下标 $(m-1, n-1)$ 的格子）总共有多少条不同的路径。

**数据范围：**

- $1 \le m, n \le 100$
- 题目数据保证答案小于等于 $2 \times 10^9$

**示例：**

```
输入：m = 3, n = 7
输出：28

输入：m = 3, n = 2
输出：3
解释：从左上角开始，共有 3 条路径可以到达右下角：
     1. 向右 -> 向下 -> 向下
     2. 向下 -> 向下 -> 向右
     3. 向下 -> 向右 -> 向下
```

---

## 2. 思路分析

### 2.1 暴力：搜索所有路径

从起点 DFS，每步两个分支（右、下），走到终点计数。路径长度为 $(m-1) + (n-1)$ 步，路径总数本身就是答案量级——$m = n = 100$ 时高达约 $10^{58}$，搜索不可行（即使加了记忆化，也就是下面的 DP）。

问题为何适合 DP？因为**到达同一格子的路径会大量汇合**：无论从上面来还是从左边来，之后能走的路完全一样——**后效性消失，子问题重叠**，这是 DP 的两个标准信号。

### 2.2 动态规划：$dp[i][j]$ = 到达 $(i,j)$ 的路径数

定义 $dp[i][j]$ 为从起点走到格子 $(i,j)$ 的路径条数。机器人只能从上边或左边进入该格子：

$$dp[i][j] = dp[i-1][j] + dp[i][j-1]$$

边界：第一行、第一列全程只有一种走法（一路向右 / 一路向下），$dp[0][j] = dp[i][0] = 1$。

以 $m = 3, n = 3$ 的表格逐格填写：

| $i \backslash j$ | 0 | 1 | 2 |
|---|---|---|---|
| **0** | 1 | 1 | 1 |
| **1** | 1 | 2 | 3 |
| **2** | 1 | 3 | **6** |

右下角 $dp[2][2] = 6$——这正是"杨辉三角 (Pascal's triangle)"的斜角摆放，每格等于上方与左方之和。

空间可以压缩：一行一行填，`dp[j] += dp[j-1]`（旧值是上方，新值是左边），一维数组即可。

### 2.3 组合数学：直接算出闭式

换个视角数路径。从起点到终点必须走**恰好** $m-1$ 步向下、$n-1$ 步向右，总共 $m+n-2$ 步。一条路径由这 $m+n-2$ 步中"哪 $m-1$ 步是向下"唯一确定——路径数就是从 $m+n-2$ 个位置里选 $m-1$ 个的组合数：

$$\text{ans} = \binom{m+n-2}{m-1} = \frac{(m+n-2)!}{(m-1)!\,(n-1)!}$$

用 $m = 3, n = 7$ 验证：$\binom{8}{2} = \frac{8 \times 7}{2 \times 1} = 28$，与示例一致。

计算时不必碰阶乘：按定义边乘边除，$\binom{N}{k} = \prod_{t=1}^{k} \frac{N - k + t}{t}$，用 `long long` 中间量即可（$N \le 198$，$k \le 99$，中间乘积远超 `int` 但在 `long long` 内安全——每次除法都是精确整除，因为前 $t$ 项之积 $\times$ ... 恰为 $\binom{N-k+t}{t} \cdot t!$ 的整数倍）。

两种方法对比：

| 方法 | 时间 | 空间 | 适用场景 |
|---|---|---|---|
| 二维 DP | $O(mn)$ | $O(n)$（滚动） | 可扩展：带障碍（63 题）、带权重（64 题）、求最小路径和 |
| 组合公式 | $O(\min(m,n))$ | $O(1)$ | 无障碍无权重的裸题，一步到位 |

数据范围稍大时组合公式占优；但只要题目一变形（障碍、代价、路径还原），DP 的框架立刻胜出。

## 3. 代码实现

```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        // 一维滚动 DP：dp[j] 滚动前是"上方"，滚动后是"当前格"
        vector<int> dp(n, 1);            // 第一行全为 1（一路向右只有一种走法）
        for (int i = 1; i < m; i++)      // 逐行向下
            for (int j = 1; j < n; j++)  // 逐列向右
                dp[j] += dp[j - 1];      // 上方 dp[j](旧) + 左边 dp[j-1](新)
        return dp[n - 1];
    }
};
```

若想要 $O(\min(m,n))$ 的组合数学版：

```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        long long ans = 1;
        int k = min(m, n) - 1, N = m + n - 2;   // 取小的做分母，循环更短
        for (int t = 1; t <= k; t++)
            ans = ans * (N - k + t) / t;        // 先乘后除，每步都精确整除
        return ans;
    }
};
```

两个实现细节：

1. **滚动数组中 `dp[j] += dp[j-1]` 的两个操作数来自不同时空**：右边的 `dp[j-1]` 已在本轮（第 $i$ 行）更新，代表"左边"；左边的 `dp[j]` 还是上一轮（第 $i-1$ 行）的值，代表"上方"。一行代码完成状态合流。
2. **组合版必须先乘后除**。`ans * (N - k + t)` 先累积再除以 $t$，能被 $t$ 整除（归纳可证前 $t$ 项之积是 $t!$ 的倍数）；若先除后乘，$(N-k+t)/t$ 可能不是整数，答案悄悄出错。

## 4. 复杂度分析

- **DP 版时间复杂度**：$O(mn)$，填满整个状态表；**空间 $O(n)$**，一维滚动（进一步可用 $O(\min(m,n))$——按较短方向滚动）。
- **组合版时间复杂度**：$O(\min(m, n))$，一次乘除循环；**空间 $O(1)$**。

对比：暴力搜索 $O(\binom{m+n-2}{m-1})$（即答案本身）→ DP $O(mn)$ → 组合公式 $O(\min(m,n))$。本题 $m, n \le 100$，DP 也只需 $10^4$ 次加法，两者都远在时限之内，选哪个看可扩展性需求。

## 5. 常见疑问

**疑问一：为什么答案不会溢出 `int`？**

题目保证答案 $\le 2 \times 10^9$，而 `int` 上限约 $2.147 \times 10^9$，恰好罩得住（$m = n = 100$ 时 $\binom{198}{99} \approx 2.25 \times 10^{58}$ 远超，所以这份数据范围下答案最大的组合是有限的——实际上约束 $m, n \le 100$ 中答案最大约 $1.9 \times 10^9$，恰在边界内）。但**组合版的中间量 `ans * (N - k + t)` 可能瞬间超过 `int`**，所以中间变量必须用 `long long`；DP 版全是加法且每格不超过答案，`int` 安全。

**疑问二：DP 从起点顺推和从终点逆推，哪个对？**

都对。顺推 $dp[i][j]$ 由上方、左方得出；逆推则定义"从 $(i,j)$ 到终点的路径数"，由下方、右方得出。两者只是填表方向不同，边界（一行一列置 1）与转移结构完全对称。面试中顺推更常见，因为"到达 $(i,j)$ 的路径数"更贴近直觉。

**疑问三：能输出具体的一条路径吗？**

组合公式只给计数，不构造方案。DP 表格天然支持回溯还原：从终点出发，若 $dp[i-1][j] = k$ 的那侧贡献了目标序号就往上走，否则往左走（第 $k$ 大路径落在哪个分支，用子问题的路径数二分定位）。这是"DP 计数 + 逆推还原第 $k$ 小方案"的通用套路，与输出字典序第 $k$ 小的排列同源。

## 6. 相关题目与模板

**可复用模板**（网格 DP 计数的滚动数组骨架）：

```cpp
// 网格从左上到右下，只许右/下移动：计数、最值、可行性共用此框架
vector<long long> dp(n, /* 第一行的初始值 */);
for (int i = 1; i < m; i++)
    for (int j = 1; j < n; j++)
        dp[j] = transfer(dp[j] /* 上 */, dp[j - 1] /* 左 */);
// 计数用 +，最值用 min/max，可行性用 ||
```

**一句话总结**：只许右和下的网格计数，DP 转移是"上 + 左"一行滚动搞定；想更快就换组合视角——路径即"$m+n-2$ 步中选 $m-1$ 步向下"，答案 $\binom{m+n-2}{m-1}$ 一步写死。
