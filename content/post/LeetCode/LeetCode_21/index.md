# LeetCode 21. 合并两个有序链表

> 题目链接：[https://leetcode.cn/problems/merge-two-sorted-lists/](https://leetcode.cn/problems/merge-two-sorted-lists/)  
> 难度：简单  
> 标签：递归、链表

---

## 1. 题目描述

给定两个**升序排列**的链表 `list1` 与 `list2`，把二者合并成一条新的升序链表并返回。新链表由拼接给定的两个链表的所有节点组成，也就是说**不允许新建节点、只许重新接线**。

**数据范围：**

- 两个链表的节点数目范围均为 $[0, 50]$
- $-100 \le Node.val \le 100$
- `list1` 与 `list2` 均按**非递减顺序**排列

**示例：**

```
输入：list1 = [1,2,4], list2 = [1,3,4]
输出：[1,1,2,3,4,4]

输入：list1 = [], list2 = [0]
输出：[0]

输入：list1 = [], list2 = []
输出：[]
```

注意第三个示例：两条链表**都可能是空链表**，这是本题最容易被忽略的边界。

---

## 2. 思路分析

### 2.1 暴力：拆下来排序再串回去

最无脑的做法：遍历两条链表把所有值倒进一个数组，对数组排序，再重建一条链表，时间 $O((m+n)\log(m+n))$，额外空间 $O(m+n)$。

这个做法的问题在于**把"两条链表各自有序"这个条件完全浪费了**。有序结构的合并本来可以线性完成——归并排序 (merge sort) 的 merge 步骤干的就是这件事——先拆散再排序，等于把现成的信息扔掉再花力气买回来。

### 2.2 利用有序性：双指针归并

两条链表都升序，那么**全局最小值一定藏在两个表头之中**。这给出一个自然的贪心流程：

1. 比较 `list1->val` 与 `list2->val`，较小者就是结果链表的下一个节点，把它取走；
2. 被取走的那条链表指针后移一位；
3. 重复，直到某条链表为空，把另一条**整条拼接到尾部**。

为什么每次"取小的"都不会出错？设取走的是 `list1` 的表头 $x$。另一条链表剩下的所有元素都 $\ge$ 它的表头 $\ge$ $x$，而 `list1` 剩下的元素更不可能比 $x$ 小（升序）。所以 $x$ 确实是当前全局剩余的最小值，接在结果尾部不会破坏有序性。这就是**双指针 (two pointers)** 归并。

### 2.3 哨兵节点：消灭"头节点特判"

实现时的第一个麻烦：结果链表的头到底是 `list1` 还是 `list2`？不比一次不知道，而且"接上第一个节点"与"接上后续节点"要分开写。

标准解法是**哨兵节点 (dummy node)**：先造一个值无意义的节点 `dummy` 挂在结果最前面，之后所有"接上新节点"的操作统一写成 `tail->next = x`，最后返回 `dummy->next`。头节点的特判从代码里彻底消失。

### 2.4 用示例走一遍

`list1 = 1 -> 2 -> 4`，`list2 = 1 -> 3 -> 4`，`tail` 是结果链表当前的尾节点：

| 步骤 | list1 表头 | list2 表头 | 取谁 | 结果链表（含 dummy） |
|------|-----------|-----------|------|----------------------|
| 1 | 1 | 1 | list1 的 1（相等取先手） | dummy -> 1 |
| 2 | 2 | 1 | list2 的 1 | dummy -> 1 -> 1 |
| 3 | 2 | 3 | list1 的 2 | dummy -> 1 -> 1 -> 2 |
| 4 | 4 | 3 | list2 的 3 | dummy -> 1 -> 1 -> 2 -> 3 |
| 5 | 4 | 4 | list1 的 4 | ... -> 3 -> 4 |
| 6 | 空 | 4 | list2 整条拼接 | 1 -> 1 -> 2 -> 3 -> 4 -> 4 |

6 步循环恰好等于 $m + n = 6$，每个节点只被访问一次。

### 2.5 递归视角

同一个决策也可以写成递归 (recursion)：设较小表头为 $h$，则

$$merge(l_1, l_2) = h \;\rightarrow\; merge(l_1', l_2')$$

其中 $h$ 所在链表去掉表头得到 $l_1'$（或 $l_2'$），另一条原样传入。递归出口是任一链表为空时直接返回另一条。递归版代码更短，但调用栈深 $O(m+n)$——本题 $m, n \le 50$ 无压力，节点数上万时必须换迭代版。

## 3. 代码实现

```cpp
class Solution {
public:
    ListNode* mergeTwoLists(ListNode* list1, ListNode* list2) {
        ListNode dummy(0);                  // 哨兵节点：统一"接尾巴"操作
        ListNode* tail = &dummy;

        while (list1 && list2) {
            if (list1->val <= list2->val) { // 相等取 list1，保持稳定
                tail->next = list1;
                list1 = list1->next;
            } else {
                tail->next = list2;
                list2 = list2->next;
            }
            tail = tail->next;
        }
        // 剩下那条非空链表整体接上（见 5.1 的不变量证明）
        tail->next = list1 ? list1 : list2;
        return dummy.next;
    }
};
```

两个实现细节：

1. **没有 `new`**。题目要求"拼接"而非"复制"，所有节点都是原链表的节点，只是 `next` 指针被重新安排，空间是真正的 $O(1)$。
2. **`dummy` 用栈上对象 `ListNode dummy(0)` 而非 `new`**。它只是个临时锚点，函数返回前就会被 `dummy.next` 跳过，栈对象自动回收，不产生内存泄漏隐患。

## 4. 复杂度分析

- **时间复杂度**：$O(m + n)$。每轮循环至少消耗两条链表之一的一个节点，循环总轮数不超过 $m + n$；退出后的一次整条拼接是 $O(1)$。
- **空间复杂度**：$O(1)$。只借用了一个栈上的哨兵节点，没有新建任何链表节点（不计递归版——递归版的调用栈是 $O(m+n)$）。

对比：暴力拆散重排 $O((m+n)\log(m+n))$ + $O(m+n)$ 空间 → 双指针归并 $O(m+n)$ + $O(1)$ 空间，而且归并版是**下界**：每个节点至少要看一眼，不可能更快。

## 5. 常见疑问

**Q1：循环退出后直接 `tail->next = list1 ? list1 : list2`，凭什么剩下的链表可以直接整条接上，不会破坏有序性？**

不妨设剩下的是 `list1`。注意每轮取走的元素都是当时两个表头中较小（或相等）的那个——它 $\le$ 当时 `list1` 的表头；而 `list1` 的表头只会向右移动、值单调不减，所以**已合并部分的每个元素都 $\le$ list1 当前的表头**。整条接上后依然全局有序。

**Q2：相等时取 `list1` 还是 `list2` 有区别吗？**

结果链表的值序列完全一样。`<=` 取 `list1` 只是让同值元素的相对先后保持原样（稳定性），与归并排序里稳定性讨论的习惯一致；面试时说清楚这点反而是加分项。

**Q3：递归版会不会栈溢出？**

本题节点最多 50 个，随便递归。但一般地递归深度是 $m + n$，链表长度 $10^4 \sim 10^5$ 级别时（如 [LeetCode 23](https://leetcode.cn/problems/merge-k-sorted-lists/) 合并 k 条长链表）就有爆栈风险。工程与面试默认写迭代版。

## 6. 相关题目与模板

**可复用模板**（哨兵 + 双指针归并，即归并排序的 merge 子过程）：

```cpp
// 有序链表归并骨架：dummy 挂头，tail 追加，尾巴整接
ListNode dummy(0), *tail = &dummy;
while (p && q) {
    if (p->val <= q->val) { tail->next = p; p = p->next; }
    else                  { tail->next = q; q = q->next; }
    tail = tail->next;
}
tail->next = p ? p : q;
return dummy.next;
```

**方法论总结**：

1. **哨兵节点**是链表题的第一习惯：凡是"结果链表的头不确定"或"可能删除头节点"，先挂 `dummy`，特判归零；
2. **有序结构合并 = 逐个摘表头较小者**，从两个表头里挑全局最小，这是归并排序、堆合并、多路归并的共同内核。

**同类题目：**

- [LeetCode 23. 合并 K 个升序链表](https://leetcode.cn/problems/merge-k-sorted-lists/)：本题的多路推广，反复两两合并或用小根堆
- [LeetCode 88. 合并两个有序数组](https://leetcode.cn/problems/merge-sorted-array/)：数组版归并，从后往前填充以避开额外空间
- [LeetCode 148. 排序链表](https://leetcode.cn/problems/sort-list/)：归并排序在链表上的落地，核心子过程就是本题
- [LeetCode 2. 两数相加](https://leetcode.cn/problems/add-two-numbers/)：同样是"两条链表并排逐节点推进"的骨架

**一句话总结**：两个有序结构求并，最小候选永远只在两个表头之中——哨兵挂头、逐个摘小者，归并的本体就这么几行。
