# LeetCode 73. 矩阵置零

> 题目链接：[https://leetcode.cn/problems/set-matrix-zeroes/](https://leetcode.cn/problems/set-matrix-zeroes/)  
> 难度：中等  
> 标签：数组、哈希表、矩阵

---

## 1. 题目描述

给定一个 $m \times n$ 的整数矩阵 `matrix`：如果某个元素为 $0$，就把它**所在的整行和整列**都置为 $0$。

要求**原地 (in-place)** 修改。陷阱在于：置零会引入新的 $0$，而这些"人造 0"**不能**再触发新一轮置零——必须只根据**原始矩阵**中的 0 来决定哪些行列清零。

**进阶要求**：用 $O(m + n)$ 甚至 $O(1)$ 的额外空间完成。

**数据范围：**

- $1 \le m, n \le 10^5$
- $-2^{31} \le matrix[i][j] \le 2^{31} - 1$

**示例：**

```
输入：matrix = [[1,1,1],
               [1,0,1],
               [1,1,1]]

输出：[[1,0,1],
       [0,0,0],
       [1,0,1]]

输入：matrix = [[0,1,2,0],
               [3,4,5,2],
               [1,3,1,5]]

输出：[[0,0,0,0],
       [0,4,5,0],
       [0,3,1,0]]
```

---

## 2. 思路分析

### 2.1 暴力：复制一份当"存档"

新建一个副本 `backup` 记录原始矩阵，遍历 `backup`，遇到 0 就在**原矩阵**上清行清列。正确且直观，时间 $O(mn)$，但空间 $O(mn)$——矩阵规模大时不可接受。

更省的做法：其实不需要整个存档，只需要记录"哪些行、哪些列要清零"。

### 2.2 记录行列号：$O(m + n)$ 空间

第一遍扫描，把含 0 的行号收进 `rows` 集合、列号收进 `cols` 集合；第二遍按集合清零。两个集合最多 $m + n$ 个元素，空间 $O(m+n)$。

| 做法 | 时间 | 额外空间 | 是否达标（进阶） |
|------|------|----------|----------------|
| 复制整矩阵 | $O(mn)$ | $O(mn)$ | ✗ |
| 行列集合 | $O(mn)$ | $O(m+n)$ | 半达标 |
| 首行首列做标记 | $O(mn)$ | $O(1)$ | ✓ |

还能再压吗？可以——**矩阵自带 $m + n$ 个现成的格子：第一行和第一列**。

### 2.3 终极压缩：用第一行、第一列当标记数组

观察 2.2 的两个集合，本质是两个布尔数组：`rowZero[0..m-1]`、`colZero[0..n-1]`。我们让它们"寄生"在矩阵里：

- **第 $j$ 列需要清零** ⟺ 在 `matrix[0][j]` 打标记（置 0）；
- **第 $i$ 行需要清零** ⟺ 在 `matrix[i][0]` 打标记（置 0）。

即：扫到 `matrix[i][j] == 0` 时，顺手把 `matrix[i][0]` 和 `matrix[0][j]` 置 0。

但有一个**交叉点冲突**：`matrix[0][0]` 既属于第一行又属于第一列，一个格子装不下两条信息。标准解法是单开一个布尔变量 `col0`，专职记录"**第 0 列**是否需要清零"，而 `matrix[0][0]` 只负责第一行。

以 `matrix = [[0,1,2,0],[3,4,5,2],[1,3,1,5]]` 走一遍打标记阶段：

| 位置 $(i,j)$ | 原值 | 动作 | 说明 |
|------|------|------|------|
| $(0,0)$ | 0 | `col0 = true` | 第 0 列上的 0 只记账到 `col0`，不写 `matrix[0][0]`（防与行标记串扰） |
| $(0,3)$ | 0 | `matrix[0][0] = 0`、`matrix[0][3] = 0` | 第 0 行要清零（行标记）、第 3 列要清零（列标记） |
| 其余 | 非 0 | 无 | — |

随后按标记清零：先清内圈（不含第 0 行、第 0 列），再处理第一行和第一列，最终得到 `[[0,0,0,0],[0,4,5,0],[0,3,1,0]]`，与示例一致。

### 2.4 顺序纪律：先打标记，后用标记

全程必须遵守一条铁律：**清零动作只能在标记全部打完之后**。原因与 2.1 节的暴力版相同——清零会制造新的 0，新 0 若参与打标记，就会把无辜的行列也拉进清零名单。"读原值/写标记"归第一阶段，"按标记动笔"归第二阶段，两类操作绝不交叉，这是从暴力解一路保留下来的不变量 (invariant)。

## 3. 代码实现

```cpp
class Solution {
public:
    void setZeroes(vector<vector<int>>& matrix) {
        int m = matrix.size(), n = matrix[0].size();
        bool col0 = false;                 // 第 0 列是否需要清零（单独记账）

        // 阶段一：打标记
        for (int i = 0; i < m; i++) {
            if (matrix[i][0] == 0) col0 = true;    // 第 0 列的标记不能写进 matrix[0][0]
            for (int j = 1; j < n; j++) {
                if (matrix[i][j] == 0) {
                    matrix[i][0] = 0;      // 第 i 行要清零
                    matrix[0][j] = 0;      // 第 j 列要清零
                }
            }
        }

        // 阶段二：按标记清零（不含第 0 行、第 0 列）
        for (int i = 1; i < m; i++) {
            for (int j = 1; j < n; j++) {
                if (matrix[i][0] == 0 || matrix[0][j] == 0)
                    matrix[i][j] = 0;
            }
        }

        // 阶段三：最后处理第一行、第一列
        // 注意顺序：先看 matrix[0][0]（行标记）清第一行，再按 col0 清第一列
        if (matrix[0][0] == 0)
            for (int j = 0; j < n; j++) matrix[0][j] = 0;
        if (col0)
            for (int i = 0; i < m; i++) matrix[i][0] = 0;
    }
};
```

三个实现细节：

1. **`col0` 单独记账**：`matrix[0][0]` 的双重身份靠它化解——它只表达"第一行是否清零"，第 0 列的生死由布尔变量保管。
2. **阶段二只清内圈**（$i, j$ 从 1 开始）：第一行、第一列此刻还是"标记区"，动了就会销毁证据。
3. **阶段三先清行再清列**：清第一行会覆盖 `matrix[0][0]`，若先清列，之后 `matrix[0][0]` 已被清成 0，无法区分"原本就要清第一行"——先读后写，顺序不能反。

---

## 4. 复杂度分析

- **时间复杂度**：$O(mn)$。三个阶段各扫一遍矩阵（阶段一只扫内圈+一次首列检查，可计为常数因子），总共仍是矩阵规模的常数倍。每个元素至少要看一眼，已是最优。
- **空间复杂度**：$O(1)$。只额外用了一个布尔变量 `col0`；$m + n$ 个标记全部寄生在矩阵的第一行与第一列里（不计输入）。

从 $O(mn)$ 到 $O(m+n)$ 再到 $O(1)$，时间始终是 $O(mn)$——**空间压缩的代价是把"标记区"和"数据区"叠在同一块内存上，因此必须小心操作顺序**。

## 5. 常见疑问

**疑问一：为什么不能扫到 0 就地清零？**

看反例 `matrix = [[1,0],[2,3]]`，正确答案是 `[[0,0],[2,0]]`。若按行优先边扫边清：扫到 $(0,1)$ 的原始 0，清掉第 0 行、第 1 列，矩阵变为 `[[0,0],[2,0]]`；继续扫到 $(1,1)$——它**本来是 3，刚被清成 0**——就地清零逻辑把它当成原始 0，再清第 1 行，得到 `[[0,0],[0,0]]`，错误地多清了一行。问题的根源是**清零产生的新 0 与原始 0 无法区分**，所以必须"第一遍只读原值打标记、第二遍才动笔清零"，两阶段各司其职。

**疑问二：`matrix[0][0]` 到底归谁管？**

它同时落在第一行和第一列，而一个格子只能存一个布尔值。约定：`matrix[0][0] == 0` 只表示"第一行需要清零"；"第一列是否清零"由 `col0` 保管。打标记时，第 0 列上的 0 只置 `col0 = true`，不写 `matrix[0][0]`（避免与行标记串扰——若第 0 列有 0 但第一行没有，把 `matrix[0][0]` 置 0 会冤枉第一行）。

**疑问三：清零顺序有哪些坑？**

两处。其一，阶段二不能碰第 0 行、第 0 列（标记还在用）；其二，阶段三里必须**先清第一行、再清第一列**：清第一行的动作会把 `matrix[0][0]` 写成 0，若把读 `matrix[0][0]` 判断放在清列之后，读到的是被自己污染的值。清零阶段改成从最后一行往第一行扫（`for i = m-1 … 0`，行内从右往左）则可把阶段二、三合并，是另一种等价写法——但"先读标记、后覆盖标记位置"的纪律不变。
