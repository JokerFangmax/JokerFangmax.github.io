# LeetCode 15. 三数之和

> 题目链接：[https://leetcode.cn/problems/3sum/](https://leetcode.cn/problems/3sum/)  
> 难度：中等  
> 标签：数组、双指针、排序

---

## 1. 题目描述

给你一个整数数组 `nums`，判断是否存在三元组 $(nums[i], nums[j], nums[k])$ 满足 $i \ne j$、$i \ne k$、$j \ne k$（下标互不相同）且 $nums[i] + nums[j] + nums[k] = 0$。

返回**所有和为 0 且不重复**的三元组。注意答案中**不能包含重复的三元组**——值相同的三元组只算一个。

**数据范围：**

- $3 \le nums.length \le 3000$
- $-10^5 \le nums[i] \le 10^5$

**示例：**

```
输入：nums = [-1,0,1,2,-1,-4]
输出：[[-1,-1,2],[-1,0,1]]
解释：下标三元组 (0,1,2)、(1,2,4)、(0,3,4) 的和都为 0：
  nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0
  nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0
  nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0
  三个下标三元组去重后只剩两个值组合：{-1,-1,2} 和 {-1,0,1}。

输入：nums = [0,0,0,0]
输出：[[0,0,0]]
```

## 2. 思路分析

### 2.1 暴力：三重循环 + 去重

直接枚举全部 $O(n^3)$ 个下标组合，把和为 0 的三元组排序后塞进 `set` 去重。$n = 3000$ 时约 $2.7 \times 10^{10}$ 次运算，必然超时；即使 $n$ 减半也过不了。而且"先收集再去重"的模式天然要付出哈希和排序的额外代价。

降一重：用哈希表把最内层"找 $-(a+b)$"变成 $O(1)$，得到 $O(n^2)$——但仍要小心去重（`nums = [0,0,0,0]` 会把同一个 $(0,0,0)$ 记录 $C_4^3 = 4$ 次），实践上去重逻辑比双指针版更繁琐。

### 2.2 排序：把"无序找数"变成"有序双指针"

换一个思路组织问题：**先排序，再固定第一个数 $a = nums[i]$，剩下的问题变成"在有序数组 $nums[i+1..n-1]$ 中找两个数之和为 $-a$"**。

子问题"有序数组两数之和"正是对撞双指针 (two pointers) 的主场（LC 167）：

- $l$ 从左、$r$ 从右出发，若 $nums[l] + nums[r]$ 偏小，只有 $l$ 右移才可能变大；偏大则只有 $r$ 左移才可能变小；
- 两指针相向而行，每步至少淘汰一整行/一列候选，子问题 $O(n)$ 解决。

排序带来两个额外红利：

1. **剪枝**：排完序后若 $nums[i] > 0$，则它右边的数全部 $> 0$，三数之和不可能为 0，直接 `break`；
2. **去重变得平凡**：相等的元素在排序后被挤到相邻位置，跳过相邻重复值即可，完全不需要哈希。

### 2.3 去重的三个关键点（本题真正的坑）

**去重是本题的实现难点**，必须在三个位置各做一次：

| 位置 | 规则 | 防止什么 |
|------|------|----------|
| 固定 $i$ 时 | `i > 0 && nums[i] == nums[i-1]` 则跳过 | 第一维重复枚举同一 $a$ |
| 找到解后移动 $l$ | 跳过 `nums[l+1] == nums[l]` | 第二维重复 |
| 找到解后移动 $r$ | 跳过 `nums[r-1] == nums[r]` | 第三维重复 |

两个经典疑问先答掉：

- **为什么 $i$ 的去重比较的是 `nums[i-1]`（前一个）而不是 `nums[i+1]`（后一个）？** 比较后一个会**错杀**：`[-1, -1, 2]` 中第一个 `-1` 与后一个相同就被跳过，解 $(-1, -1, 2)$ 永远找不到。比较前一个的含义是"这个值上一轮作为 $a$ 已经用过了"，此时它必然凑不出新解，跳过安全。
- **为什么 $l$、$r$ 的去重发生在"找到一个解之后"？** 找到解后 $l$、$r$ 本来就要各移一步；此时若不继续跳过相同值，同一 $a$ 下相同的 $(b, c)$ 组合会再次被命中（如 `[0,0,0,0]` 固定 $a=0$ 后，$(0,0)$ 会被命中两次）。把去重嵌在"移动"这个动作里，逻辑最紧凑。

### 2.4 执行过程演示

`nums = [-1,0,1,2,-1,-4]`，排序后为 `[-4, -1, -1, 0, 1, 2]`。先看外层 $i$ 的整体走向（$a$ 取下标 $i$，区间从 $i+1$ 开始）：

| $i$ | $a$ | 目标两数之和 | 区间（值） | 结果 |
|-----|-----|--------------|------------|------|
| 0   | -4  | $4$  | `[-1,-1,0,1,2]` | 最大两数之和 $3 < 4$，$l$ 一路右移，无解 |
| 1   | -1  | $1$  | `[-1,0,1,2]` | **命中两个解**（展开见下） |
| 2   | -1  | —    | — | `nums[2] == nums[1]`，第一维去重跳过 |
| 3   | 0   | $0$  | `[1,2]` | $1 + 2 = 3 > 0$，$r$ 左移后相遇，无解 |
| 4   | 1   | —    | — | $a > 0$，剪枝 `break` |

$i = 1$ 这轮是精华，逐步展开。数组仍是 `[-4,-1,-1,0,1,2]`，$a$ 取走下标 1 的 $-1$，区间是下标 2..5，值 `[-1, 0, 1, 2]`，目标 $1$：

```
l=2(-1), r=5(2):  sum = -1+2 = 1 = 目标 ✓ 记录 (-1,-1,2)
                  跳重: nums[2]=-1 与 nums[3]=0 不等 → l 不动
                        nums[5]=2 与 nums[4]=1 不等 → r 不动
                  推进: l=3, r=4

l=3(0),  r=4(1):  sum = 0+1 = 1 = 目标 ✓ 记录 (-1,0,1)
                  跳重: 两两不等，无事发生
                  推进: l=4, r=3 → l < r 失败，本轮结束
```

一轮拿下 $(-1,-1,2)$ 和 $(-1,0,1)$。再体会 $i = 2$ 的跳过为什么必要：若允许 $a$ 再取一次 $-1$（下标 2），区间为下标 3..5 的 `[0,1,2]`，双指针照样会命中 $0 + 1 = 1$，把 $(-1,0,1)$ **原样再记一遍**。而 $i = 1$ 轮内能命中 $(-1,-1,2)$，靠的正是排序把两个 $-1$ 挤到相邻位置——固定维取走一个，剩下的那个还在 $i+1$ 处等着入伙。

另看 $i = 0$ 的失败方式：区间内最大两数之和只有 $1 + 2 = 3$，凑不到目标 $4$，$l$ 一路右移到 $r$ 也没命中——说明 $-4$ 太小，无论配谁都补不平。这就是"目标够不着"型无解，双指针会自己走完流程，不需要特判。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<vector<int>> threeSum(vector<int>& nums) {
        int n = nums.size();
        sort(nums.begin(), nums.end());
        vector<vector<int>> ans;

        for (int i = 0; i < n; i++) {
            if (nums[i] > 0) break;               // 剪枝: 最小值已 > 0，后面无解
            if (i > 0 && nums[i] == nums[i - 1]) continue;  // 第一维去重

            int l = i + 1, r = n - 1;
            while (l < r) {
                int sum = nums[i] + nums[l] + nums[r];
                if (sum < 0) {
                    l++;
                } else if (sum > 0) {
                    r--;
                } else {
                    ans.push_back({nums[i], nums[l], nums[r]});
                    // 第二、三维去重: 跳过与刚命中值相同的邻居
                    while (l < r && nums[l] == nums[l + 1]) l++;
                    while (l < r && nums[r] == nums[r - 1]) r--;
                    l++, r--;                      // 常规推进一步
                }
            }
        }
        return ans;
    }
};
```

几个实现细节：

1. **第一维去重比较 `nums[i-1]`**，比较 `nums[i+1]` 会在 `[-1,-1,2]` 这类输入上错杀唯一解（见 2.3）。
2. **命中解后先跳重、再各移一步**。跳重循环的守卫 `l < r` 不能省——全相同数组 `[0,0,0,0]` 里不设防会越界或死循环。
3. **剪枝 `nums[i] > 0` 用 `break` 而不是 `continue`**：排序保证后续的 $i$ 只会更大，全部无解，跳出整个循环。
4. 三元组天然按 $(a, b, c)$ 非降序输出，省去答案再排序。

## 4. 复杂度分析

- **时间复杂度**：$O(n^2)$。排序 $O(n \log n)$；外层 $i$ 枚举 $n$ 次，内层双指针合计至多 $n - i - 1$ 步，总计 $\sum_i (n - i - 1) = O(n^2)$。$n = 3000$ 时约 $4.5 \times 10^6$ 步，轻松通过。
- **空间复杂度**：$O(\log n)$，排序的递归栈（不计返回值）。若把 `sort` 的临时缓冲计入则是 $O(\log n) \sim O(n)$ 视实现而定。

对比：暴力 $O(n^3)$ → 哈希 $O(n^2)$（去重繁琐）→ 排序 + 双指针 $O(n^2)$（去重平凡）。排序这 $O(n \log n)$ 的"预付成本"买来了两数之和的线性子过程和干净的去重，稳赚。

## 5. 常见疑问

**疑问一：去重只对第一维做行不行？** 不行。反例 `nums = [-2, 0, 0, 2, 2]`：固定 $a = -2$ 后，区间 `[0, 0, 2, 2]` 中 $(0, 2)$ 会被命中**两次**（$l$ 从两个 0 上分别出发）。没有二、三维去重就会输出重复的 `[-2,0,2]`。反过来只做二、三维、不做第一维也不行——`[-1,-1,0,1]` 里 $a = -1$ 被枚举两次，$(0,1)$ 解重复。三层缺一不可。

**疑问二：内层能不能也用哈希表（"两数之和" LC 1 的解法）？** 能，但得不偿失。哈希版要求每个 $i$ 重建（或增删维护）一张哈希表，常数大；更要命的是去重——哈希找出来的组合无序，还得靠 `set<vector<int>>` 兜底。排序版把"有序 + 相等元素相邻"两个性质一次性买断，全部去重都退化成"看一眼邻居"。

**疑问三：剪枝还能更强吗？** 可以再压两个常数级优化：若 $nums[i] + nums[i+1] + nums[i+2] > 0$ 则 `break`（当前 $a$ 连最小的两数都凑超）；若 $nums[i] + nums[n-2] + nums[n-1] < 0$ 则 `continue`（当前 $a$ 配最大的两数都不够）。对极端数据有感，但复杂度仍是 $O(n^2)$，本文从简。

## 6. 相关题目与模板

**可复用模板**（"排序 + 固定一维 + 对撞双指针"骨架，$k$ 数之和通用）：

```cpp
sort(nums.begin(), nums.end());
for (int i = 0; i < n; i++) {
    if (i > 0 && nums[i] == nums[i - 1]) continue;   // 固定维去重
    int l = i + 1, r = n - 1;
    while (l < r) {
        int sum = nums[i] + nums[l] + nums[r];
        if (sum < target)      l++;
        else if (sum > target) r--;
        else {
            /* 记录解; 跳过 nums[l]==nums[l+1], nums[r]==nums[r-1]; l++, r-- */
        }
    }
}
```

四数之和（LC 18）在此基础上再套一层外循环，配同样的两层去重；$k$ 数之和则递归降维，最后两层用双指针收口。

- [LeetCode 1. 两数之和](https://leetcode.cn/problems/two-sum/)：无序版用哈希，对照理解"有序才配双指针"
- [LeetCode 167. 两数之和 II](https://leetcode.cn/problems/two-sum-ii-input-array-is-sorted/)：本题去掉固定维后的子问题本体
- [LeetCode 18. 四数之和](https://leetcode.cn/problems/4sum/)：多一层枚举，去重与剪枝翻倍，注意目标和可能溢出 `int`
- [LeetCode 11. 盛最多水的容器](https://leetcode.cn/problems/container-with-most-water/)：另一道对撞双指针名题，"每步安全淘汰一批候选"的思想同源

**一句话总结**：三数之和 = **排序买断两个性质（有序可双指针、相等值相邻可去重）+ 固定一维降成两数之和**；坑全在去重的三个位置和"比较前一个还是后一个"的细节上。
