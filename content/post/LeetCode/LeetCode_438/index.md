# LeetCode 438. 找到字符串中所有字母异位词

> 题目链接：[https://leetcode.cn/problems/find-all-anagrams-in-a-string/](https://leetcode.cn/problems/find-all-anagrams-in-a-string/)  
> 难度：中等  
> 标签：哈希表、字符串、滑动窗口

---

## 1. 题目描述

给定两个字符串 `s` 和 `p`，找到 `s` 中所有 `p` 的**异位词 (anagram)** 子串，返回这些子串的**起始下标**。异位词指字母相同、但排列可以不同的字符串：`"abc"` 与 `"bca"` 互为异位词，`"aab"` 与 `"abb"` 不是（字母个数不同）。

换句话说，对每个起点 $i$，问子串 $s[i..i+|p|-1]$ 是否恰好是 `p` 中字符的一个排列。

**数据范围：**

- $1 \le s.length, p.length \le 3 \times 10^4$
- `s` 和 `p` 仅包含小写英文字母

**示例：**

```
输入：s = "cbaebabacd", p = "abc"
输出：[0, 6]

起始索引 0 的子串 "cba" 是 "abc" 的异位词
起始索引 6 的子串 "bac" 是 "abc" 的异位词

输入：s = "abab", p = "ab"
输出：[0, 1, 2]
// "ab"、"ba"、"ab" 都是 "ab" 的异位词
```

---

## 2. 思路分析

### 2.1 暴力：逐个起点重新数一遍

若 $|p| > |s|$ 直接返回空。否则枚举 $n - m + 1$ 个起点（$n = |s|, m = |p|$），每个起点把长度为 $m$ 的子串字符频次数出来、与 `p` 的频次比较，代价 $O(nm)$。最坏 $n = m = 3\times10^4$ 时（同量级，如 $n = 3\times10^4, m = 1.5\times10^4$）约 $4.5 \times 10^8$ 次操作，必然超时。

和 [LeetCode 76](../LeetCode_76/) 一样，问题的本质是：**相邻窗口只差"进来一个字符、出去一个字符"，大量计数信息是重复的，暴力却每次从零重数**。

### 2.2 关键观察：这是"定长"窗口

与 LC 76 的"不定长滑窗求最短"不同，本题的窗口长度**固定为 $m$**：

- 不需要"扩张到覆盖、再收缩"的循环，窗口只会**整格右移**；
- 窗口从 $s[i..i+m-1]$ 滑到 $s[i+1..i+m]$，只发生两件事：纳入 $s[i+m]$、移出 $s[i]$。

于是维护一个长度为 26 的计数数组 `cnt[26]`，代表当前窗口内每个字母的个数。滑动一步的更新只有 $O(1)$：

- 纳入字符 $c$：`cnt[c]++`；
- 移出字符 $d$：`cnt[d]--`。

初始时先把 `p` 的频次从目标 `need[]` 中"预存"，改用**差值数组**的技巧：让 `cnt[c] = need_p[c] - 窗口中 c 的个数`，即"还差多少"——但更常见的写法是直接比较 `cnt == need`。

### 2.3 比较整个数组的代价：差分计数

每次滑动后判断"窗口是否为异位词"，朴素做法是比较 26 个字母的计数，`memcmp` 一次 $O(|\Sigma|) = O(26)$，总代价 $O(26n) \approx 7.8 \times 10^5$，其实已经能过。但有个 $O(1)$ 判断的优雅写法——维护**差值**（和 LC 76 的"欠账计数"同源，但更简单）：

设 `diff[c] = 窗口中 c 的个数 - p 中 c 的个数`，另用整数 `dist` 记录 `diff[c] != 0` 的字母种数：

| 事件 | 更新 | 说明 |
|------|------|------|
| 初始化 | `diff = -need_p`，`dist` = p 中不同字母种数 | 窗口为空，全欠账 |
| 纳入 $c$ | `diff[c]++` 前后跨越 0 则 `dist` ±1 | 从 -1 跨到 0：还清一种，`dist--` |
| 移出 $d$ | `diff[d]--` 前后跨越 0 则 `dist` ±1 | 从 0 跌回 -1：重新欠账，`dist++` |
| 判断 | `dist == 0` | 26 种字母全部打平 ⟺ 互为异位词 |

判断条件从"扫 26 个格子"缩成一次整型比较，滑动每步严格 $O(1)$。

### 2.4 操作流程（以示例演示）

`s = "cbaebabacd"`, `p = "abc"`，$m = 3$，`need_p = {a:1, b:1, c:1}`。初始 `diff = {a:-1, b:-1, c:-1}`，`dist = 3`。

先纳入前 3 个字符成窗，随后每轮"先纳入 $s[i]$、再移出 $s[i-m]$"。用 `[ ]` 括住当前窗口：

| 窗口 | 纳入 / 移出 | 关键 diff 变化 | dist | 异位词? |
|------|------------|---------------|------|---------|
| `[c b a]` eba... | 成窗：c、b、a 各 -1→0 | 三种欠账全还清 | **0** | ✅ 记 0 |
| c `[b a e]` ba... | 纳入 e, 移出 c | e 0→1（盈余），c 0→-1（欠账） | 2 | ❌ |
| cb `[a e b]` a... | 纳入 b, 移出 b | b 0→1 再 1→0，净不变 | 2 | ❌ |
| cba `[e b a]` ba... | 纳入 a, 移出 a | a 0→1 再 1→0，净不变 | 2 | ❌ |
| cbae `[b a b]` ac | 纳入 b, 移出 e | b 0→1, e 1→0（盈余清空） | 2 | ❌ |
| cbaeb `[a b a]` c | 纳入 a, 移出 b | a 0→1, b 1→0 | 2 | ❌ |
| cbaeba `[b a c]` d | 纳入 c, 移出 a | c -1→0（还清），a 1→0（盈余跌回） | **0** | ✅ 记 6 |
| cbaebab `[a c d]` | 纳入 d, 移出 b | d 0→1, b 0→-1 | 2 | ❌ |

以第 2 行为例看细节：窗口从 `cba` 滑到 `bae`，纳入 `e`（`p` 里没有 `e`，`diff[e]` 从 0 到 1，跨过 0，`dist++`），移出 `c`（`diff[c]` 从 0 跌回 -1，`dist++`），`dist` 从 0 变成 2——**多余字符与欠账字符同样破坏平衡**，这正是"异位词要求恰好相等，多了少了都不行"的体现。

倒数第二行再盯一眼：上一个窗口 `aba` 里 `a` 出现了两次，`diff[a] = 1`（盈余）；滑入 `bac` 时移出一个 `a`（盈余跌回 0）、纳入一个 `c`（欠账还清），两个跨零动作让 `dist` 从 2 归零——**盈余和欠账都在被实时追踪**。最终输出 `[0, 6]`。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<int> findAnagrams(string s, string p) {
        int n = s.size(), m = p.size();
        if (n < m) return {};

        int diff[26] = {};          // diff[c] = 窗口中 c 的个数 - p 中 c 的个数
        for (char c : p) diff[c - 'a']--;   // 先记下 p 的"欠账"

        int dist = 0;               // diff[c] != 0 的字母种数
        for (int c = 0; c < 26; c++)
            if (diff[c] != 0) dist++;

        vector<int> ans;
        for (int i = 0; i < n; i++) {
            // 纳入 s[i]
            int c = s[i] - 'a';
            if (diff[c] == 0) dist++;       // 即将从 0 变非 0
            diff[c]++;
            if (diff[c] == 0) dist--;       // 恰好回到 0

            // 移出 s[i - m]（窗口长度保持 m）
            if (i >= m) {
                int d = s[i - m] - 'a';
                if (diff[d] == 0) dist++;
                diff[d]--;
                if (diff[d] == 0) dist--;
            }

            if (i >= m - 1 && dist == 0)    // 成窗且完全打平
                ans.push_back(i - m + 1);
        }
        return ans;
    }
};
```

几个实现细节：

1. **`diff` 初始化为 p 的负频次**：先 `diff[c]--` 把欠账记上，之后纳入字符就是"还账"，语义统一为"与 p 的差"。
2. **`dist` 的增减必须贴着 0 这条线**：只有**从 0 变非 0** 时 `dist++`、**从非 0 变回 0** 时 `dist--`。比如 `diff[c]` 从 1 到 2（多了一个），它本来就不为 0，`dist` 不动。
3. **移出与纳入在同一轮内做**：`i` 是窗口右端点，窗口为 $[i-m+1, i]$；当 $i \ge m$ 时要移出 $s[i-m]$。注意移出判断 `i >= m` 而不是 `i >= m - 1`——成窗的第一轮（$i = m-1$）只纳入不移出。
4. **答案下标是左端点** $i - m + 1$，不是右端点 $i$，这是最常见的差一错误。
5. 字符集只有小写字母，用 `int diff[26]` 数组即可，不需要哈希表。

## 4. 复杂度分析

- **时间复杂度**：$O(n + m + |\Sigma|)$。建 `diff` 花 $O(m + 26)$，主循环 $n$ 轮、每轮 $O(1)$（差分计数让判断也变成常数）。相比暴力的 $O(nm)$，省掉的是每个窗口内部的重数与比较。
- **空间复杂度**：$O(|\Sigma|) = O(26)$，一个差分数组和几个整型（不计输出数组）。

## 5. 常见疑问

**疑问一：为什么不能用"排序后比较"？** 把 `p` 排序作为目标，每个窗口排序后比较，$O(n \cdot m \log m)$，复杂度爆炸。排序破坏了窗口滑动的增量性——滑动窗口的一切优化都建立在"一步只改两个位置"之上，排序是全局重算。

**疑问二：`dist` 会不会漏判"窗口比 p 多了字符"的情况？** 不会。`diff` 是带符号差值，多出来的字符让 `diff[c] > 0`，同样计入 `dist`。反例走查：`s = "aab"`, `p = "ab"`，窗口 `aab` 的 `diff = {a:1, b:0}`，`dist = 1 \ne 0`，正确排除。若只数"缺口"不数"盈余"（LC 76 的欠账只看缺口，因为覆盖允许超量），这里就会误判——**"恰好相等"和"至少覆盖"是两种不同的谓词**。

**疑问三：`n < m` 的边界。** 窗口根本成不了形，直接返回空。另外 `p` 长度为 1 时每个字符自成异位词，代码天然覆盖，无需特判。

## 6. 相关题目与模板

> 📚 系统整理见模板笔记：[滑动窗口：单调性判据与三种基本形态](../../algorithms/sliding_window/)（本题是"定长窗口"形态的代表）。

**可复用模板**（定长滑动窗口 + 差分计数通用骨架）：

```cpp
// 长度为 m 的窗口扫 s，O(1) 判断"窗口内容 == 目标多重集"
int diff[26] = {}, dist = 0;   // dist: diff[c] != 0 的种数
/* 初始化 diff 为目标频次的相反数，dist 数非零种数 */
for (int i = 0; i < n; i++) {
    add(s[i]);                 // 跨 0 更新 dist
    if (i >= m) remove(s[i - m]);
    if (i >= m - 1 && dist == 0) /* 记录 i - m + 1 */;
}
```

把"判断相等"换成别的谓词，这套骨架可以迁移到很多定长窗口题。

- [LeetCode 76. 最小覆盖子串](https://leetcode.cn/problems/minimum-window-substring/)：不定长窗口 + 欠账计数，是本题的"至少覆盖"版（详见[我的题解](../LeetCode_76/)）
- [LeetCode 567. 字符串的排列](https://leetcode.cn/problems/permutation-in-string/)：和本题几乎同题，只是问"存在与否"而不是"所有下标"
- [LeetCode 239. 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/)：定长窗口问"最值"，需要单调队列而不是计数（详见[我的题解](../LeetCode_239/)）
- [LeetCode 2134. 最少交换次数来组合所有的 1](https://leetcode.cn/problems/minimum-swaps-to-group-all-1s-together-ii/)：定长窗口（环上）计 1 的个数，骨架相同

**一句话总结**：定长滑动窗口 + 差分计数，把"每个窗口重新比对 26 个字母"变成"滑一步改两个位置、整数比较判打平"——窗口滑动省下的是重复计算，差分省下的是比较。
