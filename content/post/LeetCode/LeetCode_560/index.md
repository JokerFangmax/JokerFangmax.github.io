# LeetCode 560. 和为 K 的子数组

> 题目链接：[https://leetcode.cn/problems/subarray-sum-equals-k/](https://leetcode.cn/problems/subarray-sum-equals-k/)  
> 难度：中等  
> 标签：数组、前缀和、哈希表

---

## 1. 题目描述

给你一个整数数组 `nums` 和一个整数 `k`，请你统计并返回该数组中**和为 `k` 的子数组的个数**。

子数组是数组中元素的**连续非空**序列。

**数据范围：**

- $1 \le nums.length \le 2 \times 10^4$
- $-1000 \le nums[i] \le 1000$
- $-10^7 \le k \le 10^7$

**示例：**

```
输入：nums = [1,1,1], k = 2
输出：2        // [1,1] 与 [1,1]，两种起点不同的取法

输入：nums = [1,2,3], k = 3
输出：2        // [1,2] 与 [3]
```

注意数据范围里 **`nums[i]` 可以是负数**——这一点直接排除了"正数才有的单调性"做法（比如滑动窗口），是本题的第一个陷阱。

---

## 2. 思路分析

### 2.1 暴力：枚举所有子数组

最直接的做法是枚举所有 $(i, j)$ 起点/终点对，再累加求和。用三重循环是 $O(n^3)$；如果枚举起点 $i$ 后向右扩展终点 $j$ 边走边累加，可以优化到 $O(n^2)$：

```cpp
int subarraySum(vector<int>& nums, int k) {
    int n = nums.size(), ans = 0;
    for (int i = 0; i < n; i++) {
        int sum = 0;
        for (int j = i; j < n; j++) {
            sum += nums[j];          // sum = nums[i..j] 的和
            if (sum == k) ans++;
        }
    }
    return ans;
}
```

$n = 2 \times 10^4$ 时 $O(n^2) \approx 4 \times 10^8$，会超时。需要 $O(n)$ 或 $O(n \log n)$ 的做法。

### 2.2 为什么不能用滑动窗口

如果有滑动窗口经验，很容易想到：右指针扩张使和增大，超过 `k` 就收缩左指针。但这依赖于**窗口和的单调性**——只有数组全为正数时才成立。

本题 `nums[i]` 可以为负，加入一个负数后窗口和反而变小，缩小窗口和也可能变大，窗口失去了"该进则进、该退则退"的判断依据。**滑动窗口失效的根本原因：元素符号不定。**

### 2.3 正解：前缀和 + 哈希表

定义前缀和：

$$
pre[i] = nums[0] + nums[1] + \cdots + nums[i-1], \quad pre[0] = 0
$$

那么子数组 $nums[i..j]$ 的和可以表示为：

$$
sum(i, j) = pre[j+1] - pre[i]
$$

我们要求 $sum(i,j) = k$，即：

$$
pre[j+1] - pre[i] = k \iff pre[i] = pre[j+1] - k
$$

于是问题转化：**从左到右遍历，对于每个位置 `j`，统计它左边有多少个前缀和等于 `pre[j] - k`**。

"左边有多少个值等于某目标值"——这正是哈希表的拿手好戏。用一个 `unordered_map<int, int>` 记录「前缀和 → 出现次数」，一边遍历一边查询，一次扫描即可完成。

一个关键细节：**初始化时要把 `pre = 0` 的次数设为 1**（即 `mp[0] = 1`）。它对应"空前缀"，处理从下标 0 开始、和恰好为 `k` 的子数组。以 `nums = [1,2,3], k = 3` 为例，扫到 `j = 0` 时 `pre = 1`，查询 `pre - k = -2` 不存在；但如果 `nums[0]` 本身等于 `k`（比如 `nums = [3,...]`，`pre - k = 0`），没有这条初始记录就会漏解。

**执行过程演示**（`nums = [1,1,1], k = 2`）：

| j | nums[j] | pre | 查询 pre−k | 命中数 | 累计答案 | 更新后哈希表 |
|---|---------|-----|-----------|--------|---------|--------------|
| — | —       | 0   | —         | —      | 0       | {0:1}        |
| 0 | 1       | 1   | −1        | 0      | 0       | {0:1, 1:1}   |
| 1 | 1       | 2   | 0         | 1      | 1       | {0:1, 1:1, 2:1} |
| 2 | 1       | 3   | 1         | 1      | 2       | {0:1, 1:1, 2:1, 3:1} |

注意"先查询、后插入"的顺序——查询的是**当前元素之前**的前缀和，如果把当前 `pre` 先插进去再查，就可能用 `pre - pre = 0` 错误地匹配到自己（当 `k = 0` 时会多算空子数组）。

## 3. 代码实现

```cpp
class Solution {
public:
    int subarraySum(vector<int>& nums, int k) {
        // mp[pre] = 前缀和 pre 出现的次数
        unordered_map<long long, int> mp;
        mp[0] = 1;                  // 空前缀：处理从下标 0 开始就凑出 k 的情况

        long long pre = 0;
        int ans = 0;
        for (int x : nums) {
            pre += x;                       // pre = nums[0..j] 的和
            ans += mp.count(pre - k) ? mp[pre - k] : 0;
                                            // 有多少个 i 使 pre[i] = pre - k
                                            // 就有多少个和为 k 的子数组
            mp[pre]++;                      // 先查询，后插入
        }
        return ans;
    }
};
```

几个实现细节：

1. **先查询、后插入**：保证统计的只是当前元素**左边**的前缀和，避免 `k = 0` 时自己匹配自己。
2. **`mp[0] = 1` 不能漏**：代表空前缀，漏掉会丢失"从头开始的子数组"。
3. **用 `long long` 存前缀和**：$|pre| \le 2\times10^4 \times 1000 = 2\times10^7$，本题 `int` 其实不会溢出，但养成习惯——前缀和类型放宽一档是廉价的保险。
4. 用 `mp.count()` 判存在（或 C++20 的 `mp.contains()`），直接 `ans += mp[pre - k]` 也可以——`unordered_map` 的 `operator[]` 会在键不存在时插入默认值 0，功能上等价但会往表里塞垃圾键，数据量大时略微浪费。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。每个元素一次哈希查询 + 一次哈希插入，均为均摊 $O(1)$。
- **空间复杂度**：$O(n)$。哈希表最多存 $n + 1$ 个不同的前缀和。

对比暴力的 $O(n^2)$，本质的加速来自：不再对每个终点重新扫描所有起点，而是用"值 → 出现次数"的映射把"数有多少个满足条件的前缀和"变成一次查表。

## 5. 常见疑问

**疑问一：`mp[0] = 1` 是干什么的？不初始化会怎样？**

它代表"前缀和为 0 出现过一次"——空前缀。设某个位置 $i$ 恰好满足 $pre_i = k$，那么从数组开头到 $i$ 这一段本身就是和为 $k$ 的子数组，对应的查询 $mp[pre_i - k] = mp[0]$ 必须能查到 1 才不会漏解。

不初始化的反例：`nums = [1, 2, 3], k = 6`。扫描到末尾时 $pre = 6$，查询 $mp[0]$；若没有哨兵，答案少算从头开始的整段，返回 0 而正确答案是 1。这一行与 239 题里"队头过期判断"一样，都是**边界的一次性投入，换来循环体的零特判**。

**疑问二：为什么先查后插，反过来行不行？**

顺序不能反。若先 `mp[pre]++` 再查询，当 $k = 0$ 时会把"自己减自己"这个空子数组也算进去——查询 $mp[pre - 0] = mp[pre]$ 会多出刚插入的当前前缀。先查后插保证统计的永远是**严格在左侧**的前缀，下标天然满足 $i < j$。

**疑问三：负数出现时，前缀和不再单调，为什么这不影响哈希表做法？**

这正是本题不能用滑动窗口的根本原因、也是哈希表做法的底气所在：滑动窗口依赖"窗口右移时和单调变化"来收缩/扩张；有负数时和可能不升反降，窗口没有可维护的单调性。而哈希表做法只关心**值相等**这一事件，与前缀和的增减趋势无关——负数、正数一视同仁。可以对照 239 的表格理解：单调队列利用的是顺序信息，哈希表利用的是值信息，二者互为镜像。

## 6. 相关题目与模板

这道题确立了一个非常常用的套路：**"前缀和 + 哈希表统计"处理子数组计数问题**。凡是"和满足某条件的子数组个数"，都可以往这个方向想。

> 📚 系统整理见模板笔记：[前缀和：从区间和到子数组计数](../../algorithms/prefix_sum/)（含条件变形全家桶）、[哈希表：从查找到计数的问题模式](../../algorithms/hash_table/)（模式④：状态配对）。

**可复用模板**（子数组和计数通用骨架）：

```cpp
// 统计和满足条件的子数组个数
unordered_map<long long, int> mp;
mp[0] = 1;
long long pre = 0;
int ans = 0;
for (int x : nums) {
    pre += x;
    ans += mp[pre - k];    // 把 k 换成目标条件即可
    mp[pre]++;
}
```

**同类题目：**

- [LeetCode 974. 和可被 K 整除的子数组](https://leetcode.cn/problems/subarray-sums-divisible-by-k/)：把条件换成 `(pre_j - pre_i) % K == 0`，即统计**前缀和余数相同**的次数，注意负数取模要先 `((pre % K) + K) % K`
- [LeetCode 525. 连续数组](https://leetcode.cn/problems/contiguous-array/)：把 0 看成 −1，转化为"和为 0 的最长子数组"，哈希表改存**最早出现位置**而不是次数
- [LeetCode 325. 和等于 k 的最长子数组长度](https://leetcode.cn/problems/maximum-size-subarray-sum-equals-k/)：同样改存最早出现位置，求最长而不是计数
- [LeetCode 1248. 优美子数组](https://leetcode.cn/problems/number-of-sub-arrays-with-odd-sum/)：奇偶前缀和，把元素映射成 0/1 再套同一模板

**一句话总结**：子数组问题先想前缀和；元素有负数、窗口没有单调性时，用哈希表把"往前找"变成"查表"。
