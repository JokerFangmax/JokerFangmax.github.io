# LeetCode 153. 寻找旋转排序数组中的最小值

> 题目链接：[https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/](https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array/)  
> 难度：中等  
> 标签：数组、二分查找

---

## 1. 题目描述

一个原本**元素互不相同**的升序数组，在某个未知下标处被"旋转"了。例如 `[0,1,2,4,5,6,7]` 旋转 4 次后变成 `[4,5,6,7,0,1,2]`（把末尾 4 个元素依次挪到开头也可以得到同样结果，如 `[0,1,2,4,5,6,7]` 旋转 7 次还是它自己）。

给定旋转后的数组 `nums`，返回其中的**最小值**。要求设计一个 $O(\log n)$ 级别的算法。

**数据范围：**

- $n = nums.length$
- $1 \le n \le 5000$
- $-5000 \le nums[i] \le 5000$
- `nums` 中的所有值**互不相同**
- `nums` 原来是一个升序数组，并在某个点被旋转过

**示例：**

```
输入：nums = [3,4,5,1,2]
输出：1
解释：原数组为 [1,2,3,4,5] ，旋转 3 次得到输入数组。

输入：nums = [4,5,6,7,0,1,2]
输出：0

输入：nums = [11,13,15,17]
输出：11
解释：数组可能完全没有旋转（旋转 0 次或 n 次）。
```

---

## 2. 思路分析

### 2.1 暴力：一遍扫过

数组是无序的吗？并不完全是——它是"两段各自有序"的。直接线性扫 $O(n)$ 当然能求最小值，$n \le 5000$ 也毫无压力。但题目明确要求 $O(\log n)$，这个要求本身就是提示：**必须用二分查找 (binary search)**。

可二分的前提是"有序"，而这数组看起来不是整体有序的——问题就卡在这里：**二分的判断条件怎么写？**

### 2.2 关键观察：mid 与 right 的比较能"判段"

把 `[4,5,6,7,0,1,2]` 画出来，它由两段构成：

```
值   4  5  6  7 | 0  1  2
     └── 左段 ──┘ └─ 右段 ─┘
     都 >= 4      都 <= 2
```

最小值 $0$ 是**右段的第一个元素**，即"旋转点"。于是问题转化为：找到旋转点的位置。

二分时取 $mid$，它必然落在左段或右段之一。怎么区分？**拿 $nums[mid]$ 与右端点 $nums[right]$ 比较**：

- 若 $nums[mid] > nums[right]$：$mid$ 落在**左段**（右段的任何值都小于左段的最小值，不可能出现 $nums[mid] > nums[right]$ 却同属一段）。最小值在 $mid$ **右侧**，且 $mid$ 本身肯定不是答案，收缩到 $[mid+1, right]$。
- 若 $nums[mid] < nums[right]$：$mid$ 落在**右段**。右段内部升序，$mid$ 右边的都比 $nums[mid]$ 大，最小值在 $mid$ **或其左侧**，收缩到 $[left, mid]$。

两种情况都能把区间严格缩小，且**从不把答案排除在外**——这是二分正确性的全部要求。

### 2.3 与 right 比还是与 left 比？

新手常见写法是拿 $nums[mid]$ 和 $nums[left]$ 比。这里有一个微妙的不对称：

| 比较对象 | $nums[mid] > nums[left]$ 能推出什么 | $nums[mid] < nums[right]$ 能推出什么 |
|---------|-----------------------------------|-----------------------------------|
| 含义 | 恰好**什么也推不出** | $mid$ 在右段，最小值 $\in [left, mid]$ |
| 原因 | 数组**完全没旋转**时（如 `[1,2,3,4,5]`），$mid$ 大于 $left$ 但最小值就是 $left$ 处 | 右端点必然属于右段（或整个数组就是右段），比较结果无歧义 |

和 $left$ 比时，"`mid 在左段`"与"`数组根本没旋转`"两种情况给出相同的比较结果，无法区分；而 $nums[right]$ 是右段的"哨兵"，$mid$ 无论落哪边，与它的比较结果都是确定的。**这就是本题选 right 做锚点的原因**（元素互不相同保证了比较结果不会是相等）。

### 2.4 用具体例子走一遍

`nums = [4,5,6,7,0,1,2]`，查找区间 $[l, r]$，$mid = \lfloor (l+r)/2 \rfloor$：

| 轮次 | $l$ | $r$ | $mid$ | $nums[mid]$ | 与 $nums[r]$ 比 | 结论 | 新区间 |
|------|-----|-----|-------|-------------|-----------------|------|--------|
| 1 | 0 | 6 | 3 | 7 | $7 > 2$ | 在左段，往右缩 | $[4,6]$ |
| 2 | 4 | 6 | 5 | 1 | $1 < 2$ | 在右段，往左缩 | $[4,5]$ |
| 3 | 4 | 5 | 4 | 0 | $0 < 1$ | 在右段，往左缩 | $[4,4]$ |

$l = r$，循环结束，$nums[l] = 0$ 即答案。

再验证"完全没旋转"的情况 `nums = [1,2,3,4,5]`：

| 轮次 | $l$ | $r$ | $mid$ | $nums[mid]$ | 与 $nums[r]$ 比 | 新区间 |
|------|-----|-----|-------|-------------|-----------------|--------|
| 1 | 0 | 4 | 2 | 3 | $3 < 5$ | $[0,2]$ |
| 2 | 0 | 2 | 1 | 2 | $2 < 3$ | $[0,1]$ |
| 3 | 0 | 1 | 0 | 1 | $1 < 2$ | $[0,0]$ |

最终返回 $nums[0] = 1$，正确。可以看到**无旋转的情况不需要任何特判**——它自然地被"一直在右段"的路径处理掉了。

## 3. 代码实现

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int l = 0, r = (int)nums.size() - 1;
        while (l < r) {
            int mid = l + (r - l) / 2;
            if (nums[mid] > nums[r]) {
                // mid 在左段（较大段），mid 本身不可能是最小值
                l = mid + 1;
            } else {
                // mid 在右段（较小段），mid 可能就是最小值，保留
                r = mid;
            }
        }
        return nums[l];   // 区间缩成一个点，就是旋转点
    }
};
```

三个实现细节：

1. **`mid` 用 $l + (r-l)/2$ 取下中位**。当 $r = l+1$ 时 $mid = l$，配合 `r = mid` 写法保证区间每轮至少缩小 1（若用上中位 $mid = r$，`r = mid` 会原地踏步死循环）。
2. **收缩到 $[mid+1, r]$ 或 $[l, mid]$**，而不是 $\pm 1$ 一起用。`r = mid` 说明 $mid$ 仍可能是答案，不能跳过。
3. **不需要任何关于"是否旋转过"的特判**，全程一套逻辑。

## 4. 复杂度分析

- **时间复杂度**：$O(\log n)$。每轮区间长度至少减半，最多迭代 $\lceil \log_2 n \rceil$ 次。$n = 5000$ 时约 13 次比较。
- **空间复杂度**：$O(1)$。只用三个整型变量。

对比：线性扫 $O(n)$ 对本题规模也够用，但二分是 $O(\log n)$ 的理论最优（下界来自"每次比较至多排除一半候选"），且当 $n$ 升到 $10^8$ 级别时线性扫会失效。

## 5. 常见疑问

**疑问一：为什么判断条件是 `nums[mid] > nums[r]` 而不是 `nums[mid] > nums[l]`？**

如 2.3 节所析：数组完全无旋转时，$nums[mid] > nums[l]$ 恒成立（$mid > l$ 且整体升序），此时无法区分"mid 在左段、最小值在右边"与"数组就是有序的、最小值就是 $nums[l]$"两种情形，需要额外特判；而 $nums[r]$ 永远落在右段（或数组整体有序时就是全局最大值），与它比较得到的两种结果都指向确定的行动。**选错锚点不是 bug，是"少考虑一种情况"的坑**。

**疑问二：为什么不会跳过答案？**

分情况看：`nums[mid] > nums[r]` 时，$mid$ 在左段，左段所有元素都大于右段所有元素，$mid$ 及其左侧全都不是最小值，`l = mid + 1` 安全；`nums[mid] < nums[r]` 时，$mid$ 在右段，右段升序，$mid$ 右侧都比它大，答案在 $[l, mid]$ 内，`r = mid` 把 $mid$ 留在了区间里。两种收缩都"闭眼包含"答案。

**疑问三：如果数组里有重复元素（LeetCode 154）怎么办？**

比较结果可能出现 $nums[mid] = nums[r]$，"判段"失效。经典处理是此时**单独 `r--`**：即使 $nums[r]$ 恰好是最小值，因为 $nums[mid]$ 与它相等，最小值仍在区间内，不会丢失。代价是复杂度退化到 $O(n)$（如全数组同值），但这是带重复元素时可证明的下界。

## 6. 相关题目与模板

**可复用模板**（旋转数组二分"找旋转点"骨架）：

```cpp
// nums 由升序数组旋转而来，找最小值所在下标
int l = 0, r = n - 1;
while (l < r) {
    int mid = l + (r - l) / 2;
    if (nums[mid] > nums[r]) l = mid + 1;   // mid 在左段
    else                     r = mid;       // mid 在右段（含无旋转情形）
}
// l 即旋转点；在旋转数组中二分 target 时先找旋转点再分段二分
```

这套"与右端点比较、按段落收缩"的框架是旋转数组系列的通用钥匙。

**同类题目：**

- [LeetCode 33. 搜索旋转排序数组](https://leetcode.cn/problems/search-in-rotated-sorted-array/)：同一"判段"思想，但目标是找特定值，需额外判断 $mid$ 左半还是右半有序
- [LeetCode 154. 寻找旋转排序数组中的最小值 II](https://leetcode.cn/problems/find-minimum-in-rotated-sorted-array-ii/)：本题的带重复元素版，比较相等时 `r--`
- [LeetCode 81. 搜索旋转排序数组 II](https://leetcode.cn/problems/search-in-rotated-sorted-array-ii/)：33 题的带重复元素版，同样的退化技巧
- [LeetCode 4. 寻找两个正序数组的中位数](https://leetcode.cn/problems/median-of-two-sorted-arrays/)：另一道"看似无序、实则可二分"的困难题

**一句话总结**：旋转数组二分的命门是**找一个"段落归属确定"的锚点**——右端点永远属于较小段，与它比较即可让每一步都"确定性缩小"，无旋转的情形被顺路覆盖，不需要特判。
