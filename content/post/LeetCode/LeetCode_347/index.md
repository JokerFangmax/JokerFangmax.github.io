# LeetCode 347. 前 K 个高频元素

> 题目链接：[https://leetcode.cn/problems/top-k-frequent-elements/](https://leetcode.cn/problems/top-k-frequent-elements/)  
> 难度：中等  
> 标签：数组、哈希表、桶排序、堆、快速选择

---

## 1. 题目描述

给定整数数组 `nums` 和整数 `k`，返回其中**出现频率前 `k` 高的元素**。可以按**任意顺序**返回答案。

**进阶**：算法的时间复杂度必须优于 $O(n \log n)$，其中 $n$ 是数组长度。

**数据范围：**

- $1 \le nums.length \le 10^5$
- $-10^4 \le nums[i] \le 10^4$
- $1 \le k \le$ 数组中不同元素的个数（答案保证存在，无需考虑并列）

**示例：**

```
输入：nums = [1,1,1,2,2,3], k = 2
输出：[1,2]

解释：1 出现 3 次，2 出现 2 次，3 出现 1 次，频率前 2 高的是 1 和 2。
```

---

## 2. 思路分析

### 2.1 第一步恒定：哈希表统计频次

无论后面怎么选，第一步都是用**哈希表 (hash table)** 把每个数出现的次数数出来，$O(n)$。设不同元素共 $m$ 个（$m \le n$），问题随即变成：**在 $m$ 个 `(元素, 频次)` 对里选频次最大的 $k$ 个**——这正是[LeetCode 215 第 K 个最大元素](../LeetCode_215/)的问题形状，只不过"第 k 大"的载体从元素值换成了频次。

### 2.2 堆：容量为 k 的小根堆

套用 215 的堆解法：维护容量为 $k$ 的**小根堆**（按频次比较），新元素的频次大于堆顶就替换。扫完 $m$ 个元素后堆里就是频次前 $k$ 大。

时间 $O(n + m \log k)$，空间 $O(m)$。它没有达到"优于 $O(n \log n)$"的要求吗？达到了——$m \log k \le m \log m \le n \log n$，且 $k \le m$，通常远小于 $n \log n$；但最坏情形（$m \approx n$、$k \approx m$）确实是 $O(n \log n)$ 量级。想严格更优，得把"排序"这个动作彻底换掉。

### 2.3 桶排序：频次的值域天然是 [1, n]

关键观察：**频次的取值范围只有 $[1, n]$**——一个元素最多出现 $n$ 次。值域这么小，排序就不必比较了，直接**按频次分桶 (bucket sort)**：

> 建 $n+1$ 个桶，第 $c$ 个桶里放所有"恰好出现 $c$ 次"的元素；然后**从频次 $n$ 往 $1$ 扫桶**，依次取出元素，凑满 $k$ 个为止。

每个桶内的元素之间不区分次序（题目允许任意顺序），所以连桶内都不用排。整个过程没有任何比较排序，总代价 $O(n)$——严格线性，满足进阶要求。

**用示例走一遍**：`nums = [1,1,1,2,2,3]`，$n = 6$，$k = 2$。

| 步骤 | 内容 |
|------|------|
| 哈希统计 | `1 → 3`，`2 → 2`，`3 → 1` |
| 分桶 | 桶[3] = {1}，桶[2] = {2}，桶[1] = {3}，桶[4..6] = {} |
| 从高到低扫桶 | $c=3$：取 1（已取 1 个）；$c=2$：取 2（已取 2 个）→ 凑满 $k=2$，停止 |
| 输出 | `[1, 2]` |

再如 `nums = [4,4,4,4,5,5,6]`（$n = 7$）：桶[4] = {4}，桶[2] = {5}，桶[1] = {6}；$k = 2$ 时取 4、5，桶[1] 里的 6 根本不会碰——**空桶与低频桶直接跳过，这正是它快的原因**。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        int n = nums.size();

        // 1. 哈希表统计频次
        unordered_map<int, int> cnt;
        for (int x : nums) cnt[x]++;

        // 2. 按频次分桶：buckets[c] 收集所有出现 c 次的元素
        vector<vector<int>> buckets(n + 1);        // 频次取值 [1, n]
        for (auto& [num, c] : cnt) buckets[c].push_back(num);

        // 3. 从高频桶往低频桶收集，凑满 k 个即停
        vector<int> ans;
        for (int c = n; c >= 1 && (int)ans.size() < k; c--) {
            for (int num : buckets[c]) {
                ans.push_back(num);
                if ((int)ans.size() == k) return ans;
            }
        }
        return ans;   // 题目保证 k 不超过不同元素个数，必能凑满
    }
};
```

几个实现细节：

1. **桶的数量是 $n + 1$ 而不是别的**。频次 $c \in [1, n]$，下标 $0$ 的桶永远为空（除非数组为空），开 $n+1$ 是为了下标对齐，防止差一。
2. **用 `(int)ans.size() < k` 做外层循环条件**：凑满即停，低频桶完全不用扫。最坏情况仍要扫到 $c = 1$（所有元素只出现一次时 $k = m$ 个桶都有货），不影响 $O(n)$。
3. **桶内存元素值而不是频次**：扫桶时桶下标就是频次，取出的元素直接进答案。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。统计频次 $O(n)$（均摊）；分桶遍历 $m \le n$ 个键值对 $O(m)$；扫桶收集至多扫 $n + 1$ 个桶、取 $k$ 个元素 $O(n)$。三段相加仍是 $O(n)$，**没有任何比较排序参与**，满足进阶要求。
- **空间复杂度**：$O(n)$。哈希表 $O(m)$、桶数组 $O(n)$（桶内元素总数恰为 $m$），不计输出。

| 做法 | 时间 | 空间 | 是否满足进阶 |
|------|------|------|--------------|
| 哈希 + 全排序（按频次） | $O(n \log n)$ | $O(n)$ | 否 |
| 哈希 + 容量 $k$ 小根堆 | $O(n \log k)$ | $O(m)$ | 通常够用，最坏不严格 |
| 哈希 + 快速选择（按频次） | 期望 $O(n)$ | $O(n)$ | 是 |
| **哈希 + 桶排序** | **$O(n)$ 严格** | $O(n)$ | **是，且最简单** |

快速选择版（对 `(元素, 频次)` 对做划分选第 $m-k$ 小）期望也是 $O(n)$，但需要改动数组、写划分函数；桶排序版把"值域小"这个特性用到极致，代码最短。

## 5. 常见疑问

**疑问一：为什么桶排序在这里可行，215 题里却不推荐？**

桶排序的前提是**排序键的值域可控**。本题的键是"频次"，值域被数组长度死死压在 $[1, n]$，桶数量开得起；215 的键是**元素值本身**，虽然本题数据巧合地限制在 $[-10^4, 10^4]$，可以开 $2 \times 10^4$ 个计数桶，但那是靠数据范围施舍——通用场景下元素值域可以任意大，桶/计数方案就崩了。**看到"排序"先问值域**，是桶排序、计数排序、基数排序共同的入场券。

**疑问二：频次并列怎么办？题目说"答案保证存在"是什么意思？**

约束 $k \le$ 不同元素个数保证了答案总能凑满 $k$ 个元素。真正的疑虑是并列：若第 $k$ 名和第 $k+1$ 名频次相同，取谁？本题题目数据保证**前 $k$ 个高频元素的集合是唯一的**（不存在跨过第 $k$ 名的并列），且返回顺序任意，所以桶排序从高频往低频取、**取满 $k$ 个即停**，天然正确，无需任何并列特判。若去掉这个保证，就要在"频次相同"时引入第二关键字（比较元素值或字典序），参考第 6 节的 LeetCode 692。

**疑问三：堆解法什么时候反而更好？**

两种场景：一是**数据流式到达**（先来一批数、随时问前 k 高，之后还有数进来），桶必须预先知道全部数据才能分桶，堆可以增量维护；二是**内存紧张**且 $k \ll m$，堆只要 $O(k)$（哈希表另计 $O(m)$ 无法省），桶却要整段 $O(n)$。和 215 的结论一致：**离线且值域友好用桶，在线用堆**。

## 6. 相关题目与模板

**可复用模板**（"频次 + 前 k"两段式骨架，桶排序版）：

```cpp
unordered_map<int, int> cnt;
for (int x : nums) cnt[x]++;                 // 第一段：统计（不变）

vector<vector<int>> buckets(nums.size() + 1);
for (auto& [v, c] : cnt) buckets[c].push_back(v);   // 第二段：按键分桶

for (int c = n; c >= 1; c--)                 // 从大到小扫桶收集
    for (int v : buckets[c]) { /* 收集 v，够 k 个停止 */ }
```

第二段是可替换的插槽：换成小根堆就是 $O(n \log k)$，换成快速选择就是期望 $O(n)$，换成 `sort` 就是 $O(n \log n)$——**"统计 + 选前 k"是问题分解，"用什么选前 k"才是考点**。

**方法论总结**：

1. 先把"前 k 高频"识别为"第 k 大"的换皮（哈希把值换成频次）；
2. 再按三个约束选算法：能否改动数据（快选）、是否在线（堆）、键值域是否小（桶）。

**同类题目：**

- [LeetCode 215. 数组中的第K个最大元素](https://leetcode.cn/problems/kth-largest-element-in-an-array/)：本题的前置，快速选择与容量 k 堆的完整分析，见[上一篇](../LeetCode_215/)
- [LeetCode 692. 前 K 个高频单词](https://leetcode.cn/problems/top-k-frequent-words/)：频次相同还要按字典序，桶内必须再排（或堆的自定义比较器），"任意顺序"的红利消失
- [LeetCode 451. 根据字符出现频率排序](https://leetcode.cn/problems/sort-characters-by-frequency/)：本题的"全量版"（$k = m$），桶排序同款
- [LeetCode 973. 最接近原点的 K 个点](https://leetcode.cn/problems/k-closest-points-to-origin/)：前 k 问题去掉哈希、直接对距离快选/堆
- [LeetCode 703. 数据流中的第 K 大元素](https://leetcode.cn/problems/kth-largest-element-in-a-stream/)：在线版，堆的主场

**一句话总结**：前 k 高频 = **哈希统计 + 按"频次"选前 k**；而频次的值域天然是 $[1, n]$，桶排序借这一点绕开所有比较排序，做到严格 $O(n)$。
