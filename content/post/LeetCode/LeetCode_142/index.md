# LeetCode 142. 环形链表 II

> 题目链接：[https://leetcode.cn/problems/linked-list-cycle-ii/](https://leetcode.cn/problems/linked-list-cycle-ii/)  
> 难度：中等  
> 标签：哈希表、链表、双指针

---

## 1. 题目描述

给定一个链表的头节点 `head`，返回**链表开始入环的第一个节点**。如果链表无环，返回 `null`。

同样地，`pos` 仅用于标识环的情况，不会作为参数传递给你（不允许作弊）。进阶：**不允许修改链表**——这直接堵死了"把走过的节点 next 置空"这类取巧做法；你能否用 $O(1)$ 空间解决？

**数据范围：**

- 链表中节点数目 $0 \le n \le 10^4$
- $-10^5 \le Node.val \le 10^5$
- $-1 \le pos \le n - 1$

**示例：**

```
输入：head = [3,2,0,-4], pos = 1

      3 -> 2 -> 0 -> -4
           ^          |
           └──────────┘   （-4 指回节点 2）

输出：返回节点 2（下标 1 的节点，值为 2）
解释：尾节点 -4 连接到其下标 1 的节点，整个环从节点 2 开始。
```

## 2. 思路分析

### 2.1 哈希表：第一个"二刷"的节点就是入口

沿用 [LeetCode 141](https://leetcode.cn/problems/linked-list-cycle/) 的思路并前进一步：遍历时把每个指针存进 `unordered_set<ListNode*>`，每次先查后存。**第一个已经在集合里的节点**，就是第二次被访问的节点——而环的结构决定了从入口开始整段都在环上，所以第一个被重复访问的一定是入口本身。

时间 $O(n)$，空间 $O(n)$。正确性无懈可击，但进阶的 $O(1)$ 空间要求仍然没达到。

### 2.2 第一阶段：快慢指针，先确认有环

与 141 完全相同：`slow` 每次 1 步、`fast` 每次 2 步，若两者相遇则一定有环。难点在第二阶段——**相遇点并不是入口**（示例里相遇在 -4，入口却是 2），怎么办？

先把几何关系量化。设：

- $a$：头节点到环入口的步数；
- $b$：从入口沿前进方向到相遇点的步数；
- $c$：从相遇点继续前进回到入口的步数；
- 环长 $L = b + c$。

### 2.3 第二阶段：一段漂亮的代数

**相遇时刻两者的路程**。`slow` 走了 $a + b$（进环后走到相遇点）；`fast` 速度是两倍、路程至少是两倍，且在环里可能已多绕了 $n$ 圈（$n \ge 1$），共走 $a + b + nL$。由"2 倍速度"列方程：

$$2(a + b) = a + b + nL$$

化简，把 $b$ 换成 $L - c$：

$$a = nL - b = (n-1)L + (L - b) = (n-1)L + c$$

**翻译成人话**：从头走到入口的 $a$ 步，等于"从相遇点走到入口的 $c$ 步"加上整数圈（$(n-1)$ 圈，每圈回到原地）。

于是第二阶段的做法水到渠成：

> 让一个指针 `p1` 从头节点出发、另一个指针 `p2` 从相遇点出发，**每次各走 1 步**。`p1` 走 $a$ 步到达入口时，`p2` 恰好走完 $c + (n-1)L$ 步——也站在入口。**它们相遇的地方就是环的入口**。

用示例 `[3,2,0,-4], pos = 1` 全程走一遍（$a = 1$，环 $2 \to 0 \to -4 \to 2$，$L = 3$）：

| 阶段 | 轮次 | slow | fast | 备注 |
|------|------|------|------|------|
| 一 | 0 | 3 | 3 | 出发 |
| 一 | 1 | 2 | 0 | |
| 一 | 2 | 0 | 2 | |
| 一 | 3 | **-4** | **-4** | 相遇点：$b = 2$（入口 2 走两步到 -4），$c = 1$ |

第二阶段：`p1` 从 3 出发，`p2` 从 -4 出发，同速各走 1 步：

| 轮次 | p1 | p2 |
|------|----|----|
| 1 | **2** | **2** |

一步相遇，交点正是入口节点 2。验证公式：$a = 1$，$c = 1$，$n = 1$，$a = (n-1)L + c = 0 + 1$ ✓。

## 3. 代码实现

```cpp
class Solution {
public:
    ListNode *detectCycle(ListNode *head) {
        // ---- 阶段一：快慢指针判环，并停在相遇点 ----
        ListNode *slow = head, *fast = head;
        while (fast && fast->next) {
            slow = slow->next;
            fast = fast->next->next;
            if (slow == fast) {
                // ---- 阶段二：从头 与 从相遇点 同速前进，交点即入口 ----
                // 依据 a = (n-1)L + c：p1 走 a 步到入口时，
                // p2 恰好走 c 步加整数圈，也到入口
                ListNode *p1 = head, *p2 = slow;
                while (p1 != p2) {
                    p1 = p1->next;
                    p2 = p2->next;
                }
                return p1;   // 环的入口
            }
        }
        return nullptr;   // fast 撞到 null，无环
    }
};
```

几个实现细节：

1. **阶段二的两个指针每次都只走 1 步**。速度必须相同——公式 $a = (n-1)L + c$ 是"同速"前提下的等式，若一个走 2 步等式就不再成立。
2. **`a = 0` 的情形被自然覆盖**。头节点本身就是入口时，阶段一或阶段二的两个指针可能从同一节点出发（或很快相等），`while (p1 != p2)` 判定立即/很快通过，返回的仍是入口，无需特判。
3. **全程只读不改**。没有任何 `next` 的写入，天然满足"不允许修改链表"的要求。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。阶段一同 [LeetCode 141](https://leetcode.cn/problems/linked-list-cycle/)，`slow` 至多走 $a + L \le n$ 步；阶段二两指针各走至多 $a \le n$ 步，总计仍是 $O(n)$ 常数倍。
- **空间复杂度**：$O(1)$。快慢指针加阶段二的两个指针，共四个变量，与哈希表解法的 $O(n)$ 形成对比。

| 解法 | 时间 | 空间 | 是否改链表 |
|------|------|------|------------|
| 哈希表 | $O(n)$ | $O(n)$ | 否 |
| Floyd 两阶段 | $O(n)$ | $O(1)$ | 否 |
| 置空走过的 next | $O(n)$ | $O(1)$ | **是（被禁止）** |

## 5. 常见疑问

**Q1：为什么相遇点不是入口？我直觉它们应该在入口碰头。**

直觉来自"两者速度差固定"——但相遇点由**距离差的具体数值**决定，而不是"哪里该碰头就碰哪里"。用本题验证：$a = 1$，`slow` 进环（到达节点 2）时 `fast` 已走了 2 步、在节点 0；此后两者在环内的差距要靠每轮缩 1 来消除，结果在 -4 处才追上。仅当 $a$ 恰好是 $L$ 的整数倍等特殊情形，相遇点才可能落在入口上。**结论：相遇点位置由 $a$ 与 $L$ 共同决定，一般是环上一个"随机"位置；把交点当入口是本题最高频的错误。**

**Q2：公式里的 $n \ge 1$ 是什么？会不会出现 `fast` 比 `slow` 多绕 0 圈？**

$n$ 是相遇前 `fast` 在环里多转的圈数，至少为 1——原因：`slow` 刚进环时 `fast` 已经在环里（`fast` 先进环且更快），要追上 `slow` 至少要绕到它身后，此过程至少完整地多走一圈周长的量级。$n$ 可以大于 1：当 $a$ 很长、$L$ 很小时，`fast` 可能在 `slow` 进环前已经空转了很多圈。关键是 $(n-1)L$ 这一项**只影响"多绕整数圈"，不影响落点**，所以公式的结论与 $n$ 的具体取值无关——这就是为什么代码里完全不需要知道 $n$。

**Q3：既然哈希表又好写又对，为什么非要学 Floyd？**

两个理由。其一是题目明说的 $O(1)$ 空间。其二是**这套算法能迁移到哈希表无能为力的场景**：[LeetCode 287. 寻找重复数](https://leetcode.cn/problems/find-the-duplicate-number/) 把数组看作"$i \to nums[i]$ 的隐式链表"，重复数即环入口——但那里**值域内重复天经地义、无法用集合判重**（值相同不代表同一个"节点"），哈希表思路直接失效，Floyd 却原封不动可用。判环类问题里，Floyd 是普适工具，哈希表是链表专属的便利解。

## 6. 相关题目与模板

> 📚 哈希表判重思路的整理见模板笔记：[哈希表：从判重到两数之和](../../algorithms/hash_table/)。

**可复用模板**（Floyd 判圈完整版：判环 + 找入口）：

```cpp
ListNode *slow = head, *fast = head;
while (fast && fast->next) {
    slow = slow->next;
    fast = fast->next->next;
    if (slow == fast) {              // 有环，slow 停在相遇点
        ListNode *p = head;
        while (p != slow) {          // 同速前进，交点即入口
            p = p->next;
            slow = slow->next;
        }
        return p;                    // 环入口
    }
}
return nullptr;                      // 无环
```

**方法论**：Floyd 判圈把问题拆成两个阶段——**阶段一用相对速度制造相遇（存在性），阶段二用代数关系定位入口（构造性）**。中间那步 $a = (n-1)L + c$ 的推导值得亲手写一遍：设未知数、按速度关系列方程、消元、翻译回图上意义——这是"数学拯救暴力枚举"的典范。

**一句话总结**：相遇靠的是速度差，找入口靠的是等式 $a = (n-1)L + c$——**从头出发的人和从相遇点出发的人，注定在环的门口会师**。
