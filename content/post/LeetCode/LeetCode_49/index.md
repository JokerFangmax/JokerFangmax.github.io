# LeetCode 49. 字母异位词分组

> 题目链接：[https://leetcode.cn/problems/group-anagrams/](https://leetcode.cn/problems/group-anagrams/)  
> 难度：中等  
> 标签：哈希表、字符串、排序

---

## 1. 题目描述

给你一个字符串数组 `strs`，请将**字母异位词 (anagram)**组合在一起。可以按任意顺序返回结果列表。

字母异位词的定义：由**相同字母重排**后得到的字符串。例如 `"eat"` 和 `"tea"` 互为异位词——都由一个 `e`、一个 `a`、一个 `t` 组成；而 `"tan"` 和 `"nat"` 是另一组。

**数据范围：**

- $1 \le strs.length \le 10^4$
- $0 \le strs[i].length \le 100$
- $strs[i]$ 仅包含小写字母

**示例：**

```
输入：strs = ["eat", "tea", "tan", "ate", "nat", "bat"]
输出：[["bat"], ["nat", "tan"], ["ate", "eat", "tea"]]
解释：
  "ate"、"eat"、"tea" 字母组成相同（a,e,t 各一个），是一组；
  "nat"、"tan" 组成相同（a,n,t 各一个），是一组；
  "bat" 没有搭档，自己一组。

输入：strs = [""]
输出：[[""]]   // 空串也是合法输入，自己一组
```

## 2. 思路分析

### 2.1 暴力：两两判等

对每对字符串 $(s_i, s_j)$ 判断是否互为异位词，是则并入同一组，$O(n^2)$ 对判等，每次判等若用"计数比较"是 $O(L)$（$L$ 为串长）。总计 $O(n^2 L)$，$n = 10^4$ 时约 $10^8 \times L$，必然超时。

而且还有一个工程上的麻烦：判等之外还得维护"分组归属"（并查集或反复合并），逻辑又臭又长。问题的形状其实在提示别的方向——我们不是要做 $n^2$ 次"**两两比较**"，而是想做 $n$ 次"**归类**"。

### 2.2 关键抽象：给每一组找一个"代表名字"

归类问题的通用套路：给每个对象算出一个**键 (key)**，同组对象键相同、异组对象键不同，然后用**哈希表 (hash table)** `键 → 组列表` 把它们倒进去。

所以问题归结为一件事：**怎么给"字母组成"起一个唯一的名字？**

直观候选：

| 候选键 | 同组是否同键 | 异组是否异键 | 计算代价 |
|--------|--------------|--------------|----------|
| 字符串本身 | 否（`eat` ≠ `tea`） | — | 直接失败 |
| 按字典序排序后的串 | 是（`eat`/`tea`/`ate` 都排成 `aet`） | 是 | $O(L \log L)$ |
| 各字母出现次数（计数向量） | 是（都是 `a:1, e:1, t:1`） | 是 | $O(L)$ |

两个候选都成立。验证第一个：`eat → aet`，`tea → aet`，`ate → aet`；`tan → ant`，`nat → ant`；`bat → abt`——不同组排出来不同（排序是双射，字母多重集相同当且仅当排序结果相同），键的合法性得证。

这种"把对象变换成规范形式"的手法叫**规范化 (canonicalization)**：无论输入以什么顺序出现，同一等价类总映射到同一个代表元。

### 2.3 排序键 vs 计数键

- **排序键**：`sort(s.begin(), s.end())`，每次 $O(L \log L)$。$L \le 100$，$\log 100 \approx 7$，常数极小，代码只有一行。
- **计数键**：统计 26 个字母频次，把频次向量编码成字符串（如 `"1#0#0#...#1#1"`，分隔符不能省），每次 $O(L + 26)$。渐进更好，但编码细节容易翻车——见第 5 节疑问一。

本题 $L \le 100$ 的规模下两者差距可忽略，**排序键代码最短、最难写错，是首选**；计数键作为渐进最优解在 $L$ 很大时才体现价值。

### 2.4 操作流程（以示例演示）

`strs = ["eat","tea","tan","ate","nat","bat"]`，用排序键：

| 处理串 | 排序后的键 | 哈希表状态（键 → 组） |
|--------|-----------|----------------------|
| `eat`  | `aet`     | `aet: [eat]` |
| `tea`  | `aet`     | `aet: [eat, tea]` |
| `tan`  | `ant`     | `aet: [eat, tea]`；`ant: [tan]` |
| `ate`  | `aet`     | `aet: [eat, tea, ate]` |
| `nat`  | `ant`     | `ant: [tan, nat]` |
| `bat`  | `abt`     | `abt: [bat]` |

最终表里三个键、三组，输出 `[["eat","tea","ate"], ["tan","nat"], ["bat"]]`，与期望一致。每个字符串只被"看"一次、归一次位，$n^2$ 次比较彻底消失。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<vector<string>> groupAnagrams(vector<string>& strs) {
        unordered_map<string, vector<string>> groups;   // 排序键 -> 原串列表
        for (string& s : strs) {
            string key = s;
            sort(key.begin(), key.end());   // 规范化：字母多重集的规范代表
            groups[key].push_back(s);       // 原串进组，键只当门牌号
        }
        vector<vector<string>> ans;
        ans.reserve(groups.size());
        for (auto& [key, v] : groups)       // 结构化绑定，key 未用到
            ans.push_back(std::move(v));    // move：避免整组字符串被拷贝
        return ans;
    }
};
```

几个实现细节：

1. **键用拷贝出来的 `key`，原串 `s` 原样进组**。不要 `sort(s)` 后直接把 `s` 当键——组里存的是"原样"，键是"规范形"，两者职责不能混。
2. **`groups[key]` 自动建组**。`unordered_map` 的 `operator[]` 在键不存在时会默认构造一个空 `vector`，正好承接 `push_back`，不需要手写"存在则追加否则新建"。
3. **收尾时 `std::move(v)`**。`v` 是 map 里的右值可掏空对象，move 之后内层 `vector` 的指针直接易主，省掉一次性整体拷贝；$10^4$ 组、每组最长 100 字符，这个习惯在此规模已能省下可观的拷贝。

## 4. 复杂度分析

- **时间复杂度**：$O(n \cdot L \log L)$，其中 $n$ 是串数、$L$ 是串长上限。每串排序 $O(L \log L)$、哈希插入均摊 $O(L)$（键的哈希与比较都是 $O(L)$）。本题 $n = 10^4, L = 100$，约 $10^4 \times 100 \times 7 \approx 7 \times 10^6$ 次字符操作，轻松通过。换计数键可降到 $O(n \cdot (L + 26))$。
- **空间复杂度**：$O(n \cdot L)$。哈希表里存的就是全部字符串本身（键是它们的排序副本，总量与原串同级）。

方案对比：

| 方案 | 时间 | 额外空间 | 备注 |
|------|------|----------|------|
| 暴力两两判等 | $O(n^2 L)$ | $O(1)$ | 超时 |
| 排序键 + 哈希 | $O(n L \log L)$ | $O(n L)$ | 代码最短 |
| 计数键 + 哈希 | $O(n (L + 26))$ | $O(nL)$ | $L$ 大时更优 |

## 5. 常见疑问

**疑问一：计数编码为什么必须加分隔符？**

有人把频次直接拼数字：`abb` 计数是 `a:1,b:2`，拼成 `"12"`；但 `"ac"`（`a:1,c:1`... 等等，26 位里 b 是 0）拼出来也可能是 `"1..."` 中间夹 0。真正的冲突例子：频次向量 `[1, 12]` 拼成 `"112"`，而 `[11, 2]` 拼成 `"112"`——两个不同向量撞了同一个键，会把不该同组的串分到一起。分隔符（如 `"1#12"` vs `"11#2"`）或者定宽补零（`"01102"`）都能消除歧义。凡是"把序列拼成字符串当键"，都要先问一句：**编码是不是单射？**

**疑问二：为什么不能用"字符异或和 / 乘积"当键？**

经典的哈希直觉：把每个字符映射成质数（a=2, b=3, c=5, ...），串的字母组成对应质数乘积，组成相同则乘积相同。这个键**同组必同键**，没问题；但"异组必异键"由算术基本定理保证的前提是**不溢出**——26 个字母取到 `z`（第 26 个质数 101）时乘积天文数字般膨胀，取模又会制造碰撞（不同组成同余数）。排序键是构造性证明的双射，质数乘积是"看起来优雅"的陷阱。

**疑问三：空串和单字符串怎么处理？**

什么都不用做。空串排序后还是空串，键为 `""`，`unordered_map` 完全支持空键，所有空串自动归为一组；单字符串同理，键就是它自己。规范化方案的优点正在于此：**边界情况的正确性是免费的**，不需要任何 `if (s.empty())` 特判。

## 6. 相关题目与模板

> 📚 系统整理见模板笔记：[哈希表：从查找配对到计数分组](../../algorithms/hash_table/)。

**可复用模板**（"规范化键 + 哈希分组"骨架，等价类归类问题通用）：

```cpp
unordered_map<string, vector<T>> groups;
for (auto& x : items) {
    auto key = canonicalize(x);   // 同等价类 -> 同一键（双射才安全）
    groups[key].push_back(x);
}
// values 即为所有等价类
```

写 `canonicalize` 时只需自问两句话：**同组的对象算出的键相同吗？不同组的对象键一定不同吗？**两问都过，分组就正确。
