# LeetCode 45. 跳跃游戏 II

> 题目链接：[https://leetcode.cn/problems/jump-game-ii/](https://leetcode.cn/problems/jump-game-ii/)  
> 难度：中等  
> 标签：贪心、数组

---

## 1. 题目描述

给定一个长度为 `n` 的非负整数数组 `nums`，你最初位于第一个下标。每个元素 `nums[i]` 表示从下标 `i` 最多可以跳多远（可以少跳）。**题目保证你一定可以到达最后一个下标**，返回到达下标 $n - 1$ 的**最少跳跃次数**。

**数据范围：**

- $1 \le nums.length \le 10^4$
- $0 \le nums[i] \le 1000$
- 题目保证可以到达 `nums[n - 1]`

**示例：**

```
输入：nums = [2,3,1,1,4]
输出：2
解释：先跳 1 步到下标 1（值 3），再跳 3 步到下标 4，共 2 步。
     注意不能直接从 0 跳 2 步到下标 2 再跳 1 步到 3 再跳 1 步到 4 —— 那是 3 步。

输入：nums = [2,3,0,1,4]
输出：2
解释：0 -> 1 -> 4（借下标 1 的 3 步能力直达终点）。
```

---

## 2. 思路分析

### 2.1 暴力与 DP：从"每个位置的最少步数"出发

定义 $dp[i]$ 为到达下标 $i$ 的最少步数，则 $dp[i] = \min\limits_{j + nums[j] \ge i,\; dp[j] \text{ 可达}} dp[j] + 1$。朴素实现是 $O(n^2)$：对每个 $i$ 回头扫所有能跳到它的 $j$。$n = 10^4$ 时约 $10^8$ 量级，勉强但难看；更重要的是它没有利用本题的关键结构——**跳跃能力的区间性**。

也可以抽象成图做 BFS：每个下标向它能到的所有位置连边，求 $0$ 到 $n-1$ 的最短路。边数同样 $O(n^2)$，但因为 BFS 分层的单调性，队列中每层是**一段连续区间**——这就引出了正解。

### 2.2 关键观察：步数相同的可达点恰好是一段连续区间

按 BFS 的分层视角看：

- 用 $k$ 步**恰好能到达**的下标构成一段连续区间，记为 $[\text{left}_k, \text{right}_k]$；
- 用 $k+1$ 步能到达的区间，就是 $[\text{left}_k, \text{right}_k]$ 内所有点跳跃范围的并集再拼上——由于每个点的跳跃范围 $[i+1,\; i+nums[i]]$ 本身连续，并上后依然连续，且新区间左端就是 $\text{right}_k + 1$。

于是"分层 BFS"退化成**双指针扫区间**：扫过当前层的每个点时顺便算出下一层的右端点 `farthest`，即

$$\text{farthest} = \max_{\text{left}_k \le i \le \text{right}_k} (i + nums[i])$$

扫描指针 $i$ 每跨过当前层的右边界 `curEnd`，步数 `steps` 加一，同时当前层右边界更新为已算好的 `farthest`。**这就是贪心：不关心下一跳具体落在哪，只关心下一跳最远能铺到哪里。**

### 2.3 贪心为什么最优

设贪心第 $k$ 跳后的覆盖区间右端为 $R_k$。用归纳法：任何方案（包括最优方案）$k$ 步能达到的所有下标都不超过 $R_k$。

- 归纳基础：$R_0 = 0$，显然。
- 归纳步骤：若某方案第 $k+1$ 步到达了 $j$，则它第 $k$ 步停在某个 $i \le R_k$（归纳假设），而 $j \le i + nums[i] \le R_{k+1}$（因为 $i$ 在贪心扫描的当前层内，$R_{k+1}$ 正是该层所有点 $i + nums[i]$ 的最大值）。

于是贪心的覆盖半径**永远不劣于任何方案**：终点第一次被罩住时，所用步数不可能比最优解多。配合"步数少于 $k$ 时覆盖半径必然更小"（上述命题的逆否），贪心跳数即最少步数。

### 2.4 手动模拟（以示例 1 走一遍）

`nums = [2,3,1,1,4]`，$n = 5$：

| $i$ | $nums[i]$ | $i + nums[i]$ | 跨层？ | `curEnd` | `farthest` | `steps` |
|---|---|---|---|---|---|---|
| 0 | 2 | 2 | —（第 0 层只有自己） | 0 | 2 | 0 |
| 1 | 3 | 4 | $i = 1 > \text{curEnd} = 0$，进入第 1 层 | **2** | 4 | **1** |
| 2 | 1 | 3 | 未跨层 | 2 | 4 | 1 |
| 3 | 1 | 4 | $i = 3 > \text{curEnd} = 2$，进入第 2 层 | **4** | 4 | **2** |
| — | — | — | `curEnd = 4 = n - 1`，终点已罩住，结束 | — | — | — |

分层视角：第 0 步覆盖 $\{0\}$；第 1 步覆盖 $[1, 2]$；第 2 步覆盖 $[3, 4]$，终点入层，答案 $2$。

注意循环只需扫到 $i \le n - 2$：指针走到 $i = n - 1$ 说明终点所在层已经"进入"，再步数加一就多算了。

## 3. 代码实现

```cpp
class Solution {
public:
    int jump(vector<int>& nums) {
        int n = nums.size();
        int steps = 0;        // 已用的跳跃次数
        int curEnd = 0;       // 当前这一步（第 steps 层）能覆盖到的右边界
        int farthest = 0;     // 扫过当前层后，下一层能覆盖到的右边界
        for (int i = 0; i < n - 1; i++) {          // 只扫到 n-2，见下
            farthest = max(farthest, i + nums[i]); // 预告下一层的右端
            if (i == curEnd) {                     // 走完当前层全部点
                steps++;                           //   必须再跳一步
                curEnd = farthest;                 //   换用下一层的边界
                if (curEnd >= n - 1) break;        //   终点已罩住，收工
            }
        }
        return steps;
    }
};
```

实现细节：

1. **循环上界是 `n - 1` 而不是 `n`**。若扫到 $i = n-1$ 且恰好 $i == \text{curEnd}$，会多算一步"从终点出发的跳跃"。保证可达的前提下，`i == curEnd && i == n-1` 只会发生在终点已入当前层、无需再跳的情形。
2. **`i == curEnd` 用 `==` 即可，不必 `>=`**。`curEnd` 每次更新后都保证 $\ge$ 下一层的起点，扫描指针不会越过它而不触发；不过写成 `>=` 是无害的防御式编程。
3. **`farthest` 与 `curEnd` 必须分离**。`farthest` 是"下一层"的候选边界（还在积累中），`curEnd` 是"当前层"的既定边界；若混用一个变量，会在层内中途提前换边界，导致少算步数。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。每个下标进入扫描一次，常数操作；`steps` 至多增加 $n$ 次。
- **空间复杂度**：$O(1)$。三个整型变量，没有显式 BFS 队列与 DP 数组。

对比演进：朴素 DP / BFS $O(n^2)$ → 分层贪心 $O(n)$。优化来源是发现"BFS 的每一层是一段连续区间"，从而把整层状态压成两个端点。

## 5. 常见疑问

**Q1：这不就是 BFS 吗？贪心体现在哪？**

结构上确实是隐式 BFS，但实现上我们从不记录"每个节点属于哪一层"，只维护两个端点（`curEnd` 与 `farthest`）——因为同层节点永远连续。贪心体现在**选下一跳时只看"能把下一层铺到最远"的那个点**，而最优性由 2.3 的覆盖半径归纳保证。可以说这是"贪心正确性恰好可以用 BFS 分层来证明"的漂亮例子。

**Q2：为什么不怕中途出现"断层"（某层 `farthest` 追不上下一层起点）？**

因为题目**保证可达**。在保证下，`farthest` 在层内必然能把边界推到 `curEnd` 之后；若去掉这个保证（如 [LeetCode 55](https://leetcode.cn/problems/jump-game/)），就要加 `if (farthest <= i) return -1;` 一类的判断。两题共用骨架、差一个可达性检查，正是"读条件"的价值。

**Q3：第 1 步跳到哪里真的不重要吗？**

不重要，而且这正是贪心的省力之处。以示例 1 为例：第 0 步后覆盖 $[0,2]$，其中下标 1 能跳到 4、下标 2 只能跳到 3——看似"必须选中下标 1"。但对步数而言，我们只关心"第 2 步的覆盖右端是 $\max(4, 3) = 4$"；具体跳到哪个点，留给后续层去消化（反正下一层区间是连续的，包含最优落点）。**决策被推迟、信息被合并**，这就是区间贪心比逐点 DP 快的本质。

## 6. 相关题目与模板

**可复用模板**（跳跃/覆盖类"最少步数"骨架）：

```cpp
// 求最少跳跃次数（题目保证可达）
int steps = 0, curEnd = 0, farthest = 0;
for (int i = 0; i < n - 1; i++) {
    farthest = max(farthest, i + nums[i]);
    if (i == curEnd) {                 // 当前层耗尽
        steps++;
        curEnd = farthest;
        if (curEnd >= n - 1) break;
    }
}
```

同一骨架略作改造可解"最少区间覆盖指定长度"一类问题（如跳跃游戏 VII 的可达判定、视频拼接），核心都是**维护当前覆盖边界与下一覆盖边界这两个量**。

**同类题目：**

- [LeetCode 55. 跳跃游戏](https://leetcode.cn/problems/jump-game/)：先修题，只判可达、不问步数（`../LeetCode_55/`）
- [LeetCode 1024. 视频拼接](https://leetcode.cn/problems/video-stitching/)：区间版"跳跃"，`[start, end]` 代替 `i + nums[i]`，贪心策略完全同构
- [LeetCode 1326. 灌溉花园的最少水龙头数目](https://leetcode.cn/problems/minimum-number-of-taps-to-open-to-water-a-garden/)：每个水龙头覆盖一个区间，求覆盖 $[0, n]$ 的最少数量，同样套"curEnd/farthest"骨架
- [LeetCode 1306. 跳跃游戏 III](https://leetcode.cn/problems/jump-game-iii/)：跳跃规则破坏了区间连续性（可往回跳），只能老老实实 BFS——对照之后更能体会本题贪心条件的可贵

**一句话总结**：跳跃游戏 II 是一层一层往外铺的隐式 BFS——每层是一段连续区间，于是队列消失，只剩 `curEnd` 和 `farthest` 两个指针轮换推进。
