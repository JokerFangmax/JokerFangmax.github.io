# LeetCode 1. 两数之和

> 题目链接：[https://leetcode.cn/problems/two-sum/](https://leetcode.cn/problems/two-sum/)  
> 难度：简单  
> 标签：哈希表、数组

---

## 1. 题目描述

给定一个整数数组 `nums` 和一个整数目标值 `target`，请在该数组中找出**和为目标值**的那两个整数，并返回它们的**数组下标**。

题目保证：

- 恰好存在**一个**有效答案（不会出现多个解或无解）；
- 同一个元素**不能重复使用**（即不能返回 $[i, i]$，两个下标必须不同）；
- 可以按任意顺序返回答案。

**数据范围：**

- $2 \le nums.length \le 10^4$
- $-10^9 \le nums[i] \le 10^9$
- $-10^9 \le target \le 10^9$
- 只会存在一个有效答案

**示例：**

```
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：nums[0] + nums[1] = 2 + 7 = 9，返回 [0, 1]。

输入：nums = [3,3], target = 6
输出：[0,1]
解释：值相同但下标不同的两个 3 也可以组成答案。
```

## 2. 思路分析

### 2.1 暴力：枚举所有数对

最直接的做法：两层循环枚举 $(i, j)$（$i < j$），检查 $nums[i] + nums[j] = target$ 是否成立。

$$\binom{n}{2} = \frac{n(n-1)}{2} \text{ 对候选}$$

$n = 10^4$ 时约 $5 \times 10^7$ 对，C++ 能过但已经不体面；若 $n$ 放大到 $10^5$ 就必然超时。更本质的问题是：**每个元素被反复拿出来和其他所有元素配对，而每次配对只回答了一个极小的局部问题**。

观察一下暴力在做什么：固定 $i$ 后，我们其实在问"数组里有没有一个数等于 $target - nums[i]$？"——这是一个**查找问题**，而暴力用 $O(n)$ 的线性扫来回答它。查找有更快的武器。

### 2.2 排序 + 双指针？

熟悉双指针的同学会想到：排序后左右指针从两端向中间夹。排序 $O(n \log n)$，夹逼 $O(n)$，总体 $O(n \log n)$，确实快于暴力。

但这道题有一个致命细节：**答案要的是原始下标**。排序会打乱下标，必须额外记录每个值原来的位置，排序、夹逼得到两个值之后还要回到原数组里找回下标；再叠加"值可以重复"（示例 2 的两个 3），找回下标的逻辑容易出错。

排序 + 双指针是"两数之和"家族里 167 题（有序数组版）的标准解法，但对本题这种"返回原始下标"的变体并不合身。我们换一个不打乱任何东西的思路。

### 2.3 哈希表：把查找降到 $O(1)$

回到 2.1 末尾的观察：固定一个数 $x$，要找的是 $target - x$。"出现过哪些值"用一个**哈希表 (hash table)**维护：`值 → 下标`。

两种组织方式：

| 方案 | 流程 | 问题 |
|------|------|------|
| 先建表再查询 | 全量插入哈希表，再对每个 $x$ 查 $target - x$ | 查到自己（$target = 2x$ 且 $x$ 只出现一次）时需特判下标不同 |
| 边查边插入（一遍哈希） | 对每个 $x$，先查 $target - x$ 是否已在表中，再插入 $x$ | 天然避免用到自己；且能正确处理重复值 |

**一遍哈希**更优雅。它为什么能正确处理重复值？看示例 2（`nums = [3,3], target = 6`）：处理第一个 3 时表是空的，没查到，插入；处理第二个 3 时，查 $6 - 3 = 3$，命中第一个 3 的下标 0——两个 3 在不同的时刻分别扮演了"被查者"和"查询者"，自然不会是同一个元素。

### 2.4 操作流程（以示例演示）

`nums = [2,7,11,15], target = 9`，哈希表内容随遍历演进：

| i | nums[i] | 先查 target - nums[i] | 表中已有（值→下标） | 动作 |
|---|---------|----------------------|---------------------|------|
| 0 | 2       | 查 7：未命中         | （空）              | 插入 2→0 |
| 1 | 7       | 查 2：命中下标 0     | 2→0                 | 返回 [0, 1] |
| 2 | 11      | （已返回）           | —                   | — |
| 3 | 15      | （已返回）           | —                   | — |

答案 $[0, 1]$，正确。注意遍历到 7 时查的是 2——**它是几步之前插入的**，哈希表把"过去看过的数"全部留在了桌面上，随取随用，这正是它优于暴力的地方。

## 3. 代码实现

```cpp
class Solution {
public:
    vector<int> twoSum(vector<int>& nums, int target) {
        unordered_map<int, int> seen;   // 值 -> 下标
        for (int i = 0; i < (int)nums.size(); i++) {
            int need = target - nums[i];            // 我需要的搭档
            auto it = seen.find(need);
            if (it != seen.end())
                return {it->second, i};             // 搭档在过去，一定比 i 早
            seen[nums[i]] = i;                      // 先查后插：绝不匹配到自己
        }
        return {};   // 题目保证有解，走不到这里
    }
};
```

几个实现细节：

1. **先查后插，顺序不能反**。如果先把 $nums[i]$ 插入再查 $target - nums[i]$，当 $target = 2 \times nums[i]$ 时会查到自己，返回 $[i, i]$。先查后插从机制上根除了这个错误。
2. **用 `find` 而不是两次 `operator[]`**。`seen[need]` 在键不存在时会**插入一个默认值**，既慢又污染表；`find` 只读不写。
3. **`it->second` 在前、`i` 在后**。一遍哈希命中的必然是更早的元素，按 $[小, 大]$ 返回下标，语义更自然（题目其实允许任意顺序）。

## 4. 复杂度分析

- **时间复杂度**：$O(n)$。一次遍历，每轮做一次哈希查找和一次哈希插入，`unordered_map` 两者均摊都是 $O(1)$（值的范围 $10^9$ 无所谓，哈希表按值哈希，与值域大小无关）。
- **空间复杂度**：$O(n)$。最坏情况下（答案由最后两个元素组成）表里存了 $n - 1$ 个键值对。

演进路线汇总：

| 解法 | 时间 | 空间 | 备注 |
|------|------|------|------|
| 暴力枚举 | $O(n^2)$ | $O(1)$ | 每个数组都能写对，但面试不够 |
| 排序 + 双指针 | $O(n \log n)$ | $O(n)$ | 需找回原始下标，易错 |
| **一遍哈希** | $O(n)$ | $O(n)$ | 用空间换时间的教科书示范 |

## 5. 常见疑问

**疑问一：为什么"先查后插"就不会用重复元素？**

因为查询的对象永远是"**过去**插入的元素"。处理 $nums[i]$ 时，表里只有 $nums[0..i-1]$，命中者下标必然 $< i$；而 $nums[i]$ 自己要等到本轮查询结束后才进表，物理上不可能匹配到自己。示例 2 的两个 3 正是靠这个时序被正确配对的。

**疑问二：值有重复时 `seen[nums[i]] = i` 会不会覆盖出问题？**

会覆盖——同值键只保留**最新**下标，但这不影响正确性：若答案是两个同值元素 $a + a = target$，第二个 $a$ 查询时命中的是第一个 $a$（那时还没被覆盖）；若答案不是同值配对，覆盖旧的只是丢弃一个永远不会被查到的候选。换句话说，被覆盖的下标只可能匹配与它同值的后来者，而后来者真正查询时用的是"未被覆盖前的命中机会"，已经提前发生了。

**疑问三：为什么不用 `map`（红黑树）？**

`std::map` 的查找是 $O(\log n)$，总体变 $O(n \log n)$，功能上等价但渐进更慢。本题不需要有序性（不需要按值范围查询、不需要顺序遍历），`unordered_map` 是更对口的工具。当键需要有序遍历（如"最小覆盖子串"里按字符统计）时才考虑有序容器。

## 6. 相关题目与模板

> 📚 系统整理见模板笔记：[哈希表：从查找配对到计数分组](../../algorithms/hash_table/)。

**可复用模板**（"一遍哈希找搭档"骨架，适用于所有"在数组里找满足二元关系的两个元素"）：

```cpp
unordered_map<int, int> seen;               // 值 -> 附加信息（下标/计数/...）
for (int i = 0; i < n; i++) {
    if (seen.count(需要的搭档)) { /* 用 seen[搭档] 与 i 组合出答案 */ }
    seen[nums[i]] = i;                      // 或 seen[nums[i]]++
}
```

这个骨架的要点：**查询发生在插入之前**，让"当前元素"与"历史元素"配对，天然避免自配对并正确处理重复。

**同类题目：**

- [LeetCode 167. 两数之和 II - 输入有序数组](https://leetcode.cn/problems/two-sum-ii-input-array-is-sorted/)：数组已有序，双指针 $O(n)$、$O(1)$ 空间——2.2 节方案的正统主场
- [LeetCode 15. 三数之和](https://leetcode.cn/problems/3sum/)：排序 + 固定一个数后双指针；哈希去重反而不讨好
- [LeetCode 454. 四数相加 II](https://leetcode.cn/problems/4sum-ii/)：四个独立数组，两两分组用哈希表统计和——"两数之和"的分组推广
- [LeetCode 560. 和为 K 的子数组](https://leetcode.cn/problems/subarray-sum-equals-k/)：前缀和 + 哈希表，把"找搭档"思想推广到区间上（本站题解：[../LeetCode_560/](../LeetCode_560/)）

**一句话总结**：两数之和教会我们的是——**当暴力在反复回答同一个查找问题时，把查找对象装进哈希表，让每一轮的 $O(n)$ 查找坍缩成 $O(1)$**。
