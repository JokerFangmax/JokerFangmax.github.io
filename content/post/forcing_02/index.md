# 为什么 Transformer 需要两遍解码

## 1. 这篇论文解决什么问题

[01](../forcing_01/) 的 Scheduled Sampling 在 RNN 解码器上是顺手的：训练本来就是一个 token 一个 token 算，每步抛硬币换一下「上一步 token」的来源即可。Transformer 有两个结构性差异，让这套照搬失效（论文 §1、§3）：

| | RNN 解码器 | Transformer 解码器 |
|---|---|---|
| 生成第 $t$ 个词的条件 | 上一个词（局部） | **整个前缀**（self-attention 全连接） |
| 训练时的计算 | 逐步串行 | 整个目标序列**一次前向并行**（因果掩码下） |

困难在鸡生蛋：若想在训练时把位置 $j$ 的输入换成「模型自己的预测」，这个预测本身依赖位置 $j$ 之前的输入——而它们可能也已被替换。RNN 里时间步天然串行，逐位替换顺理成章；Transformer 的并行前向没有「先算位置 $j$ 的预测、再喂给位置 $j+1$」这个中间时机。此前没有任何把 SS 搬上 Transformer 的方案发表。

本文贡献（论文自列三条）：

1. 提出训练时**两遍解码**（two-pass decoding）的 Transformer SS 方案；
2. 系统比较「用模型预测代替金标词」时的多种表示方式（Embedding Mix）；
3. 在两个语言对的机器翻译上达到**接近教师强制基线**的结果（部分模型小幅提升，论文自述最多约 1 个 BLEU 点）。

## 2. 最小背景

- [01. Scheduled Sampling](../forcing_01/)：抛硬币逐 token 混合真实历史与模型预测；$\epsilon_i$ 三种调度（linear/exponential/inverse sigmoid）。本篇全盘继承调度思想，改变的是混合发生在哪一遍前向里；
- **Transformer 解码器**：输入为右移的目标序列嵌入 + 位置编码；因果掩码（causal mask）保证位置 $i$ 只注意 $\le i$ 的位置；训练时一次前向并行算出所有位置的分数——教师强制的并行性正是要保护的对象；
- **Goyal et al., 2017（可微 SS）**：把「模型预测」表示为按输出分数加权的全部词嵌入平均（带温度 softmax 或 Gumbel softmax），从而能对采样决策回传梯度，在 RNN 上超过了标准 SS——本篇的 Embedding Mix 与梯度变体直接继承这条线。

## 3. 方法总览

**一句话主线**：编码器不动；解码器在训练时跑两遍（两遍**共享同一套参数**）——第一遍吃金标目标序列，像标准教师强制一样并行得到**每个位置**的预测分数；随后一个并行的混合步骤逐位置抛硬币，决定第二遍的条件序列里放金标 token 还是第一遍的预测表示，教师强制概率 $t(i)$ 随训练步数按线性调度退火；第二遍吃这条「新参考序列」，它的输出才是真正参与损失的预测，对其算交叉熵（论文 Figure 1）。

| 步骤 | 输入 | 输出 | 论文位置 |
|---|---|---|---|
| 第一遍解码 | 金标目标序列（标准教师强制前向） | 每个位置对全词表的分数 $s_{i-1}$ | §3.1 步骤 1 |
| 混合 | 金标序列 + 第一遍分数 | 「新参考序列」：逐位置金标 token 或预测表示 | §3.1 步骤 2 |
| 第二遍解码 | 混合序列 | 最终预测（参与交叉熵损失） | §3.1 步骤 3 |

三个容易看漏的点：

1. **两遍解码器同参数**——不是两个模型，是同一个解码器跑两次，参数更新来自两遍合起来的图；
2. **混合发生在嵌入层**：第二遍的条件序列是「金标嵌入与预测表示逐位置拼接」的序列，位置编码照常相加，因果掩码照常生效；
3. **第一遍的条件是纯金标前缀**——预测是在教师强制分布下做的，不是在混合历史下做的。这个近似正是 [03](../forcing_03/) 要用多轮迭代修正的对象（§7）。

## 4. 核心原理完整推导

### 4.1 为什么逐位置替换在并行前向里不成立

设第二遍某位置 $j$ 的输入应为 $\tilde{e}_j$（金标 $e(y_j)$ 或模型预测 $\bar{e}_j$）。若 $\tilde{e}_j$ 取预测，它来自第一遍位置 $j$ 的输出分数 $s_j$；而第一遍位置 $j$ 的输出又依赖第一遍位置 $<j$ 的输入。要求**一次**前向同时算出所有位置，就必须让「位置 $j$ 的替换值」在位置 $j+1$ 计算之前可得——并行计算里不存在这个先后。两遍解码的解法是把这依赖拆成两帧：第一遍统一在**金标**条件下产出全部预测（依赖链是已知的金标前缀，可并行），第二遍在**固定好的**混合序列上再并行一次。

### 4.2 混合步骤与线性调度

对每个位置 $i$，以教师强制概率 $t$ 放金标 token $y_{i-1}$，以 $1-t$ 放第一遍的预测表示 $\bar{e}_{i-1}$。$t$ 是训练步数 $i$ 的函数，论文比较了 [01](../forcing_01/) 的三种调度后选定**线性衰减**效果最好（论文 Eq. 1）：

$$
t(i) = \max\{\epsilon,\ k - ci\},
\tag{Eq.1}
$$

其中 $0 \le \epsilon < 1$ 是教师强制概率下限，$k$、$c$ 分别是偏置与衰减斜率。论文 §5 的经验：指数与 inverse sigmoid 衰减**降得太快**，模型性能过早退化——即对 Transformer 而言，前期保持更久的纯教师强制、之后更慢的退火是必要的（这也与 [01](../forcing_01/) 语音实验「退火终点选错代价大」的观察一致）。

### 4.3 Embedding Mix：预测表示的五种构造

第一遍给出每个位置对全词表的分数 $s_{i-1}$。当某位置要用「模型预测」时，用哪个向量表示它？

| 变体 | 构造 | 特点 |
|---|---|---|
| Argmax | 最高分词的嵌入 | 最接近 [01](../forcing_01/) 的离散替换；不可微（对第一遍无梯度可言） |
| Top-k 混合 | **top-5** 分数词嵌入的加权平均 | 介于 argmax 与全表混合之间 |
| 带温度 softmax | 全词表嵌入按温度 softmax 加权（下式） | 可微；温度 $\alpha$ 越高越接近 argmax |
| Gumbel softmax | 分数加 Gumbel 噪声后再 softmax 加权 | 可微且**随机**（采样的连续松弛） |
| Sparsemax | sparsemax 加权（Martins & Astudillo, 2016） | 稀疏支撑集的第三种归一化 |

带温度 softmax 混合（论文 §3.2 中未编号的公式）：

$$
\bar{e}_{i-1} = \sum_{y} e(y)\, \frac{\exp\big(\alpha\, s_{i-1}(y)\big)}{\sum_{y'} \exp\big(\alpha\, s_{i-1}(y')\big)}
$$

直觉：把「选一个词」松弛成「按分数给所有词的嵌入加权平均」；$\alpha \to \infty$ 时退化回 argmax，$\alpha$ 小时得到平滑的「软词向量」。Gumbel 版本在指数里加独立噪声 $G_y$（$U \sim \mathrm{Uniform}(0,1)$，$G = -\log(-\log U)$），使混合结果成为一次**可回传梯度的采样**——这是 Goyal et al. (2017) 的直接移植。

### 4.4 梯度路径：截断还是贯通

损失是第二遍输出的交叉熵。对第一遍（产出预测表示的那遍）有两种处理（论文 §3.3）：

| 变体 | 第一遍的梯度 | 对应谱系 |
|---|---|---|
| **不回传**（默认） | 第一遍的分数 $s_{i-1}$ 被视为常数（事实上的 stop-gradient），梯度只走第二遍 | 对应 [01](../forcing_01/) 的做法（采样决策不回传） |
| **回传** | 梯度穿过混合表示 $\bar{e}_{i-1}$ 继续下探到第一遍 | 对应 Goyal et al. (2017) 的可微 SS |

论文 Figure 1 用粗/细箭头区分两条路径：粗箭头（第二遍）在所有实验里都回传，细箭头（第一遍）只在部分实验回传。理论上回传更「正确」（[01](../forcing_01/) 的 §4.4 分析过：截断后目标有偏）；实验结果恰恰相反（§6）——回传版全面劣化，这是本篇最值得琢磨的负结果。

### 4.5 这个方案在优化什么

<details>
<summary><b>展开：两遍解码的目标函数及其近似误差</b></summary>

形式化（我的整理，论文未显式写出）：记第一遍在金标前缀下的分数为 $s_{i-1} = \mathrm{Dec}_\theta(y_{1:i-1})$，混合序列 $\tilde{y}$ 逐位置取 $y_j$（概率 $t(i)$）或预测表示 $\bar{e}_j = g(s_j)$。损失为

$$
\mathcal{L}(\theta) = -\sum_{i} \log p_\theta\big(y_i \mid \tilde{y}_{1:i-1},\ x\big), \qquad \tilde{y}_j = \begin{cases} y_j & \text{概率 } t(i)\\ g\big(\mathrm{Dec}_\theta(y_{1:j})\big) & \text{概率 } 1-t(i) \end{cases}
$$

与 [01](../forcing_01/) 的 SS 相比多了一层近似：**预测表示 $\bar{e}_j$ 是在金标前缀 $y_{1:j}$ 下算的**，而推理时模型的条件历史是混合的/自身的。换言之第二遍看到的「模型预测」只反映模型在干净前缀下的错误，不反映错误复合后的错误——exposure bias 只被治了一半。

补救思路正是多轮迭代：让第 $k$ 轮的预测以第 $k-1$ 轮的混合历史为条件，逐轮逼近真实的采样解码——这就是 [03](../forcing_03/) 的 Parallel SS（其单轮 $K=1$ 情形与本篇两遍解码同构），并且 [03](../forcing_03/) 给出了收敛定理。可以在本篇的框架里预告：本篇 = 03 的 $K=1$ 特例（差别只在混合的是嵌入表示还是采样的 token）。

另一个值得注意的点：**argmax 变体在离散替换下等价于 03 的 $K=1$、且第一遍不可微**——但它的成绩（DE-EN dev 23.99）远差于软混合（35.19），说明在两遍框架里，「预测表示保留分布信息」比「逼真地模拟离散替换」更重要。

</details>

## 5. 训练与推理细节

推理完全不变：标准自回归解码（beam 或 greedy）。训练侧除了两遍前向与混合，其余与教师强制基线一致。

| 实验 | DE-EN dev | DE-EN test | JA-EN dev | JA-EN test |
|---|---|---|---|---|
| 教师强制基线 | 35.05 | 29.62 | 18.00 | 19.46 |
| **不回传第一遍** | | | | |
| Argmax | 23.99 | 20.57 | 12.88 | 15.13 |
| Top-k 混合 | **35.19** | 29.42 | **18.46** | 20.24 |

<details>
<summary><b>展开：四条读表结论与论文自己的解释</b></summary>

1. **Argmax 崩、软混合活**：硬替换（argmax）DE-EN dev 只有 23.99（基线 35.05），而一切「保留分布信息」的混合表示（top-k/softmax/Gumbel/sparsemax）都回到 35.2 上下。离散替换把第一遍的单点错误无保留地灌进第二遍条件；软平均则天然带平滑，误差被词表维度的平均稀释；
2. **软混合 + 不回传 ≈ 基线，个别略胜**：DE-EN dev 上全部软混合变体（35.07–35.36）都压过基线 35.05，JA-EN dev 上 top-k（18.46）等部分变体压过 18.00（softmax $\alpha{=}10$ 的 17.79 反而更低）；test 上 DE-EN 全部略输（最高 29.58 vs 29.62）、JA-EN 全部略赢（top-k 20.24、Gumbel $\alpha{=}10$ 20.87 vs 19.46）。论文的措辞是「接近基线、对进一步探索有前景」——增益是边际性的，不是碾压；
3. **可微版（回传第一遍）全面劣化，且温度越高越惨**：Gumbel $\alpha{=}10$ 崩到 DE-EN test 10.62。论文推测是「性能开始退化的时间太早」——梯度贯通第一遍后，早期训练就被混合噪声拖垮；作者预期「前期更多纯教师强制步 + 更慢退火」能救回来，但未验证；
4. **温度的双刃**：不回传时 $\alpha{=}1$ 与 $\alpha{=}10$ 差别不大；回传时 $\alpha{=}10$（更接近 argmax、梯度更尖锐）明显更差。

</details>

## 8. 局限与个人评价

- **只治了一半的 exposure bias**：第一遍在金标前缀下做预测，第二遍的条件里从未出现「错误复合」的历史（§4.5）——模型仍没见过推理时真实的多步错误链。这个缺陷要到 [03](../forcing_03/) 的多轮结构与后续 Self Forcing 才真正解决；
- **增益边际且不稳**：DE-EN test 上所有变体都**低于**基线（最高 29.58 vs 29.62）；dev 领先是否来自按 dev 选 checkpoint 的选择偏差，论文未讨论。两个小语言对（IWSLT/KFTT）的结论外推性有限；
- **可微化的失败没有被解释**：论文只给了「退化太早」的现象描述与「调整调度也许能救」的猜想，没有消融验证——为什么 RNN 上有效的可微 SS（Goyal et al.）在 Transformer 上崩坏，是个遗留问题；
- **两遍前向的代价未报告**：训练步时间相对基线慢多少、两遍的显存开销，论文都没有数字（[03](../forcing_03/) 的同构实现实测单轮比教师强制慢约 25%，可作参照）；
- **个人评价**：这是一篇诚实的小论文——贡献是把 SS 在 Transformer 上的**结构性障碍**说清楚了（鸡生蛋问题 + 并行性），方案朴素（两遍 + 软混合），结论克制（「接近基线」）。它最大的价值是给 [03](../forcing_03/) 铺了两块砖：两遍解码的框架，以及「软表示优于硬 argmax」的经验（03 反其道用采样 token 也成功了，说明多轮条件下答案不同）。负结果（可微化劣化）同样值得收录：梯度贯通不是免费的午餐，早期训练稳定性可能比目标的理论正确性更优先。
