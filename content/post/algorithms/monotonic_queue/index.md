# 单调队列：滑动窗口最值与决策单调性

> 本篇是刷题沉淀的算法模板之一。核心思想一句话：**及时丢弃永远不可能再成为答案的候选者——"比我早来还比我弱"的元素，余生与我无关。**

---

## 1. 从滑动窗口最值说起

问题（[LC 239. 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/)）：长度为 $k$ 的窗口从左往右逐格滑动，随时报告窗口最大值。

暴力是每个窗口重扫 $O(k)$，总 $O(nk)$。但窗口每步只**一进一出**，大量信息本可复用。前提观察是窗口的淘汰顺序：

> **先进窗口的元素先离开**——元素从右端进、左端出，而左端正是最早进入的，窗口和队列一样是先进先出。

于是考察一个场景：

```
窗口内:  [ ... , 1 , ... , 3 , ... ]    （1 比 3 先进窗口，且 1 ≤ 3）
```

1 会比 3 **先**离开窗口。这意味着在 1 余下的整个生命周期里，3 始终在场且不小于 1——**1 永远当不上最大值**，存它纯属浪费。

反过来不成立：若是 `[... , 3 , ... , 1 , 2 , ...]`（3 先进，1、2 后来且更小），1、2 并**没有**被判死刑——3 出界后它们就可能接班，所以必须存着。这也解释了为什么弹队尾的方向是"新元素淘汰先来的弱者"，而不是相反。

推广成维护规则，就得到单调队列：

> 队列存**下标**，对应值从队头到队尾**递减**（求最大值时）。新元素入队前，把队尾所有 $\le$ 它的元素弹掉；队头下标滑出窗口时弹出。**队头永远是当前窗口最大值。**

### 1.1 为什么必须是 deque

两种弹的方向相反：

- **队尾弹**：新元素来了，淘汰"早来且更弱"的（维护单调性）；
- **队头弹**：队头下标出界了，淘汰过期的。

普通队列只有一端进一端出，两头都要弹只能用双端队列 `deque`。

### 1.2 可视化演示

`nums = [1, 3, -1, -3, 5, 3, 6, 7]`，`k = 3`。

**记号**：`3@1` 读作"下标 1 处的值 3"。队列从左（队头）到右（队尾）严格递减；每个代码块的第一行画出当前窗口——`[ ... ]` 括住的就是窗口内的元素。

---

**i = 0，新元素 1**

```
窗口: [ 1 ]  3  -1  -3   5   3   6   7        （不足 3 个，不产出答案）
弹尾: 队列为空，无
队列: 1@0
```

**i = 1，新元素 3**

```
窗口: [ 1  3 ] -1  -3   5   3   6   7
弹尾: 1@0 ≤ 3 → 弹出
      （1 比 3 早进窗口 → 会比 3 先离开；余生里 3 一直在场且 ≥ 1，
        1 永远当不上最大值 —— 这就是"早来且不大于后来者"的死刑判决）
队列: 3@1
```

**i = 2，新元素 −1**

```
窗口: [ 1  3  -1 ] -3  5  3  6  7             （窗口凑满，开始产出）
弹尾: 3@1 > −1 → 不弹
      （−1 是"后来的弱者"，不判死刑：3 出界后它还有接班机会）
队列: 3@1  →  3@1, -1@2
输出: 队头 = 3 ✓
```

**i = 3，新元素 −3**

```
窗口:  1 [ 3  -1  -3 ] 5  3  6  7
弹尾: -1@2 > −3 → 不弹（同理，留着接班）
过期: 队头 3@1，窗口左界 = i−k+1 = 1，1 未出界 → 不弹
队列: 3@1, -1@2, -3@3
输出: 队头 = 3 ✓
```

**i = 4，新元素 5**（本步是最精彩的一步）

```
窗口:  1  3 [ -1  -3  5 ] 3  6  7
弹尾: -3@3 ≤ 5 → 弹
      -1@2 ≤ 5 → 弹
       3@1 ≤ 5 → 弹     （5 太强，一口气清空全队，连队头都没保住）
过期: 队头已是 5@4，显然在窗口内 → 不弹
队列: 5@4
输出: 队头 = 5 ✓
```

**i = 5，新元素 3**

```
窗口:  1  3  -1 [ -3  5  3 ] 6  7
弹尾: 5@4 > 3 → 不弹
队列: 5@4, 3@5
输出: 队头 = 5 ✓
```

**i = 6，新元素 6**

```
窗口:  1  3  -1  -3 [ 5  3  6 ] 7
弹尾: 3@5 ≤ 6 → 弹
       5@4 ≤ 6 → 弹
过期: 队头 6@6 在窗口内 → 不弹
队列: 6@6
输出: 队头 = 6 ✓
```

**i = 7，新元素 7**

```
窗口:  1  3  -1  -3  5 [ 3  6  7 ]
弹尾: 6@6 ≤ 7 → 弹
队列: 7@7
输出: 队头 = 7 ✓
```

**最终答案**：`[3, 3, 5, 5, 6, 7]`，与暴力核对一致。

---

回看这 8 步，盯住三件事就抓住了全部要点：

1. **弱者分两种命运**：`-1`、`-3` 跟在 `3` 后面进队，比 `3` 小却**被保留**——它们是"后来的弱者"，等 `3` 出界后有机会接班；而 `1@0` 被弹掉，因为它是"**早来的弱者**"，被判了死刑。弹尾规则杀的只是后者。
2. **i = 4 的教训**：新元素 5 强到把队头一起清掉。所以代码里"过期检查"必须放在取答案之前，且不能假设上一轮的队头仍然活着。
3. **队列始终严格递减**：任何时刻队头就是窗口最大值——取答案永远是 $O(1)$ 读队头，不需要任何扫描。

## 2. 模板

### 2.1 定长滑动窗口最值（通用骨架）

```cpp
deque<int> dq;                          // 存下标；求最大值，值从队头到队尾递减
vector<int> ans;
for (int i = 0; i < n; i++) {
    // 1. 维护单调性：弹掉队尾所有 <= nums[i] 的（它们永远翻不了身）
    while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();
    dq.push_back(i);
    // 2. 淘汰过期：队头已滑出窗口 [i-k+1, i]
    if (dq.front() <= i - k) dq.pop_front();
    // 3. 窗口成型后队头即答案
    if (i >= k - 1) ans.push_back(nums[dq.front()]);
}
```

求**最小值**只需把弹尾条件改成 `>=`（值从队头到队尾递增）。

### 2.2 实现细节清单

1. **存下标，不存值**——"队头是否过期"只有下标能回答；
2. **操作顺序固定**：弹尾 → 入队 → 队头过期检查 → 取答案，顺序乱了会 WA；
3. 弹尾用 `<=`（求 max 时）保持**严格**递减，相等元素只留后进的那个（它活得久）。用 `<` 也能对，只是队列稍长；
4. 过期判断用 `if` 即可：一轮最多一个下标出界（窗口每步只挪一格）。若窗口一次跳多格，改成 `while`。

### 2.3 复杂度

均摊 $O(n)$：每个下标**最多入队一次、出队一次**（从队尾被弹或从队头过期），总操作数 $\le 2n$。空间 $O(k)$：队列严格单调，长度不超过窗口大小。

## 3. 第二大应用：单调队列优化 DP

凡是转移形如

$$
dp[i] = \min_{\,i-k \le j < i}\{\, dp[j] \,\} + cost(i) \qquad \text{（max 同理）}
$$

即"从前面一个**滑动区间**里取最值再转移"，都可以用单调队列把每步转移的 $O(k)$ 降到均摊 $O(1)$，总复杂度 $O(nk) \to O(n)$。

**与窗口最值的联系**：决策候选 $j$ 的范围 $[i-k, i-1]$ 正是一个随 $i$ 单调右滑的窗口——本质完全相同，只是队列里存的从前缀和变成了 `dp[j]`。

### 3.1 模板

```cpp
deque<int> dq;                          // 存 j，dp[j] 从队头到队尾递增（取 min）
for (int i = 0; i < n; i++) {
    // 决策 j 的合法范围随 i 滑动：这里以 j >= i - k 为例
    while (!dq.empty() && dq.front() < i - k) dq.pop_front();
    dp[i] = dp[dq.front()] + cost(i);   // 最优决策在队头（dq 非空前提）
    while (!dq.empty() && dp[dq.back()] >= dp[i]) dq.pop_back();
    dq.push_back(i);
}
```

代表题：

- [洛谷 P1886. 滑动窗口](https://www.luogu.com.cn/problem/P1886)（模板题，max/min 双练）
- [洛谷 P1725. 琪露诺](https://www.luogu.com.cn/problem/P1725)（跳跃 DP，决策区间滑动）
- 多重背包：体积为 $v$、数量 $m$ 的物品，按余数分组后每组是"滑动取最大"结构，单调队列把 $O(nvm)$ 优化到 $O(nv)$
- [洛谷 P3800. Power 收集](https://www.luogu.com.cn/problem/P3800)（二维版）

## 4. 与单调栈的关系

两者是同一思想在不同场景的投影：

| | 单调栈 | 单调队列 |
|---|--------|---------|
| 结构 | 一端进出 | 两端都可出 |
| 淘汰时机 | 当前元素到来时一次性淘汰 | 到来时淘汰（尾）+ 过期时淘汰（头） |
| 典型问题 | 下一个更大元素、柱状图最大矩形 | 滑动窗口最值、DP 优化 |
| 复杂度 | 均摊 $O(n)$ | 均摊 $O(n)$ |

共同本质：**一旦某个元素被"更强且更持久"的后来者覆盖，它就永远不会再被用到，立即丢弃。**单调栈没有"过期"概念（查询不随时间滑走），单调队列多了一个队头淘汰维度。

单调栈入门题：[LC 739. 每日温度](https://leetcode.cn/problems/daily-temperatures/)、[LC 84. 柱状图中最大的矩形](https://leetcode.cn/problems/largest-rectangle-in-histogram/)。

## 5. 什么时候该想到单调队列

1. **定长滑动窗口的最值**（LC 239 原型）；
2. **DP 转移里出现"前一个滑动区间内取最值"**；
3. **带"过期/出界"机制的候选集合维护**——本质是"存下标 + 双端淘汰"，形式可以很活，如 LC 862 用单调队列排除"更早且前缀和更大（即又长又差）"的决策。

一个易混点：**前缀和做不到区间最值**（$\max$ 不可逆，减法移除不了贡献），别用 `prefixMax` 去解窗口最值——详见[前缀和](../prefix_sum/)一文第 2 节。
