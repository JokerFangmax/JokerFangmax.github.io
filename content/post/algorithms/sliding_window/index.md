# 滑动窗口：单调性判据与三种基本形态

> 本篇是刷题沉淀的算法模板之一。核心思想一句话：**两个指针都只向右走、永不回退，用增量更新代替重新计算——$O(n^2)$ 的枚举降为 $O(n)$ 的双指针扫描。**

---

## 1. 适用判据：先验证单调性，再写代码

滑动窗口不是"题目长得像窗口就能用"。设谓词 $P(l, r)$ 表示"窗口 $[l, r]$ 满足条件"，滑动窗口可行当且仅当 $P$ 具有**双向单调性**：

> - **扩张保真**：$P(l, r)$ 为真 ⟹ 向**任一端**扩张（$r' \ge r$ 或 $l' \le l$）后仍为真（加元素，条件不会由真变假）；
> - **收缩保假**（逆否）：$P(l, r)$ 为假 ⟹ 向**任一端**收缩（$r' \le r$ 或 $l' \ge l$）后仍为假（删元素，条件不会由假变真）。

> ⚠️ 方向易写反："为假 ⟹ 扩张后仍为假"不成立——窗口变大、元素变多，原本不满足的可能变得满足。能传递给更大窗口的是"真"，能传递给更小窗口的是"假"。这两条合起来才是双指针不回退的完整依据：固定 $r$ 时合法的 $l$ 构成前缀，且该前缀的右端点 $l_{\max}(r)$ 随 $r$ 单调不减。

直觉检验法：**把"纳入一个元素"和"移出一个元素"分别代入条件，若两个方向都不会产生反例，滑窗成立；任何一边出现反例，立即换思路**（通常是前缀和 + 哈希表，见[前缀和](../prefix_sum/)）。

### 1.1 三道题的对照

| 题 | 条件 | 单调性 | 结论 |
|----|------|--------|------|
| [LC 76. 最小覆盖子串](../../LeetCode/LeetCode_76/) | 窗口覆盖 `t` 的字符频次 | ✅ 加字符只会更接近覆盖 | 滑窗 $O(n)$ |
| [LC 209. 长度最小的子数组](https://leetcode.cn/problems/minimum-size-subarray-sum/) | 窗口和 ≥ target（元素全正） | ✅ 加正数和增、减正数和减 | 滑窗 $O(n)$ |
| [LC 560. 和为 K 的子数组](../../LeetCode/LeetCode_560/) | 窗口和**恰好**为 `k`（元素含负） | ❌ 加负数和变小，双向都有反例 | 前缀和 + 哈希表 |

### 1.2 常见条件形态速查

- **"至多 / 至少"型**（不同元素 ≤ k 个、和 ≥ target、覆盖某频次）→ 天然单调，滑窗主力；
- **"恰好"型**（和恰好为 k）→ 一般不单调；例外是元素全非负时"和 ≤ k"单调，可先求"至多"再用容斥 `恰好(k) = 至多(k) − 至多(k−1)`；
- **窗口内最值**（LC 239）→ 与单调性无关的问题，滑窗框架照用，但窗口状态要用[单调队列](../monotonic_queue/)维护。

## 2. 形态一：定长窗口

窗口长度 $k$ 固定，右端逐格右移，每个位置问一次窗口指标。要点是**"进一个、出一个"的增量更新**，绝不每步重扫：

```cpp
// 滑动计数（字符频次，数组版），LC 438 / 567
int cnt[128] = {};
for (int i = 0; i < n; i++) {
    cnt[s[i]]++;                              // 进
    if (i >= k) cnt[s[i - k]]--;              // 出（数组版归零也无妨）
    if (i >= k - 1) { /* 用 cnt 判断窗口性质 */ }
}
```

- 频次用**数组**（字符集小）或 `unordered_map`（键稀疏）；
- map 版注意：计数归零后要 `erase`，否则 `mp.size()`（常用来表示"不同元素个数"）会失真——详见[哈希表](../hash_table/)模式②；
- 定长窗口求**最值**则换单调队列（见其模板 2.1 节）。

代表题：[LC 438. 找到字符串中所有字母异位词](https://leetcode.cn/problems/find-all-anagrams-in-a-string/)、[LC 567. 字符串的排列](https://leetcode.cn/problems/permutation-in-string/)、[LC 1052. 爱生气的书店老板](https://leetcode.cn/problems/grumpy-bookstore-owner/)、[LC 1423. 可获得的最大点数](https://leetcode.cn/problems/maximum-points-you-can-obtain-from-cards/)（反向：固定"剩窗口"）。

## 3. 形态二：求满足条件的**最短**窗口

扩张到条件满足，然后收缩到不能再缩，收缩过程中记录答案（[LC 76](../../LeetCode/LeetCode_76/)、LC 209 原型）：

```cpp
int l = 0, best = INT_MAX;
for (int r = 0; r < n; r++) {
    /* 纳入 s[r]，增量更新窗口状态 */
    while (/* 条件满足 */) {
        best = min(best, r - l + 1);          // 答案在收缩循环内记录
        /* 移出 s[l]，增量更新窗口状态 */
        l++;
    }
}
```

**答案记录位置**是这类题的标志：收缩的每一步都可能是最优解，所以必须在内层 `while` 里记录，而不是等收缩结束。

LC 76 的完整实现（欠账计数 `less` 维护覆盖性，$O(1)$ 判断）见[题解](../../LeetCode/LeetCode_76/)第 3 节。

代表题：[LC 209](https://leetcode.cn/problems/minimum-size-subarray-sum/)、[LC 76](../../LeetCode/LeetCode_76/)、[LC 1234. 替换子串得到平衡字符串](https://leetcode.cn/problems/replace-the-substring-for-balanced-string/)。

## 4. 形态三：求满足条件的**最长**窗口

与形态二镜像：**扩张直到条件被打破，然后在条件不满足时收缩**，答案在收缩完成后（窗口合法时）记录：

```cpp
int l = 0, best = 0;
for (int r = 0; r < n; r++) {
    /* 纳入 s[r]，增量更新窗口状态 */
    while (/* 条件被打破 */) {
        /* 移出 s[l]，增量更新窗口状态 */
        l++;
    }
    best = max(best, r - l + 1);              // 答案在收缩循环外记录
}
```

代表题：[LC 3. 无重复字符的最长子串](https://leetcode.cn/problems/longest-substring-without-repeating-characters/)（条件：每字符 ≤ 1 个）、[LC 424. 替换后的最长重复字符](https://leetcode.cn/problems/longest-repeating-character-replacement/)（条件：长度 − 最高频 ≤ k）、[LC 1004. 最大连续 1 的个数 III](https://leetcode.cn/problems/max-consecutive-ones-iii/)（条件：0 的个数 ≤ k）。

### 4.1 形态二与形态三的对照

| | 求最短（形态二） | 求最长（形态三） |
|---|---|---|
| 收缩时机 | 条件**满足**时收缩 | 条件**被打破**时收缩 |
| 记录答案 | 收缩循环**内** | 收缩循环**外**（窗口合法时） |
| 条件方向 | "至少"型（覆盖、和 ≥ x） | "至多"型（个数 ≤ k、无重复） |

一个非对称的观察：为什么"最短"配"至少"、"最长"配"至多"？因为答案必然产生在**条件满足的边界**上——"至少"条件满足后越缩越短（答案在收缩侧），"至多"条件满足时越长越好（答案在扩张侧）。

## 5. 工程细节清单

1. **增量更新是灵魂**：每步只处理"进"和"出"的两个元素，任何"窗口变化后重新计算"的写法都退化为暴力；
2. **指针永不回退**是复杂度的保证：两指针各走 $n$ 步，总代价 $O(n)$，与"每个元素最多进窗一次、出窗一次"的单调队列均摊分析同构；
3. 条件判断尽量维护成**一个整型变量**（LC 76 的 `less`、LC 3 的"重复字符数"），避免每次遍历状态结构；
4. 计数结构选择：字符集小 → 数组；键稀疏 → `unordered_map`（注意归零 `erase`）；
5. **先在纸上验证单调性再动手**——把扩张/收缩代入条件找反例，比写完代码调试快得多。
